# 17 - PvP、匹配与竞争结构

> **本章目标**：搞清楚匹配系统的原理和它真正解决的问题（不是"公平"，是"留存"），以及排行榜/分段/赛季的结构性作用。
> **本章有模型**：`models/m17_matchmaking.py`

---

## 1. 先想清楚：你的 PvP 是零和的吗

```
   纯零和：我赢的就是你输的（排位赛、掠夺、领土争夺）
   非零和：双方都有收获（切磋、演武、共同挑战）
```

**零和 PvP 的根本问题**：每一场都制造一个输家。而输家的负面情绪强度是赢家正面情绪的两倍（第 02 章的损失厌恶）。

> **纯零和的竞技系统，情绪总量天然是负的。**

所以所有成功的 PvP 系统都会想办法**注入非零和成分**：

| 手段 | 例子 |
|---|---|
| 败方也有奖励 | 参与奖、连败补偿、赛季累计积分 |
| 把损失限制在可承受范围 | 掠夺有上限、失败不掉道具、保护罩 |
| 提供非战斗的价值 | 战报、排名、赛季纪念、观赏性 |
| 让"输"有信息价值 | 看到对手配置，下次改进 |

**SLG 尤其需要注意**：SLG 的 PvP 往往伴随实际资源损失（兵损 + 被掠夺），是"负和"的——双方都有损失。这时候必须靠**掠夺收益**和**荣誉/领土**把总收益拉回来，否则玩家会集体选择不打（第 16 章的鹰鸽博弈）。

## 2. 匹配系统真正解决的是留存问题

```bash
cd models && python m17_matchmaking.py
```

2000 名玩家（真实实力正态分布），三种匹配策略跑 30 天：

```
策略                  留存率   评分-实力相关   胜率标准差   胜率<35%的玩家
---------------------------------------------------------------------
A 随机匹配            20.9%       0.842        0.211        41.9%
B Elo 匹配            53.5%       0.881        0.093         6.2%
C Elo + 连败保护      59.3%       0.898        0.120        13.6%
```

**随机匹配的留存只有 Elo 匹配的 40%。**

原因很直接：随机匹配下有 **41.9% 的玩家胜率低于 35%**，他们持续挨打，然后离开。Elo 匹配把这个比例降到 6.2%。

> **匹配系统的目的不是"公平"，是让尽可能多的玩家维持在 50% 附近的胜率。**
> 50% 胜率对应第 02 章的心流通道——赢一半输一半，才有持续的紧张感和成就感。

### 2.1 一个反直觉的读法

注意方案 C：留存最高（59.3%），但"胜率 <35% 的玩家"比例（13.6%）反而**高于**方案 B（6.2%）。

这不矛盾。**连败保护让那些本来会流失的弱者留了下来**，所以他们还在样本里，把低胜率的比例拉高了。

> **这是数据解读的一个经典陷阱：留存改善会让"弱势玩家占比"上升，因为他们没走。**
>
> 如果你只看"低胜率玩家比例"这个指标，会得出"C 比 B 差"的错误结论。**必须同时看留存，或者用固定同期群（cohort）来对比。** 第 23 章会讲这类幸存者偏差。

## 3. 三种评分系统

### 3.1 Elo

```
期望胜率:  E_a = 1 / (1 + 10^((R_b − R_a) / 400))
更新:      R_a' = R_a + K × (实际结果 − E_a)
```

- **400** 这个常数的含义：分差 400 时，高分方的期望胜率是 **10/11 ≈ 91%**；分差 200 时约 76%。
- **K 因子**决定收敛速度和稳定性的权衡：K 大则收敛快但波动大，K 小则稳定但新玩家要打很久才能到正确位置。**常见做法是新玩家用大 K，老玩家用小 K。**

**Elo 的局限**：

1. 假设玩家实力恒定（实际会成长）；
2. 只支持 1v1；
3. 没有"不确定性"的概念——打了 5 场和打了 500 场的 1600 分，可信度完全不同，但 Elo 一视同仁。

### 3.2 Glicko

在 Elo 基础上加了 **RD（Rating Deviation，评分偏差）**，表示系统对这个评分的置信度：

- 新玩家 RD 大 → 评分变动幅度大（快速定位）；
- 长期不玩 RD 会重新变大（因为实力可能变了）；
- RD 小的玩家评分稳定。

**这解决了 Elo 最大的痛点。** Glicko-2 还加了 volatility（波动性）参数。

### 3.3 TrueSkill

微软为 Xbox 开发，**贝叶斯方法**：每个玩家的实力建模为一个高斯分布（均值 μ = 估计实力，标准差 σ = 不确定性）。

**核心优势：原生支持多人和团队。** 它能从团队比赛结果反推每个成员的个人实力贡献，这是 Elo 和 Glicko 做不到的。TrueSkill 2 进一步引入了个人表现数据（击杀、伤害等）。

### 3.4 选型

| 场景 | 建议 |
|---|---|
| 1v1，玩家实力稳定 | **Elo** 足够，实现最简单 |
| 1v1，玩家活跃度差异大 | **Glicko-2** |
| 多人 / 团队 | **TrueSkill** 或其变体 |
| 数值型 PvP（战力主导） | **都不合适**，见第 4 节 |

## 4. 数值型 PvP 的特殊问题

这是 SLG 和卡牌最需要注意的一点。

**Elo 系这一套评分系统的前提假设是：胜负由"技术"决定，而技术是缓慢变化的。**

但在数值型 PvP 里：

- 胜负主要由**战力**决定，而战力是**可以用钱快速买到的**；
- 一个玩家昨天充了 6000 块，今天战力翻倍——他的 Elo 完全跟不上；
- 反过来，玩家可以**故意输**来降低评分，然后去虐更弱的对手（**掉分养号**）。

**四种应对手段：**

| 手段 | 说明 | 代价 |
|---|---|---|
| **直接用战力匹配** | 战力就是实力的直接度量，不需要推断 | 无法反映操作/阵容/策略差异 |
| **战力 + Elo 混合** | 战力做粗筛，Elo 做细分 | 实现复杂 |
| **战力分段 + 段内 Elo** | 主流做法 | 段位边界处体验差 |
| **限制掉分收益** | 低分段的奖励远低于高分段，让养号不划算 | 治标 |

> **对付掉分养号的根本方法是让"低分段"没有价值可拿**——奖励要和分段强相关，且赛季奖励按最高分段结算而非结算时分段。

## 5. 匹配质量 vs 等待时间

这是每个匹配系统都要面对的权衡：

```
   匹配范围窄 → 对手水平接近 → 体验好，但要等很久
   匹配范围宽 → 立刻开打     → 但可能被碾压
```

**标准解法是"逐步放宽"**：

```
   等待 0~10 秒： 只匹配 ±50 分
   等待 10~30 秒：放宽到 ±150 分
   等待 30~60 秒：放宽到 ±400 分
   超过 60 秒：   匹配机器人 / 提示稍后再试
```

**几条实践要点：**

- **放宽速度要和当前在线人数挂钩**。凌晨三点和晚上八点的匹配池大小差一个量级，用同一套参数必然出问题；
- **高分段的匹配池天然稀疏**——顶端玩家可能只有几十个人，必须为他们单独设计（更宽的范围、更长的等待、或者跨服匹配）；
- **异步 PvP 可以绕过这个问题**：不匹配真人，而是匹配对手的"阵容快照"由 AI 操作。SLG 和卡牌大量使用这种方式，代价是缺少真人对抗的临场感。

## 6. 排行榜、分段、赛季的结构作用

这三样东西经常被当作"UI 功能"，实际上它们是**竞争结构的骨架**。

### 6.1 排行榜：把连续的实力分布切成可见的名次

| 类型 | 作用 | 风险 |
|---|---|---|
| **全服总榜** | 给顶端玩家目标 | 99% 的玩家永远上不去，对他们无意义 |
| **分段榜 / 分组榜** | 让每个人都有"够得着"的名次 | 需要合理的分组规则 |
| **好友榜 / 联盟榜** | **最有效的一类**——熟人比较的驱动力远强于陌生人 | 小群体内可能形成压力 |
| **周期榜（周/赛季）** | 给落后者重新开始的机会 | 会制造周期性的冲刺压力 |

> **如果你只能做一个榜，做好友榜。** 人对身边的人的名次远比对全服第一敏感。

### 6.2 分段：制造"可达成的阶梯"

分段的本质是把连续的评分离散化，好处有三：

1. **降低理解成本**："黄金 III"比"1487 分"更有意义；
2. **提供阶段性目标**（第 02 章的目标梯度效应）；
3. **允许保护机制**——比如"段位不掉级"、"每个大段有保护"。

**分段人数分布的设计**：常见做法是做成金字塔（底部人多、顶部人少），但**不要太尖**——如果最高段只有 0.1% 的人，那么 99.9% 的玩家会觉得它不存在。

一个可用的参考分布：底部两段各占 20%~25%，中段各 10%~15%，顶段 1%~3%。`【推导】`

### 6.3 赛季：定期重置的价值

赛季重置的作用（第 22 章会完整展开）：

| 作用 | 说明 |
|---|---|
| **给落后者机会** | 重置后大家距离缩短，重新开始有希望 |
| **给领先者续命** | 第 04 章讲的"成长感耗尽"，重置让 `d(ln y)/dt` 重新变大 |
| **制造周期性收入** | 每个赛季一轮通行证和商品（第 14 章） |
| **提供数值调整窗口** | 赛季更替是唯一可以大改数值而不引发暴动的时机 |
| **天然的 sink** | 赛季货币清零（第 06、08 章） |

**代价**：重置会让老玩家的积累贬值。所以几乎所有赛季制都会保留一部分**跨赛季的永久积累**（收藏、称号、部分等级），来平衡"重新开始"和"我的投入没白费"。

## 7. 避免"强者恒强"

这是竞争系统的头号杀手：领先者拿到更多资源 → 变得更强 → 拿到更多资源。**这是第 03 章的正反馈回路，出现在竞争结构里。**

**六种刹车机制：**

| 机制 | 说明 | 副作用 |
|---|---|---|
| **匹配隔离** | 强者只和强者打 | 最基本，必须有 |
| **奖励递减** | 打赢比自己弱的对手收益极低 | 减少欺凌，但也减少了强者的活跃 |
| **保护期** | 新手/弱者有免战期 | 可能被滥用（挂保护罩） |
| **失败补偿** | 连败给补偿、失败也给积分 | 削弱竞争强度 |
| **数量对抗质量** | 多人集结可以打赢单个强者（第 05 章） | 需要协调机制 |
| **周期重置** | 赛季 | 老玩家可能觉得贬值 |

**第 5 条对 SLG 最关键。** 第 05 章讲过：`N` 个人集结的总战力是线性相加还是次线性，决定了人海战术是否有效。

> **如果你希望免费玩家有生存空间，集结战力必须接近线性相加。**
> 如果你希望个人战力主导，就用次线性。**这一个参数决定了你的服务器是"人多的赢"还是"钱多的赢"。**
