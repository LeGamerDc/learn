# 21 - 版本迭代与数值膨胀

> **本章目标**：理解数值膨胀为什么是必然的、它的速度该由谁定、以及"老玩家保值"和"新人能追上"这两个目标为什么在数学上不可兼得。
> **本章有模型**：`models/m21_power_creep.py`

---

## 1. 数值膨胀是必然的，不是失误

第 04 章 7.2 节那道题已经推导过一次，这里正式总结：

```
① 玩家感知到的成长 ≈ 战力的对数增量（第 02 章）
② 要维持恒定的成长感，战力必须指数增长（第 04 章）
③ 但等级/进度曲线是对数形态的（成本增速 > 产能增速）
④ 所以单靠已有养成线，战力对时间只是幂函数增长，成长感必然衰减
⑤ ⇒ 必须不断增加新的养成线，每条新线重新拉起一波成长感
⑥ ⇒ 战力总量必然指数膨胀
```

**这不是策划失控，是维持体验的数学必然。** 你能决定的只有**速度**，不能决定要不要。

**因此，把"控制数值膨胀"理解成"让数字别涨那么快"是错的。** 正确的理解是：

> **数值膨胀的速度，是一个在"老玩家保值"和"新人能追上"之间的取舍参数。**

## 2. 同一个参数的正反两面

```bash
cd models && python m21_power_creep.py
```

模型设定：每 30 天一个版本，新版本内容的战力价值是上个版本的 `r` 倍，跑 2 年（25 个版本）。

```
膨胀率 r    最新版占比   新人需补版本数   ≈老玩家多少天的积累   一年前积累的保值率
--------------------------------------------------------------------------
1.00         4.0%        22 个            660 天            52.0%
1.05         6.8%        19 个            570 天            37.1%
1.10        10.0%        16 个            480 天            24.9%
1.15        13.5%        13 个            390 天            16.1%
1.20        16.8%        11 个            330 天            10.3%
1.30        23.1%         8 个            240 天             4.2%
1.40        28.6%         6 个            180 天             1.7%
```

**读这张表要同时看最后两列——它们是同一个参数的正反面：**

- **膨胀慢（r=1.00）**：老玩家一年前的积累还值 52%，很保值。但新人要补 22 个版本、相当于 660 天的积累才能追上——**基本等于追不上**。
- **膨胀快（r=1.40）**：新人只要补 6 个版本就能追上老玩家的 85%。但老玩家一年前的积累只剩 **1.7%** ——**等于白玩了一年**。

> **你不可能同时让老玩家保值、又让新人容易追上。这两件事在数学上就是同一个参数的两端。**

模型最后跑了一个搜索：

```
=== 同时满足「新人 ≤ 90 天追上」和「一年积累保值 ≥ 40%」的 r 区间 ===
  空集
```

**没有任何膨胀率能同时满足这两个（都不算苛刻的）目标。** 这不是参数没调好，是结构性的——只要"老玩家持续累积、新人从零开始"这个结构不变，就无解。

**结构性的解法在第 22 章：赛季重置。** 它直接消灭了"老玩家持续累积"这个前提。

## 3. 膨胀速度怎么定

既然是取舍，就要看你的产品优先什么：

| 优先 | 建议 r（月度） | 年化膨胀 | 适合 |
|---|---|---|---|
| **老玩家体验** | 1.03~1.08 | 1.4× ~ 2.5× | 长线口碑产品、玩家沉淀深的品类（MMO） |
| **平衡** | 1.08~1.15 | 2.5× ~ 5.3× | 大多数产品 |
| **新增导入** | 1.15~1.25 | 5.3× ~ 15× | 强买量驱动、需要持续导入新用户 |
| **赛季制** | 单赛季内可以很低 | — | 靠重置解决，见第 22 章 |

`【推导】`——这些区间来自模型的两端约束，不是行业公开数据。

**三个额外的判断依据：**

**① 你的买量占比。** 买量导入的新玩家越多，越需要高膨胀（让他们追得上）。纯自然量/口碑产品可以低膨胀。

**② 你的付费深度。** 高付费深度的产品，大 R 的积累量巨大，膨胀会让他们的投入贬值得更快——**大 R 对贬值最敏感，因为他们花的是真钱**。

**③ 你的品类的社交黏性。** 社交黏性强（SLG）的产品，老玩家不完全靠战力留存，可以承受更高的膨胀；单机向的卡牌则不行。

## 4. 新养成线怎么接入

每个大版本加一条新养成线是主流做法。**四条设计规则：**

### 规则 1：新线要能立刻带来可感知的战力提升

否则玩家不会去练（第 05 章：战力权重决定玩家行为）。**具体做法**：新线开放时给一批"启动资源"，让玩家能立刻推进几层，尝到甜头。

### 规则 2：材料要提前铺垫

第 20 章 6 节讲过这个技巧：新线消耗的材料从开放前 2~3 周就开始少量投放。**玩家开放当天手里有存货，可以立刻爽一次。**

### 规则 3：不要废掉旧线，要让旧线成为新线的前置

**错误做法**：新线完全独立，旧线的投入变成沉没成本 → 老玩家愤怒。
**正确做法**：新线的解锁/效率与旧线的进度挂钩 → 旧线的投入被"继承"了。

> 比如"觉醒系统需要装备强化 +15 才能开启"——老玩家的强化投入立刻变成了新系统的入场券，而不是废纸。

### 规则 4：战力公式要预留接口

第 05 章讲过：**战力公式做成"各模块之和"的形式**，新增模块只是加一项。如果战力是个复杂的耦合公式，每加一条线都要重算全服战力，而战力数字的任何非预期变动都是舆情事故。

## 5. 旧内容的贬值处理

新版本上线，旧内容必然贬值。**怎么处理决定了老玩家的感受。**

| 手段 | 说明 | 适用 |
|---|---|---|
| **转化/继承** | 旧材料按比例换成新材料 | **最优**，玩家感觉投入没白费 |
| **保底价值** | 旧装备可分解成新系统的资源 | 次优 |
| **重新定位** | 旧内容变成新玩法的入场券（规则 3） | 优雅，但要提前设计 |
| **直接淘汰** | 旧内容变成垃圾 | **尽量避免**；如果必须，给补偿 |

**一条实用原则**：**任何一次大改动，都要给老玩家一个"我的投入被承认了"的信号**——哪怕这个信号的实际价值不高。称号、纪念品、优先兑换权都行。**这是心理账户的问题，不是数值问题。**

## 6. 数值重构：什么时候该做，代价是什么

数值重构（等级压缩、属性重置、公式重做）是核弹级操作。

**什么时候不得不做：**

| 信号 | 说明 |
|---|---|
| **数值溢出** | 战力突破了数据类型上限（第 04 章的大数问题） |
| **新老断层无法弥合** | 新人怎么都追不上，导入的用户全流失 |
| **战斗公式失效** | 比如减法公式下出现了普遍的不破防（第 05 章） |
| **玩家已看不懂数字** | 战力 9 位数以上，玩家失去了量级直觉 |

**代价：**

1. **所有玩家的数字都会变**——涨了没事，掉了就是灾难。**必须保证每个玩家重构后的相对排位不变，且绝对数字不下降**（哪怕是通过改变显示单位）；
2. **全部平衡要重做一遍**；
3. **舆情风险极高**，必须提前几个版本公告和解释；
4. **老配置表全部作废**，工程量巨大。

**执行要点**：

- **保序**：重构前后，任意两个玩家的战力大小关系必须不变。这是底线；
- **不降**：显示的数字不能变小。可以通过压缩单位（"战力"改成"评级"）来规避；
- **补偿**：即使做到了保序和不降，也要给补偿——**玩家的不安来自"不确定"，补偿是在买确定性**；
- **灰度**：先在新服/测试服跑一个版本。

> **最好的数值重构是不需要做的那次。** 在设计阶段就用饱和公式（第 05 章）、模块化战力（第 05 章）、比例型经济（第 08 章），可以把重构的必要性推迟很多年。
