# 19 - 服务器生态与玩家分层

> **本章目标**：理解一个服务器的"人口结构"，以及为什么各分层是**互相依赖**的。学完你应该能识别生态崩坏的先行信号，并知道该盯哪个指标。
> **本章有模型**：`models/m19_ecology.py`

---

## 1. 服务器是一个生态系统，不是一堆独立玩家

前面十八章我们一直在算"一个玩家"的账。但服务器上的玩家不是独立的——**他们互为对方的游戏内容**。

一个典型 SLG 服的人口结构（量级示意，具体分布因产品而异）：

| 分层 | 人数占比 | 流水占比 | 他们要什么 | 他们提供什么 |
|---|---|---|---|---|
| **大 R** | ~1% | ~50%+ | Power、Competition、地位 | 战力、联盟的攻坚能力、话题 |
| **中 R** | ~5% | ~30% | 稳定成长、集体归属 | 联盟的中坚、组织执行力 |
| **小 R** | ~20% | ~15% | 跟上节奏、有参与感 | 人数、活跃度、贡献 |
| **免费玩家** | ~74% | ~0% | 低压力的日常、能看到进步 | **人数、对手、观众、被统治的对象** |

**最后一格是本章的核心。** 免费玩家的"价值"不是流水，而是：

1. **他们是大 R 的对手和观众**——没有人可以打败、没有人围观，"最强"就没有意义（第 02 章：大 R 的主导动机是 Power + Competition）；
2. **他们是联盟的人数**——第 18 章的集结机制里，人数就是战力；
3. **他们是内容的一部分**——一个只有 100 个大 R 的服，地图上是空的。

> **免费玩家不是"成本"，是"内容"。**
> 这句话如果不能内化，你会在某次追求短期流水的决策里把服务器搞死。

## 2. 生态的耦合动力学

```bash
cd models && python m19_ecology.py
```

模型把两条耦合关系写进去了：

```python
# ① 免费/小 R：被压迫程度 = 大 R 的有效战力占比
churn[0] += oppress_k * whale_share

# ② 大 R：观众指数 = 免费玩家相对初始的存量
churn[3] += audience_k * max(0.0, 1.0 - audience)
```

用第 18 章的集结叠加指数 α 作为唯一变量（**α 作用在人数上**：α=1 时 100 个免费玩家 = 100 份战力，α=0.7 时只等于 25 份）：

```
场景                    第360天总人数   相对初始   大R战力占比   免费玩家
----------------------------------------------------------------------
α=1.00 集结线性相加        10,001      100%      15.4%      7,398
α=0.85 中等次线性           9,269       93%      17.0%      6,966
α=0.70 个人战力主导         7,893       79%      21.5%      5,981
```

参数是标定过的：**α=1.0 时服务器恰好维持在初始规模**（稳态）。所以后两行的衰减完全来自 α 的改变。

### 2.1 一个反直觉的发现

看 α=0.70 场景下各层的最终存量：

```
  免费玩家     81%
  小 R        81%
  中 R        52%
  大 R        33%    （第 114 天跌破 50%）
```

> **免费玩家只掉了两成，大 R 却掉了三分之二。**

**大 R 对生态恶化的敏感度，远高于免费玩家。** 基本盘的小幅萎缩，会被放大成头部的大幅流失。

原因回到第 02 章：大 R 的动机是 Power 和 Competition，**而这两样都需要别人在场才成立**。免费玩家少了两成，意味着地图变空、对手变少、集结打不起来——对免费玩家自己来说影响有限，对大 R 来说是核心体验的坍塌。

**这条推论非常实用：**

> **不要用大 R 的流失来判断生态健康——等你在流水上看到它时，已经晚了三个月。**

## 3. 该盯的先行指标

按"先行程度"排序（越靠前越早预警）：

| # | 指标 | 含义 | 警戒信号 |
|---|---|---|---|
| 1 | **大 R 占全服有效战力的比例** | 第 18 章的 α 效应的直接度量 | **持续上行** |
| 2 | **免费玩家的日均战斗参与率** | 他们还打不打得动 | 下降 |
| 3 | **免费玩家的 PvP 胜率分布** | 有多少人常年挨打 | 胜率 <20% 的人数占比上升 |
| 4 | **联盟数量与规模分布** | 组织结构是否健康 | 联盟数量减少、头部联盟规模膨胀 |
| 5 | 中小 R 的留存 | 中坚层的状态 | 下降 |
| 6 | 大 R 的活跃与付费 | **最滞后**的指标 | 下降时已经晚了 |

**第 1 个指标是最有价值的**，因为它可以直接从数值结构算出来，甚至不需要等线上数据——你在设计阶段就能用第 18 章的模型预测它。

**第 4 个指标常被忽略但很灵敏**：健康的服有多个势均力敌的联盟在互相博弈；生态恶化时会出现"一超多弱"，然后是"一超"——**当一个联盟统一了全服，服务器就死了**，因为没有对手意味着没有内容。

> **一个具体的运营红线**：当头部联盟控制超过 60% 的领土或战力时，就该干预了（活动、赛季、跨服，见第 22 章）。

## 4. 生态崩坏的四种典型路径

### ① 碾压型：α 太低 / 付费差距太大

**症状**：免费玩家胜率极低、参与率下降、地图变空。
**根因**：第 18 章的 α 过低，或第 12 章的付费深度过高。
**修法**：提高 α（放宽集结上限）、加强保护机制、增加不可购买的约束。

### ② 断层型：新老玩家差距无法弥合

**症状**：新进玩家在两周内流失，老玩家逐渐自然衰减，服务器慢慢空掉。
**根因**：数值膨胀过快（第 21 章），新人追不上。
**修法**：追赶机制、新手保护期、赛季重置（第 22 章）。

> **注意追赶机制的反作用**：给新人的加速会让老玩家的积累贬值（第 09 章的通缩）。这个平衡极难拿捏，是长线运营最棘手的问题之一。

### ③ 寡头型：一个联盟统一全服

**症状**：战斗次数骤降，日活尚可但活跃度质量下降，然后集体流失。
**根因**：协调成本过低（第 16、18 章）、缺少制衡机制。
**修法**：跨服玩法引入外部对手、赛季重置打散、限制联盟规模、给弱势方增益。

### ④ 空心型：中间层被掏空

**症状**：只剩大 R 和纯免费，中小 R 消失。
**根因**：付费结构断档——从"小额"到"大额"之间没有值得买的东西（第 12 章的付费漏斗第 ② 段）。
**修法**：补齐中间档位的商品和成长路径。

**这四种是可以并发的**，而且常常互为因果。诊断时先看第 3 节的指标 1 和 4。

## 5. 让免费玩家留下来的机制

第 05 章第 6 节列过三条，这里展开成一份可操作的清单：

| 机制 | 说明 | 代价 |
|---|---|---|
| **数量对抗质量** | 集结线性相加（α≈1） | 大 R 的付费获得感下降 |
| **不可购买的约束** | 体力、时间、土地（第 06、18 章） | 商业化上限降低 |
| **非战斗价值** | 采集、建设、侦察、后勤——让弱者在联盟里有位置 | 需要设计相应系统 |
| **保护机制** | 新手保护罩、连败保护、资源保护上限 | 可能被滥用（挂罩） |
| **贡献度覆盖全分层** | 免费玩家也能拿到组织货币（第 18 章） | —— |
| **异步/低强度玩法** | 让不想打架的人也有事做 | 分散核心玩法的注意力 |
| **社交绑定** | 联盟责任、师徒、好友 | **最有效，且几乎无代价** |

**最后一条是性价比最高的。** 第 15 章讲过：**留存曲线的长期底盘几乎完全由社交结构决定**。一个在联盟里有职务、有朋友、被需要的免费玩家，留存远高于一个战力更高但独来独往的玩家。

## 6. 大 R 的生态需求

反过来，大 R 需要什么？**不是更多资源**（第 08 章讲过他们资源溢出），而是：

| 需求 | 怎么提供 | 反例 |
|---|---|---|
| **值得打的对手** | 跨服、赛季、势力平衡 | 一超多弱的服 |
| **观众** | 全服公告、排行榜、战报分享 | 没有可见度的战斗 |
| **地位与影响力** | 联盟职务、指挥权、集体项目的主导 | 只能自己单干 |
| **独特性** | 限定外观、称号、专属特权 | 花钱只能买到"更多的一样的东西" |
| **可持续的消费出口** | 深度 sink（第 08 章） | 满级之后无事可做 |

> **"给大 R 更强的战力"往往不能满足大 R，反而会杀死生态。**
> 他们要的是"被看见的强"，而"被看见"需要观众——观众就是免费玩家。

**这是 F2P 生态最核心的循环**，也是本章的结论：

```
   免费玩家在场 ──► 大 R 的强有意义 ──► 大 R 付费 ──► 支撑产品运营
        ▲                                                    │
        │                                                    │
        └──── 产品能持续更新内容、免费玩家愿意留下 ◄───────────────┘
```

**任何单方面榨取一环的决策，都会让整个循环停转。**

## 7. 开服、滚服与人口调节

一个实操话题：**你可以主动调节服务器的人口结构。**

| 手段 | 作用 | 注意 |
|---|---|---|
| **控制开服节奏** | 新服人多才热闹；开太快会稀释 | 老服的人口衰减速度决定了开新服的频率 |
| **控制单服承载量** | 太少没内容，太多打不着 | SLG 通常几千到几万人一个服（视地图和玩法） |
| **分批导入** | 开服后持续导入新玩家，而不是一次性 | 避免"开服潮"之后的断崖 |
| **跨服玩法** | 把多个服的人临时拉到一起 | 缓解单服人口不足，但会暴露服间强弱差异 |
| **合服** | 把衰减的服合并 | 冲击很大，第 22 章专门讲 |

**一条实践经验**：**新服的导入结构应该刻意做成"金字塔"**——先导入一批普通玩家，再导入大 R。如果开服第一天全是大 R，他们会互相碾压然后集体流失。
