# 25 - 端到端实战：一份完整的 SLG 数值方案

> **本章是毕业实战。** 你要从 6 个产品决策出发，推导出一整套数值方案，并让它通过自检。
> **本章有模型**：`models/m25_full_spec.py`

---

## 1. 数值方案是"推导出来的"，不是"填出来的"

这是整门课最想让你带走的一句话。

一份合格的数值方案，应该满足：**改动任何一个上层决策，所有下游数值都能自动重算。** 如果你的方案是一堆手填的表格，那它不是方案，是一次性的猜测。

```
        ┌─────────────────────────────────────────┐
        │  产品决策（制作人拍板，第 01 章第 5 节）      │
        │  品类 / 生命周期 / 赛季长度 / 付费深度       │
        │  集结叠加指数 α / 战斗回合数                │
        └────────────────────┬────────────────────┘
                             │  推导
     ┌───────────────────────┼───────────────────────┐
     ▼                       ▼                       ▼
┌─────────┐           ┌─────────────┐         ┌─────────────┐
│ 节奏锚点  │           │  经济骨架     │         │  竞争结构    │
│ 第 04 章  │           │  第 06~08 章  │         │  第 16~19 章 │
└────┬────┘           └──────┬──────┘         └──────┬──────┘
     ▼                       ▼                        ▼
┌─────────┐           ┌─────────────┐         ┌─────────────┐
│ 成本曲线  │           │ 日产出预算表   │         │  匹配/集结    │
│ 战力曲线  │           │ sink 组合     │         │  赛季规则     │
└────┬────┘           └──────┬──────┘         └──────┬──────┘
     └───────────────────────┼───────────────────────┘
                             ▼
                    ┌─────────────────┐
                    │   经济体检自检     │  第 11 章
                    │  不通过就回上一层  │
                    └─────────────────┘
```

## 2. 跑一遍

```bash
cd models && python m25_full_spec.py
```

模型从这 6 个决策出发：

```
  品类              COK-like SLG，赛季制
  目标生命周期天数    540
  赛季长度           90
  付费深度上限        20000 元
  集结叠加指数 α      0.95
  单场战斗目标回合数   10
```

**它自动推导出六份交付物**，每一份都在前面章节讲过：

### ① 节奏表（第 04 章）

从 7 个时间锚点反推分段成本曲线：

```
 等级  达成日  停留天数    升级成本
    5      2       0        3,001
   10      4       0        4,739
   16      7       2       18,634
   25     30       6      142,692
   31     90      20      676,145
   36    270      76    3,315,304

  ⚠ 单级停留首次超过 7 天：27 级 / 第 43 天
     ⇒ 必须在此之前完成动机迁移（第 20 章）
```

**注意那条自动生成的警告。** 第 04 章讲过：单级停留超过一周，等级系统就不再是主要动力了。模型直接算出这个拐点在**第 43 天**——这就是你的产品必须完成"从个人成长到社交竞争"迁移的最后期限。

**这个数字不是拍脑袋的，是从节奏锚点推出来的。** 如果你觉得第 43 天太早，就要回去改锚点——而不是在设计文档里写一句"我们会在中期加强社交"。

### ② 日产出预算表（第 07 章）

```
            新手期  成长期  中期  长线期
挂机产出        22     30    35     38
主线/PvE        32     16     6      2
联盟/社交        3     10    16     20
资源地/PvP       3      9    13     16
...
社交渠道占比：新手期 3% → 长线期 20%（动机迁移的经济基础）
```

社交渠道从 3% 升到 20%，**这是第 ① 步那个"第 43 天必须完成迁移"的经济实现**——不是靠喊口号，是靠把玩家 20% 的资源来源绑到组织上。

模型里那行断言（各渠道占比之和 = 1）保证了预算的纪律性：加渠道必须从别处扣。

### ③ 战斗参数（第 05 章）

```
  伤害公式：伤害 = 攻击 × K/(K + 防御)        ← 饱和公式，对膨胀免疫
  同级对抗目标减伤 40% ⇒ 同级防御 = 0.667 × K
  K(L) = 50 × L^1.5 ⇒ 40 级时 K = 12,649
  目标回合数 10 ⇒ 生命 = 6 × 攻击
  属性最优配比：攻 43% / 防 13% / 血 43%
```

**从"一场战斗打 10 回合"这一个决策，推出了攻防血的量级关系。** 第 05 章第 3 节讲的正确顺序：定回合数 → 定 EHP/DPS 比 → 反推属性量级。

### ④ 抽卡参数（第 13 章）

```
  单价 15 元/抽，最惨玩家预算上限 1,500 元
  ⇒ 硬保底 100 抽，软保底起点 80 抽，基础概率 1.6%
  UP 机制 50% 歪 ⇒ 最坏情况 200 抽 = 3,000 元
  ⚠ 必须 ≤ 付费深度上限（20,000）—— 通过
```

**从"最惨的玩家花多少钱"倒推概率**，而不是先定概率再看结果（第 13 章第 4 节）。而且它会自动校验和"付费深度上限"这个上层决策是否一致。

### ⑤ 赛季与膨胀（第 21、22 章）

```
  赛季长度 90 天 ⇒ 生命周期内 6 个赛季
  ✓ 赛季长度 ≥60 天：重复博弈能建立声誉，外交系统有效（第 16 章）
  版本膨胀 r = 1.1/月 ⇒ 年化 3.1×
  单赛季内膨胀 = 1.33×（赛季重置吸收了跨赛季的断层）
```

**注意最后一行**：赛季制让"跨赛季的累积膨胀"不再是问题，因为每个赛季都重置。这正是第 21 章那个"空集"的解法。

### ⑥ 经济与生态自检（第 08、09、18、19 章）

```
  比例型 sink：日损耗 6% ⇒ 稳态存量 = (1−d)/d = 15.7 天
  ✓ 落在健康区间 5~20 天
  ⚠ 40 级封顶后层级 sink 失效 ⇒ 必须靠比例型 sink 兜底
  深度 sink：联盟建设 + 限定外观（不给战力，避免放大付费差距）

  α = 0.95，大 R 战力 ≈ 免费玩家 12×
  ⇒ 需 14 名免费玩家集结才能打赢
  ✓ ≤100 人（一个联盟能组织起来）
```

## 3. 毕业作业

**这是本课程的最终作业。** 建议花 8~15 小时完成。

### 任务 A：改造成你自己的方案（必做）

改 `DECISIONS` 里的 6 个决策，做一款**和示例不同**的产品。三选一：

| 选项 | 决策方向 |
|---|---|
| **率土-like** | 更长的赛季（120 天+）、更低的付费深度、α = 1.0、体力约束 |
| **卡牌放置** | 无赛季、更长生命周期、更高付费深度、无集结（α 不适用） |
| **短周期 SLG** | 30 天赛季、高付费深度、高膨胀率 |

**要求**：
1. 6 个决策全部改完，并**写清楚每个决策的理由**；
2. 调整节奏锚点，使之匹配你的品类；
3. 所有自检项必须通过；**通不过的，说明你哪个决策需要改**；
4. 输出全部交付物（节奏表 CSV、预算表 CSV、方案图）。

### 任务 B：补上缺失的部分（进阶）

示例脚本还缺三块，补齐其中至少两块：

1. **战力曲线与养成线权重**（第 05、21 章）：设计 6~8 条养成线，给出各自在战力公式里的权重和开放时间；
2. **付费点时间轴**（第 12、14 章）：把商品铺到时间轴上，每个都绑一个卡点；
3. **完整经济仿真**（第 11 章）：把 `m11_slg_full.py` 接进来，用你的参数跑 540 天体检。

### 任务 C：写一份方案文档（推荐）

把生成的数据组织成一份**能给团队评审的文档**，结构建议：

```
1. 产品定位与核心决策         （6 个决策 + 理由）
2. 玩家旅程与节奏             （时间轴表，第 20 章）
3. 经济骨架                   （货币体系图 + 资源流图 + 预算表）
4. 成长与战斗                 （节奏表 + 战力公式 + 战斗参数）
5. 商业化                     （付费结构 + 定价 + 概率）
6. 竞争与生态                 （α + 匹配 + 赛季 + 生态指标）
7. 数据与风控                 （指标树 + 埋点清单 + 风控规则）
8. 风险与未解决项             ← 最重要的一节
```

**第 8 节最重要。** 一份诚实标注了"哪些地方我不确定、依赖什么假设、什么信号出现时需要回头改"的方案，比一份看起来完美的方案有用得多。

### 任务 D：审别人的方案（如果有条件）

找一份真实的（或你同事的）数值方案，用第 01 章第 5 节那五个问题去审：

1. 日产出预算表在哪？各渠道占比多少？
2. 主要的 sink 是什么？它有上限吗？
3. 免费玩家和大 R 的战力差距是多少倍？90 天后是变大还是变小？
4. 玩家第 30 天、第 90 天分别在追求什么？
5. 这套数值跑过仿真吗？给我看 180 天的存量曲线。

## 4. 你现在应该具备的能力

对照检查。**这也是本课程的总验收标准。**

### 心智模型

- [ ] 用一句话说出数值设计的本质（人造稀缺 + 解除稀缺的路径与代价）

- [ ] 画出资源流图，识别四种设计缺陷
- [ ] 说出存量-流量关系的四条推论

### 技术能力

- [ ] 从时间锚点反推分段成本曲线
- [ ] 选择伤害公式并说明长期后果
- [ ] 设计一套货币体系并验证无兑换回路

## 5. 接下来学什么

这门课教的是**框架和方法**。要真正做好，还需要三样这门课给不了的东西：

**① 手感。** 找一款 SLG 玩满一个完整赛季，边玩边记录。**你在第 01 章开始的那份拆解，现在应该已经有 100 多条了**——回头通读一遍，你会发现很多当时看不懂的现象现在都能解释。

**② 真实数据。** 这门课的所有模型都是合成数据。真实数据的噪声、缺失、口径混乱是另一个量级的挑战。有机会接触真实项目数据时，第一件事是把第 23 章的指标树跑一遍。

**③ 别人的失败。** 成功游戏的数值有大量幸存者偏差。多找**失败案例的复盘**——尤其是经济崩盘、生态崩坏、赛季翻车的复盘。附录 B 列了几个高质量的社区。

**最后一句：**

> 数值设计的所有技术，最终都服务于一个问题——**让玩家在正确的时刻，产生正确的感受。**
> 当你在某个参数上犹豫时，回到这个问题，答案通常就清楚了。
