# 22 - 赛季制、合服与服务器生命周期

> **本章目标**：掌握长线运营的两个结构性工具——赛季重置和合服。学完你应该能设计一套赛季规则，并知道合服该在什么时候做、怎么把冲击降到最低。
> **本章有模型**：`models/m22_merge.py`

---

## 1. 赛季制：第 21 章那个空集的解法

第 21 章的结论是：**只要"老玩家持续累积、新人从零开始"这个结构不变，"老玩家保值"和"新人能追上"就无解。**

赛季制的做法很直接——**消灭前提**：

```
   非赛季制：  积累 ──────────────────────────────────────►  差距无限拉大
   赛季制：    积累 ──►│重置│──► 积累 ──►│重置│──► 积累 ──►│重置│
                       每个赛季开始时，所有人的差距被压缩回一个可追赶的范围
```

**赛季制解决的五个问题**（第 17 章 6.3 节列过，这里展开）：

| 问题 | 赛季怎么解决 |
|---|---|
| 新老断层（第 21 章） | 重置压缩差距，新人只需追上一个赛季的进度 |
| 成长感耗尽（第 04 章） | 重新开始 → `d(ln y)/dt` 重新变大 |
| 内容跑道耗尽（第 20 章） | 同一份内容可以重复消耗 |
| 生态寡头化（第 19 章） | 重置打散既有格局，重新洗牌 |
| 经济通胀（第 09 章） | 赛季货币清零 = 100% 回收 |

**代价只有一个，但很重**：**老玩家的积累被抹掉了。**

所以所有赛季制都必须回答一个问题：**重置什么，保留什么？**

## 2. 赛季设计的三个核心参数

### 参数 1：重置什么 / 保留什么

这是赛季设计的核心。一个典型的划分：

| 重置（赛季内） | 保留（跨赛季） |
|---|---|
| 领土、城池位置 | 武将/角色的收集 |
| 赛季货币、赛季道具 | 主要养成等级（或部分继承） |
| 排名、赛季积分 | 称号、成就、纪念品 |
| 联盟归属 | 好友关系、社交图谱 |
| 部分战力（如兵力、建筑） | 账号等级、VIP |

**划分原则：**

> **重置"位置和格局"，保留"身份和收藏"。**

玩家能接受"我的地盘没了"，但很难接受"我抽了半年的角色没了"。前者是**格局**（本来就该重新争夺），后者是**身份**（是他账号价值的核心）。

**一个实用检验**：问"如果这个东西被重置了，玩家会不会觉得自己这个赛季白玩了？" 会 → 保留或部分继承。

### 参数 2：赛季长度

| 长度 | 特点 | 风险 |
|---|---|---|
| **1 个月** | 节奏快，新人友好 | 老玩家觉得刚开始就结束，深度体验不足 |
| **2~3 个月** | **主流区间** | —— |
| **6 个月+** | 深度足够 | 接近非赛季制，新老断层重新出现 |

**第 16 章讲过一个关键约束**：**赛季长度直接影响外交生态**。

> 重复博弈才能让合作成为均衡。赛季太短，所有人都在玩"最后一轮"，背叛没有代价，**外交系统会失效**。

所以对强调联盟外交的 SLG（率土-like），赛季不能太短——通常至少 2 个月，让"声誉"有时间发挥作用。

### 参数 3：继承比例

不是非黑即白。常见做法是**部分继承**：

- 上赛季的等级/养成，本赛季以一定比例（比如 30%~50%）作为起点；
- 或者继承"上限"而不是"当前值"——你上赛季练到 60 级，这赛季能练到 60 级，但要重新练。

**部分继承的好处**：既压缩了差距，又承认了老玩家的投入。**这是"老玩家保值"和"新人追赶"之间唯一的实际妥协点。**

## 3. 为什么率土-like 能做赛季，COK-like 难做

回到第 18 章的三个总开关：

| | 率土-like | COK-like |
|---|---|---|
| **核心积累是什么** | **领土**（本来就是打来的，重置天经地义） | **城建等级 + 兵**（玩家投入的直接产物） |
| **重置的叙事合理性** | "新赛季，天下重新洗牌" —— 自洽 | "你的城被推平了" —— 玩家不接受 |
| **武将（真正的收藏）** | 跨赛季保留 | —— |
| **重置后的差距** | 小（大家都从一块地开始） | 大（城建等级如果保留，差距照旧） |

> **能不能做赛季，取决于你的核心积累是"格局"还是"身份"。**
>
> 率土-like 的核心积累是领土（格局），可以重置；COK-like 的核心积累是城建和兵（玩家眼里的身份/资产），重置会被视为掠夺。

**所以 COK-like 的长线手段只能是"不断加新养成线"**，这也意味着它必然承受第 21 章那个空集问题——**它的服务器生命周期天然短于率土-like**，于是必须靠**合服**来延寿。

这就引出了本章的第二个主题。

## 4. 合服：什么时候做，冲击有多大

### 4.1 为什么必须合服

服务器人口会自然衰减（第 19 章）。当人口跌到某个阈值以下：

- 联盟凑不齐人 → 集结打不动 → 核心玩法失效；
- 地图变空 → 没有对手 → 大 R 先流失（第 19 章的耦合）；
- 市场没有流动性（如果有交易）；
- 匹配池太小（第 17 章）。

**判断合服时机的信号：**

| 信号 | 阈值参考 `【推导】` |
|---|---|
| 日活跌到开服峰值的比例 | < 20%~30% |
| 活跃联盟数 | < 3~5 个（少于这个数就没有博弈了） |
| 单日战斗次数 | 持续下滑且低于设计值的一半 |
| 大 R 活跃度 | 开始下滑（**已经偏晚了**，见第 19 章） |

### 4.2 合服的真实冲击

```bash
cd models && python m22_merge.py
```

**玩家感受到的不是"人变多了"，而是"排在我前面的人变多了"。**

```
合服前：老服玩家的中位数排名 = 第 1499 名（共 3000 人）

方案                    老服中位排名   老服跌幅   新服中位排名   新服百分位
-------------------------------------------------------------------
A 同龄服合并               2986      2.0×        3010      49.8%
B 老服 + 新服              1862      1.2×        4148      30.9%
C 老服 + 新服(补偿)         2474      1.7×        3552      40.8%
```

**方案 A（同龄服合并）**：老玩家的排名**必然翻倍恶化**（前面的人凭空多了一倍）。这是合服无法回避的固有代价。但双方是公平的，新服百分位 49.8%。

**方案 B（老服 + 新服）**：老服受冲击小（1.2×），但**新服玩家的中位百分位只有 30.9%** —— 一大半新服玩家会发现自己突然垫底。**这是合服后新服侧集中流失的直接原因。**

**方案 C（给新服一次性追赶补偿）**：新服百分位从 30.9% 提升到 40.8%，而老服的额外冲击只从 1.2× 增加到 1.7×。

> **结论：合服前给弱势服一次性补偿，是性价比最高的一步。**
> 它对强势服的额外冲击远小于它对弱势服的改善。

### 4.3 合服执行清单

**合服前：**

- [ ] **给弱势服追赶补偿**（第 4.2 节的结论）
- [ ] **提前公告**（至少 1~2 周），让玩家有心理准备和处置资产的时间
- [ ] **处理经济存量**：合服会把两个服的货币合在一起，如果两服的物价差异大，会立刻套利（第 09 章）。有交易系统的话要特别注意
- [ ] **处理名称冲突**：角色名、联盟名重复的处理规则要提前说清
- [ ] **冻结部分玩法**：合服前几天关闭领土争夺等会产生复杂状态的玩法

**合服时：**

- [ ] **给一个"重新分配"的窗口**：新的领土分配、联盟重组期、迁城机会
- [ ] **保护期**：合服后 3~7 天的免战期，让玩家适应
- [ ] **合并排行榜时给双方都保留荣誉**：比如"原 X 服第一"的称号

**合服后：**

- [ ] **紧盯弱势服的留存**（这是合服失败的主要形态）
- [ ] **监控新的联盟格局**：会不会立刻形成寡头（第 19 章的 60% 红线）
- [ ] **准备一次大型活动**：给合服后的新格局一个共同目标

**一条容易被忽略的**：**合服会打破原有的社交关系**。玩家的联盟、好友、师徒可能被打散——而社交是留存底盘的主要来源（第 15 章）。**尽量整建制地保留联盟**，比补偿资源更重要。

## 5. 服务器生命周期管理

把一个服的一生画出来：

```
   开服        成长期        成熟期          衰退期         合服/停服
   ├──────────┼────────────┼──────────────┼─────────────┼────────►
   0天       30天        90天          300天         500天+

   人口   ▁▄██████▇▆▅▅▄▄▃▃▂▂▁
   流水   ▁▃▆████▇▆▆▅▅▄▄▃▃▂▂▁
   干预        ↑活动      ↑赛季        ↑跨服         ↑合服
```

**每个阶段的运营重心不同：**

| 阶段 | 重心 | 数值手段 |
|---|---|---|
| **开服（0~7 天）** | 建立人口结构和联盟 | 导入节奏、金字塔式导入（第 19 章） |
| **成长期（7~90 天）** | 动机迁移、格局形成 | 第 20 章的时间轴 |
| **成熟期（90~300 天）** | 维持博弈平衡、防寡头 | 赛季、跨服、活动 |
| **衰退期（300 天+）** | 延长寿命 | 跨服合并玩法 → 合服 |
| **末期** | 体面退场 | 见第 6 节 |

**跨服玩法是合服之前的缓冲手段**：它让多个服的人临时在一起玩，缓解单服人口不足，而不需要真的合并。代价是会暴露服间的强弱差异，且不能解决单服日常玩法的空虚。

## 6. 停服：怎么体面地结束

这一节很少有人讲，但它是产品生命周期的一部分，而且**处理方式直接影响你下一款产品的口碑**。

**几条实践准则：**

| 准则 | 说明 |
|---|---|
| **提前足够久公告** | 至少 1~3 个月。玩家需要时间告别 |
| **立刻停止销售** | 公告之后不再卖任何付费商品 |
| **未消耗的付费余额要处理** | 退款、或转移到其他产品。**这是法律和道德的双重要求** |
| **最后一段时间放开限制** | 把付费内容免费开放，让玩家尽兴 |
| **保留纪念** | 数据导出、纪念称号、社群留存 |
| **给社群一个告别场** | 最后的活动、开发者的信 |

> **玩家记住的是你怎么结束的。** 体面停服的团队，下一款产品会带着老玩家一起来；难看停服的，会带着长期的口碑损失。

## 7. 动手

### 7.1 改模型

**任务 A：找出补偿力度的最优值。** 二分搜索 `boosted` 的倍数，找出让"新服中位百分位 ≥ 45%"的最小补偿。此时老服的排名跌幅是多少？

**任务 B：三服合并。** 改成三个服合并（老/中/新），看各服的百分位分布。**多服合并对最弱的服冲击是变大还是变小？**

**任务 C：加入流失。** 假设百分位低于 20% 的玩家有 50% 概率在一周内流失，模拟合服后一周的人口。哪个方案的净人口最高？

**任务 D：模拟赛季重置。** 把"重置"实现为"所有人的战力压缩到 `x^0.5`"（差距开方），看基尼系数和排名分布的变化。**开方压缩相当于多少年的追赶机制？**

### 7.2 设计练习

给一款 COK-like 的 SLG 设计一套赛季制。要求：

1. 明确列出重置项和保留项，并说明每一项的理由；
2. 定赛季长度，并说明它怎么影响外交生态；
3. 设计部分继承的比例；
4. 说明你怎么让"城建被重置"这件事在叙事上成立（这是最难的一点）。
