# 05 - 战斗数值与战力

> **本章目标**：搞懂伤害公式的选择会带来什么长期后果，以及"战力"这个数字到底是怎么算出来的、为什么它是长线运营的中枢神经。
> **本章有模型**：`models/m05_combat.py`

---

## 1. 战斗数值要回答三个问题

不管是 SLG 的部队交战、MMO 的副本、还是卡牌的自动战斗，战斗数值都在回答同样三件事：

| 问题 | 决定了什么 | 本章位置 |
|---|---|---|
| **一场战斗打多久？** | 节奏感、操作空间、服务器压力 | 第 2、3 节 |
| **强弱差距怎么体现？** | 养成的意义、付费的意义 | 第 2、6 节 |
| **怎么把一堆属性折算成一个数？** | 匹配、推荐、排行、推图门槛 | 第 4、5 节 |

第三个问题的答案就是"战力"。它看起来只是个 UI 上的数字，实际上是整个游戏运转的中枢——第 5 节会说明为什么。

## 2. 三种伤害公式

```bash
cd models && python m05_combat.py
```

看 `figures/m05_combat.png`。三种公式，固定攻击 1000，横轴是防御。

### 2.1 减法公式：`伤害 = 攻击 − 防御`

**优点**：直观到不需要解释。玩家一眼就懂"我攻击 1000，他防御 300，我打 700"。数值感极强，加 100 攻击就是实打实多打 100。

**致命缺陷——不破防悬崖**：

看图 ①，蓝线在防御 = 攻击（1000）处直接归零。看图 ③（对数纵轴），击杀所需回合数在这个点**垂直起飞**。

再看图 ②，减法公式下**防御的边际收益是递增的**：防御越高，每 +100 防御减少的伤害占比越大，在接近攻击值时趋于无穷。

> **减法公式下，防御是一个正反馈属性——越堆越强。** 这在数值上是发散的。

实际后果：

- 玩家会发现"堆防御"是占优策略，所有人只堆防御（第 16 章讲的策略坍缩）；
- 一旦有玩家的防御超过了主流攻击水平，他就**完全无敌**；
- 版本更新时你只要把新装备的攻击提高 10%，整个防御体系就全废了——**减法公式对数值膨胀极度敏感**。

**结论**：减法公式适合**数值范围严格可控**的游戏（数值区间窄、不做长线膨胀、装备等级少）。早期端游和大量页游用它，因为好算好懂。**长线运营的手游不要用**，除非你在攻防之间设了非常强的耦合约束。

### 2.2 乘法公式（百分比减伤）：`伤害 = 攻击 × (1 − 减伤率)`

防御直接换算成一个减伤百分比。

**必须设硬顶**。看图 ②，橙线也是**递增**的——原因是数学上的：伤害正比于 `(1−r)`，当 `r` 从 0.7 涨到 0.75，伤害从 0.30 降到 0.25，降幅是 **17%**；而 `r` 从 0 涨到 0.05 时，降幅只有 5%。

> **百分比减伤的边际收益随减伤率上升而上升。** 所以它必然需要一个硬上限（图里设的是 75%），否则减伤逼近 100% 时就是另一种形式的无敌。

**优点**：调控直观（"这件装备给 5% 减伤"），PvE 生命周期长，攻防不需要严格对齐。
**缺点**：硬顶附近的体验很差——差 1% 就顶了，玩家会觉得属性"突然没用了"；而且硬顶是个明显的坎，玩家全都会精确堆到 75%。

### 2.3 除法公式（饱和公式）：`减伤率 = 防御 / (防御 + K)`

这就是第 04 章 4.2 节那个软上限公式。等价写法：`伤害 = 攻击 × K/(K + 防御)`。

看图 ②，绿线是**唯一递减的**——防御的边际收益随堆叠而下降，玩家会自然而然地停止无脑堆防御。

**三个巨大优点**：

1. **永不归零，永不无敌**。伤害趋近于 0 但永远为正，所以永远没有不破防悬崖。
2. **自带软上限**，不需要写硬顶，也就没有硬顶带来的体验断层。
3. **参数含义清晰**：`K` 就是"减伤 50% 所需的防御"，这是个可以直接和策划讨论的数字。

**关键性质：它对数值膨胀免疫。** 如果攻击和防御同步膨胀 10 倍，只要 `K` 也同步膨胀，减伤率完全不变。这意味着**你可以放心地做长线数值膨胀而不用重做战斗平衡**——这是长线手游几乎都用它的根本原因。

在真实项目里 `K` 通常写成等级的函数：`K = f(等级)`，比如 `K = 50 × 等级^1.5`。这样同等级对抗的减伤率恒定，而越级挑战会天然吃亏。

### 2.4 选型建议

| | 减法 | 乘法（百分比） | 除法（饱和） |
|---|---|---|---|
| 直观性 | ◎ | ○ | △ |
| 防御边际收益 | **递增（危险）** | **递增（需硬顶）** | **递减（健康）** |
| 不破防风险 | **高** | 无（有硬顶） | 无 |
| 对数值膨胀的耐受 | **差** | 中 | **优** |
| 长线运营适配 | 差 | 中 | **优** |
| 适用 | 数值窄、不做长线 | 中等长线、需要直观调控 | **长线手游默认选择** |

**现实中常见混合**：`最终伤害 = (攻击 × 技能系数 − 固定减伤) × K/(K+防御) × (1 − 百分比减伤) × 克制系数 × 暴击系数`。

每一层负责不同的设计目的：饱和层管基础对抗，百分比层管装备/buff，固定减伤层管特殊机制，克制层管策略（第 16 章）。**层数不要超过 5 层**，否则你自己都算不清一件装备值多少钱。

## 3. 战斗时长：一个被低估的核心参数

图 ③ 画的是击杀所需回合数。**这个数字应该是你最先定下来的战斗参数之一**，因为它牵动一切：

| 回合数 | 体验 | 后果 |
|---|---|---|
| 1~3 回合 | 秒杀 | 随机性/先手权决定一切，策略无意义 |
| **5~15 回合** | **主流区间** | 有翻盘空间，技能能放出来，策略有意义 |
| 30+ 回合 | 拉锯 | 玩家不耐烦；自动战斗还好，手动战斗劝退 |
| 100+ 回合 | 打不动 | 通常意味着数值设计出了问题 |

**从回合数反推属性关系**：

```
回合数 ≈ 有效生命(EHP) / 每回合伤害(DPS)
```

如果你要 10 回合，那么 `EHP / DPS ≈ 10`。这一个约束就把攻防血的量级关系锁死了——**这是配属性表的起点，不是终点**。

新手常见错误是先定属性再看战斗时长，结果发现打 80 回合，然后回头乱改属性。正确顺序：定回合数 → 定 EHP/DPS 比 → 反推属性量级 → 再分配到各养成线。

## 4. 战力：EHP × DPS

### 4.1 基本模型

把一堆属性折算成一个数，标准做法是：

```
EHP（有效生命） = 生命 / (1 − 减伤率)     ← 能扛多少伤害
DPS（有效输出） = 攻击 × 攻速 × (1 + 暴击率 × (暴击倍率−1)) × 命中率
战力 ∝ EHP × DPS
```

**为什么是乘积？** 因为战斗的胜负由"我打死你需要的时间"和"你打死我需要的时间"比较决定：

```
我杀你用的回合 = EHP敌 / DPS我
你杀我用的回合 = EHP我 / DPS敌
我赢  ⟺  EHP敌/DPS我 < EHP我/DPS敌  ⟺  EHP我 × DPS我 > EHP敌 × DPS敌
```

**所以 `EHP × DPS` 正是决定胜负的量。** 这不是拍脑袋定义的，是从战斗模型推出来的。

> 有些游戏用 `√(EHP × DPS)` 作为显示战力，只是为了让数字增长看起来更温和——胜负判定是等价的。

### 4.2 为什么属性必须均衡：图 ④

模型给了 3000 点属性预算，让你分配到攻击/防御/生命。结果：

```
最优分配：攻击 43%  防御 13%  生命 43%     战力 27,439,893

  全堆攻击   战力  5,054,080   仅为最优的 18.4%
  全堆防御   战力    993,280   仅为最优的  3.6%
  攻防各半   战力  6,204,640   仅为最优的 22.6%
```

**极端分配只能拿到最优解的 4%~23%。** 这是数学上的必然——**乘积在因子相等时取最大值**（算术-几何平均不等式的直接推论）。

三条实用推论：

**① 战力公式天然鼓励均衡发展，你不需要额外做限制。** 只要战力是乘积形式，玩家自己算一算就会去补短板。

**② "攻防各半"只有 22.6%，因为漏掉了生命。** 玩家很容易忽略某一维属性，而漏掉一维的代价是巨大的。这也是为什么很多游戏会显式提示"你的生命属性偏低"。

**③ 防御的最优占比（13%）远低于攻击和生命（各 43%）。** 因为防御通过饱和公式作用，边际递减（图 ②）；而攻击和生命是线性进入乘积的。

> **这解释了一个常见的玩家困惑："为什么堆防御没用？"** 不是没用，是它的最优配比本来就低。而如果你的数值表里给防御和攻击相同的成长量，玩家就会觉得防御装备是垃圾——**属性的投放量应该正比于它的最优占比**。

### 4.3 计算战力 vs 显示战力

真实项目里这是**两个不同的数**，务必分清：

| | **计算战力** | **显示战力** |
|---|---|---|
| 给谁看 | 策划、服务端 | 玩家 |
| 目的 | 判定胜负、匹配、推关卡门槛 | 让玩家知道自己变强了 |
| 特点 | 必须准确反映实际强度 | 必须**单调递增**、好看、易懂 |
| 常见做法 | `EHP × DPS`，含所有克制/技能修正 | 各属性加权求和，或 `√(EHP×DPS)` 再取整 |

**为什么要分开？** 因为两者的要求是冲突的：

- 计算战力要准确，就必须包含克制关系、技能组合、阵容搭配——但这些是**情境相关**的（第 16 章的非传递性），同一套阵容打不同对手强度不同，没法用一个数表示；
- 显示战力必须单调——**玩家做任何养成动作，这个数都必须涨**。哪怕他换了一件"理论上更差但战力显示更高"的装备，也不能让数字掉下来，否则玩家会认为游戏出 bug 了。

**新手最常犯的错**：直接把计算战力显示给玩家。后果是玩家换装备时战力忽高忽低，或者战力高的打不过战力低的，信任崩塌。

> **显示战力的第一原则是可预期，不是准确。**

**但显示战力也不能太离谱。** 如果战力 10 万经常打不过 8 万，玩家就不再相信这个数字，而战力一旦失去公信力，你的匹配、推荐、推图门槛全部失效——这就是下一节要说的。

## 5. 战力为什么是长线运营的中枢神经

一个 UI 上的数字，为什么这么重要？因为**整个游戏的其他系统都以它为输入**：

```
                        ┌──────────┐
      养成系统 ────────→ │          │ ────────→ 关卡推荐战力（我该打哪一关）
      装备系统 ────────→ │  战力     │ ────────→ PvP 匹配（跟谁打）
      阵容搭配 ────────→ │          │ ────────→ 排行榜（我第几名）
      付费   ────────→  │          │ ────────→ 联盟准入（够不够格）
                        └──────────┘ ────────→ 付费引导（差多少战力过关）
```

由此得到三条运营层面的推论：

**① 战力是玩家理解整个游戏的唯一接口。** 玩家不会去算 EHP×DPS，他只会看战力涨了多少。所以**战力的增速就是玩家感知到的成长速度**——第 04 章 2.1 节那条"必须指数增长"的结论，实际上是对战力说的。

**② 各养成线在战力公式里的权重，等于你在告诉玩家该练什么。** 如果新出的养成线在战力里权重很低，玩家就不会练，你这个系统就白做了。反过来，**调整战力权重是引导玩家行为最有力的杠杆之一**，而且几乎零成本。

**③ 战力公式一旦上线就极难修改。** 改了会导致所有玩家的战力数字变化——涨了没事，掉了就是灾难（"我什么都没做，战力掉了 3000"）。

> **实践建议：战力公式在设计阶段就要预留新养成线的接口**，比如做成"各模块战力之和"的形式，新增模块时只是加一项，不影响已有部分。第 21 章会展开。

## 6. 强弱差距该有多大

这是制作人必须拍板的问题（第 01 章第 5 节），本节给你决策依据。

**核心权衡**：

```
差距太小 → 变强没意义 → 养成和付费都失去动力
差距太大 → 弱者被碾压 → 弱者流失 → 强者失去对手 → 也流失
```

**一个实用的量化框架**：设强者战力是弱者的 `r` 倍，那么在纯数值对抗下：

| `r` | 战斗结果 | 体验 |
|---|---|---|
| 1.0~1.2 | 势均力敌，操作/策略/运气决定 | **最佳竞技体验** |
| 1.2~2.0 | 强者稳赢但有损失 | 健康的强弱差距 |
| 2~5 | 碾压，弱者无还手之力 | 弱者需要"其他出路" |
| 5+ | 完全无意义的战斗 | 必须用匹配隔离开 |

**SLG 的特殊性在于差距通常远大于 5 倍**——大 R 和免费玩家的战力差 10~100 倍是常态。那 SLG 靠什么让免费玩家留下来？三个机制：

1. **数量对抗质量**：10 个小号可以打掉 1 个大 R（集结机制），这把个人战力差距转化成了组织问题；
2. **非战斗价值**：采集、建设、侦察、后勤——**让弱者在联盟里有战力之外的位置**；
3. **不可购买的资源**：体力、时间、土地——率土-like 的核心设计（第 01 章 7 节）。

**这三条是 SLG 生态设计的基石**，第 18、19 章会完整展开。

## 7. 常见坑

| 坑 | 后果 | 对策 |
|---|---|---|
| 用减法公式做长线 | 版本膨胀后不破防或秒杀，战斗系统报废 | 用饱和公式，或严格锁死攻防比 |
| 百分比减伤没设硬顶 | 玩家堆到接近 100% 无敌 | 必须设顶，或改用饱和公式 |
| 属性投放量不匹配最优占比 | 玩家觉得某类装备是垃圾 | 投放量正比于战力公式里的最优占比 |
| 先配属性再看回合数 | 战斗要么 2 回合要么 80 回合 | 先定回合数，反推 EHP/DPS |
| 显示战力 = 计算战力 | 战力忽高忽低、高战打不过低战，信任崩塌 | 两者分离，显示战力必须单调 |
| 战力公式没留扩展接口 | 每加一条养成线都要重算全服战力 | 设计成"模块之和" |
| 新养成线在战力里权重过低 | 玩家不练，系统白做 | 上线前用战力权重反查 |
| 忽略"多打一"的战力叠加方式 | 集结机制被算错，平衡崩 | 明确 N 人集结的战力是相加还是次线性 |

最后一条值得注意：**N 个人一起打，总战力是 `N × 单人战力` 还是别的？** 这个选择决定了 SLG 里"人海"是否有效——如果是线性相加，10 个小号确实能打死 1 个大 R；如果是 `√N` 之类的次线性，人海就废了。**这是 SLG 生态最关键的一个参数之一**，第 18 章详细讨论。
