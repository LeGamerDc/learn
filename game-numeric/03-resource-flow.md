## 1. 为什么需要一种通用语言

游戏千差万别，但**资源的流动方式只有那么几种**。一旦你掌握了描述流动的词汇，你会发现《率土之滨》的兵役、《魔兽世界》的金币、《剑与远征》的英雄粉尘，在结构上是同一个东西的变体。

这套词汇最早由 Joris Dormans 在 **Machinations** 里系统化，后来 Daniel Cook 在 [Value chains](https://lostgarden.com/2021/12/12/value-chains/) 一文里补上了"为什么玩家在乎"这一环。本章把两者合起来讲，并给你一个可运行的 Python 实现。

**学完这一章的直接收益**：以后拿到任何一份数值方案，你的第一个动作应该是——"把资源流图画给我看"。画不出来的方案，基本可以判定没想清楚。

## 2. 五个基本元件

```
   ┌─────────┐
   │  源      │  SOURCE / FAUCET      凭空产出资源
   │  ○──→   │  例：挂机产出、任务奖励、签到、掉落
   └─────────┘

   ┌─────────┐
   │  池      │  POOL / STOCK         资源的存放处，有存量，可能有上限
   │  ▭       │  例：背包里的金币、体力条、全服货币总量
   └─────────┘

   ┌─────────┐
   │  汇      │  DRAIN / SINK         资源永久消失
   │  ──→ ×  │  例：升级消耗、兵损、修理费、抽卡、交易税
   └─────────┘

   ┌─────────┐
   │  转换器  │  CONVERTER            消耗 A 产出 B
   │  A→[]→B │  例：练兵（粮→兵）、合成、强化
   └─────────┘

   ┌─────────┐
   │  门      │  GATE                 限制流量的阀门
   │  ──╫──→ │  例：体力上限、每日次数、等级门槛、CD
   └─────────┘
```

还有一个只在有交易系统的游戏里出现的第六个元件：

```
   ┌─────────┐
   │  交易器  │  TRADER               资源在玩家之间转移（总量不变）
   │  A ⇄ B  │  例：拍卖行、玩家交易、公会捐献
   └─────────┘
```

### 2.1 最容易搞混的：汇 vs 转换器 vs 交易器

这三个的区别决定了你的经济会不会崩，务必分清：

| | 全服资源总量的变化 | 例子 |
|---|---|---|
| **汇（sink）** | **减少** | 金币升级建筑：金币消失了，只留下一个等级数字 |
| **转换器** | 一种减少，另一种增加 | 粮食练兵：粮食没了，但兵多了。**兵本身还是资源** |
| **交易器** | **不变** | 玩家 A 把金币给玩家 B |

**新手最常犯的错是把转换器当成汇。** 比如"金币可以换成钻石"——这不是回收，钻石还在经济体里，只是换了个池子。真正的回收必须让资源**彻底消失**。

判断方法很简单：**问"这些资源花掉之后，还能不能以任何形式换回来或者传给别人？"** 能，就不是汇。

这也解释了为什么第 00 章实验 A 里，城建满级后回收率崩到 35%——升级建筑是真正的汇（金币变成一个等级数字，永远回不来），一旦封顶，就没有汇了。

## 3. 存量-流量思维：制作人唯一能控制的东西

这是本章的核心心智模型，也是整个经济设计的支点：

> **存量的变化率 = 流入 − 流出**
>
> 你**不能直接设定存量**。你只能设定流入和流出的速率，然后存量会自己演化成什么样就是什么样。

听起来是废话，但它的推论非常反直觉：

**推论一：任何"投放 > 回收"的持续状态，最终都会导致存量趋于无穷。** 哪怕差距只有 1%。不存在"稍微多投放一点点没关系"这回事——只有时间长短的区别。

**推论二：你今天做的投放决策，效果要几十天后才看得出来。** 存量是流量的积分，积分有滞后。这就是为什么经济事故总是"突然爆发"——其实它已经积累了三个月。

**推论三：想降低存量，加大回收比减少投放更有效，而且玩家反弹更小。** 减少投放玩家立刻能感觉到（"策划砍产出"），加大回收则可以包装成新内容（"新的高级强化系统"）。**这是第 09 章治理通胀的核心手段。**

**推论四（最重要）：判断经济健康只需要看两条线。** 累计投放和累计回收，画在同一张图上。它们的间距在收敛就是健康，在张开就是通胀。**这是你审任何数值方案时都该要的那张图。**

## 4. 跑模型：一个迷你 SLG 的完整资源流

现在把这些元件组装起来。模型结构：

```
   矿场 ──→ 【金币】──→ 升级城建 ──→ ×
   ○                      │
                          │ 等级提升 → 产能提升
   农田 ──→ 【粮食】──→ 练兵 ──→ 【兵】──→ 打仗 ──→ ×
   ○                              ↑           （战损）
                                  │
   体力恢复 ──→ 【体力】(上限120)──╫  门：每天最多打 20 仗
   ○
```

```bash
cd models && python m03_slg_flow.py
```

引擎 `econ.py` 的核心设计是：**所有资源池的增减都必须经过 `_give` / `_take`**，引擎据此自动生成"哪个节点动了哪种资源多少"的账本。这样 `audit()` 打出来的收支表才不会漏项。

> 这个设计不只是编程洁癖。**真实项目里，服务端的经济日志必须用同样的原则**——每一笔资源变动都带上"是哪个系统、哪个原因造成的"。做不到这一点，线上出了经济问题你根本查不出源头。第 23、24 章会展开。

### 4.1 读收支平衡表

```
=== 资源：gold ===
矿场                    +599,684
升级城建                  -509,203
投放合计 599,684 ／ 回收合计 509,203 ／ 回收率 84.9% ／ 期末存量 90,481

=== 资源：food ===
农田                    +449,763
练兵                    -449,760
投放合计 449,763 ／ 回收合计 449,760 ／ 回收率 100.0% ／ 期末存量 3

=== 资源：stamina ===
体力恢复                  +3,700
战损                     -3,600
回收率 97.3% ／ 期末存量 100 ／ 累计溢出 1,700  ← 被浪费的投放

=== 资源：troops ===
练兵                     +5,622
战损                     -4,744
回收率 84.4% ／ 期末存量 878
```

**注意 `level` 被排除在外了**（`audit(df, skip=("level",))`）。等级是计数器不是资源——它只增不减，放进收支表会永远报"回收不足"的假警报。真实项目里做经济监控时，第一件事就是把这类计数器和真正的资源区分开。

**四种资源呈现了四种完全不同的状态**，每一种都对应一类真实的设计情形：

| 资源 | 状态 | 含义 |
|---|---|---|
| 粮食 | 回收率 100%，存量 ≈ 0 | **完全流转**。产出多少消耗多少，玩家永远觉得"粮食不够用"。这是设计得最好的一种 |
| 金币 | 回收率 84.9%，存量锯齿上升 | **健康但在缓慢积累**。锯齿是正常的（攒钱→升级），但峰值越来越高 |
| 兵 | 回收率 84.4%，收敛到 878 | **动态平衡**。源和汇都与存量相关，所以会自动收敛到一个平衡点（见 5.2） |
| 体力 | 累计溢出 1,700 | **46% 的投放被浪费掉了** |

### 4.2 从模型里挖出两个设计问题

这才是资源流图的真正价值——**它让设计缺陷变成肉眼可见的**。

**问题一：体力有 46% 被浪费，而且真正的门不是体力。**

体力每天恢复 30，但打仗每天最多消耗 20（`battles = min(stamina, 20)`）。于是每天净剩 10 点，撞到 120 上限后就开始溢出，180 天累计浪费 1,700 点。

关键在于：**设计者以为体力是限制玩家节奏的门，但实际生效的门是"每天 20 场"这个硬上限。** 体力这个系统在这套参数下是完全没用的——你把体力上限调成 1000 或者调成 50，玩家的行为一模一样。

> **识别"真正生效的瓶颈"，是资源流分析最实用的技能。** 一条链上往往有好几个限制，但同一时刻只有一个在起作用。你调整不生效的那个，玩家毫无感知；你调整生效的那个，牵一发动全身。

**问题二：兵营产能这个参数，从第 3 天起就失效了。**

练兵速度受两个限制：兵营产能（`15 × 城建等级`）和粮食供给。跑一下就知道：

```
兵营产能成为瓶颈的天数:  2 / 180
粮食成为瓶颈的天数:    178 / 180
最后一天：产能上限 195，实际只练了 38  ← 利用率 19%
```

也就是说，**从第 3 天开始，玩家升级城建带来的练兵提升，完全来自粮食产量的增加，和兵营产能一点关系都没有。**

如果你在这个游戏里加一个"兵营"建筑，专门用来提升练兵产能，玩家升了会发现毫无变化——然后他们会去论坛骂你。这类"看起来有用、实际不生效"的参数在真实项目里非常常见，而且**只有画出资源流并跑一遍才能发现**。

## 5. 三种典型结构

认出这三种结构，你就能看懂 90% 的游戏经济。

### 5.1 正反馈回路（Positive Feedback Loop）

```
   金币 ──→ 升级城建 ──→ 产能提升 ──┐
     ↑                              │
     └──────────────────────────────┘
```

**产出 → 投资 → 更多产出。** 这是所有养成游戏的引擎，也是"滚雪球"的来源。

- **好处**：制造成长感和复利快感。玩家早期的每个决策都会被放大，这让决策有意义。
- **危险**：正反馈天生放大差异。领先的玩家会越来越领先，**差距是指数级拉开的**。
- **控制手段**：给回路加一个**指数成本曲线**当刹车（第 00 章实验 C 已经证明它能把倍数差压成常数差），或者加上限（但小心第 00 章实验 A 的陷阱）。

**SLG 里几乎所有的"资源地"设计都在处理这个问题**：资源产出如果全在城内（正反馈完全内生），大 R 会无限滚雪球；把主要产出放到城外的争夺性资源点上，就把正反馈的强度交给了玩家间的博弈来调节。这是第 18 章的核心内容。

### 5.2 负反馈回路（Negative Feedback Loop）

```
   粮食 ──→ 练兵 ──→ 【兵】──→ 战损 ──→ ×
                       │         ↑
                       └─────────┘
                    兵越多，损失越多
```

**存量越大，流出越大。** 模型里兵力曲线之所以会收敛到 878 而不是无限增长，就是这个结构：战损按兵力的百分比计算，所以兵越多损失越多，最终在"每天练的 = 每天损的"处达到平衡。

平衡点很好算：`平衡兵力 = 每日练兵量 / 战损率`。模型里后期每天练 38 个，战损率 4%，平衡点 = 38/0.04 ≈ 950，和实测的 878（还在爬升中）吻合。

**这是最优雅的经济稳定器**，因为它自动生效、不需要设上限、玩家也不会觉得被针对。**按比例的损耗是 SLG 数值设计里最重要的工具之一**，第 08 章会专门讲它为什么比"每日上限"之类的硬限制好用得多。

### 5.3 转换链（Value Chain）

```
   ○ ──→ 【原料】──→ [加工] ──→ 【半成品】──→ [合成] ──→ 【成品】──→ 效用
```

**多级转换。** 每一级都是一个门槛，也是一个可调节的旋钮。链条越长：

- 优点：可调节点更多、可以给不同玩家分配不同环节（形成经济分工，见第 10 章）、内容消耗更慢；
- 缺点：玩家理解成本高、任何一环断了整条链失效、后期资源换算关系会变得极其复杂。

**Daniel Cook 的核心洞察**是：这条链必须终止于一个**锚点（anchor node）**——某个玩家真正在乎的东西（变强、赢、好看、被认可）。

> **每一条资源链都要能追溯到一个玩家动机。追溯不到的资源，就是垃圾资源。**

这直接连回第 02 章第 1 节讲的"转换链条断裂"：大 R 的金币之所以变成废纸，不是因为链条不存在，而是因为链条末端那个锚点（变强）对他已经饱和了。

## 6. 画资源流图的六步法

给任意一款游戏画图的标准流程。**建议现在就拿你在第 01 章选的那款游戏走一遍。**

**第 1 步：列出所有池。** 打开游戏的背包和资源栏，把所有数字抄下来。通常有 5~15 个。别忘了体力、次数、CD 这类隐形的池。

**第 2 步：给每个池找源。** 这个资源从哪来？至少找 3 个来源。找不到源的池，要么是你漏了，要么它是纯转换产物。

**第 3 步：给每个池找汇。** 这个资源花在哪？**这一步是最重要的**，因为找不到汇的资源就是设计缺陷（见第 7 节）。

**第 4 步：标出门。** 哪些地方有上限、每日次数、等级要求、CD？门决定了节奏。

**第 5 步：找出回路。** 哪些链条会绕回来？正反馈还是负反馈？**正反馈回路是你最需要盯着的地方**。

**第 6 步：给每条链找锚点。** 每条链最终服务于玩家的哪个动机（用第 02 章的动机模型）？找不到锚点的链，要么删掉，要么补一个。

画完之后，问自己三个问题：

1. 哪个资源是当前真正的瓶颈？（它决定了玩家的实际节奏）
2. 主要的汇是什么？它有上限吗？
3. 如果玩家付费，钱进入的是哪个节点？它会不会绕过某个门？

## 7. 四种一眼可见的设计缺陷

资源流图画出来之后，这四种毛病是**直接肉眼可见**的。

| 缺陷 | 图上长什么样 | 后果 | 真实例子 |
|---|---|---|---|
| **孤儿资源** | 有源没汇 | 无限堆积 → 玩家困惑"这东西留着干嘛" → 该资源的所有奖励都失去价值 | 后期没用的低级材料 |
| **死胡同（无底洞）** | 有汇没有后续锚点 | 玩家投入了但换不来在乎的东西 → 投入意愿归零 | 满级后还在产出经验 |
| **溢出** | 池有上限但流入 > 流出 | 投放被浪费，且**玩家会因此不敢下线/被迫上线**（打工感的主要来源） | 模型里的体力，46% 浪费 |
| **失效的门** | 一条链上有多个门，只有一个生效 | 其他门变成装饰，玩家升了没感觉 | 模型里的兵营产能，98.9% 的时间不生效 |

**注意"溢出"的两面性**：溢出通常是缺陷，但**故意留一点溢出是有价值的**——它制造"我错过了收益"的损失厌恶（第 02 章 3.2），驱动玩家提高登录频率。区别在于程度：

- 溢出 5%~15%：健康的驱动力，玩家会想"我得勤快点"；
- 溢出 40%+（像我们的模型）：玩家会觉得"这系统就是逼我上线"，转为怨恨；或者干脆无视，让这个系统失去意义。

第 07 章会给出体力类资源的具体配比方法。

然后回答：

17. 这个游戏有几个正反馈回路？分别被什么刹车控制着？
18. 它的主要汇是什么？有没有上限？
19. 你能找出至少一个孤儿资源或者一个失效的门吗？
20. 玩家付费之后，钱进入的是哪个节点？它绕过了哪个门？

**第 20 题是整个作业里最重要的一题。** 它的答案基本上就是这款游戏的商业模式，第 12 章会用到。
