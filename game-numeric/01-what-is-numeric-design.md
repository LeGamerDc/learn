# 01 - 数值设计到底在设计什么

> **本章目标**：建立正确的心智模型。学完你应该能回答：数值设计和玩法设计的边界在哪、数值要同时满足哪三个互相打架的目标、作为制作人你必须亲自拍板哪些数值决策。
> **本章不需要写代码。** 但请把第 8 节的动手作业做掉，它决定了后面几章你能吸收多少。

---

## 1. 一个思想实验：把数值全部抽掉会怎样

假设有一款 SLG，玩法系统一应俱全：能建城、能出兵、能结盟、能打仗。但我们把所有数值都设成一样——

- 所有建筑升级都花 100 金币，耗时 1 分钟；
- 所有兵种攻防都是 10；
- 每天产出 10000 金币。

这游戏会发生什么？

**第一天**：所有玩家把所有建筑升满，因为没有任何东西阻挡他们。
**第二天**：所有人战力相同，任何一场仗的结果都由人数决定，人多的一方必胜。
**第三天**：所有人加入最大的联盟（因为这是唯一的优势来源），游戏结束。

这个实验说明了三件事，也就是数值的三个职能：

| 抽掉数值后失去的东西 | 数值的职能 | 本课程对应 |
|---|---|---|
| 内容被瞬间消耗完 | **控制节奏**——让内容按你设计的速度被消耗 | 第 04、20 章 |
| 玩家之间没有差异 | **制造差异**——让投入（时间/金钱/技巧）转化为可感知的强弱 | 第 05、12 章 |
| 只剩一个最优解（人多） | **保持策略空间**——让多种玩法都有存在价值 | 第 16、18 章 |

反过来说，**数值设计就是在设计"稀缺"**。游戏里的一切价值都来自稀缺，而稀缺完全是人造的——服务器上多给玩家一万金币的边际成本是零。你要决定的是：什么东西稀缺、稀缺到什么程度、玩家用什么代价来解除稀缺。

这是整门课最底层的一句话，值得记住：

> **数值设计 = 设计人造稀缺，以及解除稀缺的路径与代价。**

投放（faucet）是解除稀缺的速度，回收（sink）是重新制造稀缺的速度，付费是插队的代价，博弈是稀缺资源的分配规则。你要学的所有东西都是这句话的展开。

## 2. 玩法 / 系统 / 数值：三者的分工

新手最容易混淆的边界。用一个具体例子说清楚：

> **玩法设计**决定："战斗是双方部队自动交战，回合制结算，每回合双方各出手一次。"
> **系统设计**决定："有 4 种兵种，兵种之间存在克制关系；每支部队可带 3 名武将；武将有等级和技能。"
> **数值设计**决定："步兵克骑兵，克制加成 30%；每级武将 +2% 攻击；3 级技能的伤害系数是 1.8；一场战斗平均持续 8 回合。"

| | 回答的问题 | 产出物 | 改动成本 |
|---|---|---|---|
| **玩法设计** | 玩家在做什么？什么时候觉得爽？ | 玩法文档、原型 | **极高**，改了要重做 |
| **系统设计** | 有哪些功能模块，怎么互相连接？ | 系统文档、流程图、UI | **高**，要改代码和美术 |
| **数值设计** | 每个参数是多少？随时间怎么变？ | 数值表、公式文档、仿真模型 | **低**，改配置就行 |

### 2.1 关键推论：数值救不了玩法，但能毁掉玩法

这是三者关系里最重要的一条。

- 如果核心战斗本身不好玩，你把所有数值调到完美，它还是不好玩。**数值不产生乐趣，它只是放大或抑制玩法本身的乐趣。**
- 但如果数值做错了，一个好玩法会彻底哑火。比如战斗系统本身有很丰富的策略空间，但你把某个兵种的数值调高了 30%，玩家发现"全出这个兵就行"，整个策略空间瞬间坍缩成一个按钮。

**对制作人的实际含义**：当游戏数据不好时，你要先分清是"玩法问题"还是"数值问题"。判断方法：

| 现象 | 更可能是 | 判断依据 |
|---|---|---|
| 玩家新手期就流失 | 玩法问题 | 数值在前 10 分钟几乎不起作用 |
| 玩家玩到第 3 天流失 | **数值问题** | 大概率是节奏断层或卡点太早 |
| 玩家玩得久但不付费 | **数值问题** | 稀缺设计不到位，没有付费动机 |
| 玩家说"没意思" | 玩法问题 | 数值造成的是"太肝"/"太氪"，不是"没意思" |
| 所有人玩法趋同 | **数值问题** | 存在占优策略，见第 16 章 |
| 大 R 流失 | **数值问题** | 付费深度不足或资源溢出，见第 12 章 |

一个粗略但好用的经验法则：**前三天的问题多半是玩法和引导，三天之后的问题多半是数值。**

## 3. 数值要同时满足的三个目标（它们互相打架）

这是数值设计的核心张力，也是为什么这活儿难。

```
                   ┌──────────────────┐
                   │   ① 体验节奏      │
                   │  玩家爽不爽、      │
                   │  什么时候爽        │
                   └────────┬─────────┘
                            │
              想让玩家爽 → 多给资源  ✗ 冲突 ✗  多给资源 → 通胀
                            │
        ┌───────────────────┴───────────────────┐
        │                                       │
┌───────▼────────┐                     ┌────────▼───────┐
│  ② 经济健康     │                     │  ③ 商业化       │
│  三年不崩、      │◄─── ✗ 冲突 ✗ ───►  │  能赚钱、       │
│  新老玩家能共存  │  卖资源赚钱 = 破坏经济 │  付费有动机     │
└────────────────┘                     └────────────────┘
```

### ① 体验节奏：玩家在第 N 天应该有什么感受

数值的第一职责是**编排情绪**。一条典型的 SLG 情绪曲线：

| 时间 | 目标感受 | 数值手段 |
|---|---|---|
| 第 1 小时 | 爽、停不下来 | 极高投放，几乎不设阻力，每 30 秒一次正反馈 |
| 第 1~3 天 | 有明确目标、进展飞快 | 投放仍高，但开始出现短卡点（几小时级） |
| 第 4~14 天 | 开始需要规划、遇到第一次真正的墙 | 投放收紧，卡点拉长到一天以上，付费点在此密集出现 |
| 第 15~60 天 | 融入组织、有社交责任 | 个人成长明显放缓，产出转向联盟/协作渠道 |
| 第 60 天+ | 长期目标、身份认同 | 成长曲线趋于水平，靠赛季和排名维持动力 |

注意最后两行：**个人成长的边际收益必然递减**（第 00 章那张锯齿图已经证明了），所以长线游戏必须在成长感衰减之前，把玩家的动机从"变强"迁移到"社交责任 + 竞争身份"。做不到这个迁移的游戏，寿命就是玩家的成长曲线走平的那一天。

这是第 19、20 章的主题。

### ② 经济健康：三年后这个服还能玩

体验节奏是短期的，经济健康是长期的，两者天然冲突：

> 让玩家爽的最简单办法是多给资源，而多给资源的直接后果是通货膨胀。

现实中的表现：运营部门每个月都想加一个"限时双倍"活动来拉当月流水，每次加的时候看起来影响都不大，一年下来全服资源存量翻了 20 倍，你的所有定价体系失效。

第 07~09 章会给你抵抗这种压力的工具：**日产出预算表**（每一次活动投放都必须从预算里扣）和**经济监控指标**（存量、流速、物价指数）。

### ③ 商业化：付费要有动机，但不能破坏前两者

最容易犯的错是**直接卖资源**。它短期有效、长期致命：

- 卖资源 = 增加投放 = 通胀 = 破坏 ②；
- 卖资源 = 用钱跳过卡点 = 破坏 ① 的节奏编排；
- 更糟的是，一旦玩家发现"充钱能买到的东西，肝几天也能拿到"，付费的稀缺感就消失了。

好的商业化设计卖的是**稀缺性本身**，不是资源：

| 卖什么 | 例子 | 对经济的影响 |
|---|---|---|
| ✗ 直接卖资源 | 6 元 = 10 万金币 | 直接通胀，最差 |
| △ 卖时间 | 加速道具、双倍收益卡 | 温和通胀，可控 |
| ○ 卖概率 | 抽卡 | 不增加资源总量，且抽卡本身是巨型 sink |
| ○ 卖独占内容 | 限定武将、赛季通行证 | 不影响资源经济，但会加速数值膨胀（第 21 章） |
| ◎ 卖便利与身份 | 外观、称号、多队列、自动化 | 几乎不影响经济，但天花板低 |

**这三个目标的冲突没有标准答案，只有取舍。** 而做这个取舍正是制作人的工作——数值策划可以告诉你"加这个活动会让 90 天后的资源存量涨 15%"，但"这 15% 换这个月的 20% 流水值不值"只能你来定。

## 4. 数值系统的三层结构

把 README 的全景图换一种切法，按抽象层次分：

```
┌─────────────────────────────────────────────────────────┐
│  第三层：博弈与商业化   ← 玩家之间、玩家与厂商之间的关系    │
│  PvP 规则、匹配、联盟、赛季 / 付费点、定价、抽卡           │
│  【第 12~19 章】                                         │
├─────────────────────────────────────────────────────────┤
│  第二层：成长与战斗     ← 资源如何变成"强"                │
│  等级曲线、战力公式、伤害公式、养成线                      │
│  【第 04、05 章】                                        │
├─────────────────────────────────────────────────────────┤
│  第一层：资源流         ← 一切的地基                      │
│  产出、消耗、存量、转化率、货币体系                        │
│  【第 03、06~09 章】                                     │
└─────────────────────────────────────────────────────────┘
```

**必须自下而上地设计。** 常见的失败是从第三层开始（"我们要做一个很酷的赛季玩法"），然后发现底层的资源流撑不住它。

正确的顺序：先确定玩家每天能获得多少资源（第一层）→ 这些资源换算成多少战力（第二层）→ 这个战力增速能支撑什么样的竞争结构和付费结构（第三层）。

反过来验证时也是自下而上：线上数据异常，先查资源流，再查成长曲线，最后才怀疑玩法规则。

## 5. 制作人的决策边界

你不需要自己配表，但下面这些**必须你拍板**，因为它们是不可逆的、跨系统的、或者涉及商业取舍的。

| 决策 | 谁定 | 为什么是这个人 |
|---|---|---|
| 品类定位与核心循环 | **制作人** | 决定后面一切，不可逆 |
| 单个赛季/版本的时长 | **制作人** | 牵动内容产能、运营节奏、商业周期 |
| 付费深度上限（最贵的东西多少钱） | **制作人** | 商业取舍，且直接决定生态形态 |
| 付费能带来多大战力优势 | **制作人** | 决定服务器生态，改不动（改了老玩家造反） |
| 有没有自由交易 | **制作人** | 一旦开放几乎不可回收，见第 10 章 |
| 数值膨胀的速度（每个版本强多少） | **制作人** | 决定产品寿命，见第 21 章 |
| 主要养成线有几条、分别多深 | 主策 + 数值 | 制作人定"几条"，数值定"多深" |
| 日产出预算总量 | 数值（制作人审） | 制作人要看的是**分配比例**，不是绝对值 |
| 等级经验曲线的具体数字 | 数值 | 执行层 |
| 伤害公式选哪一种 | 数值（制作人要懂后果） | 第 05 章会讲每种公式的体验后果 |
| 单个装备的属性 | 数值 | 执行层 |
| 抽卡概率与保底 | 数值 + 法务（制作人审） | 有合规要求，见第 13 章 |

**一条实用建议**：你审数值方案时，不要审数字，审**比例和曲线形状**。

具体来说，问这五个问题就能覆盖 80% 的风险：

1. **日产出预算表在哪？** 各渠道占比多少？（没有这张表 = 没有做经济设计，见第 07 章）
2. **主要的 sink 是什么？它有上限吗？**（第 00 章实验 A 的教训，见第 08 章）
3. **免费玩家和大 R 的战力差距是多少倍？这个差距 90 天后是变大还是变小？**（见第 19 章）
4. **玩家第 30 天、第 90 天分别在追求什么？**（答不上来 = 长线规划缺失，见第 20 章）
5. **这套数值跑过仿真吗？给我看 180 天的存量曲线。**（见第 11 章）

## 6. 一个真实项目的数值工作流

让你知道这些知识在什么时候用得上。

```
立项期                研发期                内测期              上线运营
───────────────────  ───────────────────  ─────────────────  ──────────────────
· 品类定位            · 养成线设计          · 埋点校验          · 经济监控
· 核心循环            · 战斗数值            · 小规模真人测试     · 活动数值
· 经济骨架 ★          · 成长曲线            · 曲线调参          · 版本数值 ★
· 付费框架 ★          · 配表 + 导表工具      · 付费点验证        · 赛季设计 ★
· 长线节奏草案 ★      · 仿真验证 ★          · 首日/首周节奏     · 合服/生态干预 ★
                                                              · 数值重构（罕见）
  ↑ 制作人主导           ↑ 数值主导            ↑ 数值 + 数据       ↑ 制作人 + 运营
```

★ 标记的是制作人必须深度参与的环节。注意它们集中在**头和尾**：立项期定骨架，运营期做取舍。中间的研发期你主要是审方案。

**一个常被低估的事实**：数值工作量的大头在上线之后，不在上线之前。一款运营三年的 SLG，上线时的数值只占总数值工作量的 20%~30%，剩下的都是版本、活动、赛季、生态干预。这也是为什么这门课有整整一个阶段（第 20~22 章）讲长线运营。

## 7. 同一套玩法的三种数值路线

最后用一个对比，让你直观感受"数值决定了游戏是什么"。三款游戏的**系统框架高度相似**（都是养成 + 战斗 + 联盟），但数值路线完全不同：

| | **COK-like**（万国觉醒等） | **率土-like**（率土之滨、三战） | **卡牌放置**（剑与远征等） |
|---|---|---|---|
| 主要投放 | 城内挂机产出为主 | **城外资源地为主**（城内产出压得极低） | 挂机产出为主（占日投放大头） |
| 核心 sink | 建筑/科技升级、兵种训练 | **兵损**（打仗必然掉兵，要不停补） | 英雄升级/突破、抽卡 |
| 付费能买什么 | 资源、加速、兵 | **主要买抽将（武将）**，兵和体力不能直接买 | 抽卡、体力、加速 |
| 付费战力优势 | 大 | **中等**（体力上限锁死了单人产能） | 中等偏大 |
| 竞争结构 | 迁城自由，打完就跑 | **土地绑定**，你占的地就是你的软肋 | 弱竞争，主要是排行榜 |
| 长线手段 | 不断加新养成线 | **赛季重置**，土地重新分配 | 加新英雄 + 新养成线 |
| 玩家分层 | 大 R 主导 | **组织能力 > 付费能力** | 个人向，分层弱 |

三条路线的差异几乎全部来自数值和资源流的设计，而不是玩法系统。**最典型的例子是"体力"**：率土-like 给武将设了体力上限且只能随时间恢复、不能购买，这一个设计就把"付费能力"的作用范围锁死了——你可以有更好的武将，但你一天能打的仗数和免费玩家一样多。

> **一个参数（体力能不能买）改变了整个品类的生态。** 这就是数值设计的杠杆率。

第 18 章会把这三条路线彻底拆开对比。

**注意**：上表中关于具体投放比例的描述属于 `【推导】`——来自公开拆解报告和玩家可观测数据的反推，厂商未公开真实配比。结构性的判断（哪个是主要 sink、能不能买体力）属于 `【实证】`，游戏内可直接验证。

## 8. 动手：反向拆解一款你玩过的游戏

**这个作业比读完本章重要。** 后面几章的所有内容都会更容易吸收，如果你现在手上有一个具体的分析对象。

选一款你玩过 30 天以上的游戏（SLG 最好），花 40 分钟回答下面的问题。**不要查资料，只用你自己的游戏记忆和游戏内可观测的信息。**

**第一部分：资源流**
1. 列出这个游戏里的所有货币和主要资源（通常有 5~10 种）。
2. 对每一种，写出：它从哪来（至少 3 个来源）？它往哪去（至少 2 个去处）？
3. 哪一种资源是你最缺的？为什么是它？
4. 有没有哪种资源你根本花不完？（这就是一个设计缺陷，或者说，一个尚未被利用的付费点）

**第二部分：节奏**

5. 你第 1 天、第 7 天、第 30 天分别在追求什么目标？
6. 你遇到的第一个真正的"卡点"是在第几天？当时游戏给你提供了什么解决方案（肝 / 氪 / 社交）？
7. 你什么时候开始觉得"变强变慢了"？那之后是什么让你留下来的？

**第三部分：付费**

8. 这个游戏第一次向你推销是什么时候、卖的什么、多少钱？
9. 如果你付费了，是在什么情境下？如果没有，是什么阻止了你？
10. 你能看出它的付费点是"卖资源"、"卖时间"、"卖概率"还是"卖独占内容"吗？

**第四部分：博弈**

11. 强弱差距是怎么体现出来的？强的玩家能对弱的玩家做什么？
12. 弱的玩家有什么反制手段？（没有 = 生态会崩，见第 19 章）

把答案写下来存好（建议放在 `notes/` 目录）。后面每一章末尾我都会让你回来更新这份拆解——到第 25 章你会发现它已经变成了一份完整的数值分析报告。

## 9. 常见误区

| 误区 | 为什么错 | 正确的想法 |
|---|---|---|
| "数值就是调平衡" | 平衡只是数值的一小部分，而且完全平衡通常不好玩 | 数值是设计稀缺和节奏 |
| "先做玩法，数值最后填" | 经济骨架撑不住的玩法，做完了也得推翻 | 经济骨架和核心循环同期设计 |
| "参考竞品的数值抄一套" | 竞品的数值服务于它的付费结构和内容产能，抄来必然错配 | 抄**结构**可以，抄**数字**必死 |
| "数值不好可以上线后再调" | 投放能加不能减，加过的资源收不回来 | 投放宁可保守，回收宁可多留手段 |
| "玩家投诉太肝就多给点资源" | 治标，且一次性加投放会永久破坏经济 | 先看是不是卡点位置错了，见第 20 章 |
| "大 R 越强越好，他们付钱最多" | 大 R 的付费动机来自"能欺负别人"，欺负光了就没人陪他玩了 | 生态设计，见第 19 章 |
| "把概率调低能多赚钱" | 短期成立，长期摧毁付费信任；且有合规风险 | 见第 13 章 |
