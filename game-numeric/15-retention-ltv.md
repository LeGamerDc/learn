# 15 - 留存、LTV 与回本

> **本章目标**：搞懂 LTV 是怎么算出来的、它有多不可靠、以及数值设计通过什么路径影响它。
> **本章有模型**：`models/m15_retention_ltv.py`

---

## 1. 指标关系

先把几个天天听到的词理清楚：

```
   DAU  = 日活跃用户
   ARPU = 总收入 / 总用户数           （含免费玩家）
   ARPPU = 总收入 / 付费用户数         （只算付费的）
   ARPDAU = 日收入 / 当日活跃用户数     （日粒度，最常用于 LTV 计算）
   付费率 = 付费用户数 / 总用户数

   ARPU = ARPPU × 付费率
```

**LTV（生命周期价值）的本质定义：**

```
LTV = Σ (第 t 天的留存率 × 第 t 天的 ARPDAU)
```

也就是**留存曲线下的面积，乘以人均日收入**。

> **两个乘数的地位不对等：留存的影响远大于 ARPDAU。**
> 因为 ARPDAU 是线性因子，而留存是累加进积分的——留存曲线的**尾部厚度**决定了 LTV 的量级。
>
> 这有一个重要推论：**数值设计对 LTV 的最大贡献不在"让玩家多花钱"，而在"让玩家多留一天"。**

## 2. 留存曲线是幂律的

```bash
cd models && python m15_retention_ltv.py
```

看图 ①（双对数坐标）。观测点（D1=42%，D3=28%，D7=20%，D14=14.5%，D30=10%）在双对数坐标下**几乎是一条直线**——这是幂律 `R(t) = A·t^(-b)` 的特征。

```
模型                拟合参数              RMSE
指数 A·e^(-kt)      A=0.399, k=0.074    0.04160
幂律 A·t^(-b)       A=0.424, b=0.400    0.00589    ← 好一个数量级
幂律+底(c=0.03)     A=0.395, b=0.456    0.00888
```

**为什么是幂律而不是指数**：指数衰减假设"每个玩家每天有固定的流失概率"，但现实是**玩家是异质的**——有人玩两天就腻，有人玩三年。存活下来的玩家是"更不容易流失的那批"，所以整体流失率会随时间下降。这种异质性混合出来的就是幂律（或类似的重尾分布）。

**实践上的用法**：把留存画在双对数坐标上。**如果是直线，幂律拟合就够用；如果尾部翘起来，说明有铁杆底盘**（见第 4 节）。

## 3. 外推的危险：本章最重要的一节

```
模型                 LTV30    LTV90   LTV180   LTV365
指数 A·e^(-kt)        9.24    10.34    10.36    10.36
幂律 A·t^(-b)        10.02    20.12    30.93    47.73
幂律+底(c=0.03)      10.10    21.22    34.30    56.87

LTV30  极差：1.09 倍   ← 拟合窗口内几乎没差别
LTV365 极差：5.49 倍   ← 外推到一年差 5 倍以上
```

**三个模型都拟合了同一批数据，在数据覆盖的 30 天内几乎完全重合。** 但外推到 365 天，差 5.5 倍。

更要命的是回本结论：

```
=== 回本分析（CPI = 25 元，扣除商店 30% 抽成）===
  指数模型      365 天内不回本（净 LTV365 = 7.3 元）
  幂律模型      第 228 天回本
  幂律+底模型    第 191 天回本
```

> **同一批数据，换一个函数形式，"这个产品能不能投放买量"的结论完全相反。**

这不是模型选错了的问题——三个模型在数据范围内都是"对"的。**问题在于外推本身就是在用假设填补数据的空白。**

**给制作人的三条硬规矩：**

1. **任何 LTV 数字都必须带口径**：LTV30 / LTV180 / LTV365 是完全不同的数，不标注等于没说。
2. **外推窗口不要超过观测窗口的 3 倍**。有 30 天数据就别谈 LTV365，最多谈 LTV90。
3. **要给区间，不要给点估计**。用最保守和最乐观的模型各算一遍，把区间报出来。

## 4. "底盘"是假设，不是数据

模型里第三个函数带一个常数项 `c = 0.03`，含义是"有 3% 的玩家是铁杆，长期不流失"。

**注意代码里的注释：**

```python
# 注意：底盘 c 不是拟合出来的，是**假设**出来的。
# 只有 30 天的数据，根本无法从数据里识别出"长期底盘"这个参数——
# 它必须由你根据同类产品的经验来假定。
```

这是外推问题的核心：**决定 LTV365 的关键参数（长期底盘），恰恰是 30 天数据里信息量最少的那个。**

**所以实践中的做法是：**

- 底盘值从**同类产品的历史数据**里取（你自己的老产品、发行方的行业基准）；
- 明确写在报告里："本预测假设长期底盘 3%"；
- **随着数据积累不断修正**——D60、D90、D180 的真实数据一到，立刻重新拟合。

**永远不要把"假设"当成"结论"汇报。** 这是新手在数据会议上最容易犯的错，也是最容易导致错误投资决策的一个。

## 5. LTV 的口径陷阱

真实工作中，"LTV 是多少"这个问题至少有六种不同的答案，取决于口径：

| 口径维度 | 选项 | 影响 |
|---|---|---|
| **毛 / 净** | 含不含应用商店抽成（通常 30%）、渠道分成、税 | **差 30%~50%** |
| **窗口** | LTV30 / 90 / 180 / 365 / ∞ | 差好几倍 |
| **人群** | 全部安装 / 激活 / 完成新手 | 差 20%~50% |
| **是否含广告收入** | IAP only vs IAP + IAA | 休闲品类差别巨大 |
| **是否含自然量** | 只算买量用户 vs 全体 | 自然量的 LTV 通常显著更高 |
| **同期群定义** | 按安装日 / 按首付费日 | 完全不同的两条曲线 |

> **审 LTV 数字时，先问口径，再看数值。** 两个团队报的 LTV 差 3 倍，往往只是口径不同。

**回本（ROI）分析的标准口径**：

```
净 LTV(t) = 毛 LTV(t) × (1 − 商店抽成) × (1 − 渠道分成)
回本天数 = 使 净LTV(t) ≥ CPI 的最小 t
```

业界常用的健康标准 `【推导】`（不同品类、不同市场差异很大）：

- **LTV30 / CPI ≥ 0.5** 通常被认为是可以放量的信号；
- **回本天数 ≤ 180 天**对多数中重度产品是可接受的；
- 但这些阈值高度依赖你的现金流承受能力——**回本周期长意味着需要更多的垫资**。

## 6. 数值设计怎么影响 LTV

这是本章和前面所有章节的连接点。按影响力排序：

### ① 首日与首周留存（影响最大）

留存曲线的 `A` 参数（截距）由 D1 决定，**它是整条曲线的比例因子**——D1 提高 10%，整条曲线和 LTV 都提高约 10%。

**数值上的抓手**：新手期的正反馈频次（第 07 章：新手期只占 0.6% 的投放却决定生死）。

### ② 长期底盘（影响第二大）

底盘决定尾部厚度，而尾部贡献了 LTV365 的大部分。

**数值上的抓手**：
- **社交绑定**（第 07 章的社交产出占比、第 06 章的组织货币）——有组织责任的玩家极难流失；
- **沉没成本**（第 02 章）——养成线深度；
- **动机迁移**（第 02、20 章）——在个人成长感耗尽前，把玩家转到竞争和社交动机上。

> **底盘几乎完全由社交结构决定，而不是由数值本身决定。** 这是 SLG 相对单机向卡牌的最大优势。

### ③ 曲线中段的斜率

`b` 参数（衰减指数）由中期体验决定。

**数值上的抓手**：卡点位置和强度（第 04 章的"单级停留天数"、第 12 章的软墙设计）。**中期流失的最常见原因是节奏断层**——某个卡点突然变得远比之前的陡。

### ④ ARPDAU（影响最小但最直接）

付费点设计、定价、礼包（第 12~14 章）。

**注意它是线性因子**——ARPDAU 提高 20%，LTV 提高 20%，就这么多。而留存的改善会同时放大所有后续天数的收入。

> **这就是为什么"数值设计对 LTV 的最大贡献不在让玩家多花钱"。**
> 如果你只能改一件事，改留存。

## 7. 常见坑

| 坑 | 后果 | 对策 |
|---|---|---|
| 用 30 天数据谈 LTV365 | 误差可达数倍，直接导致错误的买量决策 | 外推 ≤ 观测窗口 × 3 |
| 把假设的底盘当结论 | 高估 LTV，投放亏损 | 明确标注假设，持续修正 |
| 不说口径就报 LTV | 团队之间数字对不上，白吵 | 先对口径 |
| 只优化 ARPDAU | 线性收益，天花板低 | 优先优化留存 |
| 用指数模型拟合留存 | 系统性低估 LTV，错过好产品 | 双对数看形状，默认用幂律 |
| 忽视自然量与买量的差异 | 混算导致买量 ROI 虚高 | 分开算 |
| 按安装日分群但不排除无效安装 | 分母虚高，LTV 虚低 | 用激活或完成新手作为起点 |

**任务 A：改变底盘假设。** 把 `FLOOR` 从 0.03 改成 0.01 和 0.06，看 LTV365 和回本天数的变化。**用这三个值给出一个 LTV365 的区间**——这就是你该向老板汇报的形式。

**任务 B：模拟数据积累。** 把观测点扩展到 D60、D90（你自己编两个合理的值），重新拟合。三个模型的外推分歧缩小了多少？**这量化了"多等两个月再做决策"的价值。**

**任务 C：拆解留存改善的收益。** 分别模拟：D1 提高 10%（改 A）、衰减放缓 10%（改 b）、底盘翻倍（改 c），各自对 LTV365 的提升是多少？**排序结果会告诉你资源该投在哪。**
