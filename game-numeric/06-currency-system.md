# 06 - 多货币体系

> **本章目标**：搞清楚为什么游戏需要五到十种货币而不是一种，以及货币之间的兑换通道该怎么设计。这是经济系统的骨架，定错了后面所有调控手段都会失效。
> **本章有模型**：`models/m06_currency.py`

---

## 1. 为什么不能只有一种货币

假设你的游戏只有"金币"，所有东西都用金币买。看起来最简洁，实际上你会立刻失去四种能力：

**① 失去分渠道调控的能力。** 你想让玩家多打 PvP，于是提高 PvP 的金币奖励。结果：玩家打 PvP 拿金币，然后拿去升级建筑——**你没能引导他玩 PvP 的后续内容，只是给了全服一次通胀。** 有了独立的"荣誉币"，PvP 的产出就只能流进 PvP 相关的消费。

**② 失去分层定价的能力。** 大 R 和免费玩家的金币持有量差 100 倍。任何一个金币定价，对大 R 是零，对免费玩家是天价。多货币让你可以把"付费能买的"和"只能肝的"分开定价。

**③ 失去时间控制的能力。** 单一货币下，玩家只要有钱就能无限消费。**体力、次数这类"时间货币"是唯一能限制单日进度上限的工具**——而且它们必须是独立的池子。

**④ 失去隔离经济事故的能力。** 一旦出现刷金漏洞，单一货币会让整个经济体一起崩。多货币体系下，事故通常只污染一条链。

> **一句话：货币的数量 = 你手上调控旋钮的数量。**

代价当然也有：货币越多，玩家理解成本越高，UI 越复杂，你自己也越容易算不清换算关系。主流手游通常落在 **6~12 种**（含材料类）。

## 2. 货币分类学

按**功能**分，而不是按名字分。设计新货币时先问它属于哪一类。

| 类型 | 别名 | 特征 | 主要用途 | 通胀容忍度 |
|---|---|---|---|---|
| **软通货** | 金币、银两 | 大量产出、大量消耗、几乎不可交易 | 日常养成的燃料 | **高**（本来就该膨胀） |
| **硬通货** | 钻石、元宝 | 稀缺、**付费的主要入口**、少量免费产出 | 抽卡、加速、买软通货 | **极低**（膨胀 = 商业模式崩） |
| **绑定货币** | 绑钻、绑金 | 与硬通货等价但**不可交易** | 隔离付费与打金 | 低 |
| **时间货币** | 体力、次数、行动力 | **有上限、随时间恢复、不可囤积** | 控制单日进度上限 | 不适用（有上限） |
| **加速货币** | 加速道具、时间券 | 直接兑换"时间" | SLG 的核心付费点 | 中 |
| **组织货币** | 贡献、军功、公会币 | 只能通过组织行为获得、**不可交易** | 绑定玩家与组织 | 低 |
| **限时代币** | 活动币、赛季币 | **到期清零** | 活动兑换 | 不适用（自动归零） |
| **材料** | 各类素材 | 高度专用、来源单一 | 特定养成线的燃料 | 中 |

### 2.1 三个值得单独说明的类型

**时间货币是唯一能锁住"单日上限"的工具。** 第 01 章讲过率土-like 的体力设计：武将体力只随时间恢复、不能购买，这一条就把付费能力的作用范围锁死了。**它的威力来自"有上限 + 不可购买"这个组合**——少任何一个都不成立。

- 只有上限但可购买 → 大 R 无限刷，等于没有；
- 不可购买但无上限 → 玩家囤积，长草期一次性爆发，节奏失控。

**限时代币是天然的完美 sink。** 活动结束清零，意味着这部分投放**注定 100% 回收**。第 08 章会讲这是最省心的一类回收手段——代价是玩家的"清零焦虑"（第 02 章的损失厌恶，用得过狠会变成打工感）。

**组织货币的作用不是经济，是绑定。** 贡献度不可交易、离开公会即失效，本质上是在提高玩家的**退出成本**。SLG 里这类货币的设计直接决定了联盟的凝聚力，第 18、19 章展开。

## 3. 货币隔离原则

这是本章唯一必须记住的原则：

> **两种货币之间只要存在兑换通道，它们在经济上就是同一种货币。**

```bash
cd models && python m06_currency.py
```

模型设定：两条养成线（战力线、收集线），设计意图是让玩家两边都发展，投放比例定为 6:4。

```
方案                      第180天战力      第180天收集度
------------------------------------------------------
A 共用一种货币               360,000               0
B 两种独立货币               278,855          68,305
C 单向兑换（收集→战力）        360,000               0
```

**方案 A 和 C 里，收集线彻底归零。** 玩家的行为很简单：既然资源能自由流向战力线，而战力线的收益更高，那就 100% 投战力线。你设计的 6:4 比例被玩家的最优化行为完全抹平。

**方案 C 尤其值得注意——它是"单向"兑换，一样失败。**

### 3.1 单向兑换保护的是上游，不是下游

很多人以为单向兑换就安全了。不是的：

> **单向兑换 A → B，保护的是 A 的稀缺性（B 换不到 A），牺牲的是 B 的稀缺性（持有 A 的人可以绕过 B 的所有获取限制）。**

模型里 C 的方向是"收集币 → 战力币"，所以被保护的是收集币，被牺牲的是战力币——玩家把收集币全换成战力币，收集线归零。

**这正是所有游戏都设计成"钻石可以买金币，金币不能买钻石"的原因**：钻石是付费入口，它的稀缺性必须绝对保护；金币的稀缺性则是可以被付费绕过的——这本来就是商业模式的一部分。

**设计单向兑换时，方向的选择标准是：你愿意让哪种货币的稀缺性被绕过。**

### 3.2 隐性兑换通道更危险

明面上的兑换按钮你会注意到，但**商店会制造隐性兑换通道**：

- 商店同时卖 A 和 B → 玩家可以用任意一种买到另一种能买的东西 → **A 和 B 部分等价**；
- 交易行存在 → 玩家之间可以用 A 换 B → **完全等价**；
- 某个道具既能用 A 买也能用 B 买 → **在这个道具上等价，且确立了汇率**。

> **审经济方案时的一个标准动作：画一张"货币 × 可购买内容"的矩阵，看有没有两行的用途高度重叠。** 重叠的部分越多，两种货币越接近同一种。

## 4. 汇率设计

一旦有兑换，就必须定汇率。三条实践准则：

**① 汇率必须让付费显得"不划算但省时间"。**

如果 1 元换到的金币，比玩家自己肝一小时拿到的还多，那么所有内容对大 R 都会被瞬间买穿。合理的做法是让付费汇率对应"节省的时间"而不是"等价的资源"——**卖时间，不卖资源**（第 01 章第 3 节）。

**② 汇率要随游戏进程调整，但不能让老玩家吃亏。**

后期玩家的软通货产量是新手的几十倍，固定汇率会让硬通货换软通货在后期变得毫无价值。常见做法：

- 汇率与玩家等级挂钩（等级越高，1 钻石换更多金币）；
- 或者干脆**不让硬通货直接换软通货**，而是通过"资源包"商品，商品内容随版本更新。

**③ 汇率一旦公开就是锚点，改动代价极高。**

玩家会记住"1 钻石 = 100 金币"，并以此评估所有商品。**下调汇率等于变相涨价**，是最容易引发舆情的改动之一。第 14 章会讲定价锚定。

## 5. SLG 的货币体系

以主流 SLG 为例的典型结构 `【推导】`（结构是可观测的，具体配比是反推）：

```
┌──────────────────────────────────────────────────────────────┐
│  基础资源（软通货）：木材 / 石料 / 铁矿 / 粮食                  │
│  来源：城内产出 + 城外资源点 + 任务 + 联盟援助                  │
│  去向：建筑升级、科技研究、练兵                                │
│  特点：产量巨大、允许通胀、通常有仓库保护上限                    │
└──────────────────────────────────────────────────────────────┘
┌──────────────────────────────────────────────────────────────┐
│  加速道具（时间货币）：分钟券 / 小时券                          │
│  来源：任务、宝箱、付费                                       │
│  去向：跳过建造/研究/练兵的等待                                │
│  特点：★ SLG 最核心的付费点，本质是"卖时间"                     │
└──────────────────────────────────────────────────────────────┘
┌──────────────────────────────────────────────────────────────┐
│  硬通货：元宝 / 钻石                                          │
│  来源：付费为主 + 少量任务                                     │
│  去向：抽将、买加速、买资源包、开队列                           │
│  特点：★ 商业模式的核心，稀缺性必须绝对保护                     │
└──────────────────────────────────────────────────────────────┘
┌──────────────────────────────────────────────────────────────┐
│  体力 / 行动力（时间货币，率土-like 特有的强约束）               │
│  来源：随时间恢复，有上限                                      │
│  去向：出征、采集                                             │
│  特点：★★ 能不能购买，决定了整个品类的生态形态                  │
└──────────────────────────────────────────────────────────────┘
┌──────────────────────────────────────────────────────────────┐
│  联盟贡献 / 军功（组织货币）                                   │
│  来源：联盟任务、参战、捐献                                    │
│  去向：联盟商店、联盟技能                                      │
│  特点：不可交易，用来绑定玩家与组织                             │
└──────────────────────────────────────────────────────────────┘
┌──────────────────────────────────────────────────────────────┐
│  赛季代币（限时代币）                                          │
│  来源：赛季活动                                               │
│  去向：赛季商店；★ 赛季结束清零                                │
└──────────────────────────────────────────────────────────────┘
```

**注意"仓库保护上限"这个设计**：SLG 里被打劫时，仓库容量内的资源不会被抢走。这是一个非常精巧的多目的设计：

- 给弱者兜底（不至于被打到一无所有而弃坑）；
- 制造"超出保护量的资源要赶紧花掉"的压力 → **变相强化了回收**；
- 给"扩建仓库"这个建筑赋予了意义。

**加速道具是 SLG 区别于其他品类的关键。** 它把"等待时间"本身变成了商品，而等待时间在 SLG 里无处不在（建造、研究、练兵、行军）。这也意味着 SLG 的付费点密度天然高于其他品类。

## 6. 设计一套货币体系的六步法

**第 1 步：先列玩法，再列货币。** 每个需要独立调控的玩法模块，考虑给一种专属货币。反过来推容易造出没用的货币。

**第 2 步：给每种货币回答三个问题。**

| 问题 | 为什么重要 |
|---|---|
| **来源纯度**：它只从一个渠道来，还是到处都能拿？ | 来源越纯，调控越精准 |
| **用途宽度**：它能买的东西多不多？ | 用途越宽，越接近"通用货币"，越难调控 |
| **可交易性**：能不能给别人？ | 可交易 = 会被工作室盯上（第 10、24 章） |

**理想的专用货币是"来源纯 + 用途窄 + 不可交易"。** 越偏离这三点，它就越向"通用货币"退化。

**第 3 步：画兑换关系图。** 标出所有兑换通道（含隐性的），确认没有回路。**有回路 = 这几种货币实际上是同一种。**

**第 4 步：定通胀策略。** 每种货币是允许膨胀（软通货）、必须保值（硬通货）、还是自动归零（限时代币）？

**第 5 步：定 sink。** 每种货币的主要回收去向是什么？有没有上限？（第 08 章）

**第 6 步：做"货币 × 用途"矩阵检查。** 有没有哪两种货币的用途高度重叠？有没有哪种货币只有来源没有去向（孤儿资源，第 03 章）？

## 7. 常见坑

| 坑 | 后果 | 对策 |
|---|---|---|
| 货币太少 | 无法分渠道调控，一个漏洞污染全局 | 按玩法模块拆分 |
| 货币太多且用途重叠 | 玩家分不清，UI 灾难，你自己也算不清 | 做"货币 × 用途"矩阵，合并重叠的 |
| 存在兑换回路 | 所有货币退化成一种 | 兑换关系图必须是有向无环的 |
| 硬通货免费产出过多 | 商业模式崩塌，且不可逆 | 硬通货的免费产出要严格预算（第 07 章） |
| 体力可以购买 | 单日进度上限失效，大 R 无限刷 | 想清楚是否真的要卖 |
| 忘了给新货币设计 sink | 孤儿资源，玩家困惑 | 上线前跑一遍 `audit()` |
| 汇率上线后想改 | 变相涨价，舆情事故 | 用"商品包"代替明码汇率，商品内容可迭代 |
| 绑定/非绑定规则不清晰 | 玩家误操作后投诉，客服灾难 | 规则要极其简单，UI 上强区分 |

## 8. 动手

### 8.1 改模型

**实验 A：给方案 C 加一个兑换税。** 让收集币换战力币时损失 50%。收集线还是会归零吗？税率要多高才能保住收集线？

这个实验的现实意义：**兑换税是"部分隔离"的手段**，它不能真正隔离，只能减缓。第 10 章讲交易税时会回到这个结论。

**实验 B：让两条线的收益率随投入变化。** 把 `power_gain` 的指数从 0.5 改成 0.3（战力线边际递减更快）。现在共用货币的方案 A 里，玩家还会 100% 投战力线吗？

这引出一个重要设计手法：**当两条线的边际收益会交叉时，共用货币反而是可行的**——玩家会自发地在两条线之间平衡。这是"用边际收益代替强制隔离"的思路。

### 8.2 设计练习

用第 6 节的六步法，给一款**卡牌放置**游戏设计一套货币体系。要求：

- 至少支持四条养成线（英雄升级、装备、技能、图鉴）独立调控；
- 有明确的付费入口，且付费不能直接买断养成进度；
- 有一个能限制单日进度上限的机制；
- 画出兑换关系图，确认无回路。

做完之后和你在玩的那款游戏对照，看差在哪。
