# 04 - 成长曲线的数学

> **本章目标**：掌握数值设计里最核心的技术动作——**从"我希望玩家在第 N 天到达什么程度"，反推出具体的成本曲线**。学完你应该能看懂并审阅任何一份节奏表。
> **本章有模型**：`models/m04_curves.py`

---

## 1. 三条曲线，不是一条

新手谈"成长曲线"时通常指的是"玩家等级随时间的变化"。但那条曲线**你没法直接设计**——它是三条你能直接控制的曲线共同作用的结果：

```
   ┌────────────────┐
   │  ① 产出曲线     │   玩家每天能拿到多少资源       你直接设计
   │  income(t)     │   （第 07 章：日产出预算表）
   └───────┬────────┘
           │
           ▼
   ┌────────────────┐
   │  ② 成本曲线     │   升到下一级要花多少          你直接设计
   │  cost(L)       │   （本章重点）
   └───────┬────────┘
           │  两者相除、累加
           ▼
   ┌────────────────┐
   │  等级/进度曲线   │   玩家实际的成长节奏          ← 涌现出来的
   │  level(t)      │
   └───────┬────────┘
           │
           ▼
   ┌────────────────┐
   │  ③ 收益曲线     │   每级带来多少战力            你直接设计
   │  power(L)      │   （第 05 章）
   └───────┬────────┘
           ▼
      玩家感知到的"变强"
```

**这个结构是本章的骨架**，请先记住它：

> 你能拧的旋钮是 **产出、成本、收益** 三个；玩家感受到的 **节奏** 和 **强度** 是它们的复合结果。

第 00 章第一个模型已经演示过一次：产能 `1.06^L` 除以成本 `1.35^L`，涌现出了对数形态的等级曲线，而我们从来没有设计过那条曲线。

## 2. 四种基本曲线与它们的体验含义

```bash
cd models && python m04_curves.py
```

先看 `figures/m04_curves.png` 的两张图。

| 曲线 | 公式 | 形状 | 体验含义 | 典型用途 |
|---|---|---|---|---|
| **线性** | `a·t` | 匀速 | 平淡、可预测、无惊喜 | 日常任务奖励、签到 |
| **多项式** | `a·t^k` | 加速（k>1） | 前期慢、后期爽，容易失控 | 属性成长、伤害系数 |
| **指数** | `a·b^t` | 爆炸式 | 复利感，是唯一能维持恒定成长感的 | 成本曲线、放置游戏产出 |
| **对数** | `a·ln(t)` | 快速趋缓 | 边际递减，"越来越难" | 抗性/闪避这类需要软上限的属性 |
| **S 型** | `L/(1+e^(-k(t-t₀)))` | 慢-快-慢 | 有起势有收尾，最"完整"的一段体验 | 单个版本/赛季的整体节奏 |

### 2.1 关键：只有指数曲线能维持恒定的成长感

看第二张图。它画的是 **`d(ln y)/dt`，也就是"每天变强了百分之多少"**。

这是第 02 章那条原理的数学表达：**人感知的是相对变化，不是绝对变化**。所以要衡量"玩家爽不爽"，该看的是相对增量。

图上只有指数曲线是一条水平线——**只有指数增长能让玩家在整个生命周期里保持恒定的成长感**。

- **线性曲线的相对增量是 `1/t`**，衰减得非常快：第 10 天你还能感觉到 10% 的提升，第 100 天只剩 1%。这就是为什么"每天给固定奖励"的系统在两周后必然变得毫无感觉。
- **多项式 `t^k` 的相对增量是 `k/t`**，同样衰减，只是慢一点。
- **对数曲线衰减最快**，它天然是"给个甜头就没了"的形状。

> **实用推论**：任何你希望玩家长期在乎的数值，它的**绝对值**必须指数增长。
> 这不是策划失控，是维持体验的数学必然。第 21 章讲怎么在这个必然性下控制膨胀速度。

### 2.2 但成本曲线必须比收益曲线更陡

如果战力指数增长、成本也指数增长，谁快谁慢决定了一切。回顾第 00 章的三个实验：

| 关系 | 结果 |
|---|---|
| 成本增速 > 产能增速 | 成长逐渐放缓（对数形态）——**这是绝大多数游戏的选择** |
| 成本增速 ≈ 产能增速 | 成长接近线性，节奏均匀但缺乏后期缓冲 |
| 成本增速 < 产能增速 | **发散**。第 00 章那个 `OverflowError` 就是它 |

**这个差值是你最重要的一个旋钮。** 差值越大，后期越平缓、内容越经得起消耗、付费差距被压缩得越狠；差值越小，成长越持续、但内容消耗快、付费差距会被放大。

一个粗略的参考区间：主流长线手游的 `成本增速 / 产能增速` 通常落在 **1.1 ~ 1.3** 之间。`【推导】`

## 3. 核心技术动作：从目标时长反推曲线

这才是真实项目里做的事。**没有人是先画一条成本曲线然后看看玩家多久能升满级的**——流程永远是反的：

> 策划案先定："第 1 天玩家要到 10 级（新手期爽快），第 30 天到 40 级（首月留存目标），第 180 天到 60 级（半年生命周期）。"
> 然后**反推**：成本曲线必须长什么样，才能实现这个时间表。

模型的第二部分就是干这个的。

### 3.1 方案 A：单一指数成本曲线（会失败）

```
方案 A（单一指数，g=1.1716）：第1天 15级(目标10)  第30天 44级(目标40)  第180天 60级(目标60)
```

用一个 `cost(L) = 20 × g^(L-1)`，二分搜索 `g`，让第 180 天恰好到 60 级。结果：**最后一个锚点钉住了，前两个都偏了**（第 1 天冲到 15 级，第 30 天冲到 44 级）。

原因很简单——**一个参数只有一个自由度，钉不住三个点。**

这是新手最常见的失败：拿一个漂亮的公式套全程，然后发现前期太快、中期太慢，怎么调都是按下葫芦浮起瓢。

### 3.2 方案 B：分段成本曲线（正确做法）

把等级区间按锚点切段，**每段独立求一个增长率**，段首成本承接上一段段尾以保证连续：

```
方案 B（分段）：第1天 10级(目标10)  第30天 40级(目标40)  第180天 60级(目标60)   ✓ 全中

分段增长率：
   1→10 级：每级成本 ×1.4040    首级成本         20
  10→40 级：每级成本 ×1.1136    首级成本        424
  40→60 级：每级成本 ×1.1550    首级成本     10,694
```

**读出三个设计意图**：

- **1→10 级：增长率 1.40，非常陡。** 但因为基数极小（20），玩家 1 天就能冲完。这是标准的新手期——**用密集的等级提升制造正反馈，而不是用数值本身**。玩家 10 分钟连升 5 级的爽感，和这 5 级带来的实际战力没什么关系。
- **10→40 级：增长率 1.11，最平缓。** 这是产品的核心留存区，节奏要稳，不能有突兀的墙。
- **40→60 级：增长率 1.155，重新变陡。** 后期刻意放缓，把剩下的 20 级摊到 150 天里。

> **分段边界放在哪，就是你的产品节奏设计。** 边界通常对应：新手期结束、主要系统开放完毕、首个付费高峰、内容产能的天花板。

### 3.3 交付物：节奏表

反推出来的不是"一条曲线"，而是这张表——**这是数值策划交给团队的核心文档之一**：

```
等级    达成日     停留天数            升级成本
5       1         0                   78
10      1         1                  424
20      6         0                1,243
30      14        1                3,647
40      30        3               10,694
50      69        7               45,187
55      111       11              92,885
59      163       17             165,308
```

**审这张表时要看"停留天数"这一列，不要看"升级成本"。** 成本是手段，停留天数是玩家的真实体验。

从 0-1 天，到 3 天，到 7 天，到 17 天——这就是第 00 章那个"锯齿越来越宽"的正式版本。而它引出了长线设计里最关键的一个问题：

> **当单级停留时间超过一周，等级系统就不再是玩家的主要动力了。**

模型里这个拐点在 50 级、第 69 天左右。**这意味着你必须在第 69 天之前，准备好接替等级系统的东西**——新的养成线、赛季、PvP 排名、社交责任。

准备不足的直接后果就是第 02 章思考题里那个"90 日断崖式流失"。

## 4. 常用曲线公式手册

实际配表时会用到的形式。

### 4.1 成本 / 经验曲线

| 形式 | 公式 | 特点 |
|---|---|---|
| 纯指数 | `cost(L) = a·g^L` | 最简单，一个参数控制陡峭度；后期数字爆炸 |
| 幂函数 | `cost(L) = a·L^k` | 比指数温和，后期不至于爆炸；`k` 通常取 2~3 |
| 多项式 | `cost(L) = aL³+bL²+cL+d` | 传统 RPG 常用，可以精细控制各段 |
| **分段指数** | 每段一个 `g` | **本章推荐**，可精确对齐时间锚点 |
| 查表 | 直接手工填 60 个数 | 最灵活也最难维护；通常用来微调分段曲线的结果 |

**实践建议**：用分段指数生成基线，然后手工微调关键等级（整十级、系统解锁级）。**不要全手填**，改一个参数就要重填 60 个数是不可维护的。

### 4.2 收益 / 属性曲线

| 形式 | 公式 | 用途 |
|---|---|---|
| 线性 | `p(L) = a + b·L` | 基础属性（攻击、生命）。**加法叠加要用线性** |
| 指数 | `p(L) = a·g^L` | 战力总量、后期养成线 |
| 递减饱和 | `p(x) = M·x/(x+k)` | **抗性、闪避、暴击率等有上限的属性** |
| 对数 | `p(x) = a·ln(1+bx)` | 同上，衰减更柔和 |

**递减饱和公式 `M·x/(x+k)` 值得单独说**，它是数值设计里最常用的"软上限"工具：

- `x=0` 时为 0，`x→∞` 时趋近 `M`，永远达不到；
- `x=k` 时恰好是 `M/2`——**`k` 就是"半效点"，这是它最好用的地方**：你只需要回答"多少防御能减伤 50%"，参数就定了；
- 它自动实现了边际递减，玩家堆到后面会自己感觉到"堆不动了"，不需要你写一个硬上限去激怒他们。

第 05 章讲除法伤害公式时会再次用到它。

### 4.3 时间换算

把成本翻译成时间，这是节奏设计的基本操作：

```
到达 L 级所需天数 ≈ Σ(cost(i)) / 日产出   （i 从 1 到 L-1）
```

日产出本身随等级变化时就得逐日模拟——也就是模型里 `run()` 干的事。**手算会算错，一定要跑。**

## 5. 放置游戏：为什么必须是指数，以及随之而来的大数问题

放置/增量游戏（Idle / Incremental）把本章的原理推到了极致。Kongregate 的 [The Math of Idle Games](https://blog.kongregate.com/the-math-of-idle-games-part-i/) 三部曲是这个题材的经典拆解。

**核心结构**：产量和成本**都是指数**，且成本的底数略大于产量的底数。玩家的进度于是变成 `log(累计资源)`——**看起来是线性的稳定推进，实际上背后的数字在指数爆炸**。

这解释了放置游戏的两个标志性设计：

**① 数字后缀（K / M / B / T / aa / ab / ac...）。** 因为数值会突破任何常规数据类型：
- JS 的 `Number` 上限约 `1.8e308`，一个中等体量的放置游戏几周就能顶到；
- 业界通用做法是**存 `log10` 值**，或用 `break_infinity.js` 这类大数库（尾数 + 指数分开存）；
- **服务端同理**——Go 里 `float64` 同样在 `1.8e308` 溢出。设计阶段就要和程序确认数值上限，不要等上线后玩家把数字刷成 `Infinity`。

**② 转生 / Prestige 层。** 单纯的指数增长最终会让每一次升级的相对收益趋近于零。Prestige 的作用是**重置进度，换取一个永久乘数**——本质上是把玩家在"成长感衰减"的时候扔回曲线起点，让 `d(ln y)/dt` 重新变大。

> **Prestige 是"成长感耗尽"这个问题的通用解法之一。** 第 22 章讲赛季重置时你会发现，SLG 的赛季本质上就是 prestige 的一个变体——只不过重置的是领土和战力，换来的是赛季奖励和排名荣誉。

## 6. 曲线设计的五个陷阱

| 陷阱 | 症状 | 怎么避免 |
|---|---|---|
| **用一条公式套全程** | 前期太快后期太慢，怎么调都顾此失彼 | 分段，按时间锚点切（第 3 节） |
| **只看成本不看时间** | 表格上很漂亮，玩家体验断层 | 永远输出"停留天数"列，审这一列 |
| **忘了产出也在变** | 手算的到达时间和实测差一倍 | 跑模拟，别手算（第 4.3 节） |
| **后期曲线没留缓冲** | 玩家两个月打穿全部内容 | 末段增长率要留余量，方便后续加内容 |
| **硬上限代替软上限** | 玩家堆到 100% 闪避，或者撞墙后弃坑 | 用 `M·x/(x+k)` 这类饱和公式（第 4.2 节） |

第四条值得展开：**成本曲线的末段一定要留余量。**

如果你按"60 级 = 180 天"精确设计，那么半年后你要开放 61~80 级时会发现：老玩家的产出早就远超设计值，新等级会被瞬间打穿。实践中的做法是**末段增长率比"刚好够"再高 10%~20%**，把这部分当作后续版本的缓冲。第 21 章讲版本迭代时会展开。

### 7.2 加一条收益曲线

给模型加上 `power(L)`，试三种形式：线性 `100·L`、平方 `10·L²`、指数 `100·1.08^L`。

分别画出 `d(ln power)/dt`（**注意是对时间求导，不是对等级**）。

哪一种能让玩家在 180 天里保持大致恒定的成长感？为什么它和第 2.1 节的结论看起来矛盾（等级曲线是对数的，战力却要指数增长）？

<details>
<summary>提示（先自己想）</summary>

不矛盾，反而正是重点。等级曲线是对数形态（`L ∝ ln t`），所以如果战力对等级是指数的（`power ∝ g^L`），那么战力对时间就是 `g^(ln t) = t^(ln g)` ——**幂函数**，相对增量按 `1/t` 衰减，还是会慢下来。

要让战力对**时间**保持指数，需要 `power(L)` 比指数更陡（比如双指数），或者——**这才是真实项目的做法**——不断**增加新的养成线**，让总战力 = 多条线之和，每条新线开启时都重新拉起一波相对增量。

这就是为什么长线游戏的养成线只增不减，也是第 21 章"数值膨胀"的根源。恭喜，你刚刚自己推导出了 power creep 的必然性。
</details>
