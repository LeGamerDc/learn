# slg-defeat-psychology 文档维护规范

本目录是"赛季制 SLG 联盟战败 → 玩家心理 → 退游潮 → 支撑工具"的学习型知识库。任何人（含 AI 代理）新增或修改文件前先读本文。

## 1. 分层即性质

每个文件只属于一层。

| 位置 | 性质 | 放什么 | 不放什么 |
|---|---|---|---|
| `README.md` | 入口 | 核心结论、阅读顺序、编号速查、证据等级、待验证项 | 新证据或新结论的正文 |
| `01–05`、`A-*` | 正式文档（结论） | 心理分析（01 机制、02 分类、03 状态）与政策工具箱（04 识别、05 干预）；附录放实现规格 | 调研过程：检索日期、读取深度、轮次与版本叙事、变更记录、大段证据转述 |
| `next/` | 待验证与下一步 | 研究设计、可证伪假设、验证路线、命题表 | 已验证的结论；证据正文 |
| `research/` | 调研过程（证据来源） | 理论备忘录、游戏实证、业界机制、逐条来源笔记 `evidence-notes/N1–N9` | 我们自己的分类、规则、预案 |

判断标准：删掉一段文字后，"我们知道的事实"变少 → 调研；"我们建议做的事"或"我们对机制的理解"变少 → 正式文档；"我们接下来要做的事"变少 → next。

## 3. 文件头部

- 正式文档：标题后一段"用途"（回答什么问题、与哪几篇相连），随后一行 `依据：` 列出指向 `research/` 的相对链接。不写版本号与日期，变更记录在 `research/README.md`。
- `next/` 与 `research/`：保留原有的 `性质 / 版本 / 依据` 三行。
- 正式文档以"一页结论"开头，以"证据边界"结尾；中文正文，保留英文术语；表格优先于长段。

## 4. 证据与引用规则

1. 证据等级定义见 README"证据等级"：**A** 多项研究/元分析/验证量表；**B** 单项研究或行业一手材料、社区证词；**C** 本库推断，待产品数据检验。正式文档中每条建议都标等级。
2. 正式文档只引用 `research/`（作者 + 年份 + 等级，必要时附链接），不内嵌大段证据；需要新证据时先写进 `research/evidence-notes/`，再在正式文档中引用。
3. 读取深度（`全文` / `部分全文` / `摘要` / `二手`）只在 evidence-notes 中标注。`记忆待核` 的条目不得作为正式文档中 A/B 级的唯一依据。
4. 效应量与数字只能出现在有来源的地方；正式文档里的阈值默认为"待校准起点"（C），须注明。
5. 社区帖子、玩家原话属于 B 级定性证据，必须注明选择偏差。
6. 行业机制的版本与数值以 N5 的来源可靠度为准；N5 §13 标为"待核实"的条目引用时须保留该标注。
7. 不编造来源；找不到就写"未找到"。

## 5. 修改流程

- **新证据**：写入 `research/evidence-notes/`（新建 N10+ 或追加到相关 N 文件）→ 若改变结论，修改对应正式文档 → 若改变核心结论，更新 README → 在 `research/README.md` 变更记录追加一行。
- **新机制**：写入 01，并在 01 §7 的对应表补一行。
- **新状态/新原型**：先检查 02、03 是否已有等价项；新增项必须带可观测标志与证据等级；同步更新 05 的对应行、05 §0.1 速查表（若属高优先级）与附录 A §2 的规则。
- **新预警指标或干预**：写入 04 或 05；同一条内容不在两处重复，用链接互指（例：伦理合规只在 05 §12，next/validation-ethics §6 只放链接）。
- **验证结果**：先进入 `next/validation-ethics.md` 的命题表（支持/削弱/未测），再回写正式文档的证据等级（C→B→A）。
- 不删除旧结论，改为标注"已被 X 取代"并保留一行。

## 6. 命名与格式

- 正式文档按阅读顺序编号（`01-`…`05-`），附录用字母（`A-`）；其余文件名小写英文短横线。
- 编号全库唯一，新增只追加不重排：状态 `P01–P21`、`A01–A11`；原型 `T1–T12`（不要与状态 P 混淆）；调节器 `R1–R6`；指标 `1–24`；埋点 `#1–#59`；假设 `H1–H8`；命题 `K1–K11`；验证阶段 `V0–V5`。
- 章节号变动时，全库搜索 `§` 引用并同步修改。
- 相对链接；移动文件后校验链接：`grep -rnoE '\]\([^)#]*\.md' .` 并逐一确认目标存在。

## 7. 变更记录

在 `research/README.md` 末尾维护，格式：`YYYY-MM-DD｜文件｜变更一句话`。
