# 29 - 端到端实战：从零设计一款手游

> **本章目标**：把前 28 章的方法连成一条流水线走完一遍。学完你手里应该有**一套八份文档**：定位与支柱、三层循环图、系统清单与耦合矩阵、一份可评审的完整系统案、前期内容与引导方案、商业化与长线方案、测试计划、自评审记录。这套文档既是你的作品集，也是你在真实项目里第一次拿到"设计一个新玩法"时的操作手册。

## 1. 本章的性质：实战指导 + 参考答案的骨架

前 28 章每章教一个工具，单独用都不难。难的是串起来之后你会发现：**每一步的产出质量都被上一步限制。**

- 支柱写得软 → 系统清单砍不动，因为没有尺；
- 循环图不闭合 → 系统案会写出一个"没人有理由重复使用"的系统；
- 没画耦合矩阵 → 活动会悄悄改掉系统案定的假设，而你不会发现；
- 没写成功标准 → 测试只能测"好不好用"，测不了"对不对"。

**一条设计流水线上，错误不会停在它发生的那一步，它会一路流到下游并放大。** 这和你在服务端见过的事一样：一个接口定义时留下的语义模糊，最后表现为线上一个诡异的数据不一致。

本章的结构因此是：**给一个题目，我走一遍全程，每步说清"要回答什么 / 用哪章的工具 / 我的答案 / 哪里翻车 / 什么算做完"。** 我给的是**骨架加关键细节**——第 14 节会列出刻意留白的地方。

> **贯穿全章的声明**：示范方案《寸土》是**虚构游戏**，不对应任何真实产品。**方案里出现的所有数值（天数、上限、比例、时长）均为占位，真实取值由数值案决定**，见 [game-numeric](../game-numeric/README.md)。凡是对真实游戏设计意图的判断，一律标 `【推导】`。

## 3. 题目：二选一

**选一个，走完九步。不要两个都做，也不要中途换。** 中途换题的人做出来的通常是两个半成品。

**题目 A：面向中小团队的率土-like 轻量 SLG**（本章的示范题目，我走完全程）

| 项 | 约束（题目的一部分，不能改） |
|---|---|
| 团队 | 30 人左右，无自研引擎，美术大部分外包 |
| 内容产能 | 每赛季新增美术与剧情都很有限，**必须靠系统产生变化，不能靠内容量堆** |
| 发行 | 买不起头部买量位，靠垂类口碑与自然量。次留可以不是最高优先级，但 30 日以上口碑必须极好 |
| 目标用户 | 玩过率土-like 但觉得"太肝、太占时间"而流失的那批人 |
| 差异化命题 | **在不牺牲组织协同的前提下，把时间成本降到上班族能承受** |

**题目 B：二次元卡牌养成**

| 项 | 约束 |
|---|---|
| 团队 | 60 人左右，美术是最大成本项 |
| 内容产能 | 版本周期 6 周，每版 2 个新角色 + 1 条剧情线，**角色是产能瓶颈** |
| 发行 | 靠角色和内容拉量，首月声量决定生死 |
| 目标用户 | 有二次元消费习惯、对角色有情感投入、对 pay-to-win 容忍度低 |
| 差异化命题 | 由你自己定（这本身就是第一步的作业） |

题目 B 我不走全程，但**每一步末尾有「题目 B 的差异」**，告诉你这一步在卡牌品类上变成什么样、难点转移到哪。

**为什么是这两个**：它们代表 F2P 最主流、结构差异最大的两条路线——**SLG 的核心内容是"其他玩家"，卡牌的核心内容是"角色"**。品类细节在 [第 23](./23-genre-slg.md)、[第 24 章](./24-genre-card-rpg.md)，本章只引用不重复。

## 4. 九步总览

```
  ①定位与支柱 ─────┐
       ▼          │  支柱是后面每一步的"尺"
  ②三层循环 ───────┤  任何一步做不出取舍，就回来问支柱
       ▼          │
  ③系统清单+耦合矩阵┤ ← 循环图上每个节点都要有系统承载
       ▼          │
  ④一份完整系统案 ─┤ ← 选耦合最重的那个写，不是选最有趣的
       ▼          │
  ⑤前期内容与引导 ─┤ ← 会暴露②的 L1 是不是真的好玩
       ▼          │
  ⑥商业化设计面 ───┤ ← 会暴露①的支柱撑不撑得住收入压力
       ▼          │
  ⑦长线：赛季+活动 ┤ ← 会暴露③里被漏掉的系统
       ▼          │
  ⑧测试计划 ───────┤ ← 会暴露前面所有"不可验证的体验目标"
       ▼          │
  ⑨自评审 ─────────┘ ← 三层清单过一遍，产出 v0.2 的修改项
```

**时间预算**【行业口径】：每天 1.5 小时约需 **10~14 天**。建议 ①②③ 各一天、④ 三到四天、⑤⑥⑦⑧⑨ 各一天，剩下留给"回头改"。

右侧那条竖线不是装饰。这九步是螺旋不是流水线（[第 14 章](./14-design-process.md)）。纪律：**每完成一步，回头问上一步"这一步的产出有没有推翻上一步的某个决定"**，有就改，并在版本记录里写一行为什么。**你的版本记录比终稿更能证明你会设计。**

## 5. 步骤①：定位与设计支柱

**要回答**：这个游戏是什么（目标玩家 + 时刻 + 感受）？它**不是**什么？有争议时怎么判？

**用哪章**：[第 27 章](./27-lead-designer.md) §3（愿景格式、好支柱三特征、三种强度、"我们是 X 不是 Y"句式）；[第 28 章](./28-pitching-and-greenlight.md)（定位与差异化）；[第 03 章](./03-why-players-play.md)（写"感受"的词汇）。**方法全在第 27 章，本节不重讲**，只走一遍并展示它对后面八步的约束——因为这一步写软了，后面每一步都会缺一把尺。

### 5.1 示范：《寸土》

> **《寸土》**：一款 45 天一赛季的写实向 SLG。让**一个每天只有 20 分钟、下班后才能上线的上班族**，在**每个赛季里至少有三次**"**我们几个人商量出来的打法，把一块本来打不下来的地拿下了**"的时刻。

**这句话排除了什么**（写愿景的重点在这里，不在正面表述）："每天 20 分钟"排除了长时间在线与多次卡点；"下班后才能上线"排除了需要白天全员在场的玩法；"每赛季至少三次"既排除"每天都有高光"（高光会廉价）也排除"整季只有一次决战"；"我们几个人商量出来的"排除了单机主导与 200 人大盟的服从式组织；"本来打不下来的地"排除了数值碾压。

**设计支柱**（每条按[第 27 章](./27-lead-designer.md) 3.2 节的三种强度拆成"红线 / 原则 / 阶段目标"三格。**方法不在这里重讲，这一步只展示拆的结果和它对后面几步的约束**）：

| # | 支柱 | **红线**（踩到即出局） | **原则**（可权衡的方向） | **首赛季阶段目标** |
|---|---|---|---|---|
| **P1** | **地是打下来的，不是刷出来的** | 不做领地直购、不做纯挂机产出的资源副本 | **势力增长里"经过对抗"的比重越高越好。注意这是连续量不是布尔量**：资源最终会变成兵，所以任何非对抗产出都是间接战力（§7.1 会正面处理这一点）。真问题不是"有没有非对抗产出"，而是"它占多大比重、上限由什么封住" | 非对抗来源不足以单独支撑一条与对抗并行的成长线；具体比例由数值案定 |
| **P2** | **一天 20 分钟够用，卡点不是义务** | 不做需要精确到分钟、且无法预约/委托/代执行的必做操作（行军对时、限时开城门、要求全员同时在线的集结） | 日常时长越短越好；"必做"的边界可以随版本调整 | 20 分钟内能完成当日全部必做操作 |
| **P3** | **付费买质量，不买次数** | 不卖行动力、不卖伤兵恢复、不卖行军加速、不卖 VIP 等级 | **付费带来的战力增速差距越小越好**。同样是连续量：月卡里的每日资源包也是间接战力，它和"买行动力"的区别是程度不是种类——§10.1 会正面解决这个冲突 | 付费玩家与同等在线时长的免费玩家，战力增速差距的上限由数值案给出并对内公示口径 |
| **P4** | **45 天必须结束，结束时清空土地、保留身份** | 不做永久领地、不做赛季延期、**不做任何形式的跨赛季战力继承（含"下季启动资源"这类换了名字的形式）** | 保留下来的东西越偏"身份与收藏"越好，越偏"启动优势"越危险 | 见 §8.1 R6 继承表：只有身份、收藏、档案跨季 |
| **P5** | **盟主不是全职工作** | 不做出勤排行、不做每日捐献科技 | 同盟日常管理时间越短越好，目标是 ≤10 分钟/天 | 首赛季不做外交条约系统 |

**每条支柱只有一句红线，全部是"不做某个具体功能"的形式**——这五句是后面八步里唯一可以当场否决提案的东西。原则列不能否决任何提案，但每一次往反方向拉都要在决策记录里留一行（第 27 章 §4.1 的第二步）。

**张力检查**（[第 27 章](./27-lead-designer.md)：彼此毫无冲突的支柱说明它们都太软）：

| 张力 | 逼我们做什么 |
|---|---|
| **P1 ↔ P2**：对抗要响应，响应要在线，但承诺不卡点 | 发明**异步对抗**：预设防御指令、行军可预约、指挥权可委托、战报可复盘 |
| **P1 ↔ 新手留存**：对抗越强，新手被打就跑得越快（[第 23 章](./23-genre-slg.md) §8） | 设计"被打崩之后的第二条路"，而不是靠加长保护期 |
| **P3 ↔ 收入**：不卖次数等于放弃 SLG 最有效的一类付费 | 把付费卖成"表达 + 阵容深度 + 便利"，并**接受 ARPU 上限**（见 §10.2） |
| **P4 ↔ 长期投入感**：45 天清零，积累感从哪来 | 把"身份"做成独立于赛季的一层资产——**这条张力是步骤④选中 S11 的主要原因之一**（另一个是耦合矩阵的结论，见 §7.2） |
| **P5 ↔ 组织深度**：不要专职盟主等于放弃最强的组织粘性工具 | 把指挥能力系统化：一键集结、战术模板、盟内"谁在做什么"看板 |

**最后一列都是"逼我们做什么"，不是"要权衡一下"。说不出"逼我们做什么"的张力，说明你还没真正接受这两条支柱之一。**

### 5.2 演示：用支柱否决一个功能

**提案**：同盟科技，成员每天捐献资源提升全盟属性。看起来无懈可击——竞品都有；给同盟集体目标；是优秀的回收口（[game-numeric 08](../game-numeric/08-sinks.md)）；给不擅长打仗的人一个贡献方式；天然是付费点。

- **踩 P5 的红线**："不做每日捐献科技"，字面命中，布尔否决。追问一句就明白红线为什么这么写：谁盯着谁没捐？盟主。日常管理会从 10 分钟推到半小时。
- **P2 的原则被拉反**：每日捐献是出勤考核的变体，它把"今天你上线了吗"变成盟内可见的数字，于是盟主催、成员内疚。**这一条不是红线**（捐献本身不是"精确到分钟且无法委托"的操作），但它把"卡点不是义务"这个方向拉反了，要记账。
- **P1 的原则也被拉反**：这份增长没有经过任何对抗。同样不是红线——它不是领地直购也不是挂机副本，但它是一条纯粹的非对抗成长线，正好落在 P1 原则列警告的那个位置上。

**注意这三条的分量不同**：真正让提案出局的只有第一条；后两条决定的是"就算改造之后也不能改成什么样"。**新任主策最容易犯的错，是把后两条也说成"否决"，于是每次讨论都变成三比零的碾压，提案人下次就不提了——而你需要他继续提。**

**否决之后必须给替代**（[第 26 章](./26-design-critique.md) critique 第四步）。提案想解决的真问题是"同盟需要共同成长目标，不擅长打仗的人需要贡献方式"，这是真问题。替代方案：

> **全盟增益绑定到"共同占领的战略要地"。** 地图上有若干「关隘」，占领后为全盟提供增益；占领要打，维持要驻守，丢了就没了。不擅长主力战的成员承担驻守与补给线维护——**持续但低强度**，不需要卡点，效果全盟可见。

它同时满足 P1、P2、P5，还顺带解决了原提案的回收诉求。否决为什么要连着替代方案一起给，第 27 章 §3.6 已经讲过，这里只补一句本步骤特有的**：**写出替代方案的那一刻，你才从守门员变成设计者**——而这一步的产出物（支柱文档）如果只有红线没有替代方案，后面八步会一路缺东西。

### 5.3 常见翻车与验收

| 翻车 | 怎么救 |
|---|---|
| 支柱写成愿望清单（"策略性强""社交丰富"） | 每条后面强制写一个被它否决的功能，写不出就删 |
| 支柱有了但从不使用 | 纪律：系统清单每一行都要标"服务哪条支柱" |
| 目标玩家写"所有人"、定位抄竞品 | 强制写出三条排除项；写"我们**不要**竞品的哪一部分" |

**验收**：① 愿景一句话且能逐段说出排除了什么；② 支柱 3~5 条，每条有配套的被否决功能；③ ≥3 组张力，产出是"逼我们做什么"；④ 完整演示一次否决**含替代方案**；⑤ 有一份"不做清单"的种子。

### 5.4 题目 B 的差异

卡牌的支柱**语法不同**：SLG 的支柱多是约束，卡牌的多是**关于角色的承诺**——"每个角色都要有别人替代不了的位"（否决纯数值上位的复刻角色）、"抽到的是新打法不是新数字"。张力也换了地方：**角色深度 ↔ 出货速度**、**剧情分量 ↔ 更新频率**、**收集欲 ↔ pay-to-win 容忍度低**（[第 21 章](./21-monetization-design.md) §4.1）。定位里的"时刻"通常是"**我终于把这个角色练出来了，而且他改变了我的打法**"。

## 6. 步骤②：核心循环与三层循环图

**要回答**：玩家反复做的那件事是什么（L1）？他一天上线做什么（L2）？这个月的目标是什么（L3）？**三层之间怎么接上**（最重要）？

**用哪章**：[第 07 章](./07-loops.md) §3 画法规范、§4 三层与层间接口、§6 循环图诊断法；[第 05 章](./05-decisions.md)检查"图上有没有真决策"。符号照抄不要自创：`[ 动作 ]`、`《 反馈 》`、`【 资源 】`、`< 闸门 >`、`○ 外部输入`。三条纪律：**必须闭合、每条边写清传递什么、闸门必须画出来**。

### 6.1 示范：《寸土》的 L2 日循环

先画 L2，因为**手游的设计重心在日循环**——它决定玩家一天的形状，L1 和 L3 都被它约束。

```
        ○ 时间（每 T 分钟恢复 1 点行动力，上限 A）   ← T、A 为占位
        │
        ▼
     【 行动力 】───────────────────────┐
        │ 消耗                         │
        ▼                              │
  < 领地连通门 >（只能打相邻格子）        │
        │                              │
        ▼                              │
  [ 选一块地 / 一个玩家出征 ]            │
        │ 派出部队（武将 + 兵力）         │
        ▼                              │
  < 行军时间门 >  ← 异步的核心：出征后要等 │
        │                              │
        ▼                              │
  《 战报：损兵、占领成功/失败、对方是谁 》 │
        │                 │             │
        │ 占领成功         │ 玩家判断     │
        ▼                 ▼             │
  【 领地 / 势力值 】  [ 调队伍 / 换武将 / 决定养谁 ] ← 唯一的真决策点
        │                 │             │
        │ 每小时产出       │             │
        ▼                 │             │
  【 资源 / 兵源 】        │             │
        │ 消耗            │             │
        ▼                 │             │
  < 兵源恢复门 >（伤兵按时间恢复，不可购买） │
        │                 │             │
        ▼                 ▼             │
  [ 补兵 / 养成武将 ] ──→ 【 战力 】───────┘
                            │
                            └──→ 能打更高级的地 → 领地连通门往外推
```

**用 [第 07 章](./07-loops.md) §3.3 的三步读法自查**：

1. **找闸门**：行动力、领地连通、行军时间、兵源恢复。四个里**三个是时间型的**，没有一个能用钱绕过——这就是 P3 在循环图上的样子。
2. **找真决策**：图上只有一个（"练谁"）。**这是警告信号**——只有一个决策点的日循环偏薄。修正办法是把"选哪块地"从操作升级为决策：让每块地有明确的战略含义（连通性、产出类型、是否堵路）。**这个修正会传导到步骤③：需要一个系统承载地块的战略属性。**
3. **看闭合**：战力 → 打更高级的地 → 更多领地 → 更多资源 → 更多战力，闭合。

### 6.2 L1 与 L3 的骨架

**L1（一次出征）**：SLG 的 L1 操作极短、等待极长。

```
  [ 选目标 ] → [ 选武将与兵力 ] → [ 确认出征 ]   （~30 秒）
        ▼
  < 行军时间 >（异步）
        ▼
  《 战报：逐回合回放 + 损失明细 》  ← L1 的乐趣绝大部分在这里【推导】
        ▼
  [ 复盘：下次换谁 / 换阵型 / 换时机 ] → 回到"选武将与兵力"
```

**这张图暴露一个必须做对的判断**：既然乐趣集中在战报，那么**战报的可读性就是核心玩法，不是 UI 需求**——它必须能回答"我为什么输了"（[第 09 章](./09-challenge-difficulty-skill.md)、[第 13 章](./13-game-feel-and-feedback.md)）。这条会变成步骤③里"战斗结算"系统的首要体验目标，也会变成步骤⑧的一条测试假设。

**L3（一个赛季 45 天）**：开荒 D1-7 → 圈地 D8-20 → 争霸 D21-38 → 决战 D39-45 → 空窗 D46-50。玩家在每段的问题依次是："我该怎么玩" / "我该加哪个盟" / "我们打谁" / "还有没有机会" / "我这季干了啥、下季跟谁"。

**层间接口检查**（[第 07 章](./07-loops.md) §4.1）：

| 接口 | 靠什么接上 | 断了会怎样 |
|---|---|---|
| L3 → L2 目标 | 赛季日历常驻主界面，每阶段有"要做的三件事" | 每天打地不知道图什么 → 打工感 |
| L2 → L3 进度 | 势力值、领地数、同盟排名每日可见；关隘归属全服公开 | 看不到接近目标 → 觉得遥遥无期 |
| L2 → L1 资源与情境 | 今日行动力决定能打几次；同盟今天打哪一路决定打哪 | 每次出征都一样 → L1 变纯重复 |
| L1 → L2 产出 | 一次出征直接改变势力值与版图 | 打了没用 → 玩家立刻发现 |
| **隐藏接口：L2 的养成必须改变 L1 的体验** | 新战法**改变战报里的回合结构**（先手、群伤、反击），不只是数字变大 | 伤害从 1200 变 1350、战报一模一样 → 养成动力靠数字硬撑 |

**最后一行最容易被跳过、也最致命。** 它在卡牌品类是命门（[第 24 章](./24-genre-card-rpg.md)），在 SLG 里表现为"战法改变战报的形状"。

### 6.3 常见翻车与验收

| 翻车 | 怎么救 |
|---|---|
| 只画 L2，没有 L3 | 强制画 L3 并检查 L3→L2 的目标接口 |
| 图不闭合 | 问"他做完之后为什么还要再做一次" |
| 图上找不到决策点 | 这个循环是纯劳动，回步骤①看支柱有没有承诺"策略" |

**验收**：① 三张图，符号照抄；② 每张闭合、边上写清传递什么、闸门全画；③ 每张跑过三步读法并写下结论；④ 五条接口逐条写清"靠什么接上"；⑤ **至少有一处因为画图而修改了步骤①或产生了新的系统需求**（没有的话，说明你在描述而不是在设计）。

### 6.4 题目 B 的差异

卡牌的 L1 是**真正的一局战斗（2~5 分钟）**，局内有连续决策，L1 内部本身就有循环图。L3 是**版本（6 周）而不是赛季**——没有硬终局，闭合要靠"新角色 + 新剧情"这类外部输入（`○`）驱动，这是卡牌结构性的脆弱点：**内容产能一跟不上，L3 就断了**（[第 22 章](./22-live-ops-design.md) §5）。检查 L2→L1 的方法：**逐条问"练满这条养成线之后，玩家在战斗里会做出不同的操作吗"**。答案是"伤害更高"的是数字线不是玩法线，它可以当长期目标的容器（[第 08 章](./08-goals-progression-rewards.md)），但不能假装是玩法。

## 7. 步骤③：系统清单与耦合矩阵

**要回答**：循环图上每个节点由哪个系统承载？一共需要多少个？**哪些耦合是危险的**（尤其没有数据流动、只有体验依赖的那种）？

**用哪章**：[第 15 章](./15-system-design-method.md) §8——四种耦合（**D** 数据 / **E** 事件 / **R** 资源 / **X** 体验）、两种画法、"耦合超过 8 项通常意味着职责过载"的经验；[第 27 章](./27-lead-designer.md) §4 定优先级。

### 7.1 示范：《寸土》的 15 个系统

**"服务支柱"这一列不许留空，但它不是砍系统的唯一依据。** 有一整类系统天生填不出支柱，却必须做：**合规（实名、防沉迷、概率与掉落公示）、安全与反作弊、可观测性（埋点、日志、监控、GM 工具）、客服与补偿链路、数据合规与账号体系**。它们服务的不是体验目标，是"这款游戏能不能合法、安全、可运维地上线"。**处理办法是给它们单开一栏"底座"，不进支柱筛，但同样要列进系统清单并估工作量**——漏掉它们是新手系统清单最常见的缺口，而且它们往往到上线前两周才被想起来，那时最贵。**砍系统的正确依据是风险驱动**：先问"不做它会出什么事"（体验目标落空？合规上不了线？线上出事没法定位？），再问它服务哪条支柱。下表为了聚焦设计问题只列了玩法侧的 15 个系统，**这个省略本身就是你在自己的作业里要补上的东西**。

| # | 系统 | 承载什么 | 支柱 |
|---|---|---|---|
| S1 | 地图与领地 | 领地、连通门、地块战略属性 | P1 |
| S2 | 行动力 | 行动力闸门 | P2、P3 |
| S3 | 武将与养成 | 战力、战法 | P1、P3 |
| S4 | 部队编成与出征 | 派兵、行军时间门 | P1、P2 |
| S5 | 战斗结算与战报 | 《战报》——L1 的乐趣载体 | P1 |
| S6 | 兵源与伤兵 | 兵源恢复门 | P2、P3 |
| S7 | 内城与建造 | 资源产出、部队上限 | —— **（见下）** |
| S8 | 同盟 | 组织实体、成员关系 | P5 |
| S9 | 同盟指挥（集结/委托/战术模板） | L2 的组织协同 | P2、P5 |
| S10 | 关隘与州府 | L3 的阶段目标 | P1、P5 |
| S11 | **赛季与结算** | L3 的终局与传承 | P4 |
| S12 | 战绩与身份档案（跨赛季） | P4 的"保留身份"那一半 | P4 |
| S13 | 商城与付费 | —— | P3 |
| S14 | 新手引导与保护期 | 前 7 天 | P1 ↔ 留存的张力 |
| S15 | 战报/邮件/聊天（基础设施） | 所有异步沟通 | P2、P5 |

**S7 的空白是故意的。** 内城建造所有 SLG 都有，但 P1 的原则说增长应该尽量经过对抗，而建造是典型的"刷出来的"增长——**这个冲突是被这张表逼出来的**。

**先承认一件很容易被话术糊弄过去的事**：内城提供的资源产出、部队上限和建造加速，**每一样都是间接战力**。资源变成兵；部队上限决定你一次能投多少兵；加速决定你多快恢复再战。所以"内城只提供容量与速度，不提供战力"这种说法是自欺——它提供的是**延迟一步的战力**，而延迟一步的战力仍然是战力。**承认这一点之后，P1 在这里就不是布尔判断（有没有非对抗增长），而是连续判断（非对抗增长占多大比重、上限由什么封住）。**

三种处理：A 砍掉（前期太干，新手第一天没有"我的家"）；**B 保留，但把它变成对抗的下游**；C 照常做成第二条成长线（P1 的原则名存实亡，产能也扛不住）。

**选 B，并把"下游"写成三条可检查的约束**（否则"后勤不是成长线"只是一句口号）：

1. **内城的产出上限由你占了多少地、什么地决定**——不打地，内城升到顶也没有原料。这一条把 S7 挂到了 S1 下面。
2. **不存在任何只能由内城获得的战力来源**：没有内城专属科技树、没有内城专属兵种、没有内城专属加成。
3. **内城等级对战力的贡献封顶**，封顶值由数值案给出（§8.1 第 5 节的写法）。

支柱列因此填"**P1（作为对抗的下游，非独立成长线）**"，三条约束连同理由写进不做清单。**三个月后一定会有人提"内城科技树"，那时没人记得当初为什么不做，除非你现在写下来**——而且他提的时候不会说"我想加一条成长线"，他会说"内城内容太薄了"。

### 7.2 全局耦合矩阵

```
        S1  S2  S3  S4  S5  S6  S7  S8  S9  S10 S11 S12 S13 S14 S15
   S1   ─   D   ─   D   D   ─   ─   D   D   D   D   ─   ─   E   ─
   S2   D   ─   ─   D   ─   ─   ─   ─   X   ─   D   ─   X   E   ─
   S3   ─   ─   ─   D   D   ─   ─   ─   ─   ─   D   D   R   E   ─
   S4   D   D   D   ─   E   R   D   ─   E   D   D   ─   ─   E   E
   S5   D   ─   D   E   ─   R   ─   ─   ─   D   D   D   ─   ─   E
   S6   ─   ─   ─   R   R   ─   D   ─   ─   ─   D   ─   X   E   ─
   S7   ─   ─   ─   D   ─   D   ─   ─   ─   ─   D   ─   R   E   ─
   S8   D   ─   ─   ─   ─   ─   ─   ─   D   D   D   D   ─   E   X
   S9   D   X   ─   E   ─   ─   ─   D   ─   D   ─   ─   ─   ─   X
   S10  D   ─   ─   D   D   ─   ─   D   D   ─   D   ─   ─   ─   E
   S11  D   D   D   D   D   D   D   D   ─   D   ─   R   R   ─   E
   S12  ─   ─   D   ─   D   ─   ─   D   ─   ─   R   ─   ─   ─   ─
   S13  ─   X   R   ─   ─   X   R   ─   ─   ─   R   ─   ─   E   ─
   S14  E   E   E   E   ─   E   E   E   ─   ─   ─   ─   E   ─   E
   S15  ─   ─   ─   E   E   ─   ─   X   X   E   E   ─   ─   E   ─
```

**结论一：S11 耦合 12 个系统，全局最高。** 按经验这该拆，但要区分两种高耦合：**职责过载型**（一个系统做了三件不相干的事 → 拆分）和**横切关注点型**（对所有系统做**同一件事** → **不拆，但必须最早定**）。

S11 属于后者：它对每个系统做的都是"赛季结束时你归零还是保留、保留多少"。这类系统像鉴权、事务、审计：横切一切，不该拆散，但**接口必须在其他系统开工之前定下来**，否则每个系统都会自己假设一套重置规则，到赛季末才发现互相矛盾。**这就是步骤④我选 S11 而不是更有意思的 S9 或 S10 的理由：新人的本能是先写最有趣的，正确做法是先写被依赖最多的。**

**结论二：四处关键的 X（体验耦合）**——没有数据流动，但一动就要重做设计：

| X 耦合 | 断裂会怎样 |
|---|---|
| **S9 ↔ S15**（指挥 ↔ 聊天） | 聊天没有分组频道 → 商量成本高 → "我们几个人商量出来的打法"这条愿景落空 |
| **S2 ↔ S13**（行动力 ↔ 付费） | 行动力的价值完全建立在"不可购买"这个事实上；一个"限时行动力礼包"就能摧毁 P3，而代码上它只是加了个商品 |
| **S6 ↔ S13**（伤兵 ↔ 付费） | 同上，"伤兵秒恢复"= 卖次数 |
| **S8 ↔ S15**（同盟 ↔ 聊天） | 同盟归属感依赖日常对话而不是功能；聊天弱化则同盟变成"领福利的按钮" |

**中间两条是本设计最脆弱的地方**，脆弱不在技术而在组织：三个月后运营缺业绩时，"上一个行动力礼包"最容易被提出、最难被反驳——它在代码上只是加一个商品，而这类礼包的短期数据通常是正向的【行业口径】——**它的代价要到几个月后才会以"付费玩家和免费玩家不在一个游戏里"的形式出现，那时已经收不回来**。**主要的防御是把它写进全局不做清单并注明理由**，其次是把 P3 的红线写在支柱文档最显眼的地方，让提出的人自己先看见。

**结论三：S14（引导）对几乎所有系统都是 E 耦合**，说明引导不是独立系统而是**所有系统的横切面**。这决定了步骤⑤不能等到最后做——否则你会得到"系统全做完了再想办法教给玩家"，那是最糟的顺序。

### 7.3 常见翻车与验收

| 翻车 | 怎么救 |
|---|---|
| 系统清单变成功能许愿池（列了 30 个） | 每行强制填"服务哪条支柱"，填不出的删 |
| 矩阵全是 D 和 E，一个 X 都没有 | 多半是没找，不是真没有。逐格问："哪两个系统之间没有任何数据往来，但一个改了另一个就废了？"问完仍然是零，也可以，但要在文档里说明你问过 |
| "改动影响"写"无影响" | 每格问一遍"对方要跟着改吗" |

**验收**：① 10~15 个玩法系统，每个标了支柱与是否首发，**并另列一栏"底座"类系统**（合规、安全、可观测性、客服补偿）；② **至少一个系统因为"填不出支柱、又说不出不做它会出什么事"而被砍掉或重新定义**；③ 全局矩阵画完；④ **逐格问过 X（体验耦合）并把找到的每一处写清"为什么它不是数据耦合"和"断了会怎样"**——**不设数量指标**：矩阵里有几处 X 由这个设计本身决定，为了凑数去编耦合，会让整张矩阵失去可信度；⑤ 找出耦合最高的系统并判断是过载还是横切；⑥ 产出一份**全局不做清单**（含理由）。

### 7.4 题目 B 的差异

卡牌的**养成线会有 5~7 条**，彼此是强 R 耦合（共享材料），于是多出一个 SLG 没有的问题：**养成线之间必须有清晰的卡点分工**（[第 24 章](./24-genre-card-rpg.md) §6.3），否则玩家不知道该练哪条。另一个差异：**"角色"本身就是耦合最重的实体**——它同时是内容单元、付费单元、叙事单元和数值单元（四重身份，[第 24 章](./24-genre-card-rpg.md) §3），四种耦合全都有。处理方式和 S11 一样：不拆，但接口最早定。

## 8. 步骤④：写一份完整的系统案

**要回答**：把步骤③选中的系统写到"**两个程序各自实现，跑出来的行为一致**"。注意这个标准指向的是**规则、边界与状态迁移的确定性**，不是把最终数值也写进去——数值接口怎么写见 8.1 第 5 节。这是工作量最大的一步（约占三分之一），也是唯一一份别人可以据此判断你水平的产出物。

**用哪章**：[第 15 章](./15-system-design-method.md) 全章（五步链条、系统七面、规则四段式、状态机/幂等/事务边界/时间七问/并发裁决、"删掉会怎样"四变体、15 条坏味道）；[第 16 章](./16-design-docs.md)；模板 [system-spec.md](./templates/system-spec.md) 九节全写。

### 8.1 示范：《寸土》S11「赛季与结算」（骨架 + 关键细节）

> **所有数值均为占位，由数值案决定**（继承比例、空窗期长度、名次段划分参考 [game-numeric 22](../game-numeric/22-seasons-and-merges.md)）。

#### 第 1 节：体验目标与业务目标

> **体验目标**：让**投入了一整个赛季、但最终没能进入前三同盟的中游玩家**，在**赛季结束后的 48 小时里**，感到**"我这一季干的事被记下来了，而且我知道下一季从哪儿接着来"**。

**为什么是中游而不是所有人**：赢家在结算时一定满足；输得很惨的在决战期就已流失。**结算真正要救的是"打了 45 天、尽力了、名次一般"的那批人**——他们只有两种走向：带着"这季挺值"进入下一季，或带着"白干了"卸载。**这个人群的选择决定了这款游戏能不能活过第三个赛季。**

**业务目标**：压低空窗期流失；提高次赛季回归率；提高**同盟整体迁移比例**（老同盟整建制进入下一季是长期留存最强的单一因素之一【推导】，理由见 [第 11 章](./11-social-design.md)）。

**成功标准**（必须可埋点，[第 20 章](./20-playtesting-and-validation.md) §8）：主指标是 **T+3 回归率（按同盟名次段分层）** 与 **同盟整体迁移率**（新赛季首日成员重合度 ≥50% 的同盟占比）；过程指标是战绩册停留时长与分享率、空窗期日活留存；**反向指标**是结算后 24h 卸载率与客服工单中"结算/继承"类占比。

**删掉会怎样**：《寸土》变成无限成长 SLG，P4 消失，格局两三个月内固化（[第 22 章](./22-live-ops-design.md) §6.4），只能靠合服打补丁。**不能删。** 另外三个变体（[第 15 章](./15-system-design-method.md) §7）：**合并**——不能与"新赛季开启"合并，但两者**必须共享同一份"继承清单"结构**；**减半**——空窗期 5 天减到 2 天，价值在于逼我问"空窗期长度被什么决定"，答案是"**一个同盟商量出下季去哪、留谁、拉谁需要多久**"，不是"维护要多久"；**反转**——领地不清零则头部永远占着州府，P1 与 P4 同时失效，**这证明清零是地基**。

#### 第 2 节：玩家视角的流程

| 时刻 | 玩家看到什么 | 设计意图 |
|---|---|---|
| D39 | 倒计时出现；地图上州府高亮 | 终局可预期，不是突然结束 |
| 结束前 24h | 公告 + 推送；**出征仍开放**（不提前锁） | 最后一天是高光，不该被冻结 |
| **T0** | 不再受理新的出征与兑换；**已在飞的仗继续打完**；界面提示"赛季已结束，正在等最后的战斗结束" | 有明确的终止时刻，但不粗暴打断进行中的战斗 |
| **T1** | 在途排空完毕，地图转只读，提示"正在结算你的这一季" | **只读发生在排空之后，不和终止同一时刻**（见 R2） |
| T+0~2h | 结算动画 + **个人战绩册** | "我干的事被记下来了" |
| D46~50 | 功勋馆（见 §11）；同盟频道开放；**下赛季意向报名** | "我知道下一季从哪儿接着来" |
| D51 | 新赛季开启，同盟按意向整体分配 | 关系不被打断 |

**玩家的决策点**：赛季货币怎么花（身份/收藏类永久物 / 当季即时消耗 / 不花则作废，**必须在结算前决定**——**没有"下季启动资源"这个选项**，理由见 R6）；下赛季跟谁；传承哪个武将（名额有限，且传承的是"人"不是"练度"）。

#### 第 3 节：规则

**3.1 参与者**：中游玩家（**首要对象**）、头部玩家与头部同盟（本来就满足）、**已流失但未卸载的玩家**（赛季末是最好的回流窗口）、**同盟实体**（迁移的单位）、**系统**（自动结算者，不写清则规则无人执行）、运营 GM（异常裁定与补偿）。

**3.2 状态与资源**（七列规范，**后三列不许空**；下表省略取值域等前几列）

玩家赛季档案——**这张表就是战绩册的数据来源，也是体验目标的物理载体**：

| 字段 | 持久化 | 可见性 | 归属与生命周期 |
|---|---|---|---|
| 最终 / 最高势力值 | 永久 | 全服可查 | 属于玩家，跨赛季永久 |
| 所属同盟 / 同盟最终名次 | 永久 | 全服 | 快照，不随同盟后续变化 |
| 攻城次数、攻下的关隘州府 | 永久 | 全服 | 永久 |
| 歼敌 / 损失兵力 | 永久 | 公开 | 永久 |
| **"高光时刻"（≤5 条结构化事件）** | 永久 | 默认盟内，可设为全服 | 永久 |
| 盟内贡献名次 | 永久 | 同盟内 | 快照 |
| 赛季货币余额 | **结算时清零** | 仅自己 | 属于赛季 |

> **"高光时刻"是本案最重要、也最容易被当成 UI 装饰砍掉的字段。** 它把 45 天压缩成 3~5 条**具体的、可讲述的**句子（"你在 D27 顶住了 XX 盟对 XX 关的第三次进攻"），而不是一堆数字。**体验目标里的"被记下来了"靠它，不靠势力值。**
>
> **它同时暴露了一个问题**：这些事件要从 S5（战斗结算）提取，而 S5 的案子只记录了输赢与总损失。**正确的修法是让 S5 输出一份结构化的战斗事件流（数据契约），由 S11 来解释哪些事件值得讲**——不要反过来要求战斗结算系统去理解"叙事价值"，那是把一个横切的价值判断塞进一个只该管裁决的系统。**但事件粒度定多细，只有从 S11 的体验目标出发才知道，这一层依赖没有代码痕迹——它会进第 13 节的自评审。**

同盟赛季档案：同盟名与旗帜（名字**跨赛季保留占用**防抢注）、最终名次、成员名单快照（均永久）、迁移意向（盟内可见，空窗期内有效）。

**3.3 动作与规则**（先给总表，再挑两条做完整形式定义——**这就是"骨架 + 关键细节"的具体含义**）

| 规则 | 触发 | 关键边界 |
|---|---|---|
| R1 决战期进入 | D39 日刷新 | 公告提前 72h；规则变更须公示 |
| **R2 赛季终止** | 结束时刻到达 | **四阶段流水线**：截止水位 → 排空在途 → 冻结快照 → 分批结算，见下 |
| R3 冻结与快照 | R2 阶段 1 排空完成（T1） | 地图转只读并打只读快照；**聊天保持开放**（设计决定） |
| R4 档案写入 | 结算中 | 幂等；失败进重试队列并告警 |
| **R5 高光时刻提取** | 档案写入后 | 每人 ≤5 条，见下 |
| R6 继承计算 | 档案写入后 | 见下方继承表 |
| R7 赛季货币兑换窗口 | 决战期 → 终止时刻 | **窗口不延长**；提前 72h 起每日提醒 |
| R8 同盟迁移意向 | 空窗期 | 仅盟主发起、成员逐个确认（**这条有洞，见 §13**） |
| R9 空窗期内容 | 冻结完成后 | 功勋馆、盟频道、意向报名开放；**不开放战斗与养成** |
| R10 新赛季分配 | 新赛季开启 | 按意向整体分配；未报意向的常规匹配 |
| R11 未领取奖励 | 结算时 | 转邮件，30 天有效，**跨赛季有效** |
| R12 补偿申诉 | GM 触发 | 幂等键 = 批次ID + 玩家ID；T+7 后只补不改档案 |

```
R2 【赛季终止：四阶段、分批、幂等、可恢复】
  触发：服务器时间到达赛季结束时刻（配置项，须提前 ≥14 天公示）
  校验：① 赛季状态 = 决战  ② 无 GM 冻结

  **这条规则不是一个瞬间，是一条有顺序的流水线。** 原因很简单：
  "禁止新出征"和"地图不再变化"不可能在同一时刻发生——总有仗正在打。
  分四个阶段，每段有自己的幂等键、可单独重跑、失败可从断点恢复。

  ── 阶段 0：截止水位 T0 ──────────────────────────────
    T0 = 赛季结束时刻。此后**不再受理任何新的写入意图**：
    禁止发起出征、集结、迁城、交易、赛季货币兑换。
    判定依据是**事件的发生时刻**而不是服务器的处理时刻：
    发生时刻 < T0 的请求即使晚到也照常受理；≥ T0 的一律拒绝并给明确提示。
    （这是 3.4 时间七问第 3 问"左闭右开"在这里的落地。）

  ── 阶段 1：排空在途（T0 → 最迟 T0+Δ）───────────────
    T0 时刻已经在飞的部队、已经开打的攻城，**都按原定时间线继续跑完**，
    结果全部计入本赛季。**所以这一段地图仍然在变，"只读"不在这里发生。**
    - 在途部队：到达时刻 ≤ T0 → 正常结算；> T0 → 原路返回，不结算、不损兵
    - 已开战未结束的攻城：打完为止；到 T0+Δ 仍未结束的按"守方保有"裁定，
      并写一条系统事件说明原因（Δ 是配置项，取值见第 5 节，须提前公示）
    - **排空完成的判据是可检查的**：在途队列为空 且 进行中战斗数为 0，
      或 T0+Δ 到达——两个条件先到先算，先到的那个时刻记为 T1

  ── 阶段 2：冻结与快照（T1）──────────────────────────
    **此刻才地图转只读**，赛季状态 → 冻结。
    对 S1/S3/S4/S5/S8/S10 打一份只读快照，带 snapshot_id 与校验和。
    **此后所有结算只读快照，不读线上表。** 这一条是整个设计的关键：
    它把"结算"与"线上状态"解耦，于是结算可以重跑、可以并行、
    可以在出错后回到同一份输入重算，**而不需要"把玩家数据倒回去"**。

  ── 阶段 3：分批结算（读快照 → 写档案）──────────────
    按玩家分批，每批一个事务：写 S12 档案 → 提取高光（R5）
    → 计算继承（R6）→ 发放继承物与邮件。
    幂等键 = snapshot_id + player_id + 步骤名，重复执行返回"已完成"。
    **失败批次进重试队列并告警，不阻塞其他批次**；
    结算未完成的玩家看到的是"结算中"，不是一个错误的结果。
    全部批次完成后，赛季状态 → 空窗。

  ── 阶段 4：清空（前置条件：阶段 3 全部成功）─────────
    对 S1/S3/S4/S6/S7 执行清空。**清空排在最后，且以档案写入成功为前置**，
    因为它是全流程里唯一真正难以撤销的动作。
    即便如此也不能只靠"不出错"：清空前保留一份**赛季末原始状态冷备**
    （保留期至少覆盖到补偿窗口结束，具体由运维定）。
    **于是"重跑"有了明确含义：用同一份快照重算档案**，而不是回滚玩家数据。

  幂等：每阶段独立幂等；整条流水线的幂等键 = season_id + snapshot_id
  边界：
    - **"抢秒"**：结束前最后一分钟发起、发生时刻 < T0 的短途出征，结果有效。
      **这是设计决定不是漏洞**——它保留了最后一刻的戏剧性，
      代价是 T0 前后的请求峰值与判定争议。
      反面选择"结束前 N 分钟禁止出征"会让最后那段时间变成死时间。
      **两种都可以，但必须写出来并提前公示。**
    - 跨时区：内部用服务器时区，界面显示玩家本地时间
    - 若 T0 恰逢故障：顺延至恢复后的整点并公告，顺延期视同阶段 0，
      不因故障产生额外收益
    - **发现错误怎么办**：阶段 3 完成前，用同一份快照重跑对应批次；
      阶段 4 之后发现的问题，一律走 R12 的补偿事务修正
      （幂等键 = 批次ID + 玩家ID），**不再重跑清空**

R5 【高光时刻提取】
  触发：玩家赛季档案写入完成后
  校验：档案已写入；幂等键 = season_id + player_id
  结果：从本赛季事件流按优先级提取 ≤5 条，生成结构化文案：
        1 参与攻下关隘/州府的战斗   2 **成功防守**（尤其以少胜多）
        3 单次歼敌最多的一战        4 被指挥点名 / 受援记录
        5 势力值排名的最高时刻
  边界：- **不足 5 条不补齐、不留空位**，用一条兜底文案
          （设计决定：宁可少，不可假。凑数的高光会让整册失去可信度）
        - 排除已判定作弊的战斗
        - 提取失败不阻塞结算，异步重试 ≤24h
  可见性：默认盟内可见，玩家可设为全服（设计决定：默认不全服，
          避免中游玩家的战绩被拿去和头部对比，那会制造相反的体验）
```

> **R5 把"成功防守"排在"歼敌最多"之前，这是一个纯设计决定。** 中游玩家很少是攻城主力，但经常是**守住某条线的那个人**。只提取进攻数据的话，他们的战绩册会全是"参与了 XX 战役"这种没有主语的句子。**排序即价值观**，这一行决定了这个系统到底服务谁。

**R6 继承表**（P4 的"保留身份"那一半）。**先给分类规则，再给逐项处理**——三个月后一定会有人新增一条养成线，那时能用的是规则不是表：

| 类别 | 判据（一句话） | 跨季？ |
|---|---|---|
| **身份** | 它只说明"我是谁、我做过什么"，不进入任何战斗或产出计算 | **保留** |
| **收藏** | 它是可展示的物件，同样不进入战斗或产出计算 | **保留** |
| **战斗力** | 它直接或间接影响战斗结果（含兵、资源、等级、战法、建筑、加速） | **清空** |
| **启动优势** | 它不直接进战斗，但让你在新赛季 D1 比同期玩家跑得快 | **清空**——这是最容易被换个名字混过去的一类 |

| 资产 | 类别 | 处理 |
|---|---|---|
| 领地、城池、位置 | 战斗力 | **全部清空**，付费购买的也不例外 |
| 赛季资源、兵力 | 战斗力 | 清空 |
| 内城建筑等级 | 战斗力（它决定产出与部队上限，见 §7.1） | 清空 |
| **武将** | **双重身份**：收藏 + 战斗力 | **拥有关系保留**（收藏），**等级、装备、加成全部重置到与新号相同的基准**（战斗力）。传承名额只决定"新赛季 D1 你手上有哪几张脸"，不决定"他们有多强" |
| **战法 / 技能解锁** | 战斗力 | **清空。**（前一版把它归到"我学会了什么"而保留，那是错的：可用战法池更大就是直接战力，等于跨季继承战力，正面踩 P4 的红线。**要保留的是"我解锁过它"这条记录——那属于身份，展示在档案里，不进战斗**） |
| **称号、旗帜、外观** | 身份 / 收藏 | 永久保留，**含付费购买的**，否则等于赛季末清空玩家买的东西 |
| **战绩册与档案** | 身份 | 永久保留且可回看 |
| 赛季货币 | 战斗力（可兑换成资源） | 清零。**兑换窗口在赛季内**（R7），须从决战期起每日提醒；**兑换标的仅限身份/收藏类物件与当季即时消耗** |
| **"下季启动资源"** | **启动优势** | **不做。** 前一版把它列在赛季货币的兑换选项里，与 P4 的红线冲突，本版删除 |
| 同盟关系 | 身份 | 不自动继承，但提供**整体迁移通道**（迁的是人的关系，不是任何数值） |

> **这张表最容易出错的地方，是"看起来不像战力的战力"。** 下季启动资源、战法解锁、建筑等级、"新赛季前 7 天产出加成"、"老玩家专属新手礼包"——**全都是换了名字的跨季战力**，而且每一个提出来的时候都有一个听起来很合理的理由（"总得给老玩家一点回报吧"）。
>
> **判据只有一条：它会不会让一个老玩家在新赛季 D1 跑得比同期新玩家快？会，就是启动优势，就该清空。** 唯一被允许的例外写在第 5 节的数值接口里——武将等级重置基准可以让老玩家 D1 略有优势，**但这个优势必须在 D7 前被抹平**。它是新手期的体验缓冲，不是继承；判断它有没有变质的方法也很简单：**看这个优势是不是随时间自动消失**。

**3.4 时间**（[第 15 章](./15-system-design-method.md) §4.5 的时间七问）

| # | 答案 |
|---|---|
| 1 刷新点 | 阶段切换在 05:00 日刷新；**赛季终止时刻例外**，取晚间时段——终止是高参与度事件，不能在凌晨 |
| 2 时区 | 内部服务器时区；**对玩家一律显示本地时间并标注** |
| 3 周期边界 | 赛季 = [开启, 终止)，左闭右开；归属按**事件发生时刻**判定 |
| 4 CD 起算 | 迁移意向窗口从"盟主发起"起算，不跨新赛季开启时刻 |
| 5 **结算多久** | 结算是**有长度的过程**，而且分四段（R2）：T0 截止水位 → 排空在途 → T1 冻结快照 → 分批结算。**期间玩家可登录，看到专属页而不是主界面**，写操作被拒绝并给明确提示。**三段的措辞必须不同**："赛季已结束，正在等最后的战斗结束"≠"正在结算你的这一季"——玩家能不能分清"我的仗还在打"和"我的仗已经算完了"，决定了这段时间产生多少客服工单 |
| 6 离线怎么算 | 不要求在线；**未登录玩家档案照常生成**，登录时补播（回流玩家第一眼看到自己的战绩册，是最好的回流钩子） |
| 7 跨赛季 | 见 R6。跨赛季有效的只有四类：**档案（身份）、身份与收藏物（含武将的拥有关系）、未领取的邮件、同盟迁移意向**。任何进战斗或进产出计算的东西都不跨季 |

> **第 5 问最容易出事故**：玩家在结算窗口做的操作"消失了"而他不知道为什么。案子必须写清"结算中"玩家看到什么——**否则程序会让它看起来和正常状态一样**（[第 15 章](./15-system-design-method.md) §6.11）。

**3.5 输入 / 输出**：输入是 R2 阶段 2 在 T1 打的那份**带 snapshot_id 的只读快照**（S1/S3/S4/S5/S8/S10）与赛季货币余额——**注意快照的时刻是 T1（排空完成）而不是 T0（终止），这个区别写不清就会有一批最后时刻的战斗结果算不进档案**；输出是写入 S12 的永久档案（本系统唯一的永久产出）、幂等的继承物发放、转邮件的未领奖励、给新赛季的分配请求，以及最后执行的清空指令（R2 阶段 4，以档案写入成功为前置，且有冷备与 R12 补偿通道兜底）。

#### 第 4 节：与其他系统的接口

| 系统 | 类型 | 改动影响 |
|---|---|---|
| S1 地图 | D + E | 分区规则一改，"整体迁移"的目标区服计算全变 |
| S3 养成 | D + R | **养成线新增一条，就必须在 R6 继承表新增一行**；漏了就会有"这条线到底清不清"的争议 |
| S5 战斗结算 | D + **X** | **两件事要分开。（D）S5 目前只输出输赢和总损失，缺的是一份结构化战斗事件流**——攻守方、兵力对比、目标地块类型、是否守住、参战人数、关键回合。这是数据契约缺失，补字段能解决。**（X）而"哪些事件值得被讲出来"是 S11 的价值判断，不该塞进 S5**：S5 只如实产出原始事件，S11 负责解释和排序。X 依赖仍然存在——**S5 的事件粒度一旦不够细，S11 想解释也解释不了，而这一点在 S5 自己的案子里看不出来** |
| S8 同盟 | D + E | 人数上限一改，迁移匹配逻辑全变 |
| S10 关隘州府 | D | 名次算法改动 → 战绩册的名次段划分全变 |
| S12 档案 | R | **强依赖**：S12 是 S11 唯一的永久产出去向 |
| S13 商城 | R + **X** | 一旦出现"跨赛季保留领地"的付费商品，P4 立刻失效 |
| S15 邮件/聊天 | E + **X** | 空窗期若关闭同盟频道，"整体迁移"就没有商量的场所，业务目标落空 |
| S14 引导 | E | 太晚告知"赛季会结束" = 结算时的震惊；太早 = 打击投入意愿 |

#### 第 5 节：数值接口（写体验要求与合法范围，不写最终取值）

**先把"策划不许写数字"这句口号拆开**，因为按字面执行既做不到、也不该做到——一份实现级规格里必然会出现数字，问题是**哪一种数字**：

| 种类 | 例子 | 谁写 | 规格里怎么标 |
|---|---|---|---|
| **占位值** | 空窗期 = 5 天 | 系统策划 | 必须显式标 `（占位）`，让所有人知道它随时会变 |
| **合法范围与边界** | 空窗期 ∈ [2, 7] 天；传承名额 ≥ 1 | **系统策划** | 写死。**这是设计约束不是数值结论**：超出范围的取值会让规则本身失效 |
| **体验要求** | "老玩家 D1 的优势必须在 D7 前被抹平" | 系统策划 | 写死，且必须可观测 |
| **工程默认配置** | 结算批大小、重试次数、快照超时、Δ 的技术上限 | 主程（策划复核） | 写进规格并标明它是工程参数，不进数值案 |
| **最终取值** | 空窗期到底是 3 天还是 5 天 | **数值** | 规格里不写，只留参数名与上面三样 |

**所以准确的纪律是：系统策划可以写占位值、必须写合法范围和体验要求，但不写最终取值。** "策划拍数字就是越界"这句话只对最后一行成立——对系统策划来说，**写不出合法范围反而是失职**，因为范围是设计决定：空窗期短于 2 天，同盟来不及商量，R8 的整体迁移通道就是空的；长于 7 天，玩家会养成不上线的习惯。这两条边界不是数值算出来的，是规则要求的。

| 参数 | 体验要求（策划写死） | 合法范围 / 边界（策划写死） | 最终取值 |
|---|---|---|---|
| 赛季长度 | **上班族在这个长度内能完整经历"从新手到参与过一次大战"** | 必须长于开荒—圈地—争霸—决战四阶段的最短时长之和 | 制作人 + 数值 |
| 空窗期长度 | 足够一个同盟商量出"下季去哪、留谁、拉谁"，且不长到养成不上线的习惯 | **[2, 7] 天**：< 2 天迁移通道形同虚设，> 7 天流失风险陡增 | 数值 + 运营 |
| 武将等级重置基准 | 老玩家新赛季 D1 有优势，**这个优势要在 D7 前被抹平** | **不得高于新号 D7 可达的水平**，否则它就是 R6 禁止的启动优势 | 数值 |
| 传承名额 | 让玩家做一次"带谁"的真取舍 | **≥1**（否则这个决策不存在）且 **< 一队编制人数**（否则无取舍） | 数值 |
| 赛季货币兑换比 | "打满全季"与"打了一半"的结果有明显但不悬殊的差距 | 兑换标的仅限身份/收藏类与当季即时消耗（R6） | 数值 |
| 名次段划分 | **中游玩家看到自己的段位时不能感到羞辱** | "体面"区间必须覆盖多数玩家——**我给的占位是 60%，具体分位点由数值定** | 数值 + 策划 |
| 在途排空上限 Δ | 不粗暴打断进行中的战斗，也不让结算无限期等待 | **上限必须存在且提前公示**；须长于单场攻城的典型时长 | 程序 + 数值 |
| 结算窗口时长 | 短到玩家愿意等，长到不牺牲数据一致性 | 分批大小与重试次数是工程参数，由主程定 | 程序 + 数值 |

**说不清"短到什么程度"和"合法范围是多少"是失职；自己去拍最终取值是越界。** 上面这张表里唯一出现的具体数字（60%、[2,7] 天）都带着标签：一个是显式声明的占位，一个是合法范围——**它们能出现在规格里，正是因为它们回答的不是"应该是多少"，而是"超出这个范围规则就不成立了"。**

#### 第 6~9 节（简）

- **表现需求**：结算动画（一个赛季的情感落点，不能用通用弹窗）、可截图分享的战绩册版式、**"结算中"状态页**（最容易漏的一张图）、空窗期专属主界面。高光要逐条揭示（[第 13 章](./13-game-feel-and-feedback.md)），一次全屏展示会变成报表。
- **埋点**：`profile_written`（**高光条数 < 3 的玩家占比**，体验目标的直接风险）、`memoir_view`（停留、滑到底、分享）、`currency_expire`、`migration_intent`、`return_T3`（分名次段）。
- **风险**：① **高光提取依赖一份 S5 还没有产出的结构化战斗事件流**，S5 不补这份契约、或者补出来的粒度不够，本系统的体验目标就无法达成，**这是最大风险且它不在本系统内部**（拆解见第 4 节的 S5 行与 §13.1 的问题 B）；② 结算是全服批量写，出错的影响面是全服。**缓解手段就是 R2 的四阶段结构**：读快照而不读线上表、按玩家分批且每批幂等、清空以档案写入成功为前置、并保留赛季末冷备——**所以"重跑"是可行的，它的含义是用同一份快照重算档案**。真正不可重跑的只有阶段 4 的清空，因此它被排在最后。**剩余风险转移到了快照本身**：快照口径（取哪些表、取哪个时刻、怎么校验）必须在写案时定死并做校验和比对，快照错了，重跑多少次都是错的；③ 赛季货币清零最容易引发集体投诉【行业口径】。
- **待定**："抢秒"保留还是禁止（主策）；传承名额是否可付费扩充（主策 + 制作人，立项前）。
- **明确不做**：付费保留领地 / **任何形式的跨赛季战力继承**——含"下季启动资源""战法解锁保留""老玩家专属开局礼包""新赛季前 N 天产出加成"这几种换皮形式（踩 P4 红线，一旦开口赛季制失去意义）；赛季延期（开一次口就回不去）；结算排行按付费额分档（踩 P3 红线）；高光凑数补齐（见 R5）。
- **版本记录**：v0.1 初稿；v0.2 待修（见 §13 的四条）。

### 8.2 常见翻车与验收

| 翻车 | 怎么救 |
|---|---|
| 选了最有趣的系统写 | 按耦合矩阵选被依赖最多的 |
| 体验目标写"提升留存" | 业务目标冒充体验目标，规则失去判据。补"谁、何时、感到什么" |
| 规则只写"能做什么" | 对每条约束问"它保护的是体验目标里的哪个词" |
| 边界与异常整节缺失 | 过一遍 [第 15 章](./15-system-design-method.md) §3.2 的八类边界清单 |
| 数值接口留"待定" | 留空的参数会被别人按自己的理解填。写体验要求**和合法范围**——范围是设计决定，留空等于把设计权让出去 |

**验收**：① 九节全写；② 第 1 节含四要素 + 四变体结论；③ 字段表七列齐全，后三列无空；④ 规则总表 + **≥2 条完整四段式**，含幂等与事务边界；⑤ **至少一张状态图**并回答三个检查（孤立状态 / 死路 / 每个状态玩家看到什么）；⑥ 时间七问逐条答；⑦ 接口表 ≥6 个系统含 ≥1 处 X，"改动影响"无"无影响"；⑧ 数值接口 ≥5 个参数，每个都写清"体验要求 + 合法范围 + 最终取值由谁定"，**占位值必须标（占位）**；⑨ 不做清单每条有理由；⑩ 用 15 条坏味道自查，命中项记在文末。

> **本示范刻意省略了状态图**（赛季：预热 → 进行 → 决战 → **排空在途（T0 后）** → **冻结/已快照（T1 后）** → 结算中 → **已清空** → 空窗 → 已归档，另加 GM 冻结旁路与"结算失败重试中"这一旁支）。**注意 R2 的四个阶段全部要在图上有对应状态**——把它们画出来，你会立刻看到本案没写清的那几条迁移条件。**这是留给你的第一件作业**——画状态图是暴露漏洞最快的动作，别人替你画没有意义。

### 8.3 题目 B 的差异

建议写**「抽卡与保底」**。难点从"时间边界"转到"**概率与预期管理**"：状态面的重点是**保底计数器的归属与生命周期**（跨池继承吗？跨版本呢？UP 池与常驻池分开计数吗？——这一列写不清就是客服工单重灾区）；规则面是概率的形式定义与公示口径（合规见 [第 21 章](./21-monetization-design.md) §7）；数值交给 [game-numeric 13](../game-numeric/13-probability-systems.md)；边界面新增一类 SLG 没有的：**支付与发货的一致性**。

## 9. 步骤⑤：前期内容与新手引导方案

**要回答**：前 5 分钟 / 1 天 / 3 天 / 7 天分别发生什么？每个窗口的**唯一目标**是什么？他在哪里最可能流失、你用什么接住？

**用哪章**：[第 18 章](./18-onboarding.md) §6 的四个时间窗口、§2 的教学四层、§10 的引导坏味道；[第 17 章](./17-level-design.md) 的四步教学结构；[第 23 章](./23-genre-slg.md) §8 的 SLG 新手三种死法。

### 9.1 示范：《寸土》的前 7 天

| 窗口 | 唯一目标 | 怎么做 | 流失点 |
|---|---|---|---|
| **前 5 分钟** | 制造第一个爽点 | **开场就是一场必胜但精彩的攻城战**（不是种田）：**60 秒内完成第一次出征，90 秒内看到第一份战报**，战报里有一次戏剧性反击。必胜战要用真实战报，不是播片 | 开场种田、开场剧情、首次操作没反馈 |
| **前 1 天** | 核心循环闭合一次 | 打地 → 拿资源 → 补兵/升武将 → 打更高级的地。**资源必须给够到能完成一次完整养成动作**，不能卡在"差一点"；结束时留 12 小时钩子 | 循环没闭合；变强了但战报看不出差别 |
| **前 3 天** | 看到"一个月后是什么样" | 赛季日历首次露出；远处的关隘与州府**可见但不可达**（"引力点"手法，[第 25 章](./25-genre-openworld-narrative-roguelike.md)）；第一个中期目标带进度条。**第 3 天只解锁两个系统** | **引导断崖**；解锁过密 |
| **前 7 天** | 从"一个人玩"变成"有关系的玩" | **第 4 天强推同盟**——SLG 里没进同盟的玩家留存明显更差，从业者常用的说法是"基本可视为已流失"【行业口径】（注意这是经验判断，且它是相关不是因果：会进盟的人本来就更投入，见 §12 的 H3）。加入后自动在盟频道生成介绍，并给盟内一个**低成本欢迎动作**（一键送新人物资）；D5~7 出现第一次不卡点的组织协同 | 进了盟没人搭理；保护期结束被打；付费墙太早 |

**SLG 特有的三个前期问题**（[第 23 章](./23-genre-slg.md) §8）：

| 问题 | 处理 | 回指 |
|---|---|---|
| 保护期结束的断崖 | 不是"到期解除"，而是**随玩家主动出击逐步解除**：第一次主动攻击后缩短。把"被动挨打"变成"我自己选择了下场" | P1 |
| 被打崩之后怎么办 | "迁城 + 保留武将与战绩"的低成本重来路径，**新位置由同盟决定**。被打崩不是退游理由，是"我要抱团"的理由 | P1 ↔ 留存 |
| 新人不知道干什么 | 不用任务列表，用**同盟的"今日重点"看板**（S9 产出）。下一步由组织给出而不是系统给出 | P5 |

**前 5 分钟的逐屏分镜是本步骤最有价值的部分，我刻意只给了描述**（理由见第 14 节）。

### 9.2 常见翻车与验收

| 翻车 | 怎么救 |
|---|---|
| 引导方案最后才写 | 引导是所有系统的横切面（§7.2 结论三），必须同期写 |
| 把付费塞进引导流程 | [第 18 章](./18-onboarding.md) §6.4：此时玩家还在判断值不值得玩 |
| 用加长保护期解决新手被打 | 保护期越长，断崖越陡。把"解除保护"变成玩家的主动选择 |

**验收**：① 四窗口各写清"唯一目标 + 手段 + 流失点 + 接法"；② 前 5 分钟能逐屏讲出来；③ 教学四层分别在哪个窗口教；④ 品类特有的前期问题逐条有处理；⑤ 每条设计回指某条支柱。

### 9.3 题目 B 的差异

卡牌的前 5 分钟核心是"**让玩家看到一个他想要的角色**"，通常是一场使用高稀有度角色的必胜战斗【推导】。前 3 天的主要风险不是"引导断崖"而是**养成线过载**（[第 24 章](./24-genre-card-rpg.md) §6.2），处理方式是**分批交付**：第 1 天只有等级，第 3 天开突破，第 7 天开技能。另外卡牌有真正的关卡，[level-spec.md](./templates/level-spec.md) 可以完整用上——**用起承转合设计前 10 关，每关只引入一个新元素**（[第 17 章](./17-level-design.md)）。这是 SLG 做不了的作业，选 B 的读者应该认真做。

## 10. 步骤⑥：商业化的设计面

**要回答**：付费点放在哪、长什么形态？每个是"体验的延伸"还是"拦路"？哪些**明确不做**、理由是什么？（数字全交给数值案）

**用哪章**：[第 21 章](./21-monetization-design.md) §2 延伸 vs 拦路三问、§3 付费动机六分类、§4 pay-to-win 谱系、§5 各形态设计逻辑、§6.2 黑暗模式自检。定价与概率交给 [game-numeric 12/13/14](../game-numeric/12-monetization-structure.md)。

### 10.1 示范：《寸土》的付费结构

**先看约束**：P3 的红线砍掉了 SLG 最主流的几类收入（卖行动力、卖行军加速、卖伤兵恢复、卖 VIP）。**所以真问题是：在 P3 下还有什么可以卖？**

**但在列清单之前，要先解决一个很容易被话术盖过去的矛盾**：月卡里的"每日资源包"算不算"买次数"？按 §7.1 已经承认的事实——**资源是间接战力**——它确实是：付费的人每天多一份资源就是每天多一点兵，累积 45 天就是一条与在线时长并行的付费成长线。**它和"买行动力"的区别是程度，不是种类。** 含混过去的话，P3 会在自己的月卡里被悄悄破掉。所以这里必须做一个显式决定：

- **A（本案选它）：月卡不含任何进入战斗计算的产出。** 月卡 = 便利功能（地图标记、战报检索、编成预设）+ 内城建造加速 + 一件外观。
- B：月卡含资源包，但**产出上限由你占了多少地封顶**（不打地就领不满，即挂到 §7.1 的第 1 条约束下），**并把这次让步写进 P3 的原则层记账**——它把 P3 从"干净的红线"拉向灰色地带，代价必须公开、必须有人签字。

**选 A 的代价要一起写下来**：月卡的感知价值会明显低于同品类，付费率大概率更低【行业口径】。换来的是 P3 的红线保持干净，以及 §10.2 那个"低 ARPU 换高留存"的交换仍然成立。**这就是第 27 章说的原则层记账：不是不能选 B，是选了 B 必须有人签字，而不是让它作为"月卡的标配"混进来。**

按付费动机六分类：省时间**大部分不能卖**（那是买次数），唯一例外是内城建造加速（理由见下面的三问）；变强只卖**武将**（新武将 = 新战法 = 新打法，不是新数字）；**表达是主推**（旗帜、称号、城池外观、战绩册装帧）；社交卖盟内荣誉外观（**同盟集体获得，不可个人购买**）；收集卖图鉴与赛季纪念；便利卖地图标记、战报检索、编成预设。

**形态清单**：首充（一个表达物 + **当季即时消耗**，**不在引导流程里**）；月卡（便利功能 + 内城建造加速 + 一件外观，**不含资源包**）；**赛季通行证**（当季资源 + 专属外观 + 战绩册装帧，**赛季末可回溯购买已达成的进度奖励**）；武将卡包；外观商城。**明确不做**：行动力、伤兵秒恢复、加速行军、VIP 等级、领地直购、传承名额扩充、**任何跨赛季生效的启动礼包**（R6）。

**跑"延伸还是拦路"三问，示范两个对照**：

**加速建造券**：①掏钱时是"想要它停止"——警告信号；②不付费的人体验到"完整但更慢"，因为内城是对抗的下游、且它对战力的贡献封顶（§7.1 的三条约束）；③删掉它是"解除一个厌恶"。**判定：灰色地带，可以卖，但条件是内城不能成为打仗的前置。** 换句话说，**它的正当性完全建立在 §7.1 那三条约束上**——只要有一条被破坏（比如加了内城专属科技树，或者把封顶值提上去），它会立刻从"便利"滑向"拦路"，**而且滑的时候没有任何报错**。**这个联动必须写进 S7 与 S13 的接口表，并且写成可检查的形式："S7 的这三条约束是 S13 加速券成立的前置条件，改动 S7 必须回来重判这个商品。"**

**加速行军**：①"想要它停止"；②不付费的人体验到的是**被打断，而且更糟**——行军时间是对抗的一部分，是防守方的**预警窗口**，付费缩短行军等于付费剥夺对方的反应时间；③删掉它玩家会欢呼。**判定：拦路，且伤害的是别人。明确不做。**

> **同样是"卖时间"，加速建造可以卖而加速行军不能，区别不在机制像不像，而在这段时间是不是玩法的一部分。** 用 [第 21 章](./21-monetization-design.md) §2.3 的判断法：假设永远不收钱，你还会保留这堵墙吗？行军时间会（它塑造攻防节奏），建造时间不一定。

**黑暗模式自检**。[第 21 章](./21-monetization-design.md) §6.2 那句"把完整规则用一句人话写在按钮正上方，玩家还会买吗"是**一道很好的第一道筛子，但它只是必要条件，不是充分条件**——透明度解决的是信息不对称，解决不了诱导、强迫、虚假紧迫和取消障碍。经合组织（OECD）关于暗黑商业模式的公开研究也明确指出，**仅仅增加信息披露不足以消除这类模式的影响**【实证：OECD 关于 dark commercial patterns 的公开报告】。所以本案用一张四维表，**四项全过才算过**：

| 维度 | 问什么 | 通行证 / 促销在这一项上的处理 |
|---|---|---|
| **透明** | 完整规则用一句人话写在按钮正上方，玩家还会买吗 | 写"奖励在赛季结束时全部发放，赛季末可补购"→ 还买 → **过** |
| **无诱导层级** | 界面有没有在视觉权重、默认选项、路径长度上偏袒付费项？拒绝的按钮是不是被做小、做灰、藏深？ | 购买与不购买同等字号同等权重；不做"确认放弃这些奖励吗"这类羞辱式二次确认 → **过** |
| **无虚假紧迫** | 倒计时、"仅剩 X 份"、限时折扣，是真的稀缺，还是每期都有的排期？ | 赛季末的"最后 24 小时"促销**每季都会出现**，所以它不是稀缺，是排期。**处理：必须在活动说明里如实写明它会周期性出现**，否则这一项不过 |
| **可取消 / 可退出** | 订阅类能不能一键取消、取消路径是不是和购买一样短？未成年人保护与消费限额的口子留了吗？ | 月卡到期不自动续费；续费入口与取消入口同级；接入平台实名与消费限制 → **过** |

**四项里最容易挂的是第三项**，而且挂掉的时候通常没人觉得自己在做坏事——"赛季末促销"听起来天经地义。**判据不是"我们有没有说谎"，而是"玩家如果知道全部事实，他的决定会不会不一样"。** 如果会，那么无论规则写得多清楚，你都在利用一个他没有的信息。

### 10.2 关于收入天花板的诚实说明

P3 会让 ARPU 低于同品类均值【推导】。**这不是失误，是一个必须在立项时被制作人和发行明确接受的取舍**（[第 28 章](./28-pitching-and-greenlight.md)）。系统策划能做的是把取舍**写在纸上**：放弃了什么、换来了什么、这个交换成立的条件是什么。

成立条件是：**低 ARPU 必须被高留存和低买量成本抵消**。如果发行策略是"大规模买量快速回本"，P3 就不成立，应该在立项阶段推翻它，而不是上线三个月后偷偷加一个行动力礼包。**支柱和商业模式必须同时成立，这是本步骤最重要的一课。**

### 10.3 常见翻车与验收

| 翻车 | 怎么救 |
|---|---|
| 商业化留到最后想 | 系统做完了才发现没地方放付费点，硬塞出来的一定是拦路型 |
| 把商业化甩给数值 | 付费点的**位置和形态**是策划的决定，只有数字是数值的 |
| 支柱和商业模式打架却不说 | 把取舍写在纸上交给制作人决策 |

**验收**：① 付费点清单（形态 + 卖什么 + 出现时机）；② 每个跑过三问并写出判定；③ **至少讨论一个灰色地带**，并说清它的正当性依赖哪个上游决定、以及那个决定一旦变了要回来重判；④ **四维黑暗模式自检（透明 / 无诱导层级 / 无虚假紧迫 / 可取消），四项逐条给结论**；⑤ 不做清单含理由；⑥ **写出这套结构对收入的影响以及取舍成立的条件**；⑦ **检查有没有"看起来不像战力的战力"混进付费包里**（资源包、启动礼包、跨季加成）。

### 10.4 题目 B 的差异

卡牌主收入是抽卡，带来两个 SLG 没有的问题：① **"这关就是逼你抽 XX"的争议**（[第 24 章](./24-genre-card-rpg.md) §7.2）——被判定为逼氪则口碑崩得极快，抓手是**每关至少两条通关路线，且至少一条不依赖当期 UP 角色**；② **二次元用户对 pay-to-win 容忍度低但对外观付费意愿高**（[第 21 章](./21-monetization-design.md) §4.1），重心应往"表达"和"收集"倾斜。

## 11. 步骤⑦：长线 —— 首赛季的活动与版本节奏

**要回答**：第一个赛季 45 天每个阶段发生什么？活动分别解决什么问题？谷底在哪、怎么接？

**用哪章**：[第 22 章](./22-live-ops-design.md) §2 生命周期、§3 活动类型学、§4 活动案写法、§5.1 版本节奏与谷底、§6 赛季三问。模板 [event-spec.md](./templates/event-spec.md)。

### 11.1 示范：《寸土》首赛季骨架

赛季三问的前两问在 R6 已答（重置位置、保留身份）。第三问"这季有什么不一样"：**首赛季主题是"标准局"，不加任何变体规则**——首季的任务是让玩家学会基础规则。**这个决定必须写下来，因为团队里一定会有人想在首赛季就放大招。**

| 阶段 | 天数 | 玩家的问题 | 主要活动 | 类型 | 解决什么 |
|---|---|---|---|---|---|
| 开荒 | D1-7 | 我该怎么玩 | 开荒目标 | 累计 | 把新手带过核心循环 |
| 圈地 | D8-20 | 我该加哪个盟 | 同盟招募季 | 限时玩法 | **进盟率是这一段的首要指标**（次留、日活仍然要看，但这一段的成败看它） |
| 争霸 | D21-38 | 我们打谁 | 关隘争夺 + 一次跨盟事件 | 排行 + 限时 | 制造第一次大规模对抗 |
| 决战 | D39-45 | 还有没有机会 | 州府争夺 + 货币兑换倒计时 | 排行 + 回收 | 终局 + 资源回收 |
| **空窗** | D46-50 | 我这季干了啥 / 下季跟谁 | **功勋馆**（下面完整写） | 回流 + 收集 | **最易被忽略、也最决定次季回归率的一段** |

**版本节奏**：赛季即版本，约 7 周。[第 22 章](./22-live-ops-design.md) §5.1 说的"W4 谷底"在这里对应 **D21-27**——开荒与圈地的新鲜感耗尽、大战还没打起来。**接法：把关隘争夺的第一个窗口排在这一周，用组织事件而不是新内容来接住谷底。**

### 11.2 活动案：空窗期「功勋馆」

**头部**：功勋馆 / **收集 + 回流**（**不是排行，这是设计决定**）；结算完成后开启至新赛季开启（约 5 天，占位），领奖截止延至新赛季 D7；目标玩家是全体，**尤其中游玩家与赛季中期流失的玩家**。

**第 1 节 目标**：业务上压低空窗期流失、提高整体迁移率、**唤回赛季中期流失的玩家**（此刻他们没有"被落下"的压力，是最好的回流窗口）；体验上让**没拿到名次的中游玩家**在**空窗期任意一次登录时**感到**"这一季我做的事有人看见，而且我和这群人还有下一季"**；指标是空窗期日活留存、分享率、迁移意向确认率、**中期流失回流率**。

**第 2 节 规则**：参与条件是本赛季有过任意一次出征记录（**不设势力值门槛**——设了就等于告诉中游玩家"这里没有你的位置"）。

```
  [ 打开功勋馆 ] → 《本赛季战绩册（S11 的 R5 产出）》
        ▼
  [ 领取"功勋徽记" ]  ← 按行为类型发放，不按名次
        │   （守城 / 远征 / 援助 / 连胜 / 坚守）
        ▼
  【 徽记收藏（永久） 】 ──→ 可镶嵌在旗帜/称号上（表达）
        ▼
  [ 与同盟成员互相授予"感谢" ]（每人 N 个，被感谢会推送）
        ▼
  《 盟内感谢墙（公开） 》 ──→ [ 确认下赛季迁移意向 ]
```

| 档位 | 触发条件（**按行为类型，不按名次**） | 奖励结构 |
|---|---|---|
| 参与 | 有过出征记录 | 基础徽记 + 战绩册解锁 |
| 行为类 | 守城 / 远征 / 援助 / 连胜达到次数（占位） | 对应类型徽记（永久可展示） |
| 同盟类 | 所属同盟达成集体条件 | 同盟徽记（**全盟同得，不分名次**） |
| 名次类 | 同盟名次段 | 名次纪念物（**仅纪念，无属性**） |

> **"按行为类型而不按名次发徽记"是本活动最重要的设计决定。** 排行型活动会把空窗期变成又一次"你排第几"的公示，而空窗期的目标恰恰是安抚中游玩家。**同一份数据，不同的切法，制造完全相反的体验**——这条在 [第 15 章](./15-system-design-method.md) §6.1 出现过，这里是第二次应用。

结算：徽记与纪念物为永久资产写入 S12；未领奖励转邮件跨赛季有效。与常驻系统：空窗期**不开放战斗、养成与商城的战力类商品**（否则它变成"提前备战期"，不上线的人在新赛季一开始就落后，违反 P2）。

**第 3 节 流程与界面**：入口是空窗期主界面唯一主按钮；结算完成后一次强推送；红点是**每日一次的"有人感谢了你"**（空窗期唯一的回访钩子）；典型流程 3~5 分钟（占位）。

**第 4 节 经济影响**：徽记与纪念物**不进入战力体系**（纯表达），对经济无影响——这是刻意的：空窗期投放任何战力资源都会破坏新赛季的起跑线。赛季货币已在 R6 清零，本活动不承担回收职责（框架见 [game-numeric 22](../game-numeric/22-seasons-and-merges.md)）。

**第 5 节 风险清单**

| 风险 | 预案 |
|---|---|
| **可被刷**：小号互相"感谢" | 感谢只在同赛季同盟成员之间有效，且每人每季被感谢有上限（占位） |
| **规则歧义**："守城次数"怎么算 | 必须给出可判定的定义并在界面写清 |
| 与同期冲突：空窗期同时开新赛季预热 | 预热信息只在功勋馆内部展示，不抢主按钮 |
| 结算依赖：档案生成失败则本活动对该玩家为空 | 兜底给"参与档"并进人工队列 |
| **体验风险**：中期流失玩家打开后发现只有 1 条高光 | 见 R5 的"不凑数"边界；**但这条风险没有被解决，进自评审** |

**第 6~7 节 埋点与版本记录**：`hall_open`（来源、名次段 → 推送有效吗、中游玩家来了吗）、`badge_claim`（是不是所有人都只拿到"参与"档）、`thanks_sent/received`（**人均被感谢数是体验目标的核心指标**）、`intent_confirm`。复盘固定四问：目标达成？哪一档参与率最低？投诉集中在哪？下次改什么？

### 11.3 常见翻车与验收

| 翻车 | 怎么救 |
|---|---|
| 活动全是排行型 | 按 [第 22 章](./22-live-ops-design.md) §3 的类型学配比，排行型不超过一半 |
| 空窗期不设计（"维护三天"） | 空窗期日活与次季回归率高度相关【行业口径】，而且它是你唯一还能主动干预的窗口 |
| 活动改掉了系统案的数值假设 | 回耦合矩阵查"活动 → 各系统"这一行 |

**验收**：① 阶段表（玩家问题 + 活动 + 类型 + 解决什么）；② 标出谷底与接法；③ 一份七节全写的 event-spec；④ 奖励只写**结构与档位**不写数字；⑤ 风险清单含"可被刷"与"规则歧义"；⑥ **回耦合矩阵检查这个活动会不会改掉某个系统案的假设**。

### 11.4 题目 B 的差异

卡牌靠**版本**驱动（6 周）：W1 新角色/新剧情一次给出（峰值）→ W2 消耗完 → W3 中期活动 → **W4 谷底** → W5-6 下版本预热（[第 22 章](./22-live-ops-design.md) §5.1）。活动案建议写**限时复刻池**（难点是预期管理：复刻会不会伤害首发购买者）或**角色活动关**（难点是"这关是不是在逼你抽当期角色"），两者都比功勋馆更接近你日常会遇到的活动案。

## 12. 步骤⑧：测试计划

**要回答**：我的设计里有哪些**假设**（不是"功能"）？每条若成立会观察到什么，**若不成立呢**？用什么测试、什么样本、多久？**这条假设是要做因果结论还是只做诊断——随机分配的是什么？** 最后：**这次测试测不出什么？**

**用哪章**：[第 20 章](./20-playtesting-and-validation.md) §8 假设模板与翻译表、§4 测试类型学、§6 think-aloud 与 RITE、§11.5 观察表与严重度、§11.8 "测不出什么"。

### 12.1 示范：《寸土》的三条假设

**写假设之前，先定一条纪律，否则下面三条会全部滑成"看起来验证了、其实什么也没验证"**：

> **随机分配的必须是"设计"，不能是"玩家的行为"。** 按玩家行为事后分组做比较（按日均时长分组、按进没进盟分组、按看没看战绩册分组），得到的永远是相关性——因为行为本身由动机、可支配时间、以及"是不是已经掉队了"共同决定。**"掉队了所以不玩了"和"玩得少所以掉队"在这类数据里长得一模一样。**
>
> 所以每条假设都要先声明它属于哪一类：**（因果）随机鼓励 / 灰度对照**，还是**（相关）预先分层的诊断**。**后者不是没用——它是发现问题最快的工具——但报告里不许用它写因果句。**

```
H1：轻量化设计（P2）会让"每天只有 20 分钟"的玩家在赛季中期不掉队。
  验证方式：两条都做，用途不同。
    ① **预先分层（相关性诊断）**：招募时就按"每天可支配时长"分层配额
       （20~30 分钟组 / 60~90 分钟组各占一半），赛季中固定测两组的
       势力值曲线与留存。**结论只能写"两组有无差异"，不能写"设计导致了差异"。**
    ② **随机鼓励 / 灰度对照（因果）**：把 P2 落地的某一个具体机制
       （如"行军可预约 + 指挥可委托"）做成灰度开关，在同一批玩家里
       随机分配开/关，比较两组中低时长玩家的掉队率。
       **这是唯一能说"是这个设计造成的"的做法**，代价是一次只能测一个机制，
       且关闭组的体验会变差（伦理与口碑成本，须提前评估并在测试须知里写明）。
  若成立：① 灰度实验中，开启组的中低时长玩家 D21 掉队率显著低于关闭组
          ② 预先分层的两组势力值曲线不出现持续扩大的分叉
          ③ 20~30 分钟组担任盟内职位的比例不显著低于高时长组
  若不成立：① 灰度两组无差异 → 这个机制没起作用（注意：P2 本身并未被证伪）
            ② 分层的两组在 D14 后曲线明显分叉，分叉后留存断崖
            ③ 访谈中出现"我跟不上""我不敢接职位"
  最小证据：一次 ≥4 周、200 人以上、能形成 6~8 个真实同盟的封测，
            且招募时就按可支配时长分层。
            **短于 4 周或人数不足以形成同盟对抗的测试，无法验证这条。**

H2：赛季结算的战绩册（S11）会让中游玩家在赛季末不流失。
  验证方式：**这条最难，因为完整赛季通常只跑一版，没有天然对照组。** 二选一：
    ① **灰度对照（因果，推荐）**：战绩册做成开关，同赛季内随机分配。
       代价是"有人有、有人没有"的公平争议，必须在测试须知里写明。
    ② **不做对照 → 明确降级为相关性诊断**：只回答"打开的人后来怎么样"
       和"哪些人打开 10 秒就关了"。**报告里不许出现"战绩册提升了回归率"。**
  若成立（灰度版）：① 有战绩册组的中游名次段 T+3 回归率显著高于对照组
          ② 战绩册停留时长足够且滑到底比例高
  若不成立：① 打开后 10 秒内关闭
            ② **高光条数 < 3 的玩家占比很高**（最关键：说明 R5 对中游玩家
               没有生效，即中游玩家的行为根本没有被 S5 的事件流记录下来）
            ③ 两组 T+3 回归率无差异
  最小证据：必须是完整赛季的真实测试。**这条无法用短周期测试验证**，
            而且不做灰度就只能拿到相关性。

H3：第 4 天强推同盟 + "新人第一小时"机制，能让 7 日进盟率显著高于基线。
  **注意假设的落点是"进盟率"，不是"进盟能提高留存"。** 后者不能用
  "进盟玩家 vs 未进盟玩家的留存"来证明——会进盟的人本来就更投入，
  这是教科书级的自选择。所以拆成两条：
    H3a（因果）：**随机分配的是引导方案，不是进不进盟。** 一组走
      "第 4 天强推 + 新人第一小时"，一组走原方案，比较 7 日进盟率与 D14 留存。
    H3b（只做诊断）：进盟玩家的后续表现。**只报相关性**，用途是发现问题
      （如进盟后 3 天内退盟率高），不用来论证"同盟提升留存"。
  若成立：① H3a 实验组 7 日进盟率显著高于对照组，且 D14 留存不低于对照组
          ② 新人加入后 1 小时内收到过 ≥1 条真人消息的比例高
  若不成立：① 进盟率高但"1 小时内收到真人消息"比例极低
               → 进了盟没人搭理，**这比不进盟更糟**
            ② 大量玩家进盟后 3 天内退盟
            ③ 进盟率上去了但 D14 留存反而下降
               → 强推把不合适的人塞进了同盟，对双方都是负担
  最小证据：2 周、100 人的定向封测（两组各 50）+ think-aloud。
```

**轮次分工**：① 内部走查 + 纸面推演（团队 5~8 人）→ 答"规则有没有歧义、结算能不能跑通"，**不答"好不好玩"**（团队不是目标用户）；② 目标用户 think-aloud + RITE（8~12 人两批）→ 答前 7 天引导（H3）、界面与战报能不能看懂，**不答长线**；③ 小规模封测 4 周+（200 人以上）→ 答 H1、H3、同盟能否自然形成，**不答 H2**（需要完整赛季）。

**观察表**（照抄 [第 20 章](./20-playtesting-and-validation.md) §11.5，含四级严重度）：

| 被试 | 任务 | 完成 | 用时 | 需提示 | 卡在哪 | 原话（逐字） | 严重度 |
|---|---|---|---|---|---|---|---|
| P4 | 加入一个同盟 | 是 | 4:12 | 是 | "同盟"页找不到申请按钮，先去了排行榜 | "同盟在哪申请……这个是排行" | **1 阻塞** |
| P7 | 看懂上一场为什么输 | 否 | 3:00+ | 是 | 战报只显示总损失，看不到回合过程 | "我不知道我为啥输了，是不是他人多" | **1 阻塞** |

> **P7 那一行是刻意写的**：反复出现"看不懂为什么输"不是 UI 问题，是步骤②里"L1 的乐趣绝大部分在战报"这个判断没有被实现。**测试的价值不在于发现 bug，在于发现哪个设计假设是错的。**

**这次测试测不出什么**（必须写进报告）：赛季结算（H2，需完整 45 天）；真实的同盟政治（封测的同盟是陌生人临时组的）；**服务器人口密度效应**（200 人的封测里地图是空的，所有关于"抢地""被偷家"的体验都不真实）；商业化（样本偏核心）；长期疲劳；**以及所有没有做灰度对照的那些结论的因果性**——H1 的分层部分和 H3b 只能说"看到了什么"，不能说"是设计造成的"，这一条要在报告里逐条标出来，否则三个月后它们会被当成因果结论引用。

> **最后一条对 SLG 尤其重要**：**这个品类的核心体验只能在真实人口密度下验证。** 所以测试计划里要有一个"最小可玩人口"实验——不是"我们测 200 人"，而是"**找出让这张地图产生冲突所需的最少人数**"，据此定开服人数与地图大小。**这是测试计划反过来决定设计参数的例子。**

### 12.2 常见翻车与验收

| 翻车 | 怎么救 |
|---|---|
| 只写"要做用户测试"，没有假设 | 每条体验目标翻译成一条可证伪假设 |
| 不写"若不成立" | 事后能给任何结果编个解释；先写反证，断了后路 |
| 用业务指标验证单个系统 | 业务层指标被无数因素污染（[第 20 章](./20-playtesting-and-validation.md) §8.4） |
| **按玩家行为事后分组做比较，然后写因果结论** | 时长、进不进盟、看不看某个页面都是玩家自选的，分组即混杂。要么随机分配"设计"（灰度/A-B），要么明说这是相关性诊断 |

**验收**：① ≥3 条假设含"若成立/若不成立/最小证据"；② **每条假设标明它属于因果（随机分配设计）还是相关（事后分层诊断）**，相关性的那些不许写因果结论；③ 对应到行为层或体验层指标（不是业务层）；④ 轮次分工表含"**不回答什么**"；⑤ 观察表 + 四级严重度；⑥ "测不出什么"一节，**含"哪些结论只是相关性"**；⑦ **至少一条假设你诚实承认现有资源验证不了**。

### 12.3 题目 B 的差异

卡牌的核心假设通常围绕 **build 分布的熵**（[第 20 章](./20-playtesting-and-validation.md) §8.3）：如果 90% 的玩家走同一条路，"阵容是玩家的表达"这条支柱就是假的。测它不需要真实人口密度，几十人封测加埋点就够，**所以卡牌的设计假设比 SLG 好验证得多**。另一条是"新角色改变了打法而不只是数字"，观测方法是**新角色上线后阵容分布有没有出现新的簇**。

## 13. 步骤⑨：自评审

**要回答**：用 [review-checklist.md](./templates/review-checklist.md) 的三层把自己的方案当别人的案子打一遍，产出评审记录。**硬性要求：至少三个真问题，每层至少一个。**

"真问题"的判据：**你写下它的时候会有点不舒服。** 如果三个都是"文档还不够详细""还需要更多测试"，那你在应付作业。

**用哪章**：[第 26 章](./26-design-critique.md) §3 三层问法、§8.2 评审记录模板、§10 三个自评技巧——**换人称**（把"玩家会"全换成"我猜玩家会"再读一遍）、**删一半**（排期砍半留哪一半？**没被留下的那一半为什么在案子里**）、**反串**（写 200 字《这个设计为什么会失败》，把最有杀伤力的两条主动写进"已知风险"）。

### 13.1 示范：《寸土》v0.1 自评审记录（节选）

**三层过一遍**：第一层"真问题还是别人有" ⚠️（**S7 内城差点因为"SLG 都有"被无理由保留**），成功指标 ⚠️（见 D）；第二层"决策有意思吗" ⚠️（L2 只有一个真决策点，已修正但**未验证**）、"接口列全了吗" ❌（见 B）、社交压力 ⚠️（功勋馆的"感谢"可被小号刷）；第三层"规则有歧义吗" ❌（见 C）、边界与异常 ⚠️（其余 14 个系统只有清单没有案子）、表现资源量 ⚠️（结算动画成本未估）。

**四个真问题**：

> **A（第一层）：P2 和 P1 的张力在"睡觉时被偷家"这个场景上没有解决。**
> 我在步骤①写了这条张力，也写了"逼我们做异步对抗"，然后给出"预设防御指令"作为答案。但**它只是把决策提前，没解决体验问题**：我睡觉时被打光兵，早上打开游戏看到一份"你输了"和一座空城，接下来几小时因伤兵恢复什么都做不了，这直接摧毁 P2 承诺的"一天 20 分钟够用"。**这是我目前没有答案的结构性问题。** 三个未验证的方向：夜间损失上限；被打后的"重整"机制；把"防守成功"做成可累积的收益。**我把它写进已知风险，而不是假装解决了。**

> **B（第二层）：S11 的体验目标依赖一份 S5 还没有产出的战斗事件流。**
> S11 的核心是"高光时刻"，要从战斗记录提取；但 S5 只记录了输赢和总损失。**这里其实有两层，我在 v0.1 里把它们混成了一层，这本身就是个错误**：
> - **数据契约缺失（D 型，可修，工作量明确）**：S5 需要输出一份结构化战斗事件流——攻守方、兵力对比、目标地块类型、是否守住、参战人数、关键回合。**修法是在 S5 的案子里加一节"对外事件"，把它当成一份对下游稳定的契约来定**，而不是"给 S11 加几个字段"。
> - **体验依赖（X 型，真正难的那层）**：**事件的粒度决定了 S11 能讲出什么样的故事，而这一点在 S5 的案子里完全看不出来。** S5 的作者按"够用来算战斗结果"的标准定粒度是完全合理的，只有从 S11 的体验目标出发才会发现它不够。**同时要守住分工：S5 如实产出原始事件，S11 负责解释和排序——不要要求战斗结算去理解"叙事价值"，那会把一个横切的价值判断塞进一个只该管裁决的系统。**
> **这是本次自评最有价值的发现**，它印证了第 15 章那句话：**体验耦合没有代码痕迹，只有从体验目标出发的人能发现。** 先写 S5 再写 S11 就不会发现它；正因为先写了被依赖最多的那个，才在写接口表时撞上它。

> **C（第三层）：R8 与 R10 之间有一段没人管的时间。**
> R8 写了"盟主发起、成员确认、48 小时窗口"，R10 写了"新赛季开启时按意向整体分配"，两者之间有时间差而案子没写：**在意向确认之后、新赛季分配之前退盟的玩家会被分到哪里？** 三种答案（跟原盟走 / 单人匹配 / 禁止退盟）对应三种完全不同的体验，而**案子不写，程序会实现最好写的那种**（[第 15 章](./15-system-design-method.md) §4.2）。发现它的方法是把两条规则的时间轴画在一起——**规格层的问题几乎都要靠画图才能发现。**

> **D（第一层，影响全局）：我没有回答"这套商业化能不能养活 30 人团队"。**
> 步骤⑥我诚实写了"P3 会让 ARPU 低于均值"，然后把问题"交给制作人"。**但我没给制作人任何可以据此决策的材料**：低多少？靠什么补？补不上时哪条支柱先松？定 ARPU 不是我的工作（越界），但**把取舍量化到"ARPU 只有均值的 X 成时留存要高多少才能打平"**，是我该配合数值一起做的。看起来尽了责，实际是把问题原样推走了——这正是"把问题推给数值"（[第 26 章](./26-design-critique.md) §6）的一个变体。

**总结论：打回（第一层未过）。** 四种结论（通过 / 修改后通过 / 暂缓决策 / 打回，见[第 26 章](./26-design-critique.md) §8.2）里选打回，理由是问题 A：体验目标与支柱之间的结构性冲突没有解决，这不是补几条规则能修的。

**为什么不是"暂缓决策"**——这个区分值得写下来，因为它是四种结论里最容易被用来回避决定的一种：暂缓的合法前提是"**知道了 X 我们就能定**"。问题 D（这套商业化能不能养活 30 人团队）符合这个条件，所以它**在修改项里被单独列为一条暂缓**：

> **暂缓项（D）**：P3 下的收入结构能不能支撑 30 人团队。**缺什么**：ARPU 相对同品类均值的折损幅度，以及"折损 X 成时留存要高多少才能打平"的粗算。**谁补**：我 + 数值。**何时**：立项评审前两周。**逾期默认动作**：按"不成立"处理，即在立项评审上把 P3 作为待推翻项提出，而不是默认它成立往下走。

问题 A 则不是暂缓——**我说不出"知道了什么就能定"，我是真的没有答案**，所以它是打回的理由。B、C 属于第三层与第二层的规格/接口问题，留待第一层修完后再看。

**修改项**：① A 出三个方向的一页纸并做纸面推演（我，v0.2）；② B 给 S5 补一节"对外事件"（结构化事件流的契约），作为 S11 的前置（我 + S5 作者，v0.2）；③ C 补规则并画时间轴（我，v0.2）；④ D 已单列为**暂缓项**（缺什么/谁补/何时/逾期默认动作见上）。

**未解决的分歧**（自评时是"我和我自己的分歧"，仍然要写）："抢秒"保留（戏剧性）还是禁止（公平与稳定）——暂定保留并公示；传承名额是否可付费扩充——暂定不做（红线优先）。两条都留到立项评审再议。

### 13.2 常见翻车与验收

| 翻车 | 怎么救 |
|---|---|
| 找的问题都是"文档不够细" | 判据：写下它时你会不舒服 |
| 自评完就当过了 | 自评抓的是"我知道我没想清楚"，抓不住"我以为我想清楚了"（[第 26 章](./26-design-critique.md) §10.1） |
| 不写"未解决的分歧" | 半年后变成"我早就说过" |
| 写完当天自评 | **隔一天**，否则你会自动补全缺失信息 |

**验收**：① 三层逐条过，每条有结论（✅/⚠️/❌）；② **≥3 个真问题，每层至少一个**，各写清"哪一层 / 影响什么 / 可能怎么改"；③ **至少一个你没有答案**（有答案的不叫风险，叫待办）；④ **总结论四选一**（通过 / 修改后通过 / 暂缓决策 / 打回）——**写"暂缓决策"必须附上缺什么证据、谁去补、什么时候补完、逾期补不出来的默认动作，说不出"知道了什么就能定"的不是暂缓，是打回**（[第 26 章](./26-design-critique.md) §8.2）；⑤ 修改项表 + 未解决的分歧表；⑥ 用过三个自评技巧中的至少两个。

### 13.3 题目 B 的差异

卡牌自评最常撞到的三层问题依次是：**第一层**体验目标写成"让玩家喜欢这些角色"（这是结果不是设计目标，且不可证伪）；**第二层**养成线之间没有卡点分工（[第 24 章](./24-genre-card-rpg.md) §6.3）；**第三层**保底计数器的跨池/跨版本归属没写清。

## 14. "参考答案的骨架"：我刻意留白了什么

| 步骤 | 我给了什么 | **刻意没写的（留给你）** | 为什么 |
|---|---|---|---|
| ① | 5 条支柱 + 5 组张力 + 1 次否决演示 | 一页纸的其余部分（30 秒典型体验故事、风险与未知） | 那个故事必须用你自己的语言讲 |
| ② | L2 完整图；L1、L3 骨架 | **L1 的完整图**（含战报的信息层次）、**L3 的完整图** | 画图是设计动作不是记录动作 |
| ③ | 15 个系统 + 全局矩阵 + 四处 X 分析 | **矩阵里每一格的"改动影响"**（我只详写了 S11 那一行） | 填矩阵的过程就是理解系统的过程 |
| ④ | 九节全写，但只有 R2/R5 是完整形式定义 | **R1、R3、R4、R6~R12 的形式定义**；**赛季状态机的状态图** | 状态图是暴露漏洞最快的工具，别人画完你就失去这次暴露 |
| ⑤ | 四窗口时间线 + SLG 三个特有问题 | **前 5 分钟的逐屏分镜**；前期地图 / 前 10 关的 level-spec | 分镜是把"要给爽点"变成"第 17 秒屏幕上是什么"的唯一途径 |
| ⑥ | 付费点清单 + 两个三问对照 + 灰色地带 | 礼包结构、展示位排布、首充与月卡的权益组合 | 高度依赖定价策略，交给 [game-numeric 14](../game-numeric/14-pricing.md) 配合 |
| ⑦ | 阶段表 + 一份收集/回流型活动案 | **另外三个阶段的活动案**，至少要有一份**排行型**和一份**累计型** | 我给的是最不典型的一种，典型的那两种你必须自己写 |
| ⑧ | 3 条假设 + 轮次分工 + 观察表 + "测不出什么" | 招募配额、任务脚本、RITE 的可改范围清单 | 这些最需要贴合你自己的产品 |
| ⑨ | 完整记录 + 4 个真问题 | **这 4 个问题我故意没修。** 你要给出修法并产出 v0.2 | 找到问题只是一半，能不能改是另一半 |

**为什么给骨架不给完整答案**：第一，**完整答案会让你去"对答案"而不是"做设计"**。这题没有唯一解——把 P3 换成"可以卖行动力但赛季更短"，会长出一款完全不同但同样自洽的游戏。**设计能力的标志不是产出正确答案，是产出自洽的答案并说清楚它为什么自洽。** 第二，本章教的是"下一次你自己走这九步时怎么走"；我给的每处细节，作用只是标定"深度应该到这里"。

## 15. 回看：和三个月前的自己比

**把三样东西摆在一起**：[第 00 章](./00-how-to-learn.md) §7.2 的**第一次拆解**、[第 01 章](./01-what-designers-do.md)时的**读案子笔记**、[第 15 章](./15-system-design-method.md) §11.1 的**系统案**。然后回答六个问题，写成 300~500 字放在 `notes/作业/29-端到端/自我评估.md`：

| # | 问题 | 你在找什么 |
|---|---|---|
| 1 | 第一次拆解的第五层（意图）现在重写会有什么不同？ | 意图推理有没有从"我猜是为了赚钱"变成"它保护的是哪个体验目标" |
| 2 | 当时回答的"删掉会怎样"现在站得住吗？ | 你现在会不会跑四个变体 |
| 3 | 第 01 章那份案子里当时看不懂的地方，现在还剩哪些？ | **剩下的那些就是你的下一步学习方向** |
| 4 | 用三层清单打第 15 章的系统案，能过第几层？ | 三个月前大概率过不了第一层 |
| 5 | `模式库.md` 有多少条？这一章真的用上了哪几条？ | **用上过的模式才是你的，没用过的只是笔记** |
| 6 | 九步里花时间最长、卡住最久的分别是哪步？ | **这两个答案指向你最弱的能力** |

第 6 问的含义：卡在**①支柱**说明你还在描述功能、不习惯做排除；卡在**②循环**说明你看不到玩家一天的形状；卡在**③矩阵**说明你还在孤立地想系统；卡在**④系统案**是**正常的**，但若卡在"边界与异常"，说明你的工程优势没发挥出来；卡在**⑤引导**说明你不习惯从玩家的时间线想；卡在**⑥商业化**说明你在回避它；卡在**⑦长线**说明你没真正玩到过第 30 天；卡在**⑧测试**说明你把体验目标当成了不可验证的东西；卡在**⑨自评审**说明你找不出自己的问题。

**另外**：[game-numeric 第 25 章](../game-numeric/25-end-to-end-lab.md)也是一份 SLG 端到端实战，走数值路线。**选了题目 A 的话，把两章的产出拼在一起就是一份设计案 + 数值案配套的完整方案**——那是真正可以拿去立项评审的东西。

## 16. 之后怎么办：进入真实项目的前三个月

**第 1 个月：不写案子，先建地图。** 三件事：① **读现有案子做笔记**，每份用三层清单**只问不评**，一个月后你会有一份自己项目的"设计债清单"；② **画全局耦合矩阵**——**这件事多数团队没人做过**，因为它要横跨所有系统，而每个策划只熟悉自己那几个；画出来你就是团队里唯一有全局视图的人，这是新人建立专业信任最快的路径，而且完全依赖你的工程背景；③ **建模式库**（[第 00 章](./00-how-to-learn.md) §5），每条"为什么这么设计"都标【实证】还是【推导】。

**第 2 个月：接一次"改一条规则"。** 改规则会逼你走完整条耦合链（被谁依赖、改了谁跟着改），**这是学系统设计最快的方式**；新系统可以靠"写得全"蒙混过关，改规则不行，它会立刻在线上暴露你有没有想到边界。改完强制**写变更记录**——改了什么 / 为什么 / 影响哪些系统 / 观察什么指标 / 一周后实际发生了什么。**这是你在团队里的第一个信誉资产。**

**第 3 个月：第一次评审别人的案子。** 按 [第 26 章](./26-design-critique.md) 的三层顺序从第一层问起。**新人最大的价值恰恰是"傻问题"**——"为什么这里要有个同盟"，写案子的人三个月前就不再问了。三条纪律：先复述对方的目标再提意见；每条意见指明是哪一层；每个反对意见附一个替代方案，或明说"我只是提示风险"。

**长期**：三个不能停——持续拆解（**尤其拆你不喜欢的游戏**）、持续更新模式库（第三年会有两三百条，那就是你的资历）、玩自己的游戏玩到第 30 天。三个会毁掉你——靠职级而不是论证赢得争论（团队会停止给你提意见）、把"竞品有"当理由（抄来的是外形）、不再写"删掉会怎样"（三年后六十个系统，新玩家看一眼就跑）。

**最后一句**：这门课从 [第 00 章](./00-how-to-learn.md) 到这里，反复用的只有三个动作——

> **先问体验目标，再看机制；区分事实与推测；每个东西都问一遍"删掉会怎样"。**

方法可以忘，工具可以查（[附录 A](./A-toolkit.md) 就是给你查的），这三个动作要变成本能。

## 17. 常见误区（实战时的误区）

前面每章的误区讲"理解错了什么"。本章的误区讲"**方法都懂，实战时还是会犯的错**"——它们几乎全部关于顺序、纪律和诚实，而不是关于知识。

| 误区 | 为什么错 | 正确的想法 |
|---|---|---|
| "先列系统清单，支柱后面补" | 没有尺就砍不动清单；**而且清单一旦列出来就有了惯性**，之后写的支柱会不自觉地迎合它 | 支柱在清单之前定，清单写完回头检查有没有系统填不出支柱 |
| "支柱写完了，进入正题" | 不用来否决就等于没写。**判断一个团队有没有支柱，不看文档，看会议现场有没有人拿它说话** | 每个系统、功能、付费点都标"服务哪条 / 与哪条有张力" |
| "先写最有意思的那个系统" | 写完发现它依赖三个还没定的系统，返工 | 按耦合矩阵选**被依赖最多**的先写 |
| "这是练习，边界和异常就不写了" | **边界与异常是工程师出身的策划最大的优势项**，跳过等于自废武功；而且大量边界是设计决定不是技术决定 | 越是练习越要写全，练习没有 QA 帮你兜底 |
| "数值会解决的" | 把"这条曲线该给玩家什么感受"推给数值，等于让数值替你做设计决定 | 你写**体验要求 + 合法范围**，数值写最终取值。写不出体验要求和合法范围是失职，自己拍最终取值是越界——**注意这两句话的边界，不是"策划一个数字都不能写"** |
| "自评审就是打个勾" | 你只会找到"我知道我没想清楚"的问题 | 用反串技巧强迫自己攻击自己；找到的问题要让你不舒服 |
| "九步做完就结束了" | 真实设计是螺旋不是流水线 | **版本记录里有几次"因为下游发现问题而改上游"，是判断这套文档质量最快的指标** |
| "找不到问题说明我做得好" | 更可能是你没认真找。一份 v0.1 不可能没有结构性问题 | 强制指标：≥3 个真问题，≥1 个你没有答案 |
| "这只是虚构题目，不用较真" | 你在练的是较真这件事本身 | 当成下周就要拿去立项评审的东西来写 |

## 18. 动手：提交清单与自评标准

**本章整章就是动手。** 这一节给提交清单和评分标准。

### 18.1 提交清单

```
notes/作业/29-端到端/
  00-题目与约束.md      ← 你选了 A 还是 B，抄一遍约束（防止中途放宽约束）
  01-定位与支柱.md        05-引导方案.md        09-自评审记录.md
  02-循环图.md            06-商业化方案.md      自我评估.md  ← §15 的六问
  03-系统清单与耦合矩阵.md  07-长线与活动案.md    不做清单.md  ← 全局的，贯穿所有步骤
  04-系统案-XX.md         08-测试计划.md
```

**`不做清单.md` 单独成文件是有意的**：它是这套文档里唯一会在上线两年后还被反复翻出来的东西。每条格式固定：**"不做什么 / 为什么不做（回指支柱）/ 什么条件下可以重新讨论"**。第三栏最重要——它把"永远不做"变成"在这些条件下不做"，既诚实，也让后来者知道该拿什么来说服你。

### 18.2 自评标准

**别给自己放水，这个表的唯一读者是你。**

| 产出物 | 及格 | 良好 | 优秀 |
|---|---|---|---|
| 支柱 | 有 3~5 条 | 每条能否决一个功能 | 张力被写出来，每组有"逼我们做什么" |
| 循环图 | 三层都画了 | 闭合、有闸门、边上写清传递什么 | **因为画图而修改了上一步的某个决定** |
| 耦合矩阵 | 画完了 | 逐格问过 X 并写下结论 | 判断出高耦合系统是过载还是横切，据此决定写哪个案子 |
| 系统案 | 九节全写 | 有状态图、时间七问、数值接口只写体验要求与合法范围 | **写案子过程中发现了一个上游系统的设计缺失** |
| 引导方案 | 四窗口时间线 | 每窗口有唯一目标和流失点 | 前 5 分钟能逐屏讲出来 |
| 商业化 | 有付费点清单 | 每个跑过三问 + 四维黑暗模式自检 + 有不做清单 | 讨论了灰色地带并说清它依赖哪个上游决定、上游变了要回来重判 |
| 长线 | 阶段表 + 一份活动案 | 活动案七节全写、有风险清单 | 回耦合矩阵检查过活动对系统假设的影响 |
| 测试计划 | 有假设 | 每条有"若不成立"，且标明因果/相关 | 有一条你诚实承认验证不了，并说明需要什么条件 |
| 自评审 | 三层过完 | 三个真问题 | **有一个你没有答案，并且写进了案子的已知风险** |

### 18.3 时间盒与读者

**给自己设一个截止时间，到点就交，不完美也交。** 理由在 [第 14 章](./14-design-process.md)：设计文档没有"写完"的时刻，只有"这个版本的决定已做完"的时刻。一份带着四个已知风险的 v0.1，比一份永远在改的草稿有用一百倍。

**最后一步，也是最重要的一步：找一个人，把方案讲 15 分钟。** 对方不需要是策划。你要的不是他的意见，是**你在试图解释时卡住的那些时刻**（[第 26 章](./26-design-critique.md) §10 的"橡皮鸭评审"）。注意听自己说"这个……嗯，其实是因为……"的时刻——**那个"嗯"的位置，就是你还没想清楚的地方。**

### 18.4 思考题（不用写，但要能口头回答）

1. 示范里 S11 被选为要写完整案子的系统，理由是"横切关注点型高耦合"。举出你熟悉的产品里另一个横切关注点型系统，说明如果它的接口没在早期定下来，会在哪个时刻爆炸。
2. 问题 B 之所以被发现，是因为"先写了被依赖最多的系统"。如果先写 S5，这个问题会在什么时候、以什么形式暴露？代价差多少？
3. P3 直接导致了收入天花板。假设制作人说"这个天花板我们接受不了"，你有哪几种改法？每种牺牲哪条支柱、连带影响哪些系统？（提示：用耦合矩阵找连锁）
4. 本章要求"至少一个你没有答案的问题"。在真实项目里，把"我没有答案"写进案子，对你的职业信誉是加分还是减分？你见过的资深策划怎么处理这类问题？
5. 如果把题目 A 的约束改成"团队 200 人、买量预算充足"，九步里哪几步的产出会发生根本变化？哪几步基本不变？（这一问检验你有没有理解"约束决定设计"。）
