## 1. 三条万能纪律

来源：[第 00 章第 6 节](./00-how-to-learn.md)、[第 15 章第 7 节](./15-system-design-method.md)、[第 26 章第 2 节](./26-design-critique.md)。

**纪律一："删掉会怎样"。** 全课频率最高的问题，四个场合通用：拆解（找系统的真正职责）、写案子（把"我觉得应该有"变成"因为 X 所以必须有"）、评审（第一层第四问）、砍功能。三个变体一起用：

| 测试 | 问法 | 答案说明什么 |
|---|---|---|
| **删掉** | 整个拿掉，游戏会怎样 | "没什么影响" → 该删，或你没找到它的职责；"变成另一个游戏" → 支柱级系统 |
| **合并** | 能不能和另一个系统合成一个 | 能 → 两者体验目标重合；不能 → 那个理由就是它的独特价值 |
| **减半** | 规模砍一半，体验会怎样 | 变化不大 → 当前规模是虚胖；崩掉 → 找到了临界规模 |
| **反转** | 把最核心的那条约束反过来 | 想清楚这个，才算真正理解那条约束在保护什么 |

**纪律二：先目标，再系统，最后规格。** 下层每条结论都建立在上层的答案之上，上层一变，下层里"随方案失效的细节"要重做，但"可复用的边界约定"（时区、幂等、异常处理）通常还能留下。它同时管写案子的顺序、评审的顺序、和吵架时先确认吵的是哪一层。

**纪律三：事实与推测分开。** 你能观察到规则，观察不到设计意图。它在拆解时保证准确，评审时保证不冤枉人，写案子时区分"我验证过的"和"我希望的"。

## 2. 拆解五层与 MDA 对照

来源：[第 00 章第 2 节](./00-how-to-learn.md)、[第 04 章第 9 节](./04-mda-and-lenses.md)。模板：[deconstruction.md](./templates/deconstruction.md)。

| 拆解层 | 写什么 | MDA |
| --- | --- | --- |
| 一 **体验** | 最爽的一刻、最烦的一刻、想让你产生什么情绪 | **A** |
| 二 **机制** | 参与者、状态、动作、规则、输入输出、边界 | **M** |
| 三 **动态** | 循环、反馈回路、玩家的最优解、涌现行为 | **D** |
| 四 **决策** | 每个决策点：选项 / 信息 / 后果 / 最优解 | D 的切面 |
| 五 **意图** | 系统的职责、删掉会怎样、替代了什么更简单的方案 | 之外 |
| 六、七 | 如果是我来做 / 可复用的模式 | 之外 |

三条层内纪律：第一层先写感受再写规则；第二层**只写能验证的**，没试过的写"未验证"；第五层**一律标【推导】**。

**升级版拆解顺序**（第 04 章起用这个）：

```
 ① A：我感受到什么？用八种乐趣命名，标出主乐趣
 ② D：玩家实际怎么玩？形成了什么策略？涌现出什么？
 ③ M：哪些规则支撑了 ②？逐条列，只写事实
 ④ 反查：M 里哪一条最关键？删掉它，②和①会怎样？  ← 找"撑着整个 A 层的那一条 M"
 ⑤ 决策：玩家在这里做什么决定？
 ⑥ 意图【推导】：设计者想要什么？删掉这个系统会怎样？
 ⑦ 批评与模式
```

## 3. 动机与乐趣速查

来源：[第 03 章第 3、6、7、8 节](./03-why-players-play.md)。四套词汇一张表，写体验目标时从这里挑词。

| 体系 | 项 | 一句话 / 分组 |
|---|---|---|
| **SDT 三需要**<br>（诊断用） | **自主** Autonomy | 我在做我选的事 |
| | **胜任** Competence | 我做得到，而且在变好 |
| | **关联** Relatedness | 我和别人有真实联系（**小规模**的被看见） |
| **LeBlanc 八种乐趣**<br>（写体验目标用） | Sensation 感官 | 好看好听手感好 |
| | Fantasy 幻想 | 成为别人、身处别处 |
| | Narrative 叙事 | 想知道后来怎样 |
| | Challenge 挑战 | 我能做到（可失败，且失败便宜） |
| | Fellowship 社交 | 和人一起 |
| | Discovery 发现 | 这后面有什么 |
| | Expression 表达 | 让别人看到我的选择 |
| | Submission 服从 | 不想动脑，只想待着（挂机、日常、放置） |
| **Lazzaro 四种乐趣**<br>（配方用） | Hard Fun | 挫败 → 得意（fiero）：高难关、攻城 |
| | Easy Fun | 好奇、探索、摆弄：闲逛、装扮 |
| | Serious Fun | 放松、秩序、发泄 |
| | People Fun | 和人有关的情绪：开黑、看人翻车 |
| **Quantic Foundry**<br>**十二动机**<br>（取舍用） | 六组十二项 | Action（Destruction 破坏 / Excitement 刺激）、Social（Competition 竞争 / Community 社群）、Mastery（Challenge 挑战 / Strategy 策略）、Achievement（Completion 完成度 / Power 强大）、Immersion（Fantasy 幻想 / Story 故事）、Creativity（Design 设计 / Discovery 探索） |

**分工**：SDT 是**机制**（用来诊断为什么上瘾或疲惫），另外三套是**分类学**（命名与取舍）。写案子挑**一个主要动机 + 最多两个次要**；评审时反问"它落在哪几行"——落不到任何一行的系统大概率不该存在，落到五六行的说明职责不清。

**三个需要最容易坏在哪**：自主坏在清单化与红点驱动（"像上班"），胜任坏在数值碾压与全自动（"挂机就行"），关联坏在公会只是领奖处（"公会就是个群"）。

## 4. 透镜精选

来源：[第 04 章第 7.2 节](./04-mda-and-lenses.md)，出自 Jesse Schell《The Art of Game Design》。**每个透镜是一组问题，不是一组答案。**

| 透镜 | 它问什么 |
| --- | --- |
| **本质体验** Essential Experience | 我想给的本质体验是什么？哪些部分在支持它、哪些在削弱它 |
| **问题陈述** Problem Statement | 我到底在解决什么问题？当成问题而不是功能会怎么描述 |
| **玩具** The Toy | 拿掉所有目标和奖励，还有人愿意摆弄吗 |
| **好奇心** Curiosity | 玩家脑子里现在有什么问题？怎么让他更想知道答案 |
| **有意义的选择** Meaningful Choices | 选择有意义吗？有没有一个选项永远是对的 |
| **三角权衡** Triangularity | 能不能在低风险低回报与高风险高回报之间选 |
| **反馈** Feedback | 玩家任意时刻知道自己做得怎样吗？信息早了还是晚了 |
| **可见进度** Visible Progress | 玩家看得到自己在进步吗？频率够吗 |
| **优雅** Elegance | 每个元素承担几个作用？能用更少的元素做到吗 |
| **间接控制** Indirect Control | 怎么不剥夺自由感又让玩家走向我要的方向 |
| **兴趣曲线** Interest Curve | 兴趣随时间画出来长什么样？开头抓人吗？中间塌了吗 |
| **恶意破坏** Griefing | 玩家能用它恶心别人吗？能不劳而获吗 |
| **内生价值** Endogenous Value | 玩家真在乎这个资源吗？它换得到他想要的东西吗 |
| **公平** Fairness | 玩家**觉得**公平吗（不是"是不是"） |

**三条纪律**：① **一次只用三个**——新系统用「本质体验 + 问题陈述 + 玩具」，评审用「本质体验 + 有意义的选择 + 恶意破坏」，砍功能用「本质体验 + 优雅」。② 用在提交**之前**。③ 它给的是问题不是标准，答"各有必要"也合格，**只要你真的回答过**。

## 5. 决策诊断表

来源：[第 05 章第 4、8 节](./05-decisions.md)。**评审任何系统时，把它的每个决策点扔进这张表过一遍。**

四条判据**都要成立**：① 没有明显最优解 ② 后果可感知 ③ 与当前目标相关 ④ 有取舍。隐藏前提是**玩家必须理解规则**，否则再深的决策对他也只是抛硬币。判据 ① 的用法：问"什么情况下另一个选项会更好"——答得出来是好决策，答"没有那种情况"是最优解问题，答"都一样"是等价选项。

| 病症 | 症状 | 坏的是哪个构件 | 修法 |
|---|---|---|---|
| **有最优解** | 选择高度一致；论坛有"必选 X"共识；抄作业文化 | 权衡 | 让选项在不同情境下各有优势；给强选项加代价 |
| **无信息** | 选完说不出理由；乱点；要求"给个推荐" | 信息 | 补预览 / 试用 / 对比；或承认它是抽签 |
| **无后果** | 选完记不住自己选了什么；奖励进入巨大的池子 | 后果 | 让结果立刻可见；提高结果占比；加入不可逆 |
| **无关目标** | 跳过、点默认、"这有什么用" | 目标相关性 | 接到玩家真正在乎的东西上；或删掉这个系统 |
| **假选项** | 选项灰着、需付费才能选、选了被系统纠正 | 选项 | 要么让它真可选，要么别显示 |

**"假选项"是手游高频错误**，最隐蔽的变体是把"付费才能选"伪装成设计深度：灰掉的选项持续提醒玩家"你是个穷玩家"，这不是付费驱动，是流失驱动。

## 6. 反馈回路速查

来源：[第 06 章第 3~5 节](./06-systems-and-emergence.md)。数值面见 [game-numeric 第 03 章](../game-numeric/03-resource-flow.md)。

| | **正反馈**（越好，变好越快） | **负反馈**（越好，变好越慢） |
|---|---|---|
| 给的体验 | 成长感 / 复利快感；早期决策变重要；"势"与戏剧性；缩短游戏时长 | 追赶的希望；维持悬念；保护弱势生态位；自动稳定 |
| 失控时 | 数字通胀、一步错满盘输、胜负中途已定；**手游里加速把玩家推到天花板** | 努力失去意义、拖沓无高潮、大 R 觉得充值没用 |
| 最优雅的形态 | —— | **按比例的损耗**（不设硬上限也自动收敛，玩家不觉得被针对） |

1. **看到正反馈，第一反应必须是"它的刹车在哪"。** 买断制有终局，正反馈是必要引擎；手游跑三年，不加限制会让玩家第 30 天就吃干抹净。三种刹车：指数成本、时间门、内容门。
2. **健康的系统 = 一条强正反馈 + 两三条负反馈。** 评审时要能在一张图上同时指出引擎和刹车：只有引擎的两周炸，只有刹车的两个月流失。
3. **延迟这个旋钮被低估。** 绕一圈要三天的回路，玩家归因不到三天前的决定，对他等于不存在；解法通常是**把回路显式化**而不是缩短延迟。

## 7. 循环图画法与三层循环

来源：[第 07 章第 3、4 节](./07-loops.md)。**全课统一规范，写案子和实战都用它。**

```
  [ 动作 ]      玩家主动做的事（动词）
  《 反馈 》     游戏给的即时回应（看到 / 听到什么）
  【 资源 】     积累下来的东西（数值、进度、解锁）
  < 闸门 >      限制条件（体力、CD、次数、等级、付费）
  ○            外部输入（时间恢复、运营活动），从圈外指进来
```

**三条纪律**：① **必须闭合**（不闭合说明玩家做完之后没有理由再做一次）② **每条边写清楚传递了什么**（光秃秃的箭头等于没画）③ **闸门必须画出来**（没有闸门的循环图画的一定是买断制）。**读图三步**：先找闸门 → 再找真决策（**找不到决策点的循环是纯劳动**）→ 看闭合。

| 层 | 时间尺度 | 玩家的问题 | 主要闸门 | 失败的表现 |
|---|---|---|---|---|
| **L1** 单局 | 30 秒 ~ 10 分钟 | 这一局怎么打 | 局内资源（能量、费用、回合） | 战斗无聊、必须开自动 |
| **L2** 日循环 | 一天 | 今天上线做什么 | 体力、每日次数、CD、签到 | 打工感、只领奖不玩 |
| **L3** 长线 | 一周 ~ 赛季 | 这个月的目标是什么 | 赛季、活动排期、材料稀缺 | "练满了不知道干嘛" |

**大部分"不好玩"的问题在层与层的接口上，不在某一层内部**：

| 接口 | 断了会怎样 |
|---|---|
| L3 → L2 目标 | 每天做日常但不知道图什么 → **打工感的第一来源** |
| L2 → L3 进度（要**可见**） | 看不到自己在接近目标 → 遥遥无期 → 弃坑 |
| L2 → L1 资源与情境 | 每局都一样 → L1 变成纯重复 |
| L1 → L2 产出 | 打了没用 → **玩家立刻开自动** |
| **隐藏接口：L2 的养成必须改变 L1 的体验** | 只有伤害数字变大而过程一样 → 养成动力靠数字硬撑 |

经验法则【行业口径】：相邻两层的尺度差 **10~50 倍**比较舒服，差太多中间是空的——"周任务"就是填这个空隙的。五种停止原因里只有"挫败 / 疲劳"是坏的（**区别不在什么时候关掉游戏，在关掉时的情绪**），五种回归动机里"未完成的进度"最健康（[5.2、5.3 节](./07-loops.md)）。

## 8. 奖励分类学

来源：[第 08 章第 2、5、9 节](./08-goals-progression-rewards.md)。

**目标四层**（先查断层）：即时 / 短期 / 中期 / 长期，空缺症状依次是"没什么可操作的""领完就退了""不知道该练谁""已经毕业了"。**低层目标的完成必须能推动高层目标。**

| 类别 | 满足什么动机 | 能否付费替代 | 贬值速度 |
| --- | --- | --- | --- |
| **内容**（新关卡 / 角色 / 剧情） | 发现、好奇、叙事 | 部分 | **最慢**（但产能最贵） |
| **能力**（新动作 / 新可能性） | 胜任 + 自主 | 通常不可 | 慢（会影响平衡） |
| **资源**（金币 / 材料 / 券） | 进度感 | **完全可以** | **最快** |
| **装饰**（皮肤 / 称号 / 家园） | 表达、审美 | 完全可以 | 中 |
| **社交地位**（排行 / 稀有展示） | 关联 + 社会证明 | 间接 | 慢，**依赖稀缺性** |
| **信息**（地图揭示 / 弱点 / 概率公示） | 发现 + 改善后续决策 | 一般不可 | **几乎不贬值** |

**四条结论**：① **能被付费完全替代的奖励，作为"努力的回报"时价值会被削弱**【行业口径】——所以付费深的游戏里，成就感必须由内容 / 能力 / 装饰 / 地位来撑。② 装饰奖励的前提是**可被看见**。③ 社交地位奖励**宁可少发，不可通胀**。④ **重要关卡的奖励里必须至少有一条非资源奖励**。

**奖励坏味道**：奖励贬值 / 奖励疲劳（领完连内容都不看）/ **奖励替代了乐趣**（"这玩法我不喜欢但奖励好所以刷"）/ 虚假进度（进度条动了但没有可感知的后果）/ 目标断层 / 用奖励卡付费 / 补偿式奖励（训练玩家把"闹"当产出手段）/ 奖励通胀（正确做法是换类型不是加量）。

> **给一个玩法加奖励之前，先问它在没有奖励的时候有没有人玩。有人玩，奖励是加速器；没人玩，奖励只是雇佣。**

## 9. 卡点诊断与随机分类

### 9.1 "考试还是墙"（[第 09 章 7.1、7.2 节](./09-challenge-difficulty-skill.md)）

| 维度 | **考试** | **墙** |
|---|---|---|
| 玩家能做什么 | 有多条明确、可行动的路径 | 只能等，或只能付费 |
| 失败的信息量 | **高**：知道自己差在哪 | **低**：只知道"打不过" |
| 跨越所需时间 | 几小时到一两天 | 几天到几周 |
| 情绪 / 留存 | "我知道该干什么了"；正 | "这游戏在逼我充钱"；负，是流失点 |

**区别不在难度，在四个要素**：① **可归因**（"前排在第 40 秒被击破" ≫ "挑战失败"）② **出路不止一条**——**只有一条出路的卡点等于墙**，这反过来要求养成线足够多样 ③ **距离可估算**（估不出来，玩家会按最坏情况脑补然后放弃）④ **卡点旁边**要放替代进度、缺什么就给产出入口、低门槛成功体验、社交出口；**不该放的是失败后立刻弹"充值即可通过"**。

### 9.2 输入随机 vs 输出随机（[第 10 章 3~5 节](./10-randomness.md)）

| 维度 | **输入随机**（在决策**之前**） | **输出随机**（在决策**之后**） |
|---|---|---|
| 一句话 | 洗牌决定你拿到什么牌 | 掷骰决定你打不打得中 |
| 玩家的角色 | **应变者** | **赌徒** |
| 技能表达 / 可复盘性 | **强 / 高** | 弱 / 低 |
| 挫败的形态 | "开局太差"（可接受） | "我明明做对了却输了"（最难接受） |
| 戏剧性 | 中 | **高** |
| 与惩罚的关系 | 可归因 → 惩罚可以重 | 不可归因 → **惩罚必须轻** |

> **随机越靠近决策的"后面"，玩家越难通过技能改善结果，也越难接受失败。**

**但输出随机不是坏东西**：只有它能制造"最后 1% 血翻盘"、压缩技能差距、让重试有意义。正确做法不是消灭它，而是**知道每个位置用的是哪一种、为什么**。三种改造手法：**随机出选项让玩家选**（总量不变，玩家从赌徒变决策者）、**加下界**（有下界的是"惊喜"，没下界的是"风险"）、**过程可见**（不改数学，改信任）。

**四种作用**：多样性、削弱最优解、戏剧性、公平感。每一种都要问"**有没有非随机手段能达到同样效果**"。最常见的滥用是**用随机掩盖数值差距**。

**让随机"感觉公平"的七种手法**：受控随机（袋式随机、递增概率 PRD，注意不是 PRNG 意义上的伪随机数）/ 保底 / 概率公示 / **进度可见** / 补偿式产出 / 结果分层 / 过程可见（几乎无代价，应默认做）。"进度可见"把概率问题重述成进度问题，玩家从"赌"切到"推进度条"，底层数学一点没变。

**三条准则**：有可预期的下界 / 随机导致的失败惩罚必须低 / **随机可以决定"玩得多好"，不能决定"能不能玩"**。

## 10. "感觉不好"诊断表

来源：[第 13 章第 3、7 节](./13-game-feel-and-feedback.md)。有人（包括你自己）说"这个操作感觉不对"时，**从 1 号往下查，不要跳**。

| # | 症状 | 可能的原因 | 修改方向 |
| --- | --- | --- | --- |
| 1 | **迟钝**："我点了它才动" | 输入到响应有延迟 | **本地预表现**；缩短启动帧 |
| 2 | **粘滞**："操作完了还要等" | 后摇过长且不可打断 | 加可取消窗口；缩短后摇 |
| 3 | **飘**："像打在空气上" | 缺顿帧、击退、受击反馈 | 加顿帧、闪白、位移 |
| 4 | **无反馈**："不知道点上没有" | 缺功能反馈 | 补按下态、音效、状态变化 |
| 5 | **反馈错位** | 音画不同步；特效与判定点不一致 | 对齐时间轴；跳字放在命中点 |
| 6 | **反馈过量**："眼花" | 特效失控、音效无优先级 | 建强度分级与抢占规则 |
| 7 | **不可归因**："不知道为什么输" | 缺信息反馈 | 战报、伤害构成、关键时刻 |
| 8 | **重复疲劳**："第一百次烦" | 高频动作用了高规格演出 | 降规格；加跳过 / 倍速 |
| 9 | **判定与视觉不符** | 判定框与特效不匹配 | 对齐，**通常让判定迁就视觉** |

**为什么不能跳着查**：1、2 属实时控制层，3、9 属模拟空间层，4~8 才是润色层。**在实时控制有问题的时候去调特效，是这方面最常见的浪费。**

**反馈的三层**：功能（缺了会重复点击）/ 情绪（缺了动作变成劳动）/ 信息（缺了归因给运气）。**缺信息反馈是手游最被低估的问题**：自动战斗打完只显示"失败"，玩家唯一能做的就是去充值——**这会把策略游戏退化成数值游戏**。Juice 清单见 [13 章 4.1 节](./13-game-feel-and-feedback.md)，纪律是**juice 是放大器不是发生器**。

## 11. 系统七面、耦合矩阵与系统坏味道

来源：[第 15 章第 3、8、9 节](./15-system-design-method.md)。模板：[system-spec.md](./templates/system-spec.md)。

| # | 面 | 回答的问题 | 最常见的遗漏 |
|---|---|---|---|
| 一 | **目标** | 为什么要有这个系统 | 只写业务目标不写体验目标；不写"删掉会怎样" |
| 二 | **参与者** | 谁在这里有位置 | 只写"玩家"，漏掉组织、系统自动化、运营 GM |
| 三 | **资源与状态** | 有什么东西、存在哪、归谁 | 可见性、归属与生命周期 |
| 四 | **规则** | 什么条件下发生什么 | 只写"能做什么"，不写约束与禁止 |
| 五 | **输入 / 输出** | 从哪拿、往哪送 | 只写产出不写消耗；漏掉送出去的影响 |
| 六 | **边界与异常** | 不能做什么、出错怎么办 | 并发、跨天、掉线、回滚、人满、重复 |
| 七 | **接口** | 改一条规则会影响谁 | **体验耦合** |

**四种耦合**（发现难度和改动代价递增）：**D 数据**（A 读 B 的数据，如公会读战力）→ **E 事件**（A 触发 B，如任务完成发邮件）→ **R 资源**（共享资源池，如两个商店卖同一种材料，改一处动全局经济）→ **X 体验**（玩家在 A 的体验依赖 B 的存在，如公会协作依赖聊天频道、归属感依赖头部玩家不能包办一切）。

**X 体验耦合是系统策划的专业价值所在**：前三种程序会发现，第四种**没有代码痕迹**，只有从体验目标出发的人才能发现，而它出问题时改的是整个设计。接口表"改动影响"写成"无影响"的，说明没想过。三个用法：改动影响评估 / 砍功能的连锁评估（**真正成本在矩阵里**）/ 排期顺序。**耦合超过 8 项的系统，大概率承担了太多职责。**

**系统坏味道**（写完自查）：① 体验目标写成"提升留存 / 付费" ② 玩家没有真正的决定 ③ 字段没写可见性 / 归属 / 生命周期 ④ 出现"应该""参考 XX 游戏" ⑤ 没有人满 / 重复 / 掉线 ⑥ 一个系统服务三个以上体验目标 ⑦ 接口表"改动影响"全是"无影响" ⑧ 用新系统救老系统的问题 ⑨ 所有奖励汇入同一个资源池 ⑩ 时间规则没写刷新点 / 时区 ⑪ 权限是"会长可以做一切" ⑫ 没有不做清单 ⑬ 用数字替代规则 ⑭ 入口在三层菜单下却假设玩家天天来 ⑮ **每条规则都自洽，但说不出哪条服务于体验目标**。

**第 ⑮ 条是终极检查**：能对每条规则说出"它服务于体验目标里的哪个词"，这份案子就是可评审、可取舍、可改的；做不到，它只是一堆功能。

## 12. 文档家族与文档坏味道

来源：[第 16 章第 4、12 节](./16-design-docs.md)。

| 文档 | 篇幅【行业口径】 | 回答什么 | 失效的信号 |
| --- | --- | --- | --- |
| **一页纸概念** | 1 页，≤600 字 + **1 张图** | 要不要做 | 写到第二页 |
| **概念案** | 1500~3000 字 | 多大、风险在哪 | 开始写字段和边界 |
| **系统案** | 5000~15000 字 | 具体怎么做 | 出现"应该""一般" |
| **关卡案** | 每关 300~1500 字 + 图 | 空间、节奏、教什么 | 只有敌人表没有节奏 |
| **活动案** | 1000~3000 字 | 规则、奖励结构、时间 | 复制粘贴，时间没改 |
| **配置表** | —— | 数字是多少 | 表里出现了规则 |
| **变更记录** | 每条 1~3 行 | 改了什么、为什么、影响谁 | 只写"优化体验" |
| **评审记录** | 500~1500 字 | 结论、谁何时做什么 | 只有"讨论了 XX" |

**最容易搞混的两条**：① **一页纸和系统案不是简繁关系，是不同问题**——前者回答"要不要做"，后者回答"怎么做"。② **系统案从第 3 步一直活到下线**，"文档与实现分叉"就是这根长条断掉了。

**文档坏味道**（写完自查，也用来批注别人的案子）：

1. **"应该""原则上"**——决定没做完，程序会自己定。
2. **"一般来说""通常"**——规则里没有"一般"，这词出现处要么是参数要么是没想清的例外。
3. **"参考 XX 游戏"**——抄的是"是什么"不是"为什么"，而且各人心里的《XX》不是同一版本。
4. **只有流程没有规则**——没有校验和失败分支，程序只能写出 happy path。
5. **没有不做清单**——三个月后一定有人重提已否掉的东西。
6. **没有成功标准**——上线后无法判断对错，复盘只能讲故事。
7. **没有埋点**——没埋点 = 没有反馈回路 = 这个设计永远不会被改对。
8. **数字和体验要求混写**——改一个数要改两处，体验要求又模糊到无法指导数值。
9. **形容词做判据**（"战力较高的"）——翻译成阈值的人是程序，设计权就此转移。
10. **同一条规则写两遍**——只会改一处，案子自相矛盾。
11. **用界面代替规则**——换个入口规则就不存在了。
12. **时间没有基准**（"每天 0 点"）——谁的 0 点？跨时区算谁的？
13. **只有正常流程没有异常**——边界是设计决定，不写程序会选最好实现的那个。
14. **TODO 没有责任人和时限**——它会静静地待到提测那天。
15. **把决定写成选项**——把设计权交给了实现成本。

**第 15 条最隐蔽**，因为它看起来很谦虚——但上游给你的接口文档要是写着"这个字段可以是 string 也可以是 int，你看着办"，你不会觉得他谦虚。

## 13. 引导与 UX 坏味道

**要教的四层**（[第 18 章第 2 节](./18-onboarding.md)）：**控制**（唯一必须强制的，预算三十秒）→ **规则**（情境教学）→ **策略**（**不该"教"，该用关卡"逼"**）→ **元游戏**（靠社区）。**大多数手游的问题是把这四条线全压缩到了前 15 分钟。**

| 引导坏味道（[第 18 章第 10 节](./18-onboarding.md)） | 后果 |
|---|---|
| **一口气教完** | 什么都没记住；第二天面对满屏红点不知所措 |
| **教了不用**（教完三天后才能用） | 白教一遍，还占了认知预算 |
| **点点点**（全程只有一处能点） | 完成率 100%，理解率 20%；玩家进入"找亮处点"模式 |
| **遮罩地狱** | 全程没有自主感 |
| **文字墙** | 没人读。规则该放在可选引导里 |
| **假选择** | 玩家对之后所有选择的信任度下降 |
| **必胜教学关** | **学不到东西**。教学关应"能输，但输了没有代价" |
| **把付费塞进引导** | 极低的首充率，代价是次留和口碑 |
| **无法中断与恢复** | 直接流失（案子没写边界导致的） |
| **没有埋点** | 知道流失率，不知道流失在第几步 |

**引导埋点最小集**：`guide_step_enter` / `_finish` / `_retry` / `guide_abort` / `guide_skip`——有了这五个，引导优化就从"讨论哪里有问题"变成"看漏斗，最陡的先改"。

**五个认知约束**（[第 19 章 2.1 节](./19-ux.md)）：感知（**你以为玩家看到了，其实没有**）/ 注意力（变化盲视）/ 记忆（**识别优于回忆**）/ 动机 / 情绪（**挫败时一个小卡顿会被当成"这游戏真烂"**）。

> **设计者对自己的界面永远是"知道答案的人"，所以永远无法判断它好不好用。**

| UX 反面案例（[第 19 章第 10 节](./19-ux.md)） | 修法 |
|---|---|
| **弹窗轰炸** | 登录弹窗上限 2 个；建跨系统的优先级规范 |
| **入口过深** | 画信息架构图，做频率 × 重要性分级 |
| **图标无法识别** | 去掉文字自测；让图标在**形状轮廓**上有差异 |
| **状态不可见** | 每个入口显示进度（3/5）而不只是名字 |
| **反馈延迟或缺失** | 点击 100ms 内必须有可见反馈；请求期间置灰 |
| **破坏性操作无确认** | 二次确认 + 显示"将失去什么" |
| **数字没有量级** | 按量级格式化，全游戏统一 |
| **极值没设计** | 需求必须写**空状态、极值、加载中、错误态** |
| **多入口行为不一致** | 收敛入口；确需多入口的行为必须一致 |
| **返回路径不一致** | 返回永远回上一级；回主界面用独立按钮 |

**这份清单里有七条是"没有全局负责人"造成的**：弹窗预算、导航规范、图标规范、数字格式，单看都简单，没人负责就一定失控。**红点三条判据**（须同时满足）：玩家一定想处理、成本低、处理后一定消失。

## 14. 付费动机与黑暗模式

来源：[第 21 章第 3、4、6 节](./21-monetization-design.md)。数字面见 [game-numeric 12/13/14](../game-numeric/12-monetization-structure.md)。**一条原则：付费点是体验的延伸，不是拦路。**

| 动机 | 玩家心里的话 | 设计要点 / 风险 |
| --- | --- | --- |
| **省时间**<br>扫荡券、加速、离线收益 | "我知道怎么打，只是不想再打一遍" | 卖的必须是**已被证明掌握**的重复劳动；卖太多等于承认玩法无聊 |
| **变强**<br>抽卡、装备、战力包 | "我想赢 / 我想过这一关" | 强度差异**在什么场合被感知** |
| **表达**<br>皮肤、时装、家园 | "我想让我的角色是我的" | 前提是**有人看得见** |
| **社交地位**<br>榜单、限定标识 | "我想让别人知道我是谁" | 地位必须**稀缺**且路径公开 |
| **收集**<br>图鉴、碎片兑换 | "我要集齐" | 收集的**边界**要可见，否则没有完成感 |
| **便利**<br>免广告、多队列、跳过 | "我不想被琐事烦" | 先问：这个不便**为什么存在** |
| **支持 / 情感**<br>订阅、支持包 | "这游戏值这个钱" | 需要可辨识的团队关系；规模有限 |

**判断顺序**：最强烈的动机是哪种（**往往不是"变强"**）→ 对应形态已经有了吗（**有就复用，不要新开付费类目**）→ 会蚕食已有形态吗 → 延伸还是拦路 → 不付费的玩家还有事做吗。

**pay-to-win 连续谱**：纯装饰 → 便利 → 时间加速 → 内容解锁 → 概率提升 → 强度上限 → 直接买战力；你的工作是知道该站在哪一格、为什么。**p2w 的痛感不来自"付费能变强"，而来自"我的失败是因为别人付费"。**

**黑暗模式清单**：虚假稀缺 / 币中币 / 零头设计 / 误触陷阱 / 痛点定向推送 / 沉没成本收割 / 社交压迫 / 逃逸困难 / 隐藏或嵌套概率。

> **自检：如果把这个机制的完整规则，用一句人话写在按钮的正上方，玩家还会买吗？**

必须靠隐藏信息才能促成购买的，就是黑暗模式。这个自检把伦理问题转成了**信息完整性**问题，而后者是评审会上可以讨论的具体条款。分界线：**信息真实且完整 = 商业设计；信息缺失或情绪操纵 = 黑暗模式。**

## 15. 活动类型学

来源：[第 22 章第 2、3 节](./22-live-ops-design.md)。模板：[event-spec.md](./templates/event-spec.md)。

**玩家生命周期六阶段**（**同时在线，玩同一个游戏**）：新手 D0~D7 / 成长 D7~D30 / 成熟 D30+ / 疲劳 / 流失 / 回流。每个系统都要问"这六种人看到它各是什么样"；**"疲劳"是设计问题不是玩家问题**，对抗它要给新模式去学，**加日常是最错误的应对**；回流的核心是**降低回归成本**。

| 类型 | 设计的核心问题 | 典型事故 |
| --- | --- | --- |
| **累计型** | **档位定在哪，就是在要求玩家做多少** | 最高档远高于自然产出 → 变付费墙 |
| **排行型** | **分组**。不分组则只有头部参与 | 跨服大榜让 99% 的人第一天放弃 |
| **收集型** | **最后一片的获取路径** | 人人差一片，只能付费补 |
| **限时玩法型** | **学习成本 vs 存续时间** | 教三天玩五天；难热修 |
| **回流型** | **不能让在线玩家觉得亏** | 老玩家挂机等回流资格 |
| **付费型** | **会不会破坏常驻付费的锚点** | 折扣比首充狠，之后礼包卖不动 |
| **联动型** | **版权期限与永久保留的冲突** | 下架后图鉴空洞、资产失效 |

三条推论：**累计型的第三档定在哪，决定了活动在玩家心里是"福利"还是"逼氪"**；**排行型更好的做法是把"排名"换成"达标"**（达标的人拿一样的奖，头部额外加奖）；**限时玩法应该复用**（每赛季回归一次）。

## 16. 品类设计清单索引

这些清单是**动笔写案子之前必须先有答案的问题**，不是事后检查。

- **SLG**：[第 23 章第 11 节](./23-genre-slg.md) —— 路线（战斗次数能不能买 / 成长有没有终点 / 领地是否连通 / 同盟规模 / 免费玩家的生态位）、空间、时间、组织、战争与终局。
- **卡牌 / RPG 养成**：[第 24 章第 11 节](./24-genre-card-rpg.md) —— 角色（机制位 / 代价 / 叙事身份 / 养成成本 / 进哪个池 / 会废掉谁 / 一年后还有位置吗）、阵容与深度、抽卡与获取、养成线、关卡与 PvP。
- **开放世界 / 叙事 / Roguelike**：[第 25 章第 12 节](./25-genre-openworld-narrative-roguelike.md) —— 开放世界（引力点 / 四层内容比例 / 能否自产目标）、叙事驱动（选择系统的成本 / 后果是"实现"还是"提及" / ludonarrative 一致性）、Roguelike（run 长度与元进度配对 / 三段弧线 / 构筑有没有减法）。
- **三者共同**：**可感知的因果**（能说出"因为我做了 X，所以 Y"吗）、**不可撤销性**（选择有代价吗）、**可讲述性**（能用一句话讲给别人听吗）。

## 17. 评审三层与设计谬误

来源：[第 26 章第 2、4、6 节](./26-design-critique.md)。模板：[review-checklist.md](./templates/review-checklist.md)。

| 层 | 问什么（判断依据） | 不过的后果 |
|---|---|---|
| **一：目标** | 为什么做、给什么体验、在哪条循环上、删了会怎样、怎么算成功（依据：设计支柱、循环图、数据） | **直接打回，下面两层不看** |
| **二：系统** | 决策有没有意思、反馈回路、接口、生命周期、付费与社交（依据：第 05~11 章的词汇） | 打回或大改，规格不看 |
| **三：规格** | 歧义、边界、数值接口、资源量、埋点、不做什么（依据：**两个程序读了会不会实现出同一个东西**） | 修改后通过 |

**只有第三层的问题才配得上"修改后通过"。** 90 分钟的时间盒：复述 5 / 第一层 15（**放不完必须散会**）/ 第二层 45 / 第三层 15 / 结论 10（**不许以"再改改"结束**）。**倒着评审的团队症状固定**：会议很长、结论都是"再改改"、同一个案子评三五次而每次都在改细节。

**一条 critique 的四步**：复述目标 → 指出层级 → 说出后果（把"我的判断"变成"可被检验的预测"）→ 替代或免责；最后一步**"我没有替代方案，只是提示风险"也是合法的**。

| # | 设计谬误 | 当场可执行的检验动作 |
|---|---|---|
| 1 | **more is better** | "加了这条线之后，玩家每天多做的那个决定是什么？" |
| 2 | **抄而不解** | "原作里这条规则解决了什么问题？我们有这个问题吗？" |
| 3 | **为系统而系统** | 沿"它服务于谁"追问三次，追不到玩家体验就是自循环 |
| 4 | **feature creep** | 对比每次评审后的页数与功能数；用支柱否决 |
| 5 | **把问题推给数值** | "参数调到极端两端，体验会是两种不同的东西吗？"会 → 设计决定 |
| 6 | **以己度人** | "身边有几个不做游戏的人试过？他第一次花多久搞明白？" |
| 7 | **"玩家会懂的"** | "玩家是在哪个界面、哪一秒学会这条规则的？" |
| 8 | **用付费掩盖设计问题** | "如果这个道具不能卖钱，我们还会这样设计吗？" |
| 9 | **"上线再调"** | "上线后哪个数据会让我们决定砍掉它？谁有权砍？" |
| 10 | **把复杂当深度** | "玩家做的决定，有没有一个不依赖攻略的正确答案？"有 → 复杂而不深 |
| 11 | **把新鲜当好玩** | "玩家玩第 20 次的时候脑子里在想什么？" |
| 12 | **只看成功案例** | "有没有做了同样设计却失败的产品？怎么解释差别？" |
| 13 | **把玩家的方案当成需求** | 把方案翻译回问题："他为什么想要一键扫荡？" |
| 14 | **"加个引导就好了"** | "引导教完之后，玩家能自己推导出第二步吗？"不能 → 是设计问题 |

复杂度 = 规则和状态的数量；深度 = 有意义决策的数量。**两者可以完全无关。**

## 18. 设计支柱与立项文档

来源：[第 27 章第 3 节](./27-lead-designer.md)、[第 28 章第 8 节](./28-pitching-and-greenlight.md)。

**好支柱的三个特征**：① **可以用来否决**（唯一的硬标准，测试方法是**为每条写出一个"它会否决掉的、看起来不错的功能"，写不出来就删**）② **互相有张力**（彼此毫无冲突说明它们都太软）③ **3~5 条**（使用场景是会议中间的三十秒，不是文档）。

**五种坏支柱与改法**："好玩"（不可否决 → 说清是哪种好玩）、"画面精美"（品质要求不是设计决定 → 改成"战斗必须在静帧截图里就能看懂"这类可否决形式）、"留存和付费都要好"（业务目标不是支柱 → 写成"我们靠什么留住人"）、"既硬核又休闲"（张力没被承认 → 写成"上手三分钟，精通三百小时"）、"对标《XX》并超越"（会让团队抄机制而非意图 → 写清要它哪部分、**不要**哪部分）。

好用的句式是 **"我们是 X，不是 Y"**——强制写出 Y 就能逼出否决力。**支柱是全局的，一页纸的体验目标是支柱在一个具体系统上的投影**，所以一页纸进评审第一层时必须回答"它服务于哪条支柱？**它和哪条支柱有张力？**"——第二问更重要。

**立项文档十节与判据**（判据 = 什么样算写好了）：

| 节 | 判据 |
|---|---|
| 1 一句话 | 不了解项目的人读完能复述，并说出这句话**排除了什么** |
| 2 目标用户 | 写行为不写人口统计：指出他在玩的那款产品和那个具体时刻 |
| 3 核心体验 | **它是一个时刻，不是一个形容词** |
| 4 核心循环图 | 必须是图；每个箭头有触发条件，能看出一次会话走了哪一段 |
| 5 设计支柱 | 3~5 条，每条附"它会否决什么"；写不出否决案例的删掉 |
| 6 差异化 | 核心是那句**可证伪的假设**（设计选择 / 玩家群 / 可观测行为都具体） |
| 7 品类与竞品 | 有品类分析表和品类地图，且有"**我最可能错的一条判断**" |
| 8 风险与验证 | **最高的那条风险，验证成本必须在探索期内**（全文最重要） |
| 9 团队与资源 | 写出了"我们没做过的那一块是什么，打算怎么补" |
| 10 里程碑 | **每个是决策点，不是交付点** |

第 10 条的差别：交付点写"完成战斗系统"，决策点写"完成战斗原型，若盲测 5 人里少于 3 人在卡关后主动换阵容，就回到品类分析重选方向"。**没有决策点的里程碑表，等于承诺"无论发生什么我们都会做完"。**

两条配套工具：**验证阶梯**（[第 28 章第 11 节](./28-pitching-and-greenlight.md)）一句话 → 纸面原型 → 可玩原型 → 垂直切片 → 真人测试，纪律是**一级只回答一级的问题、判据事先写死**；**不做清单**（[第 27 章 4.2 节](./27-lead-designer.md)）记录被否决的提案、理由和**什么条件下会重新讨论**。
