# 12 - 叙事与世界观

> **本章目标**：学完你应该能回答三个问题：一款游戏的"故事"到底由哪几层构成、每一层归谁做；机制和故事互相打架（ludonarrative dissonance）是怎么发生的、怎么在系统设计阶段就避免；以及作为系统策划，你和文案策划之间的接口该怎么定。
> **前置**：[第 02 章](./02-what-is-a-game.md)（游戏与故事的边界）、[第 05 章](./05-decisions.md)（决策的四要素，本章讲"选择与后果"时直接用）、[第 06 章](./06-systems-and-emergence.md)（涌现）。
> **边界**：叙事驱动品类（选择与后果类 AVG、开放世界的叙事密度）的整体设计在 [第 25 章](./25-genre-openworld-narrative-roguelike.md)；关卡里的引导与教学在 [第 17](./17-level-design.md)、[18 章](./18-onboarding.md)。本章讲的是**叙事作为一个设计元素**：它在系统设计里能干什么、不能干什么。

## 1. 开场：一个每天都在发生的矛盾

一款卡牌手游的后台数据大致会呈现这样的组合【行业口径】：主线剧情的跳过率很高，一大半玩家在第一个对话框就点了跳过；但同一批玩家里，有相当一部分会因为"这个角色的故事打动我了"而抽卡、会在角色的语音和档案上停留、会去看同人。

**跳过剧情的人，和为角色付费的人，是同一批人。**

这个现象把这一章要解决的问题直接摆了出来：**玩家跳过的是"剧情文本"，但他消费的是"世界观和角色"。** 这两件事被行话里的"叙事"这个词混为一谈，导致了大量的设计浪费：项目花大钱写了几十万字主线，玩家跳过；同时角色的机制身份和叙事身份对不上，玩家抽到之后觉得"这个人怎么跟剧情里不一样"，付费转化受损。

所以本章的第一个动作是**把"叙事"这个词拆开**。拆开之后你会发现，作为系统策划，你能控制的那几层恰恰是玩家最不跳过的那几层。

## 2. 叙事的四层

把游戏里所有和"故事"沾边的东西分成四层。**这四层的生产成本、被消费的比例、和机制的耦合程度完全不同，必须分开谈。**

下面所有关于"成本"的说法都是**【行业口径】**，而且必须拆成三笔账才有意义：**基础建设成本**（第一次把它立起来：设定、命名体系、美术风格、配音方向）、**边际成本**（在已有地基上多加一份内容）、**返工成本**（做错之后改回来）。同一层在这三笔账上的表现可以完全相反 —— 世界观的边际成本很低，返工成本却是四层里最高的。

```
  ┌─────────────────────────────────────────────────────────┐
  │ 第一层：世界观（setting）                                  │
  │  这是一个什么世界？有什么规则、什么种族、什么冲突、什么美学？   │
  │  生产成本：基建高/边际低 被消费比例：接近全部 与机制耦合：极高  │
  ├─────────────────────────────────────────────────────────┤
  │ 第二层：背景故事（backstory / lore）                        │
  │  这个世界和这些角色在玩家到来之前发生过什么？                  │
  │  生产成本：低   被消费比例：低（爱好者）      与机制耦合：低    │
  ├─────────────────────────────────────────────────────────┤
  │ 第三层：剧情（plot）                                       │
  │  玩家在游戏过程中被讲述的那条线：主线、支线、活动剧情          │
  │  生产成本：极高 被消费比例：中低（跳过率高） 与机制耦合：中     │
  ├─────────────────────────────────────────────────────────┤
  │ 第四层：玩家自己的故事（player story）                       │
  │  玩家玩完之后会讲给别人听的那个故事                          │
  │  生产成本：由系统产出   被消费比例：接近全部 与机制耦合：极高   │
  └─────────────────────────────────────────────────────────┘
```

| 层 | 它是什么 | 谁负责 | 玩家在哪里接触到 | 手游例子 | 买断制对照 |
|---|---|---|---|---|---|
| **世界观** | 世界的设定与规则、视觉语言、名词体系 | 主策 + 文案 + 主美共同定 | **无处不在**：UI 风格、货币叫什么、按钮上的字、角色立绘 | 明日方舟的"源石/感染者/罗德岛"这套名词，出现在几乎每个界面上 | 《黑暗之魂》的世界设定 |
| **背景故事** | 前史、角色档案、图鉴、道具描述 | 文案 | 图鉴、档案、道具说明、可选阅读物 | 角色档案、干员密录、书籍 | 《黑暗之魂》的道具描述 |
| **剧情** | 玩家跟着走的那条叙述线 | 文案 + 关卡 | 主线关卡、过场、活动 | 主线章节、活动剧情 | 《哈迪斯》的逃脱线 |
| **玩家的故事** | 玩家自己经历出来的事件 | **系统策划**（间接） | 战报、失败、逆转、和别人的互动 | SLG 的"我们盟昨晚偷了他们的城" | 《杀戮尖塔》的"我那把无限连爬到心脏" |

### 2.1 第一层：世界观的边际曝光成本最低

**世界观是四层里最难被跳过的一层。** 玩家不看剧情，但他每天都在看你的 UI、点你的按钮、读你的资源名字。（"无法跳过"是程度不是绝对：扫荡、挂机、老玩家的"只看数字"状态都会把这一层的实际曝光压低。）

一个具体的例子：假设你要设计一个"每日恢复的行动力"资源。它可以叫：

| 名字 | 传达的世界观 | 玩家的心理预期 |
|---|---|---|
| 体力 | 我在操作一个人，人会累 | 累了就该休息，恢复是自然的 |
| 理智 | 我在操作一个精神紧绷的指挥官 | 消耗是有代价的，"理智耗尽"暗示某种危险 |
| 行军令 | 我在下达军事命令，命令数量有限 | 这是权力的限制，不是身体的限制 |
| 燃料 | 我在驱动一台机器 | 燃料可以被补给、可以被囤积、可以被抢 |

**同一条规则，四个名字，四种体验。** 这就是世界观层的杠杆：**在已经立起来的世界观地基上，多曝光一次的边际成本很低**（改几个字符串），但它改变了玩家对规则的理解方式。而"玩家如何理解一条规则"直接决定了他对这条规则的接受度。

**但边际成本低不等于这一层便宜。** 这四个名字之所以能"改几个字符串"就生效，前提是背后已经有一套立得住的设定、美术风格和名词体系——那是**基础建设成本**，它不低。而一旦世界观定错要改，**返工成本是四层里最高的**：所有界面文案、立绘、已录制的配音、已做的本地化、已经建立的品牌认知都要跟着动。所以准确的说法是：**世界观是一笔高基建、低边际、极高返工的投资**。这也是 11.3 第一道思考题要问"立项阶段怎么验证世界观"的原因。

**结论：世界观不是文案的私产，是系统策划的工具。** 你设计的每一个系统、每一种资源、每一个按钮，都在往玩家脑子里装世界观。系统案里那一栏"这个资源叫什么"，值得认真填。

### 2.2 第四层：玩家自己的故事是系统策划的产物

问一个问题：玩家在电梯里跟朋友描述一款游戏时，会讲哪一层？

几乎永远是第四层。**"我昨天在率土被人偷了城，结果盟主半夜带人打回来了"** 这种故事，没有一个字是文案写的，全部是系统跑出来的。同样，《杀戮尖塔》玩家会跟你讲他那把牌组，不会跟你讲游戏的背景设定。

第四层故事的三个必要条件（这三条完全是机制问题，不是文案问题）：

| 条件 | 含义 | 缺了会怎样 |
|---|---|---|
| **有可变的过程** | 每次玩的过程不一样（随机、他人、选择的分歧） | 每个人的经历都一样，没什么可讲的 |
| **有可被记住的转折** | 出现意外、逆转、险胜、惨败 | 平淡的成功不构成故事 |
| **玩家有归因权** | 玩家觉得结果是他自己的选择造成的 | 纯运气的结果不会被当成"我的故事"（见 [第 10 章](./10-randomness.md)） |

**这三条对应的都是系统设计动作**：可变性来自随机与他人（第 10、11 章），转折来自难度曲线和失败设计（第 09 章），归因权来自决策的设计（第 05 章）。

所以本章一个反直觉但重要的结论：**作为系统策划，你对游戏叙事最大的贡献不在剧情，在第一层和第四层。** 剧情是文案的活，世界观是你和文案共有的，玩家自己的故事完全是你的活。

## 3. 叙事结构在游戏里会变形

传统叙事结构是给"观众"设计的，游戏的接受者是"玩家"，两者的根本差别是：**观众的时间由作者控制，玩家的时间由玩家控制。** 所有结构上的变形都源于这一条。

### 3.1 三种常用结构

| 结构 | 形态 | 在游戏里的用法 | 问题 |
|---|---|---|---|
| **三幕** | 建置 → 对抗 → 解决 | 最常用的宏观框架：序章/主体/终章 | 第二幕在游戏里会被拉得极长（几十小时），需要内部再分节奏 |
| **英雄之旅** | 平凡世界 → 冒险召唤 → 试炼 → 回归。这是对神话共同结构的归纳，后来被编剧教材大量简化使用 | 天然契合"玩家从菜鸟变强"的成长曲线，所以 RPG 用得极多 | 太熟悉，容易套路化；且它假设一个"完成态"，与长线运营的手游冲突 |
| **起承转合** | 起（引入）→ 承（发展）→ 转（反转）→ 合（收束） | 短单元的结构，四段式非常适合游戏的"一个章节/一个关卡" | 单元之间怎么串起来还需要更大的框架 |

**起承转合值得单独说。** 它原本是文章/诗的结构，但它在游戏设计里的用法远远超出了叙事：[第 17 章](./17-level-design.md) 会讲到任天堂的林田宏一（Koichi Hayashida）2012 年接受 Gamasutra 采访（*The structure of fun: Learning from Super Mario 3D Land's director*）时谈到的做法【实证】——用起承转合编排关卡里的教学（引入新元素 → 变化 → 组合 → 收束）；Mark Brown 的 GMTK 视频是把它普及成"四步关卡设计法"的那个渠道。**它是一个启发式模板，不是硬规则。**

**同一个结构可以同时用在叙事和关卡上，这不是巧合**：两者都在解决同一个问题，即"如何在有限的时间内让接受者理解一个新东西并感到满足"。你在做活动设计、做新系统的开放节奏时，都可以套这个四段式。

### 3.2 游戏对线性结构的三种破坏

| 破坏 | 现象 | 设计上的应对 |
|---|---|---|
| **玩家会停在中间** | 玩家在第二幕玩了 40 小时，把前情忘光了 | 反复重申当前目标（任务日志、NPC 提醒）；把长线拆成一个个自带起承转合的小单元 |
| **玩家会失败** | 剧情写的是"英雄突破重围"，玩家死了 15 次 | 让失败被叙事吸收（见第 8 节的《哈迪斯》）；或者把剧情高潮点的难度调低（【行业口径】常见做法） |
| **玩家会乱序** | 开放世界里玩家可能先遇到第三幕的内容 | 把叙事做成**可乱序的单元**（每个单元自洽），或用区域难度做软性引导 |

**"把长线拆成自带起承转合的小单元"是手游最实用的一条。** 手游玩家的会话是碎的，一个横跨三个月的宏大叙事对他没有意义。**每个活动本身就是一个完整的起承转合**，这是手游叙事的标准单位。

## 4. 作者叙事 vs 玩家叙事

这是本章的核心分类，比"四层"更常用：

| | **作者叙事（embedded）** | **玩家叙事（emergent）** |
|---|---|---|
| 故事从哪来 | 设计者预先写好，玩家去接收 | 系统跑出来，每个人的不一样 |
| 控制力 | 强：情绪节奏、信息释放、高潮点都可控 | 弱：设计者只能设定规则，无法保证发生什么 |
| 生产成本【行业口径】 | **边际成本高、接近线性**：一小时内容要一小时的产能 | **边际成本低**：地基（可玩的规则 + 记录器）建好之后故事由玩家跑出来；但地基本身不便宜，且要长期平衡维护 |
| 重玩价值 | 低（知道结局了） | 高 |
| 手游例子 | 主线章节、活动剧情 | SLG 的战况、竞技场的逆转 |
| 买断制对照 | 《最后生还者》类线性叙事 | EVE 的势力战争、《矮人要塞》的传奇史 |

**两者不是对立，是配比问题。** 每个项目都要明确自己的配比，因为它直接决定内容产能预算：

```
  100% 作者叙事                                  100% 玩家叙事
  ├──────────────┼──────────────┼──────────────┤
  线性剧情游戏      多数卡牌/RPG      多数 SLG      沙盒/模拟
  内容吃完就结束    靠版本更新续命    靠玩家续命    几乎不需要内容更新
  产能压力：极大    产能压力：大      产能压力：小   产能压力：极小
```

**一条实用判据：如果你的项目是长线运营的 F2P，而你的叙事配比偏向左边，那你签下的是一份永远还不完的内容债务。** 每个版本都要产出新剧情，产能一旦跟不上，留存就掉。这也是【推导】为什么大量长线手游的叙事在两三年后明显退化：不是团队变懒了，是内容债务追上来了。

### 4.1 涌现叙事：设计者能做什么

涌现叙事听起来像"随缘"，但它有可设计的成分。以 EVE 和《矮人要塞》这类以涌现叙事著称的作品为例（不引具体演讲，只描述可观察的共性），能提炼出四个条件：

| 条件 | 含义 | 在手游里怎么落地 |
|---|---|---|
| **持久的世界状态** | 玩家的行为留下不可逆的痕迹 | SLG 的地图归属、城池归属；卡牌游戏几乎没有这一条，所以涌现弱 |
| **玩家之间有真实的利害冲突** | 不是分数，是资源、领地、机会的实际争夺 | 排行榜不算（只是分数）；抢地、抢 boss、抢限量资源算 |
| **足够多的可能行动** | 玩家能做的事组合起来空间大 | 单一动作（打）不产生故事，"打/守/骗/结盟/背叛"才产生 |
| **故事能被记录和传播** | 有战报、有日志、有能截图分享的东西 | **这一条最容易被忽略且最便宜**：一份写得好的战报能把一场战斗变成一个可讲的故事 |

**最后一条值得单独强调：涌现叙事需要一个"记录器"。** 一场精彩的攻城战如果结束后只剩一条"你方获胜"的系统消息，那它没有变成故事。战报、录像、赛季总结、年度报告，这些系统的真实作用是**把系统的输出翻译成可被讲述的语言**。这是系统策划的活。

## 5. 环境叙事与"虚构层"

### 5.1 Sylvester 的虚构层与机制层

Tynan Sylvester 在《Designing Games》（中译《体验引擎》）里用了一组很适合工程师的概念【实证】：一个游戏同时存在**机制层**（mechanics：真正在运行的规则和数值）和**虚构层**（fiction：这些规则被包装成的故事和意象）。玩家的体验来自两层的叠加。

**虚构层不是"给机制起个名字"，它是机制状态的可感知、可解释呈现。** 它至少有四类载体：**角色**（谁在做这件事、他是什么立场）、**视听**（立绘、动作、音效、音乐、字体）、**环境**（场景、痕迹、布局）和**情境**（这件事发生在什么时刻、为什么是现在）。命名和文本只是其中最便宜、也最容易被系统策划直接控制的那一部分。

用你熟悉的类比只能说到一半：一段代码叫 `f(x)` 还是叫 `calculateDamage(attacker)`，运行结果一样，但读的人理解成本完全不同。区别在于：代码的读者只要"看懂"，玩家还需要"看到"和"被触动"——所以**虚构层不只降低理解成本，还直接产生情绪**。

虚构层的三个作用：

| 作用 | 说明 | 例子 |
|---|---|---|
| **降低学习成本** | 玩家用现实经验推断规则 | 看到"火"就知道能烧木头；看到"盾"就知道防御。这是[第 18 章](./18-onboarding.md)引导设计的地基 |
| **提供情绪** | 同样的数值，包装不同，情绪不同 | "损失 20% 兵力"vs"你的三千将士没能回来" |
| **让抽象的系统可被记忆** | 人记不住数值表，记得住角色和意象 | 玩家记得"那个奶妈"，记不住"治疗系数 1.4" |

**虚构层最重要的纪律：它必须和机制层指向同一个方向。** 一旦两层打架，玩家会感到别扭，而且通常说不出为什么。这就是下一节。

### 5.2 环境叙事：让空间讲故事

环境叙事（environmental storytelling）指的是**不通过对话或旁白，而通过场景、道具、布局、痕迹让玩家推断出发生过什么**。它是"show, don't tell"在空间上的实现。

它为什么有效，有一个明确的心理机制：**玩家自己推断出来的故事，比被告知的故事记得牢。** 因为推断需要玩家主动参与，参与产生投入。

| 手段 | 例子 | 手游里能不能用 |
|---|---|---|
| 场景痕迹 | 一具尸体旁边的日记、烧毁的村庄 | 能，但成本高（要做场景） |
| 道具描述 | 一件装备的说明文字里藏着一段历史 | **非常能，且极便宜**：这是手游性价比最高的叙事手段 |
| 界面与 UI | UI 本身的风格、字体、音效传达世界的质感 | 能，零额外成本 |
| 角色配置 | 敌人的编成暗示了对方的处境（残兵、精锐） | 能 |
| 空间布局 | 关卡的形状暗示这里曾经是什么 | 有限（手游关卡通常抽象） |

**手游里被严重低估的是"道具描述"这条路径。** 一段 50 字的装备描述，成本几乎为零，可以被反复阅读，而且只有想看的玩家才会看（不打扰跳过党）。《黑暗之魂》系列把这条路径用到了极致，几乎全部背景故事都藏在道具描述里，这是买断制的经典对照。

## 6. Ludonarrative dissonance：机制与叙事的不一致

### 6.1 这个词是怎么来的

Clint Hocking 在 2007 年的一篇博客里针对《生化奇兵》（BioShock）提出了 **ludonarrative dissonance（游戏性与叙事的不协调）** 这个说法【实证：Hocking 的 2007 博客】。他的论点大意是：这款游戏的**故事**在讲一套关于利己主义的批判，但它的**机制**却在奖励玩家去做利己主义的选择，两者传达的价值观互相矛盾，因此玩家在体验上产生了割裂。

这个词后来被泛用到几乎所有"剧情说 A、玩法做 B"的场合。作为设计工具，它最有价值的部分是给了你一个**明确的诊断方向**：

> **当你觉得一个游戏"哪里怪怪的"但说不出原因时，先检查机制在奖励什么，再检查叙事在赞美什么，看两者是不是同一件事。**

### 6.2 手游里的不一致，比买断制严重得多

因为 F2P 的商业化机制天然会往叙事里塞入与叙事无关的动机。常见的几种：

| 不一致类型 | 叙事在说 | 机制在做 | 玩家的感受 |
|---|---|---|---|
| **紧迫感 vs 体力墙** | "快！同伴命在旦夕！" | 体力耗尽，明天再来 | 荒诞；紧迫感被彻底破坏 |
| **角色平等 vs 强度分层** | "每个干员都很重要" | 三星角色在高难关卡完全无法使用 | 叙事被拆穿 |
| **英雄叙事 vs 抽卡** | "他是命中注定的救世主" | 你没抽到他 | 主角不在自己队里 |
| **牺牲叙事 vs 数值保值** | "他为了大家牺牲了" | 但他还在你的仓库里，可以继续培养 | 死亡失重 |
| **反战叙事 vs 战力排行** | "战争没有赢家" | 全服战力榜第一名 | 说一套做一套 |

**注意：这些不一致不一定要修。** 大量成功的手游长期带着这些不一致运行，玩家也接受了（因为他们知道这是手游的惯例）。真正的设计问题是**在哪些地方不一致是致命的**：

**判据：当不一致出现在你希望玩家投入情绪的那个时刻，它就是致命的。**

- 体力墙出现在日常刷本时，玩家无感（那里本来就没情绪）。
- 体力墙出现在主线高潮的最后一场战斗前，是灾难。

【行业口径】所以常见做法是：**主线剧情关不消耗体力，或消耗极低**。这不是发福利，是在保护叙事的完整性。这是一个典型的"叙事需求变成系统规则"的例子，也是本章希望你养成的思维方式。

### 6.3 一致性的四条设计原则

| 原则 | 说明 | 检验方法 |
|---|---|---|
| **机制在奖励什么，玩家就相信什么** | 玩家从奖励结构里读出这个游戏的价值观，而不是从台词里 | 列出你的游戏里收益最高的三种行为，问：它们和你想传达的主题一致吗？ |
| **虚构层不能承诺机制层做不到的事** | 叫"永久盟约"的系统如果三天后自动解散，玩家会觉得被骗 | 逐个检查系统命名和文案，有没有过度承诺 |
| **在情绪高点关闭商业化与打断** | 高潮时刻不弹礼包、不断体力、不插广告 | 走一遍主线，标出所有中断点 |
| **角色的机制身份要能支撑它的叙事身份** | 见第 9 节，这是系统策划与文案的核心接口 | 见 9.2 节的对照表 |

## 7. 选择与后果：分支的代价和"假分支"的技巧

叙事里的"选择"和 [第 05 章](./05-decisions.md) 讲的"有意思的决策"是同一个东西，只是后果发生在故事而不是数值上。它的四要素同样适用：**选项、信息、后果、权衡**。

### 7.1 真分支的成本是指数级的

```
  真分支（每个选择都产生独立后续）        收束式分支（选择影响过程，不影响主干）

        ●                                        ●
       ╱ ╲                                      ╱│╲
      ●   ●                                    ● ● ●
     ╱╲   ╱╲                                    ╲│╱
    ●  ● ●  ●                                    ●
   ╱╲ ╱╲ ╱╲ ╱╲                                  ╱│╲
  ●  ●  ●  ● ...                               ● ● ●
                                                 ╲│╱
  3 个二选一 = 8 条线                              ●
  内容成本 8 倍，玩家只看 1 条              内容成本约 1.5 倍
```

**真分支的经济性极差**：你花了 8 倍的成本生产内容，单个玩家只消费其中 1/8。对买断制的叙事游戏来说这是可以接受的（它换来重玩价值和口碑），对内容产能本就吃紧的手游来说通常不可接受。

### 7.2 "假分支"的四种正当技巧

"假"这个字没有贬义。**玩家要的不是"我的选择改变了世界"，而是"我的选择被看见了"。** 满足后者的成本远低于前者。

| 技巧 | 做法 | 玩家的感受 | 风险 |
|---|---|---|---|
| **收束式分支** | 短期内不同，若干场景后回到主干 | 我的选择有影响 | 收束太快会被看穿 |
| **状态记录 + 后续回响** | 选择不改变剧情走向，但被记住，后面有 NPC 提起 | **我的选择被记住了**，这是最高性价比的手段 | 忘了回响就白做 |
| **表达型选择** | 选项只影响我说话的语气/立场，不影响事件 | 我在扮演我想扮演的角色 | 玩家发现"选什么都一样"会失望 |
| **结局变量** | 过程中的选择累积成变量，只在结局分歧 | 我这一路的选择汇总成了结果 | 变量不可见时玩家不知道自己在积累 |

**"状态记录 + 后续回响"是手游最该用的一种。** 成本：存一个字段，若干章之后加一段对话。收益：玩家会截图发到社区说"它居然记得我三个月前的选择"。这是极高杠杆的设计。

### 7.3 选择设计的三条底线

1. **玩家做选择前必须知道自己在选什么**（哪怕不知道结果）。看不懂选项含义的选择不是选择，是抽奖。
2. **后果必须可感知**（Doug Church 在《Formal Abstract Design Tools》里把"可感知的后果"列为核心工具之一【实证】）。做了选择却看不到任何变化，等于没做。
3. **不要在玩家已经投入情感之后惩罚他的选择**，除非惩罚本身就是主题。手游尤其要小心：玩家会认为"选错了"是设计陷阱，进而怀疑这是逼氪。

## 8. 贯穿案例（上）：《哈迪斯》用死亡循环承载叙事

《哈迪斯》（Hades，Supergiant Games，买断制 Roguelike）是"用系统解决叙事问题"的教科书案例。Supergiant 就这款游戏的早期访问（Early Access）开发方式与叙事系统做过多场公开分享【实证：Supergiant 的 GDC 分享与公开访谈】，具体标题不在这里编造，建议自己去找来看。以下机制描述来自可观察的游戏内容，**设计意图一律【推导】**。

### 8.1 它要解决的结构性矛盾

Roguelike 的结构和线性叙事天然冲突：

| Roguelike 的结构特征 | 对线性叙事的破坏 |
|---|---|
| 每次 run 从头开始 | 剧情无法连续推进 |
| 玩家会死很多次 | "英雄失败"要重复几十次 |
| run 的长度和顺序随机 | 无法安排固定的叙事节拍 |
| 玩家会玩几百小时 | 内容量要求极高 |

大多数 Roguelike 的做法是**放弃叙事**（把故事压缩成一个开场和一个结局）。《哈迪斯》选了相反的路。

### 8.2 它的机制方案（可观察的事实）

**（1）把"死亡"写进世界观。** 主角是冥王之子，死了会从冥河里复活回到冥界的家。于是**"重开一局"这个游戏行为在虚构层上是完全合理的**：他没有"读档"，他是真的死了又活了。

这是本章第 5.1 节说的虚构层与机制层对齐的最强示例：**机制要求玩家反复重来，虚构层给了一个反复重来完全说得通的设定。** ludonarrative dissonance 被从源头消除了。

**（2）把叙事的推进单位从"章节"改成"每次回家"。** 每次 run 结束（无论成功失败），玩家回到冥界之家，家里的 NPC 会说新的话。于是：

```
      出发 ──→ 战斗（随机、可变）──→ 死亡或胜利 ──→ 回家 ──→ 对话推进叙事
        ▲                                                        │
        └────────────────────────────────────────────────────────┘

   叙事的推进不挂在"关卡进度"上，挂在"循环次数"上
   ⇒ 玩家打不过也在推进故事；打得过也在推进故事
```

【推导】这个设计的关键收益是：**叙事进度与战斗能力解耦**。菜的玩家不会被卡在剧情外面，强的玩家也不会一口气把剧情冲完。这解决了几乎所有动作游戏都有的"叙事节奏被玩家水平打乱"的问题。

**（3）用条件调度的对白池替代线性剧本。** 游戏中的对白量极大，且不是线性播放的：每次回家，NPC 说的话取决于一堆条件（你死在哪一层、被谁杀的、这是第几次、你送过谁礼物、你和谁的关系到了哪一级）。玩家能观察到的现象是：**几乎每次回家都有新内容，而且这些内容和你刚才那局的经历有关。**

【推导】从可观察的行为反推，这套系统的形态更接近**一个带优先级和触发条件的对白数据库**，而不是一份线性剧本。它的工程含义你应该很熟悉：这就是一个规则引擎 + 优先级队列。对策划的含义是：**叙事内容被拆成了可独立生产、可独立上线的最小单元**，产能可以线性投入，不需要一次写完一整章。

**（4）把叙事任务变成一份可勾选的清单。** 游戏里有一份"命运列表"，把很多叙事相关的事情（和某个角色的关系推进、某种武器的特定成就）做成明确的条目和奖励。玩家为了拿奖励去做这些事，顺便把剧情看了。

【推导】这是把"叙事内容"接到"目标系统"上（[第 08 章](./08-goals-progression-rewards.md)），让不爱看剧情的玩家也有理由去触发剧情。

**（5）用送礼系统把 NPC 关系数值化。** 玩家可以送礼给 NPC，关系提升会解锁对话和实际的机制收益（纪念品）。

【推导】这一条把"我想多了解这个角色"这种纯情感动机，翻译成了一条有资源投入、有产出、可以被玩家规划的养成线。**这是本章最值得手游借鉴的一条**：让叙事消费本身成为一条养成线。

### 8.3 提炼出的四条可复用模式

| 模式 | 内容 | 在手游里怎么用 |
|---|---|---|
| **让虚构层解释机制的重复性** | 玩家必须重复做的事，在故事里要说得通 | 每日任务叫"日常巡逻"而不是"每日任务"；赛季重置在世界观里有解释 |
| **叙事挂在循环上而不是进度上** | 用"第几次"而不是"第几关"推进叙事 | 登录天数、赛季次数、公会战场次都可以挂叙事 |
| **对白池 + 条件调度** | 把叙事拆成条件触发的最小单元 | 角色语音、家园对话、活动期间的角色反应；产能可线性投入 |
| **把叙事消费接到目标系统上** | 用奖励驱动玩家去触发叙事 | 剧情章节给养成资源；角色好感度给实际收益 |

## 9. 贯穿案例（下）：《明日方舟》的叙事分配，与系统/文案的接口

《明日方舟》（鹰角网络，手游）用来做对照，因为它是"手游叙事分量高"的少数派，而且它的叙事分配方式非常清晰。以下是可观察的事实，**意图一律【推导】**。

### 9.1 它把叙事分配到了哪几个容器里

| 容器 | 内容形态 | 消费方式 | 谁会看 |
|---|---|---|---|
| **主线章节** | 大量文字对话 + 立绘 + 少量演出，穿插关卡 | 跟着推关 | 中等比例 |
| **活动剧情（SideStory 等）** | 一个自洽的中篇故事，配套限时关卡与角色 | 首发期有时限；之后多以复刻、插曲/别传、记录修复等形式回访 | 较高 |
| **干员档案 / 密录** | 角色的背景与个人故事，需要用资源解锁 | 主动查看 | 爱好者 |
| **道具与关卡文本** | 名词、说明、关卡前后的短对话 | 被动接触 | 几乎所有人 |
| **世界观名词体系** | 源石、感染者、罗德岛这套设定渗透在所有界面 | **无法跳过** | 所有人 |

**一个常被说错的细节："限时"限的主要是奖励，不是剧情本身。** 可观察的事实是：活动**首发期间**的活动商店、限时任务奖励和部分限时获取物确实有时限；而**剧情本身之后通常可以回访**——旧活动会进入插曲/别传这类常驻入口，并可通过记录修复补拿一部分奖励。具体哪些内容能回访、能补拿多少随版本变化，**以你手上版本的实际界面为准**。

【推导】这个分配的结构性聪明之处在于：**它把不同投入意愿的玩家分层了。** 不看剧情的人照样在名词体系里接受世界观（第 2.1 节的第一层）；愿意投入的人有档案、密录、活动可以深挖；限时**奖励**给了一个在首发期就参与的紧迫理由，代价是错过的玩家要多绕一道。

### 9.2 系统策划与文案策划的接口：机制身份 vs 叙事身份

这是本章对你日常工作最直接有用的一节。

**一个角色（或任何游戏实体）同时有两个身份：**

| | **叙事身份** | **机制身份** |
|---|---|---|
| 定义 | 他在故事里是谁：性格、立场、能力设定、和别人的关系 | 他在系统里是什么：定位、数值、技能类型、使用场景 |
| 谁定 | 文案策划 | 系统 / 数值策划 |
| 玩家怎么感知 | 剧情、语音、档案 | 实战中怎么用他 |

**两者必须互相支撑。** 检验方法是问三个问题：

**问题一：他的机制定位能不能从他的叙事设定里推出来？**
一个在剧情里以"精准、冷静、远距离狙击"著称的角色，机制上应该是高单体伤害、长射程、低生存。如果他被做成了近战肉盾，玩家会本能地觉得别扭。

**问题二：他在剧情里的强弱，和他在系统里的强弱一致吗？**
剧情里所向披靡的角色如果是个三星低强度单位，会同时损失两样东西：叙事的可信度和抽卡的转化率。反过来，一个剧情里的路人变成版本最强，玩家会觉得强度是硬凑的。

**问题三：他的使用场景和他的故事定位一致吗？**
一个"守护者"人设的角色，如果机制上只在速刷本里有用，那他的守护叙事没有任何机制支撑。

**接口清单：系统案里应该给文案留哪些钩子**

反过来，文案也需要系统给他留位置。一份系统案里，下面这些位置是**必须显式留给叙事的**（可以直接加进 `templates/system-spec.md` 的第 2 节和第 6 节）：

| 钩子 | 说明 | 例子 |
|---|---|---|
| **命名槽** | 这个系统、这些资源、这些等级叫什么 | 行动力叫"理智"；公会等级叫"分部规模" |
| **入口的叙事理由** | 为什么这个系统在这个时间点开放 | "你现在有了自己的据点，可以开始……" |
| **状态变化的播报** | 系统里的重要事件用什么口吻告诉玩家 | 战报的措辞：是"你损失 300 兵"还是"三百将士没能回来" |
| **失败与异常的说法** | 失败、超时、被抢，用什么语言 | 失败叫"撤退"还是"全军覆没"，情绪完全不同 |
| **角色在系统里的反应位** | 系统事件发生时，角色说什么 | 升级时、抽到时、上阵时、失败时的语音 |
| **可选阅读物的位置** | 哪里可以放不打扰人的深度文本 | 图鉴、档案、道具说明 |

**这份清单是你和文案对接的实际界面。** 一份只写规则不留命名槽和播报口吻的系统案，会导致文案在实现末期被迫给一堆已经定死的功能"补文案"，结果就是名字生硬、播报是纯数字、叙事和系统各说各话。

### 9.3 为什么手游叙事分量普遍低（结构原因）

这一节要讲清楚，因为它决定了你在项目里为叙事争取资源时能说什么。

| 结构原因 | 机制 | 后果 |
|---|---|---|
| **会话短且被打断** | 手游平均一次会话几分钟，可能在地铁上、在排队时 | 需要长时间沉浸的叙事无法成立；玩家养成了跳过习惯 |
| **跳过率高形成负循环** | 玩家跳过 → 数据显示剧情没人看 → 资源被砍 → 剧情质量下降 → 跳过率更高 | 【推导】这是一个自我强化的正反馈回路，很多项目就是这样把叙事做没的 |
| **内容成本高且不可复用** | 剧情是一次性消费品，成本随时长线性增长 | 同样的预算做养成线的收益（长期消耗）远高于剧情 |
| **商业化打断叙事** | 体力、礼包、限时活动不断插入 | 见第 6.2 节 |
| **多线并行的运营节奏** | 同时在跑三四个活动，玩家的注意力被切碎 | 连续的长篇叙事没有播放窗口 |

**例外为什么能成立（【推导】）**：像《原神》《明日方舟》这类叙事分量高的产品，共同点是**它们把叙事直接接到了商业化的核心上**——角色本身是付费标的，而玩家愿意为一个角色付费的很大一部分理由是这个角色的故事。**当叙事直接产生付费转化时，它就不再是成本中心，而是收入的一部分。** 这时候投入几十万字主线是有商业逻辑的。

**推论：一款游戏该投多少叙事资源，取决于它的付费标的是什么。**

| 付费标的 | 叙事的商业价值 | 合理的叙事投入 |
|---|---|---|
| 角色 / 皮肤（卡牌、二次元） | **高**：故事直接驱动抽卡 | 高 |
| 数值成长（多数 SLG、传奇类） | 低：玩家为战力付费，不为故事 | 低，够撑起世界观即可 |
| 时间与便利（放置类） | 极低 | 极低 |
| 一次性买断 | 中高：故事是口碑与复购的一部分 | 视品类 |

**这张表就是你在立项会或版本会上为叙事争取资源时该讲的话。** "我们要有好故事"说服不了任何人；"我们的付费标的是角色，角色的故事是抽卡转化率的直接输入"可以。

## 10. 常见误区

| 误区 | 为什么错 | 正确的想法 |
|---|---|---|
| "叙事就是写剧情" | 剧情只是四层里被跳过率最高的一层 | 世界观和玩家自己的故事同样是叙事，边际成本更低、也更难被跳过 |
| "手游玩家不看剧情，所以不用做叙事" | 他跳过的是文本，但他消费了世界观、角色和自己的故事 | 把资源从剧情移到世界观、道具文本、角色反应上，而不是全砍掉 |
| "叙事是文案的事，跟系统策划无关" | 命名、播报、失败措辞、角色反应位全部在系统案里 | 系统案要显式留出叙事钩子（第 9.2 节的清单） |
| "分支越多剧情越好" | 分支成本指数增长，玩家只消费其中一条 | 收束式分支 + 状态记录回响，性价比高一个数量级 |
| "玩家要的是改变世界" | 玩家真正要的是"我的选择被看见/被记住" | 记录 + 回响就够了，不需要真的改变主干 |
| "剧情和玩法各做各的就行" | 机制在奖励什么，玩家就相信什么；两者打架玩家会别扭 | 先检查收益最高的行为和你想传达的主题是否一致 |
| "把体力/礼包插在哪都一样" | 情绪高点被打断的破坏是不可逆的 | 主线高潮段关闭商业化打断，这是系统规则不是福利 |
| "涌现叙事靠玩家自己产生，不用设计" | 涌现需要持久状态、真实冲突、行动空间和**记录器** | 战报、录像、赛季总结是把系统输出翻译成故事的关键系统 |
| "角色强度归数值，人设归文案" | 机制身份和叙事身份不一致会同时损失可信度和付费转化 | 角色定位表要同时写两个身份，且要能互相推出来 |

## 11. 动手

### 11.1 拆解：《明日方舟》一次限时活动的"叙事—机制接口"

用 [templates/deconstruction.md](./templates/deconstruction.md) 拆解一个具体对象：**《明日方舟》任意一次大型限时活动（SideStory 等），或者你正在玩的任意一款卡牌/RPG 手游的最近一次剧情活动。**

拆解的重点不是剧情好不好看，是**叙事和机制是怎么接在一起的**。要回答：

**机制层（事实）**

1. 这次活动一共有哪几种容器承载叙事？（剧情关、纯剧情段落、角色档案、道具描述、UI 主题、BGM、活动商店的商品名……全部列出来）
2. 剧情段落和战斗关卡是怎么交替的？画出这个序列（剧情 → 关 → 剧情 → 关 …），标出每段的长度。
3. 剧情关消耗体力吗？和普通关卡相比消耗多少？纯剧情段落能不能重看？
4. 跳过按钮在哪、有多显眼、跳过之后会不会丢失任何东西？
5. 活动的奖励结构里，有多少是"看剧情就能拿"的？有多少必须打关卡？

**动态层**

6. 假设一个完全跳过所有剧情的玩家，他从这次活动里接收到了多少世界观信息？（去列一遍他能看到的所有文字：关卡名、道具名、商店商品名、角色名、UI 上的字）
7. 这次活动新出的角色，他的**机制身份**（定位、技能、使用场景）和**叙事身份**（性格、立场、能力设定）是否一致？用第 9.2 节的三个问题逐条检验，找出至少一处不一致或一处配合得特别好的地方。

**决策层**

8. 这次活动里有没有"玩家的选择"？如果有，属于第 7.2 节的哪种技巧？如果没有，为什么设计者不加？

**意图层【推导】**

9. 这次活动的叙事分量（文本量、演出投入）和它的商业目标是什么关系？它想卖什么？叙事在这个销售链路上的位置是什么？
10. 如果把这次活动的所有剧情全部删掉，只留关卡和奖励，参与率和付费会怎么变？（分成"跳过党"和"剧情党"两类玩家分别推演。）

### 11.2 写作作业：给一个现有系统写叙事包装

**选题**：从你正在玩的手游里选一个**当前叙事包装很弱**的系统。推荐的候选：每日任务、体力/行动力、公会捐献、竞技场、签到、扫荡、装备强化失败。

**产出**：写进 `notes/作业/12-叙事包装-XX.md`，包含五部分：

**第一部分：现状记录（事实）**
- 这个系统现在的所有对外文本逐条抄下来：系统名、按钮名、资源名、提示语、失败提示、成功提示、奖励说明。
- 标出哪些是纯功能性描述（"体力不足"），哪些有世界观色彩（"理智已耗尽"）。

**第二部分：叙事包装方案**
- 给出新的命名与文本，至少覆盖：系统名、核心资源名、玩家的主要动作（动词）、成功/失败/异常三种播报、一句入口处的叙事理由。
- **每一条都要说明它传达了什么世界观信息、以及它会让玩家对这条规则产生什么预期**（参照第 2.1 节那张"体力/理智/行军令/燃料"的对照表格式）。

**第三部分：机制身份与叙事身份的一致性论证**（本作业的核心，**至少 600 字**）

回答下面这几个问题，**每个问题都要落到具体规则**：

1. 这个系统的机制在**奖励**什么行为？（列出收益最高的三种玩家行为）
2. 你的叙事包装在**赞美**什么？两者一致吗？
3. 如果不一致，是改叙事还是改机制？为什么？（**必须选一个并给出理由**，不能写"两边都调整一下"）
4. 你的包装有没有承诺机制做不到的事？（逐条检查你写的每一句文案，找出至少一处潜在的过度承诺并修正）
5. 这个系统的失败/异常情况，在你的世界观里说得通吗？举一个具体的异常（比如"跨天结算时正好在打"）说明它的文案该怎么写。

**第四部分：给文案的接口文档**
按第 9.2 节的六个钩子（命名槽、入口理由、状态播报、失败说法、角色反应位、可选阅读物位置），列一张表，写清楚每个钩子的位置、字数限制、语气要求、以及**它出现的频率**（频率高的文本要短且耐看，频率低的可以长）。

**第五部分：成本与收益**
- 你的方案需要多少额外产能？（文本字数、是否需要新美术资源、是否需要程序改动）
- 你预期它改善什么？用一个可观测的指标表述（引用 [game-numeric 第 23 章](../game-numeric/23-metrics.md)）。
- 如果只能做其中一条，你做哪一条？为什么？

### 11.3 思考题

1. 第 2.1 节说世界观是"高基建、低边际、极高返工"的投资：多曝光一次几乎不要钱，定错了却几乎改不动（所有界面、所有名词、所有美术、所有配音都要跟着动）。那么在立项阶段，你会用什么方法**在基建成本还没花出去之前**验证一个世界观设定是否成立？（提示：想想[第 14 章](./14-design-process.md)的"原型只回答一个问题"。）
2. 《哈迪斯》把"死亡"写进了世界观，从而消除了 Roguelike 的叙事不协调。请为下面三个手游里的常见机制各设计一个"能让它在虚构层说得通"的世界观解释：(a) 每日体力上限；(b) 赛季结束后一切重置；(c) 抽卡抽到重复角色转化成碎片。
3. 第 9.3 节的推论是"叙事投入取决于付费标的"。假设你在一款**SLG**（付费标的是数值成长）里想加大叙事投入，你需要先改变什么，才能让这笔投入有商业逻辑？（提示：SLG 里有没有可能创造出一个"角色式"的付费标的？）
4. ludonarrative dissonance 在手游里几乎无处不在，但玩家大多接受了。这是否意味着这个概念在 F2P 里没有用？如果有用，它最该被用在哪个具体环节上？
5. 本章说"玩家自己的故事是系统策划的产物"。请说出你玩过的游戏里，**最近一次你想讲给别人听的游戏经历**是什么。然后逆向分析：是哪几条规则让这件事成为可能的？（这是最好的涌现叙事练习。）
