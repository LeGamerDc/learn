# 07 - 核心循环、元循环与会话

> **本章目标**：学会用循环图作为设计的第一张图。学完你应该能：给任意一款手游画出单局/日/长线三层循环并标出层与层之间的接口；说出玩家为什么在这一刻停下、又为什么明天会回来；用循环图诊断"这游戏为什么无聊"；并且知道循环设计和数值投放的分工线在哪。
> **前置**：[第 05 章](./05-decisions.md)（决策）、[第 06 章](./06-systems-and-emergence.md)（回路与反馈）。本章的"循环"和第 06 章的"反馈回路"是**两个不同的东西**，第 3 节会说清楚区别。

---

## 1. 把内容全删掉，还剩什么

思想实验。把一款手游的所有内容删光：所有关卡、所有角色、所有剧情、所有活动、所有美术。**剩下的那个东西，就是它的循环。**

对一款卡牌手游来说，剩下的是：

```
 花体力打一关 → 拿到材料 → 材料升级角色 → 角色变强 → 能打更高的关 → 花更多体力
```

对一款 SLG 来说，剩下的是：

```
 攒体力 → 打地/打人 → 拿资源和地盘 → 造兵造建筑 → 更强 → 打更好的地
```

对《哈迪斯》来说，剩下的是：

```
 开一局 → 打到死 → 带回资源 → 强化永久能力 → 再开一局，走得更远
```

这几行字看起来平淡无奇，但它们是这些游戏**真正的骨架**。内容是挂在骨架上的肉：肉可以换，骨架换不了。你会发现两款美术、题材、内容完全不同的游戏，循环图画出来可能一模一样——**这时候它们在体验上就是同一款游戏**，玩家会说"这不就是换皮"。

反过来，两款题材相同的游戏，如果循环不同，体验会天差地别。这就是为什么本课把循环图当成设计的第一张图：

> **写任何一份系统案之前，先画循环。画不出闭合循环的想法，还没有成为一个设计。**

这条规矩在 [templates/one-pager.md](./templates/one-pager.md) 里已经写死了（"一张图：循环图 / 状态图 / 界面草图，三选一必须有"），在 [templates/review-checklist.md](./templates/review-checklist.md) 第一层第二条也写死了（"它服务于哪条核心/元循环？在循环图上指出来"）。本章教你怎么画这张图、怎么读它、怎么用它诊断问题。

## 2. Daniel Cook 的两个工具

Daniel Cook（博客 Lostgarden）给了游戏设计两个最实用的概念工具，本章都要用到。

### 2.1 技能原子（skill atom）

出自他 2007 年的文章 ***The Chemistry of Game Design***【实证】。他把"玩家学会一件事"的最小单位拆成四个部分，围成一个圈：

```
        ┌──────────────────────────────────────┐
        │                                      │
        ▼                                      │
   ① 行动 ──→ ② 模拟 ──→ ③ 反馈 ──→ ④ 建模 ───┘
   (action)   (simulation)  (feedback)  (modeling)

   玩家做了     游戏内部按     游戏把结果   玩家更新自己
   一个动作     规则算了一下   告诉玩家     脑子里的模型
```

四个环节缺一不可，**缺任何一环，玩家就学不到东西**：

| 缺哪一环 | 症状 | 手游里的典型 |
|---|---|---|
| 缺**行动** | 玩家没有可做的事，只能看 | 过长的过场动画、纯挂机 |
| 缺**模拟** | 动作没有实际规则支撑，只是表演 | 假的"选择"（选什么结果都一样） |
| 缺**反馈** | 做了但看不到结果 | 属性加了但战斗表现看不出来 |
| 缺**建模** | 玩家看到了结果但归因不了 | 结果被太多随机因素污染；反馈延迟太久 |

**一个版本差异，你读原文时会碰到**：Cook 在 2021 年把这篇文章重新发到 Lostgarden 上时，把这个圈画成了**五段**——在"行动"前面多了一段 **决策（decision）：玩家观察当前的可供性、权衡各个选项的后果**【实证，Lostgarden 2021 重发版】。本章沿用 2007 年原文的四段讲法，但你要知道那一段是存在的，而且它就是[第 05 章](./05-decisions.md)讲的东西：**没有可权衡的选项，"行动"就退化成了执行指令，技能原子也就无从学起。**

**"建模"这一环是工程师最容易忽略的。** 你实现了规则、做了数字显示，但玩家能不能从这次反馈里推出"下次我该怎么做"，是另一回事。第 06 章讲的"回路延迟"就是在破坏这一环。

技能原子会**串起来**：学会 A 之后才能学 B，B 和 C 组合成 D。串起来的结构 Cook 叫技能链 / 技能树。**这是"教学设计"的理论基础**（第 18 章会用它来排新手引导的顺序），也是 Raph Koster 那句"乐趣来自学习模式"（[第 03 章](./03-why-players-play.md)）的机制版解释：**一个技能原子被掌握的那一刻，就是"有趣"发生的那一刻；掌握之后再重复它，趣味归零。**

这直接推出一条设计判断：

> **一个循环能撑多久，取决于它里面还有多少没被掌握的技能原子。** 循环本身不产生乐趣，循环里的学习才产生乐趣。

### 2.2 循环与弧（loops and arcs）

出自他 2012 年的文章 ***Loops and Arcs***【实证】。他把游戏里的结构分成两类：

| | **循环（loop）** | **弧（arc）** |
|---|---|---|
| 形状 | 闭合，可以无限重复 | 有起点有终点，走完就没了 |
| 例子 | 战斗、采集、交易、日常 | 剧情、关卡、一次性成就、教程 |
| 内容成本 | 做一次，用无数次 | 用一次，就得再做一个 |
| 玩家的感受 | 熟悉、掌握、节奏感；久了会腻 | 新鲜、高潮、意义；用完就没了 |
| 提供什么 | **长度**（游戏能玩多久） | **峰值**（游戏最难忘的时刻） |

**这个区分对手游从业者的价值极高**，因为它一句话解释了 F2P 和买断制在结构上的差异：

- **买断制在购买时收完钱**，之后要做的是"值回票价"，也就是提供足够多的**峰值**。所以买断制游戏是**弧为主**：主线剧情、精心设计的关卡、Boss 战、结局。做完就做完了，游戏 30 小时通关，收工。
- **F2P 要在三年里持续收钱**，它需要的是**长度**。所以 F2P 是**循环为主**：日常、体力、养成、赛季。内容成本必须摊薄，否则产能撑不住（[game-numeric 第 20 章](../game-numeric/20-long-term-pacing.md)的"内容跑道"）。

**但纯循环的游戏没有峰值，纯弧的游戏没有长度。** 所以现实中所有成熟产品都是混合的：

```
  弧（内容）      ▲     ▲          ▲      ▲            ▲
                 │     │          │      │            │
  循环（日常）  ──┴─────┴──────────┴──────┴────────────┴──→ 时间
                主线   角色PV     赛季    大版本      联动活动

  循环负责"每天都有事做"，弧负责"这个月我记住了什么"
```

**一个实用的诊断**：玩家在论坛上怀念的多半是弧（"那个剧情""那次开荒战"），抱怨的多半是循环（"每天肝得像上班"）。**如果一款游戏运营两年后，玩家想不起来任何一个弧，那它的留存只剩下沉没成本在支撑**【推导】，这种留存非常脆弱。

### 2.3 别把"循环"和"反馈回路"搞混

[第 06 章](./06-systems-and-emergence.md)讲的**反馈回路**和本章讲的**循环**都画成圈，但它们是两个东西：

| | 反馈回路（第 06 章） | 循环（本章） |
|---|---|---|
| 圈上跑的是 | **资源和状态**（数值） | **玩家的行为**（动作序列） |
| 回答的问题 | 系统会不会失控？强者会不会恒强？ | 玩家在这段时间里反复做什么？他为什么继续？ |
| 画的时候节点是 | 存量、流量、门 | 动作、反馈、资源、决策 |
| 谁最关心 | 数值策划 + 系统策划 | 系统策划 + 主策 |

一条循环上通常挂着好几条反馈回路。**画循环图是在描述玩家的时间；画反馈回路是在描述系统的稳定性。** 评审时两张图都要看：循环图回答"好不好玩"，回路图回答"会不会崩"。

## 3. 核心循环的画法（本课的统一规范）

从这一章开始，本课所有循环图都用同一套画法。**请照抄这套规范，因为第 15 章写系统案、第 29 章做端到端实战时都会要求用它。**

### 3.1 四个节点类型

```
  [ 动作 ]      玩家主动做的事（动词）
  《 反馈 》     游戏给玩家的即时回应（看到/听到什么）
  【 资源 】     积累下来的东西（数值、进度、解锁）
  < 闸门 >      限制条件（体力、CD、次数、等级、付费）
```

外部输入（时间恢复、运营活动）用 `○` 表示，从圈外指进来。

### 3.2 三条纪律

**纪律一：必须闭合。** 一条不回到起点的链不是循环，是流程。**画不闭合就说明玩家做完这件事之后没有理由再做一次**，这是最严重的设计问题。

**纪律二：每条边必须写清楚"传递了什么"。** 光秃秃的箭头等于没画。写"→ 材料"、"→ 战力 +5%"、"→ 解锁下一关"。

**纪律三：闸门必须画出来。** 闸门决定节奏，是循环图上信息密度最高的东西。**一张连时间型、次数型、付费型闸门都没有的循环图，画的通常是买断制游戏**【推导】——注意买断制并非没有闸门，它一样有等级门、能力门（拿到滑翔伞才能过去）、剧情门，只是它不靠闸门去压慢玩家的消耗速度；**F2P 的设计张力则大多压在这三类消耗型闸门上。**

### 3.3 一个标准示例

一款卡牌手游的单局循环：

```
        ○ 时间（6 分钟恢复 1 点）
        │
        ▼
     【 体力 】
        │  消耗
        ▼
  < 关卡等级门 > ──→ [ 打一关 ] ──→ 《战斗表现：伤害数字、过关星级》
                        │                      │
                        │ 掉落                 │ 玩家判断"我的队够不够强"
                        ▼                      ▼
                   【 材料 / 经验 】      [ 调整阵容 / 决定练谁 ]  ← 真决策在这里
                        │                      │
                        │ 消耗                 │
                        ▼                      │
                  < 材料稀缺门 >               │
                        │                      │
                        ▼                      │
                   [ 升级角色 ] ──→ 【 战力 】 ─┘
                                        │
                                        └──→ 解锁更高关卡（回到上面）
```

读这张图的方法：

1. **先找闸门**：体力、关卡等级、材料稀缺。这三个决定了玩家一天能做多少、能做到哪。
2. **再找真决策**（第 05 章）：图上只有一个真正的决策点（"练谁"）。**如果一张循环图上找不到决策点，这个循环是纯劳动。**
3. **最后看闭合**：战力 → 解锁更高关卡 → 打一关，闭合了。如果战力涨了但关卡没变化（比如所有关卡都能过），循环就断在这里，玩家会问"我练角色干嘛"。

**这三步就是读任何循环图的标准动作。**

## 4. 手游的三层循环

单张循环图不够用，因为手游的玩家行为发生在三个差好几个数量级的时间尺度上。**本课把它统一叫"三层循环"**：

| 层 | 名字 | 时间尺度 | 玩家的问题 | 主要闸门 | 失败的表现 |
|---|---|---|---|---|---|
| **L1** | 单局循环 / 分钟级循环 | 30 秒 ~ 10 分钟 | "这一局怎么打" | 局内资源（能量、费用、回合） | 战斗无聊、必须开自动 |
| **L2** | 日循环 | 一天 | "我今天上线要做什么" | 体力、每日次数、CD、签到 | 打工感、只领奖不玩 |
| **L3** | 长线循环 | 一周 ~ 一个赛季 | "我这个月的目标是什么" | 赛季、活动排期、养成材料稀缺 | 没有目标、"练满了不知道干嘛" |

三层的关系不是并列，是**嵌套**：

```
  ┌────────────────── L3 长线循环（周 / 赛季 / 版本）──────────────────┐
  │  定目标（练出那个角色 / 打进前 100 / 通关新章节）                   │
  │                                                                    │
  │   ┌──────────────── L2 日循环（一天）─────────────────┐            │
  │   │  分配今天的体力 / 换班 / 做日常 / 参加今日活动      │            │
  │   │                                                    │  ×30 天   │
  │   │    ┌────────── L1 单局循环（分钟）──────────┐      │            │
  │   │    │  打一关：部署、出牌、走位、结算         │ ×20 │            │
  │   │    └────────────────────────────────────────┘      │            │
  │   └────────────────────────────────────────────────────┘            │
  └────────────────────────────────────────────────────────────────────┘
```

### 4.1 层与层之间的接口（本节最重要）

**大部分"这游戏不好玩"的问题不在某一层内部，在层与层的接口上。** 每两层之间有两条接口，都必须成立：

```
      L3 ──── ① 上层给下层"目标和意义" ────→ L2
      L3 ◄─── ② 下层给上层"进度" ──────────── L2

      L2 ──── ① 上层给下层"资源和情境" ────→ L1
      L2 ◄─── ② 下层给上层"产出" ──────────── L1
```

| 接口 | 具体是什么 | 断了会怎样 |
|---|---|---|
| **L3 → L2**：目标 | 我今天做的日常，是为了这个月的哪个目标 | 玩家每天做日常但不知道图什么 → **打工感的第一来源** |
| **L2 → L3**：进度 | 今天做完之后，长线目标推进了多少（要**可见**） | 玩家看不到自己在接近目标 → 觉得遥遥无期 → 弃坑 |
| **L2 → L1**：资源和情境 | 我今天的体力决定我能打几局；今天开的是资源本还是活动本 | 每局都一样 → L1 变成纯重复 |
| **L1 → L2**：产出 | 打一局的产出要能推进当天的目标 | 打了没用 → **玩家会立刻发现并开自动** |

**还有一条隐藏的接口，最容易断，也最致命：**

> **L2 的养成必须能改变 L1 的体验。**

也就是说：我今天练了角色，明天打关卡的**手感/打法/局面**要真的不一样。如果练了半天只是伤害数字从 1200 变成 1350，而战斗过程一模一样，那么 L2 的养成对 L1 就没有可感知的后果（[第 05 章](./05-decisions.md)第 3.3 节），玩家的养成动力会靠"数字变大"硬撑，撑不了太久。

**做得好的表现**：练出一个新角色之后，某一类关卡的打法完全变了（原来要打三分钟，现在一个技能秒掉）；解锁一个新机制之后，L1 出现了新的决策点。**这就是把 L2 的进度兑换成了 L1 的新技能原子**（第 2.1 节），玩家因此又有东西可学了。

**这是卡牌 / RPG 养成品类最核心的设计功课**，第 24 章会专门讲。

### 4.2 相邻两层的时间尺度差

一条经验法则【行业口径】：**相邻两层的时间尺度差 10 到 50 倍比较舒服。**

- L1 三分钟，L2 一天（差 ~200 倍，中间有点空，所以很多游戏在中间加了一个"一次会话"的半层：一次上线 10~20 分钟）
- L2 一天，L3 一个月（差 30 倍，舒服）
- L2 一天，L3 一年（差 365 倍，太远，所以需要在中间插入"周"和"赛季"）

**差得太少**（比如 L2 是一天、L3 是三天）：两层感觉是同一件事，玩家没有"阶段感"。
**差得太多**：中间是空的，玩家做完今天的事之后，看不到通往长线目标的路。**手游里"周任务""周常本""赛季手册的周度节点"存在的原因就是填这个空隙**【推导】。

## 5. 会话设计：玩多久、为什么停、为什么回来

**会话（session）** = 玩家一次打开到关闭游戏之间的时间。这是手游设计里最被低估的一个单位，因为它是**闸门设计的直接目标**。

### 5.1 会话长度的品类差异

下表的数字是**量级参考，用于建立体感**，各产品差异很大【行业口径】：

| 品类 | 单次会话 | 每天会话次数 | 一天总时长 | 会话结构的成因 |
|---|---|---|---|---|
| 超休闲 / IAA 小游戏 | 1~3 分钟 | 3~10 | 10~20 分钟 | 广告位需要频繁的自然断点（见 [game-solo 第 02 章](../game-solo/02-session-pacing.md)） |
| 卡牌 / RPG 养成 | 10~30 分钟 | 1~3 | 20~60 分钟 | 体力一次放完，做完就没事了 |
| SLG（率土-like） | **3~8 分钟** | **5~15** | 30~90 分钟 | **体力慢回 + 行军等待 + 同盟随时召集** |
| MMO | 30~120 分钟 | 1~2 | 1~3 小时 | 组队和副本需要连续时间 |
| 买断制单机 | 40~180 分钟 | 视玩家 | 视玩家 | 没有消耗型闸门，由内容节奏和玩家自己决定 |

**SLG 那一行是最特别的**，也是最值得学的：它把一天的总时长切成十几段，每段都很短。这种结构的好处是：

1. **对碎片时间友好**，玩家在任何三分钟的空隙都能玩一次
2. **每天有十几次"打开游戏"的行为**，习惯形成得极快（这是留存的行为学基础，见 [game-numeric 第 15 章](../game-numeric/15-retention-ltv.md)）
3. **每次上线都可能有社交事件**（有人打我了、盟里在集结），制造"必须看一眼"的紧迫感

代价也很明确：**它对玩家生活的侵入性极强**。第 00 章提到的"设闹钟按体力恢复上线"和"玩游戏像上班"，就是这个结构的副产品。**这是一个设计者必须诚实面对的伦理问题**，第 21 章会正面讨论。

### 5.2 玩家为什么停下：五种停止原因

**这是本章要求你必须能张口就说的一张表。**

| 停止原因 | 机制上是什么 | 玩家的感受 | 好还是坏 |
|---|---|---|---|
| **① 资源耗尽**（硬停） | 体力清零、次数用完 | "没体力了，明天再来" | **中性偏好**。可预期、有明确的回归时间。但耗尽的那一刻本身是负体验 |
| **② 内容耗尽**（软停） | 该做的都做完了 | "今天没事干了" | **好**。有完成感 |
| **③ 自然断点** | 打完一章、结束一局、领完奖 | "打完这局就睡" | **最好**。玩家自己决定的，有掌控感（第 03 章的"自主"） |
| **④ 外部中断** | 地铁到站、老板来了、电话 | 被打断 | **中性**，但要求游戏能随时中断且不丢进度 |
| **⑤ 挫败 / 疲劳** | 卡关、被打、界面繁琐、无聊 | "算了，不玩了" | **坏**。这一类停止的下一步经常是卸载 |

**关键判断：⑤ 和其他四种的区别，不在于玩家什么时候关掉游戏，而在于他关掉游戏时的情绪。** 前四种关掉游戏时玩家是平静或满足的，第五种是带着负面情绪走的。

**你能观察到的信号**：如果玩家总是在同一个界面/同一个环节退出（埋点会告诉你），那基本是第五种。第 20 章会讲怎么用埋点区分这五种停止。

### 5.3 玩家为什么回来：五种回归动机

| 回归动机 | 机制上是什么 | 强度 | 副作用 |
|---|---|---|---|
| **① 资源恢复** | 体力回满、免费次数刷新、离线收益攒够 | 中 | 最基础，但**单靠它撑不住**：玩家可以决定不在乎那点体力 |
| **② 定时事件** | 限时活动、Boss 刷新、赛季结算、每日刷新点 | 强 | 制造"错过就没了"，但用多了会变成压迫 |
| **③ 社交约定** | 盟里说晚上八点集结、朋友在等你 | **最强** | **最强也最危险**：社交压力是留存神药也是流失毒药（第 11 章） |
| **④ 损失厌恶** | 连续签到断了会重置、排名会掉、建筑会被打 | 强 | 制造焦虑。**用它换来的留存，质量很差** |
| **⑤ 未完成的进度** | 差一点就升级了、还差 3 个材料、剧情断在悬念处 | 中偏强 | **最健康的一种**。人对未完成的事有天然的记忆和回归倾向（行为学机制见 [game-numeric 第 02 章](../game-numeric/02-player-motivation.md)） |

**这张表的用法**：数一数你的游戏用了哪几种。

- **只用①**：留存很脆弱，玩家一旦有一天没上线，就会发现"其实不上线也没什么"。
- **重度依赖③④**：短期数据会很好看，但玩家会积累怨气，一旦有替代品出现会集体迁移。**手游社区里"终于解脱了"这种弃坑发言，通常对应的是③④过重**【推导】。
- **能用好⑤**：这是设计能力的体现，因为它要求你在玩家离开的那一刻**恰好**把他留在一个"差一点"的状态上。这是可以设计的，见下一节。

### 5.4 好的停止点 vs 强迫停止

**"停止点"（stopping point）是一个可以主动设计的东西**，不是被动等玩家自己走。

| | 好的停止点 | 强迫停止 |
|---|---|---|
| 玩家的感受 | "今天玩得挺好，收工" | "又被卡住了" / "又没体力了" |
| 有没有完成感 | 有：一件事被做完了 | 没有：正在做的事被打断 |
| 下一步清不清楚 | 清楚："明天要练那个角色" | 不清楚，或者只有"等" |
| 有没有损失 | 没有 | 有：进度丢了、奖励没领、结算被打断 |
| 回归时间可不可预期 | 可以："明天早上体力就满了" | 不确定："不知道啥时候能过" |
| 玩家的掌控感 | 玩家自己决定停 | 系统决定停 |

**设计好停止点的六个手法**（可以直接拿去用）：

1. **结算即时化**：一件事做完立刻结算完毕，不要留"待领取"。留着领取的东西会让玩家不敢关游戏。
2. **断点保存**：任何流程被打断都不丢进度。**这条对手游是硬性要求**，因为外部中断（第 5.2 节④）随时会发生。
3. **让"再来一局"的成本可见**：明确告诉玩家"再打一局需要 X 体力，你还剩 Y"，让他自己算得清。**信息透明会增加掌控感，掌控感会让停止变成一个决策而不是一次挫败。**
4. **在停止的那一刻给下一步预告**：体力空了的界面上不要只放充值按钮，要放"你的角色离下一级还差 2 个材料，明天的资源本会掉"。**把强迫停止转化成未完成进度**（第 5.3 节⑤）。
5. **离线也有产出**：让玩家关掉游戏之后世界还在动（挂机收益、建造进度、行军）。这既缓解了"停止即损失"的焦虑，又制造了回归动机。
6. **不要在会话末尾放最难的东西**：玩家在会话尾声的注意力和耐心最低，把最难的挑战放在这里，命中的是第 5.2 节的第⑤种停止。

**第 4 条是本节最值得记的一条。** 它是一个通用的转化：**把"资源耗尽"这个硬停，包装成"未完成的进度"这个健康的回归动机。** 同一个客观事实（没体力了），两种呈现方式，玩家的情绪完全不同。这不是话术，是设计——因为它要求你**真的知道玩家的下一个目标是什么**，而这需要 L3 → L2 的接口是通的（第 4.1 节）。

## 6. 用循环图诊断"为什么无聊"

这是本章最实用的一节。**"这游戏不好玩"是一句没法执行的话，但把它翻译到循环图上，就变成了七种可以修的具体病。**

| 病症 | 玩家怎么说 | 循环图上长什么样 | 修法 |
|---|---|---|---|
| **① 循环太短 / 太快被掌握** | "玩两天就腻了" | 循环只有 2~3 个节点，且没有决策点 | 加技能原子（新机制/新交互），不是加内容量。参考第 2.1 节 |
| **② 反馈太弱或太慢** | "感觉没什么变化" | 《反馈》节点缺失，或者从动作到反馈延迟很久 | 补即时反馈（第 13 章的 juice）；缩短回路延迟（第 06 章第 5 节） |
| **③ 循环不闭合** | "这东西攒着干嘛" | 有一条【资源】没有出边 | 就是 [game-numeric 第 03 章](../game-numeric/03-resource-flow.md)的"孤儿资源"。给它找汇，或者删掉这个产出 |
| **④ 只有循环没有弧** | "每天都一样，像上班" | 图上全是圈，没有一次性的高潮 | 加弧：剧情节点、大型活动、赛季高潮、限时联动 |
| **⑤ 只有弧没有循环** | "内容打完就走了" | 图是一条直线，走完到头 | 加循环：把内容变成可重复的玩法（Roguelike 化、PvP 化、排行榜化） |
| **⑥ 层与层脱节** | "练了半天没感觉" / "不知道每天图什么" | L2→L1 或 L3→L2 的接口箭头断了 | 第 4.1 节四条接口逐条检查，特别是"养成要改变 L1 的体验" |
| **⑦ 闸门太紧或太松** | "五分钟就没体力了" / "打了三小时还打不完" | < 闸门 > 的开合量和会话目标不匹配 | 调闸门（这是**数值**的活，但**要什么会话结构是你定的**，见第 8 节分工） |

**用法**：把玩家的抱怨、你自己的直觉、测试的观察，全部翻译成这七条之一，然后修对应的地方。**翻译不出来的抱怨，说明你还没弄清楚问题在哪，不要动手改。**

**一个高频的误诊**：玩家说"内容太少了"，团队的反应是加内容。但如果真实病症是①（循环被掌握了）或⑥（养成不影响体验），加多少内容都会被以同样的速度消耗掉，**而且加内容是这七条修法里最贵的一条**。第 26 章讲评审时会把这个当成典型的设计谬误。

### 6.1 把三条真实抱怨走一遍

诊断这件事必须练，光看表学不会。下面三条是手游社区里最常见的抱怨，我们把它们逐条翻译成循环图上的位置。**注意每一条的关键动作都是"先问一个反问句"，用来区分几个长得很像的病症。**

**抱怨一："每天上线二十分钟，全是点点点，跟上班一样。"**

- 反问：**他做的这些事，有几个是真决策？**（[第 05 章](./05-decisions.md)第 7.2 节的数决策动作）
- 如果答案是"0~1 个"，病症是 **① 循环太短**，L2 已经退化成签到流程。修法是给日循环加一个真决策（比如"今天的有限资源投给哪条线"），不是加更多日常。
- 如果答案是"有 3~5 个真决策，但他还是觉得像上班"，病症是 **⑥ 层间脱节**中的 L3→L2 接口断了：他做的决策**是真的**，但他不知道这些决策服务于哪个长线目标。修法是把长线目标做可见（进度条、材料缺口、赛季手册节点），**一行代码的规则都不用改。**

**这两个病的症状完全一样，修法完全不同，误诊的成本是几个月的开发量。**

**抱怨二："我练了半个月，感觉跟没练一样。"**

- 反问：**练完之后，他在核心玩法里能做到什么以前做不到的事？**
- 答不出来（只有数字变大）→ 病症是 **⑥ 的隐藏接口断裂**（L2 养成没有改变 L1 体验）。修法见第 7.4 节：让养成兑换成新解法，而不是新数字。
- 答得出来但玩家没感觉 → 病症是 **② 反馈太弱**。修法是把"变强"这件事在 L1 里显式呈现（战斗中的表现差异、通关时间对比、"这一关你上次打了 3 分钟，这次 40 秒"）。

**抱怨三："开服那阵挺好玩的，现在没什么好期待的了。"**

- 反问：**最近一个月，玩家能说出一件"值得记住的事"吗？**
- 说不出 → 病症是 **④ 只有循环没有弧**。这是长线运营手游的常见病，而且它有一个特征：**数据上还没坏**（DAU 还在，玩家还在做日常），但玩家的情绪已经空了，属于流失的前兆。修法是排期弧（大型活动、剧情节点、赛季高潮），这是第 22 章的内容。
- 说得出但都是半年前的事 → 病症相同，只是**弧的排期间隔太长**。经验上【行业口径】，长线手游需要**每 2~6 周有一个能被玩家记住的弧**，中间用循环填。

## 7. 贯穿案例：《明日方舟》的三层循环

《明日方舟》适合当本章的标本，因为它的三层循环边界特别清晰，而且每一层都有明确的闸门。

**说明**：下面的规则是我拆解时观察到的（版本会变，具体数字请你自己在游戏里核对），**所有关于设计意图的判断一律标【推导】**。

### 7.1 L1：单局循环（一次作战，2~5 分钟）

这是一个塔防：干员部署到格子上，消耗"费用"（部署费用随时间自动增长），敌人沿固定路线推进，漏过去就掉生命点数。

```
   ○ 时间（费用自动增长）
   │
   ▼
 【 部署费用 】
   │  消耗
   ▼
 [ 部署一个干员 ]  ← 决策：部署谁、放哪个格子、朝向哪边、什么时候放
   │
   ├──→ 《阻挡敌人 / 输出伤害》──→ 【 战场局势 】
   │                                    │
   │                                    ▼
   │                          [ 撤退干员回收部分费用 ] ← 决策：换血还是硬撑
   │                                    │
   └────────────────────────────────────┘
```

**L1 的决策密度很高**（[第 05 章](./05-decisions.md)第 7 节），因为费用是持续增长的稀缺资源，玩家每隔几秒就要做一次"现在放还是攒着"的决定。**朝向**这个规则很关键：干员部署时要选面朝方向，放错了就打不到人且不能撤销（只能撤退重放，代价是费用和 CD）。**这一条把"部署"从一个操作变成了一个不可逆的决策**【推导】——它同时满足了第 05 章四个构件里最难做到的那个：**代价**。

**L1 的可重复性来自哪里**：关卡机制不断更换（新的敌人类型、地形、特殊规则），每一关都是一次"这套阵容能不能解这道题"的考试。**这是"递进内容驱动的 L1"**（第 06 章第 6 节的递进结构）：L1 的循环本身是固定的，变的是每关的题目。

### 7.2 L2：日循环（一天，两次会话）

这一层有**两个并行的闸门**，这是明日方舟结构上最有特点的地方。

```
  ┌─────────────── 闸门 A：理智（体力）───────────────┐
  │  ○ 时间：约 6 分钟恢复 1 点，上限随等级增长       │
  │     （回满大约需要十几个小时）                    │
  │              │                                    │
  │              ▼                                    │
  │        【 理智 】───→ < 关卡消耗 > ───→ [ 打关卡 ] │
  │                                            │      │
  │                                            ▼      │
  │                              【 材料 / 经验 / 钱 】│
  └───────────────────────────────────────────┬───────┘
                                              │
  ┌─────────────── 闸门 B：基建 ──────────────┼───────┐
  │  干员在设施里工作 → 消耗心情 → 心情耗尽停工│       │
  │       （大约 8~12 小时需要换一次班）       │       │
  │              │                             │       │
  │              ▼                             ▼       │
  │      [ 换班 / 收取产物 ] ──→ 【 赤金 / 作战记录 /  │
  │                                源石碎片 / 线索 】  │
  └────────────────────────────────────────────┬──────┘
                                               │
                                               ▼
                                    [ 养成：升级 / 精英化 ]
                                               │
                                               ▼
                                        【 干员强度 】
                                               │
                                               └──→ 回到 L1（能打更难的关）
```

**两个闸门的周期被设计成大致同频**【推导】：理智回满要十几个小时，基建换班周期八到十二个小时。**两个都指向"一天上线两次"（早上一次、晚上一次）**。这不是巧合，它精确地塑造了一种会话节奏：

| 时间 | 玩家做什么 | 用时 |
|---|---|---|
| 早上 | 收基建产物、换班、把攒的理智花掉、做日常 | 10~15 分钟 |
| 晚上 | 同上 + 打活动 / 剿灭 / 推图 | 15~30 分钟 |

**和 SLG 对照**：SLG 是"一天十几次、每次三分钟"，明日方舟是"一天两次、每次十几分钟"。**闸门的恢复速度直接决定了会话结构**，这是本章最重要的因果链之一：

> **闸门恢复周期 → 会话次数与长度 → 玩家和游戏的关系（是"随时惦记"还是"每天两次"）**

从玩家生活侵入性的角度看，明日方舟这种结构比 SLG 温和得多。**这是一个设计取舍**：温和的结构降低了 DAU 上限和社交紧迫感，换来了更低的疲劳度和更长的玩家生命周期【推导】。

**日循环里的资源本轮换**：不同日子开放不同的材料本。这条规则给日循环加了一个"今天该刷什么"的决策，同时也制造了"周三没开我要的本，我得等"的**跨日规划**——**它把日循环和周循环连了起来**，是层与层接口的一个具体实现。

### 7.3 L3：长线循环（周 / 版本 / 赛季）

- **活动周期**：每隔一段时间一个限时活动，带独立的剧情、关卡和活动商店（**这是弧**：剧情一次性，关卡打完就结束）
- **养成目标**：把某个干员练到精二、练某个技能到专三，这是需要跨越几周的目标（**这是循环，但周期很长**）
- **卡池**：限时的角色获取窗口（第 24 章会讲抽卡作为内容分发机制）
- **周期性玩法**：每周结算的剿灭作战、赛季制的危机合约（**这是循环 + 玩家自选难度**，它的具体规则和天花板在[第 09 章](./09-challenge-difficulty-skill.md)第 10.2 节拆）

**L3 → L2 的接口**：玩家今天刷材料，是为了那个"练精二"的长线目标。**这个接口是通的，而且是可见的**——干员的养成界面会直接列出"精英化二阶段需要什么材料、你还差多少"。

**这就是第 5.4 节第 4 条手法的完美实现**：理智空了的时候，玩家脑子里不是"没体力了"，而是"还差 4 个聚合剂"。**同一个硬停，因为 L3 目标可见，被转化成了"未完成的进度"。**

### 7.4 三层接口的完整检查

用第 4.1 节的四条接口逐条查：

| 接口 | 明日方舟怎么做的 | 通不通 |
|---|---|---|
| L3 → L2（目标） | 养成界面明确列出材料缺口；活动有倒计时和进度条 | ✓ 通 |
| L2 → L3（进度） | 每次刷本掉的材料直接减少缺口，数字可见 | ✓ 通 |
| L2 → L1（资源/情境） | 理智决定能打几关；资源本轮换决定今天打什么 | ✓ 通 |
| L1 → L2（产出） | 打关卡的掉落直接进养成 | ✓ 通 |
| **L2 养成 → L1 体验**（隐藏接口） | **练出一个新干员，某些关卡的解法完全变了**（比如原本要卡时间的关，有了某个干员可以直接站住） | ✓ 通，**而且这是它的核心竞争力** |

最后一行值得强调。**一个塔防关卡是一道有多种解法的题，而"练干员"就是在扩充你的解题工具箱**【推导】。这让 L2 的养成产生了 L1 的**质变**而不只是量变——玩家不是"伤害高了 12%"，是"我现在会做这类题了"。回到第 2.1 节：**这等于把 L2 的进度直接兑换成了 L1 的新技能原子**，而技能原子是乐趣的来源。

**这条设计判断是可以迁移的**，也是本章最值得写进你的模式库的一条：

> **养成系统的价值不在于让数字变大，在于让玩家在核心玩法里获得新的解法。** 如果你的养成只产生数值增长，那 L2 对 L1 就只有量的影响，玩家很快会开自动。

## 8. 对照案例：《哈迪斯》的 run 循环

同一套工具用在买断制上，差异会立刻显现。

### 8.1 循环图

```
  ┌──────────────────── 元循环（meta loop，L2 等价物）────────────────────┐
  │                                                                       │
  │   [ 用黑暗/宝石/钥匙强化永久能力 ] ──→ 【 永久强度 + 新武器/新选项 】  │
  │            ▲                                     │                    │
  │            │ 带回资源                            ▼                    │
  │   ┌────────┴──────────── run 循环（L1）──────────────────┐            │
  │   │                                                      │            │
  │   │  [ 开一局 ] ──→ [ 清一个房间 ] ──→ 《门上显示奖励图标》│            │
  │   │       ▲              │                    │          │            │
  │   │       │              │              [ 选下一扇门 ]   │  ← 决策    │
  │   │       │              │                    │          │            │
  │   │       │              └────────────────────┘          │            │
  │   │       │                        │                     │            │
  │   │       │                        ▼                     │            │
  │   │       └──────────── 【 死亡 / 通关 】─────────────────┘            │
  │   │                             │                                     │
  │   └─────────────────────────────┼─────────────────────────────────────┘
  │                                 ▼                                     │
  │              [ 回到冥界之家：和 NPC 对话，剧情推进 ]  ← 这是**弧**      │
  │                                 │                                     │
  └─────────────────────────────────┴─────────────────────────────────────┘
                       回家几乎总有新对话可听 → 失败也在推进故事
```

### 8.2 三个关键差异

**差异一：没有消耗型闸门。**
玩家想连打十局就打十局，没有体力、没有每日次数、没有付费门。它并不是一个闸门都没有——新武器、镜子里的强化选项、部分房间和剧情要用元资源去解锁，那些是**解锁型/能力型闸门**；缺的是**时间型、次数型、付费型**这三类用来压慢消耗速度的闸门。**买断制不需要压慢玩家的消耗速度**（钱已经收完了）【推导】，这一条差异导致了后面所有差异。

**差异二：停止点是"完成"，不是"耗尽"。**
一次 run 结束（无论死了还是通关）就是一个天然的完成节点——**这是第 5.2 节里最好的那种停止（③自然断点）**。玩家关游戏的时候是平静的，因为一件事刚好做完了。

**差异三：用弧给循环补充意义。**
《哈迪斯》最被称道的设计是：**死亡回家之后，NPC 常常还有你没听过的新台词**——角色关系在推进、剧情在展开。准确的说法不是"每一次回家都必定有新对话"，而是**条件化触发的对话储备量大到玩家在很长一段时间里感觉不到重复**。Supergiant 在 GDC 的分享里讲过他们的叙事系统怎么支撑这种量级的对话【实证，Supergiant 的 GDC 分享】。

体验上这解决了 roguelike 的一个根本问题：**失败本身是负反馈，重复失败会累积挫败。** 而如果每次失败都带回一段新剧情，失败就同时是一次进度推进。**这是"用一串小弧把一个循环粘住"的教科书案例**【推导】：

```
  纯循环的 roguelike：    死 → 重开 → 死 → 重开 → 死 → 腻了
  哈迪斯：               死 → 【新对话】→ 重开 → 死 → 【新对话】→ ...
                              ↑ 每一次都是一个微型的弧，提供峰值
```

### 8.3 和明日方舟并排看

| | 明日方舟（F2P） | 哈迪斯（买断制） |
|---|---|---|
| 闸门 | 理智 + 基建心情，**两个时间闸门** | **无消耗型闸门**（只有解锁型） |
| 一次会话为什么开始 | 理智满了 / 基建停工了（**外部提醒**） | 我想玩（**内部驱动**） |
| 一次会话为什么结束 | 理智空了（① 资源耗尽） | 一局打完了（③ 自然断点） |
| 为什么回来 | 资源恢复 + 活动限时 + 未完成的养成目标 | 想看下一段剧情 + 想通关 |
| 循环 vs 弧的比例 | 循环为主，活动剧情提供弧 | **弧和循环深度交织**（每局都带一小段弧） |
| 内容成本 | 循环摊薄，弧靠活动周期性补充 | 弧的成本极高（海量对话），但只需付一次 |
| 长度 | 设计寿命以年计 | 设计寿命以"通关 + 若干次重玩"计 |

**结论**：两者的循环结构差异，几乎完全由"什么时候收钱"决定。**F2P 必须用闸门把内容消耗速度压到产能之内，所以它的停止点主要是"资源耗尽"；买断制不需要闸门，所以它可以把停止点做成"自然完成"，体验更舒服。**

**这条因果链是本课"手游 vs 买断制"对照的核心之一**（[README](./README.md) 第 0 节的第四条）。你在评审手游设计时经常会想"要是没有体力该多好"，答案是：**没有体力，你的内容会在两周内被吃光，然后玩家因为没东西玩而流失——那是比"没体力了"更差的结局。** 闸门是一个不得已但必要的设计，你能做的不是删掉它，是**让停止点尽可能靠近"完成"而不是"被打断"**（第 5.4 节的六个手法）。

## 9. 和数值课的分工：循环 vs 投放

这一节明确边界，避免你在写案子时和数值策划撞车或者留下真空。

[game-numeric 第 07 章（投放设计）](../game-numeric/07-faucets.md)讲的是"每个产出渠道每天投放多少、预算怎么分配"，本章讲的是"循环长什么样、玩家在哪里停"。两者的接口是这样的：

| 问题 | 归谁 | 输出物 |
|---|---|---|
| 这个游戏有几层循环？每层的玩家行为是什么？ | **系统策划（本章）** | 三层循环图 |
| 每层之间的四条接口是什么？ | **系统策划** | 接口说明 |
| 每层有哪些闸门？闸门的**性质**是什么（时间型/次数型/等级型/付费型）？ | **系统策划** | 闸门清单 |
| 一次会话应该多长、一天几次？停止点设计成什么样？ | **系统策划** | 会话设计说明 |
| 体力上限具体是多少、每几分钟回一点？ | **数值** | 配置表 |
| 每天从每个渠道投放多少材料？ | **数值** | 日产出预算表（numeric 07） |
| 这个闸门开合之后，30 天的成长曲线是什么形状？ | **数值** | 成长曲线（numeric 04） |

**分工的关键句式**（你在系统案第 5 节"数值接口"里应该这样写）：

> "理智是一个**时间型闸门**，目标是把玩家的会话结构塑造成**一天两次、每次 10~20 分钟**。请数值按这个会话目标配恢复速率和上限，并保证**攒满一夜的理智能在一次会话里花完**（不要制造溢出焦虑，也不要让玩家一次上线花不完）。"

**注意这句话里没有一个数字，但它给了数值策划三个明确的约束**：会话次数、会话长度、溢出策略。这就是[第 01 章](./01-what-designers-do.md)第 4 节说的"系统策划负责说清楚要什么体验"的具体样子。

反过来，**下面这些话是失职的**：

- "体力上限配 120，6 分钟回 1 点"（越权：你替数值拍了数字，而且没说为什么）
- "体力你看着配"（失职：没给体验约束，数值配出来的一定不是你要的会话结构）

## 10. 常见误区

| 误区 | 为什么错 | 正确的想法 |
|---|---|---|
| "核心循环就是主玩法" | 循环是玩家反复做的**行为序列**，包含玩法但也包含养成、领奖、决策 | 循环图上必须有动作、反馈、资源、闸门四类节点，缺一类就画漏了 |
| "画循环图就是画个圈" | 不标传递内容、不标闸门的圈没有信息量 | 三条纪律：必须闭合、每条边写传了什么、闸门必须画出来 |
| "循环越多越好" | 多条并行循环会争夺玩家的注意力（第 06 章的注意力耦合） | 先保证一条主循环成立，再考虑加第二条 |
| "反馈回路和循环是一回事" | 一个跑资源（系统会不会崩），一个跑行为（玩家为什么继续） | 两张图都要画，回答不同的问题 |
| "玩家说内容太少，那就加内容" | 真实病症可能是循环被掌握了或层间接口断了，加内容是最贵的修法 | 先用第 6 节七病诊断，翻译不出病症就不要动手 |
| "体力是为了逼玩家付费" | 体力主要是**节奏调速器**（控制内容消耗速度、塑造会话结构），付费只是副产品 | 设计体力时先问"我要什么会话结构"，[第 00 章](./00-how-to-learn.md)的率土案例是反例中的正例 |
| "养成就是让数字变大" | 只有量变的养成对 L1 没有可感知的后果，玩家会开自动 | 养成要在核心玩法里给玩家**新的解法**（第 7.4 节） |
| "会话长度是玩家决定的" | 会话长度由闸门恢复速度直接塑造 | 先定会话结构，再让数值倒推闸门参数（第 9 节） |
| "停止点没法设计，玩家想走就走" | 停止点的**质量**完全可以设计（有没有完成感、有没有下一步、有没有损失） | 第 5.4 节的六个手法，特别是第 4 条 |
| "有循环就够了，弧是锦上添花" | 只有循环的游戏没有峰值，玩家两年后想不起任何事，留存只剩沉没成本 | 循环给长度，弧给峰值，两者都要排期 |

## 11. 动手

### 11.1 拆解：给你在玩的那款 SLG 画三层循环图并标注停止点

**这是本章的主作业**，也是第 15 章和第 23 章的前置。用 [templates/deconstruction.md](./templates/deconstruction.md)，重点写第三层（动态层），产出物写进 `notes/拆解/07-循环-游戏名.md`。

**第一部分：三层循环图（用第 3 节的规范画）**

分别画出 L1、L2、L3 三张图，要求：

1. 每张图**必须闭合**，每条边**必须标注传递了什么**
2. 每张图**必须标出所有闸门**（用 `< >`），并注明闸门的性质：时间型 / 次数型 / 等级型 / 付费型 / 社交型
3. 每张图上**标出真决策点**（用 [第 05 章](./05-decisions.md)第 8 节的诊断表判断哪些是真的）。**如果某一层一个真决策都没有，把这件事显眼地写下来**
4. 画一张嵌套关系图（参考第 4 节），标出三层的时间尺度以及相邻两层差几倍

**第二部分：四条接口检查**

照抄第 7.4 节那张表的格式，逐条检查五条接口（含隐藏接口"L2 养成 → L1 体验"）通不通。**每一条不通的，写清楚断在哪里、玩家会因此产生什么感受。**

**第三部分：会话与停止点（连续记录 3 天）**

记录你自己每次上线的：开始时间、结束时间、这次做了什么、**为什么停**（第 5.2 节五种之一）、**下次为什么会回来**（第 5.3 节五种之一）。三天后统计：

1. 一天几次会话、每次多长？和第 5.1 节的品类表对得上吗？
2. 五种停止原因各占多少次？有没有第⑤种（挫败/疲劳）？出现在什么环节？
3. 五种回归动机各占多少次？**如果③社交约定和④损失厌恶加起来超过一半，写下你对这件事的感受**（这是第 21 章的素材）
4. 用第 5.4 节的六条对照表，这款游戏的停止点做到了几条？没做到的那几条，玩家的感受是什么？

**第四部分：诊断**

用第 6 节的七病表，给这款游戏打一遍诊断。**至少找出一条它得的病**（任何一款运营中的游戏都至少有一条），说明症状、在循环图上的位置、以及你会怎么修。

### 11.2 写作作业：一份"会话与循环"设计说明

**产出物写进 `notes/作业/07-循环.md`。**

假设你要给你公司项目（或你拆的那款 SLG）的一个**新玩法**写案子。用 [templates/one-pager.md](./templates/one-pager.md) 写一页纸，但**在标准模板之外额外加下面三节**，这三节是本章特有的要求：

**附加节 A：三层循环定位**

- 这个新玩法挂在哪一层（L1 / L2 / L3）？
- 它和上下层的接口是什么？（上层给它什么、它给上层什么）
- 它会**新增**还是**占用**闸门？如果占用现有闸门（比如也花体力），说明它会和哪些系统产生资源耦合（[第 06 章](./06-systems-and-emergence.md)第 9 节），以及那些系统的参与率会怎么变

**附加节 B：会话设计**

- 玩家一次参与它需要多久？这个时长和现有的会话结构冲突吗？
- 它期望玩家一天参与几次？为什么是这个次数？
- **玩家在什么情况下会停下来？**（五种停止原因中的哪种）
- **玩家为什么明天还会来？**（五种回归动机中的哪种，**不允许只写"资源恢复"**）
- 用第 5.4 节的六个手法，你为这个玩法设计了哪几个停止点手法？

**附加节 C：数值接口（按第 9 节的句式写）**

- 列出这个玩法需要数值配的所有参数
- 对每个参数，**只写体验约束不写数字**。至少写清楚：会话次数目标、会话长度目标、溢出策略
- 检查一遍：你有没有偷偷替数值拍数字？有没有出现"你看着配"？

**自检**：写完之后，让循环图上的每一条边都能回答"这条边如果断了，玩家会怎样"。断了没影响的边，说明它不该在图上。

### 11.3 思考题

1. 第 2.2 节说"玩家怀念的是弧，抱怨的是循环"。那么在做玩家调研时（第 20 章），如果玩家说"我最喜欢的是去年那个联动活动"，你应该往游戏里加更多联动活动吗？为什么？
2. 明日方舟的两个闸门（理智、基建）周期大致同频，都指向一天两次。如果把基建换班周期改成 4 小时，玩家的一天会变成什么样？留存会涨还是跌？（提示：先想会话次数，再想疲劳度，最后想第 5.3 节的回归动机会不会从⑤滑向④。）
3. 《哈迪斯》的循环图上没有任何消耗型闸门。如果要把它改成一款 F2P 手游，你必须在哪里加闸门？加了之后，第 8.2 节的"差异二"（停止点是完成而非耗尽）还保得住吗？有没有办法两者兼得？
4. 第 4.1 节的隐藏接口说"L2 的养成必须能改变 L1 的体验"。SLG 里的养成（练兵、升科技、升级武将）改变了 L1（一场战斗）的什么？如果只改变了战力数字，SLG 靠什么弥补？
5. 一个反直觉的问题：**为什么"离线收益"这个设计能同时缓解焦虑和制造回归动机？** 它属于第 5.3 节五种回归动机的哪一种？如果离线收益上限设得太高（比如攒 48 小时），会破坏什么？
