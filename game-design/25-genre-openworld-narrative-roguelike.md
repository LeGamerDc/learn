## 1. 开场：三种结构在解决同一个问题

把这三样东西放进同一章，看起来是拼盘。它们不是。**它们是同一个问题的三种解法。**

那个问题是：

> **设计者生产内容的速度，永远追不上玩家消耗内容的速度。**

这个比例有多悬殊，做过内容的人都知道【行业口径】：一个团队几个月做出来的关卡，玩家几个小时打完。前面两章的品类各有自己的对策——SLG 让玩家互相生产内容（[第 23 章](./23-genre-slg.md)），收集养成靠持续出角色（[第 24 章](./24-genre-card-rpg.md)）。而本章的三种结构用的是第三种对策：

| 结构 | 用什么放大内容 | 玩家消耗的到底是什么 |
|---|---|---|
| **开放世界** | **空间**：同样的内容散布在一个可自由穿行的空间里，玩家的路径本身成为内容 | 不是关卡，是"我怎么走过去的这段经历" |
| **叙事驱动** | **分支与状态**：同一段剧情因为玩家的选择而不同 | 不是文本，是"这是我做的决定" |
| **Roguelike** | **组合**：几十个元素的随机组合产生近乎无限的局面 | 不是关卡，是"这一局的构筑" |

三种放大方式不一样，但产出的东西是同一个：

> **它们都在用结构制造"玩家自己的故事"。设计者交付的不是故事，是一台能让每个玩家长出不同故事的机器。**

这句话是本章的主线，最后第 9 节会回来把它讲透。

**但要先说清一件事，否则这一章会被误读：三者都能增强玩家的自主经历，可是它们的生产成本和复用效率完全不同，绝不是"没产能时的三种省钱办法"。**

| 结构 | 内容成本 | 素材复用效率 |
|---|---|---|
| **开放世界** | **最贵**：要先造出一个足够大、足够可信、还得处处有东西看的空间，是三者里前期投入最重的 | 中（同一片空间可以被多个版本反复使用，但每次加内容仍要做新场景） |
| **叙事分支** | 看结构：真分支的成本随选择数指数增长；分支汇合与状态追踪可控（第 7 节） | **最低**（真分支写出来的内容，多数玩家一辈子只看到其中一条） |
| **Roguelike** | **最低**：几十个元素 + 一套组合规则 | **最高**（同一批元素被反复重组，这才是真正的"少量素材换大量局面"） |

所以对你的实际意义不是"缺内容就上这三样"，而是：**当你要放大玩家的自主经历时，先按你手上的产能结构挑工具——有世界与美术产能就用空间，有文案产能就用状态，只有玩法产能就用组合。** 手游里的开放世界、剧情分支、roguelike 模式，都是这三台机器的移植版本，而移植时最先撞上的墙就是这张表。

## 2. 三种结构的定义与谱系

### 2.1 开放世界的谱系

"开放世界"被用得很滥。真正有设计意义的区分是**玩家的自由度落在哪一层**：

| 分支 | 自由的是什么 | 典型结构 | 代表 |
|---|---|---|---|
| **开放地图 + 任务板** | 只有"先做哪个任务"自由，任务本身是线性的 | 地图是任务的容器 | 大量开放世界 RPG、多数手游"大世界" |
| **开放世界（探索驱动）** | **路径**与**顺序**都自由，地图本身承载内容 | 地标 → 探索 → 发现 → 新地标 | 《塞尔达传说：旷野之息》 |
| **沙盒（系统驱动）** | 连**目标**都是玩家自己定的 | 一套可自由组合的系统规则 | 生存建造类 |

**本章讲的是中间那一类**，因为它是设计难度最高、也最值得学的一类。左边那类本质上是"把关卡列表铺在地图上"，右边那类的核心问题在系统设计（[第 06 章](./06-systems-and-emergence.md)）而不是空间设计。

### 2.2 叙事驱动的谱系

| 分支 | 玩家的输入 | 结构成本 | 代表形态 |
|---|---|---|---|
| **线性叙事 + 演出** | 无（只是推进） | 低 | 大部分手游主线剧情 |
| **选择驱动（分支/汇合）** | 关键节点做选择 | 中 | 选择驱动的叙事 RPG |
| **状态追踪型** | 大量小选择累积成状态，后期结算 | **高**（组合爆炸） | 深度叙事 RPG |
| **环境叙事 / 涌现叙事** | 玩家自己拼出故事 | 低到中，但设计功力要求高 | 探索类、系统驱动类 |

[第 12 章](./12-narrative.md) 讲过叙事的四层与 ludonarrative 一致性，**本章不重讲**，只讲一件那一章没细讲的事：**选择与后果的结构该怎么搭，以及它的成本**。

### 2.3 Roguelike 的谱系

| 分支 | 死亡后保留什么 | run 长度 | 代表 |
|---|---|---|---|
| **传统 roguelike** | 几乎什么都不留 | 数小时 | 早期地牢探索类 |
| **Roguelite（带元进度）** | 永久解锁与永久强化 | 20~60 分钟 | 《哈迪斯》 |
| **构筑型 roguelike** | 只留知识与解锁的选项，不留数值 | 40~90 分钟 | 《杀戮尖塔》 |
| **割草 / 生存肉鸽（手游）** | 强元进度 | **3~15 分钟** | 微信小游戏的主力品类之一 |

**注意最后一行的 run 长度：它是手游移植时改动最大的一个参数，也是所有其他改动的源头。** 第 8 节会展开。

### 2.4 本章的边界

- 关卡设计的通用方法、引导手段、节奏曲线 → [第 17 章](./17-level-design.md)
- 叙事的四层、ludonarrative、环境叙事的原理 → [第 12 章](./12-narrative.md)
- 输入随机 vs 输出随机、玩家对随机的感知 → [第 10 章](./10-randomness.md)
- 手游 roguelike 的数值（构筑多样性判据、协同倍率、方差归因、广告点位）→ [game-solo 07~09 章](../game-solo/07-build-diversity.md)
- **本章只讲这三种结构独有的设计问题。**

## 3. 开放世界之一：引导，或者说"怎么让玩家自己想去"

### 3.1 这个品类独有的矛盾

线性关卡的引导问题是"怎么让玩家走对路"（[第 17 章](./17-level-design.md) 的视线、光、颜色、路径）。开放世界的引导问题完全不同：

> **玩家有一百个方向可以走，你不能指定方向，但你必须保证他不会站在原地不知道去哪。**

这是一个**牵引**问题，不是一个**指路**问题。指路是"往这边走"；牵引是"让他自己想往那边走"。

### 3.2 三角形法则与"引力"

任天堂在 2017 年就《塞尔达传说：旷野之息》做过两场性质不同的公开分享，**引用时要分开**：

- **GDC 2017**，*Change and Constant: Breaking Conventions with The Legend of Zelda: Breath of the Wild*（Hidemaro Fujibayashi、Satoru Takizawa、Takuhiro Dohta）【实证】。这一场讲的是系统层面的设计，[第 06 章](./06-systems-and-emergence.md) 引用的"化学引擎"（乘法式的玩法交互）出自这里。
- **CEDEC 2017** 关于《旷野之息》场景 / 地形制作的分享【实证】。**下面这两条地形方法——三角形法则与"引力"——出自这一场**，不是 GDC 那场。

这两条对任何做开放世界的人都直接可用：

**三角形法则**：地形里大量使用三角形（山、坡、岩体）。一个三角形同时做三件事：

1. **遮挡**：挡住后面的东西，制造"翻过去看看"的动机；
2. **再暴露**：翻过去/绕过去之后，新的景象一次性展开，制造"发现"的高光；
3. **给选择**：面对一座三角形的山，玩家可以绕左、绕右、或者爬过去，**三种选择的成本和收益不同**，于是一个纯地形障碍变成了一个决策（[第 05 章](./05-decisions.md)）。

**引力（gravitational pull）**：设计者在地图上布置"引力点"——玩家从任何位置抬头，视野里都应该有至少一个让他想去的东西（塔、遗迹、烟、异常的地貌）。走向 A 的路上会看到 B，到了 B 又看到 C。**玩家永远在被下一个东西拉着走，而这条路径是他自己选的。**

这两条合起来构成了开放世界引导的核心循环：

```
        ┌──────────────────────────────────────────┐
        │                                          │
        ▼                                          │
   ┌─────────┐    ┌─────────┐    ┌─────────┐    ┌─────────┐
   │ 看见远处 │ →  │ 决定去   │ →  │ 路上被   │ →  │ 到达 /   │
   │ 的东西   │    │ 哪个     │    │ 别的东西 │    │ 发现新的 │
   │（引力点）│    │（决策）  │    │ 打断     │    │ 引力点   │
   └─────────┘    └─────────┘    └─────────┘    └─────────┘
                                      │
                                      └─→ "我本来是要去 A 的" ← 玩家自己的故事从这里产生
```

**"路上被打断"那一步是整个循环里最重要的一步，也是最反直觉的一步。** 从任务系统的角度看，玩家没有直达目标是效率损失；从体验角度看，**"我本来要去 A，结果在路上发现了 B"就是玩家自己的故事的原材料**。设计上要保护它：不要给太强的自动寻路，不要让路径变成传送。

### 3.3 手游对照

手游里的开放世界（《原神》是最典型的）显然继承了引力点的做法：视野里总有可攀爬的高处、发光的宝箱、异常的地貌。但手游有三个约束会削弱它：

| 约束 | 影响 |
|---|---|
| **屏幕小、视野窄** | 远景的引力点看不清，需要更强的视觉信号（发光、轮廓描边、更大体量的地标） |
| **触屏操作精度低** | 复杂地形的攀爬/滑翔操作成本高，玩家更倾向走大路 |
| **会话短、目的性强**（[第 07 章](./07-loops.md)） | 玩家上线常常是"做日常"而不是"逛"，探索循环被日常循环挤压 |

**第三条是最本质的，它导致了一个结构性后果**：手游的开放世界必须同时容纳"闲逛型会话"和"打卡型会话"，而这两种会话对同一个空间的要求是相反的（前者要绕、要发现；后者要快、要直达）。多数手游的解法是**分层**：给打卡型会话传送点和任务标记，给闲逛型会话保留未标记的区域。**这个分层做得好不好，直接决定了开放世界是"世界"还是"带风景的菜单"**【推导】。

## 4. 开放世界之二：内容密度与"空"的价值

### 4.1 密度不是越高越好

新手（尤其是从手游过来的策划）设计开放世界的本能是"把地图填满"：每 50 米一个收集品，每个角落一个宝箱。结果是两个后果同时发生：

1. **发现失去价值**。到处都有东西，找到东西就不再是发现，只是拾取。
2. **玩家变成清单执行者**。一旦玩家意识到"地图上所有点都能被标记出来"，他就从探索者变成了扫图机器，体验从"我想去看看"变成"还剩 37 个没收"。

**"清单式开放世界"是这个结构最常见的失败形态。** 它的诊断信号很清楚：玩家打开地图的次数远多于抬头看世界的次数。

### 4.2 "空"在做什么

留白不是内容缺失，它有三个明确的功能：

| 功能 | 说明 |
|---|---|
| **呼吸** | 高密度的刺激需要低密度的间隔才有对比。这就是 [第 17 章](./17-level-design.md) 的节奏曲线在空间上的版本——一张全是高潮的地图等于没有高潮 |
| **期待** | 一段长而空的路会积累"前面应该有什么"的预期，让终点的内容收益翻倍 |
| **规模感** | 世界之所以让人觉得大，是因为有走了很久什么也没有的地方。**填满的世界感觉是小的** |

### 4.3 可操作的密度设计法

一个能落到案子上的做法【行业口径】：**不要用"每平方公里几个兴趣点"来定密度，用"玩家每次移动的时间预算"来定。**

```
   玩家从一个引力点走到下一个引力点，应该花多久？
        ↓
   30 秒 → 密度过高，变成清单
   1~3 分钟 → 主要区域的典型密度（路上有小事件）
   3~8 分钟 → 边缘区域，制造规模感与期待
   > 8 分钟 → 需要有非常强的目标牵引，否则玩家会觉得"在赶路"
```

同时给"路上"分层：

| 层级 | 内容 | 玩家的反应 |
|---|---|---|
| **主目标**（大地标） | 需要专门去一趟 | "我今天要去那个塔" |
| **次目标**（中等发现） | 路过顺手做 | "顺路把这个打了" |
| **微内容**（可交互的小东西） | 几乎不打断行进 | 让"空"不完全空 |
| **纯留白** | 无 | 呼吸与规模感 |

**做案子时的检查：把这四层在地图上标出来，看比例。如果微内容和次目标铺满了整张图，你做的是清单不是世界。**

## 5. 开放世界之三：目标的自我生成

### 5.1 为什么这是这个结构独有的问题

线性游戏里，玩家的目标由设计者给出。开放世界里，如果所有目标都由设计者给出（任务列表），那它就退化成了第 2.1 节的"开放地图 + 任务板"。

**真正的开放世界要求玩家能自己产生目标。** 这是一个非常具体的设计问题：什么样的结构会让玩家自己给自己定目标？

### 5.2 四个条件

Doug Church 在 *Formal Abstract Design Tools*（1999）里提出的三个工具中，有两个正好是这个问题的答案【实证】：**意图（intention）**——玩家能形成一个计划；**可感知的后果（perceivable consequence）**——他能看到计划的结果。加上开放世界的两个额外条件，凑成四条：

| 条件 | 说明 | 反例 |
|---|---|---|
| **可见的远处目标** | 玩家必须能"看到"目标而不只是"被告知"目标 | 只在地图上有标记、在世界里看不见的目标，不会产生"我要去那儿"的冲动 |
| **多解的问题** | 同一个障碍有多种解法，玩家才会规划"我要怎么做到" | 只有一条路能过的障碍，玩家不需要形成意图，只需要执行 |
| **可组合的工具** | 玩家手上的能力可以互相组合，产生设计者没预设的解法 | 每个道具只有一种用途 = 每个问题只有一把钥匙 |
| **无强制顺序** | 玩家可以先做后面的事 | 强制解锁顺序会把"我想去"变成"还没到时候" |

第三条正是 GDC 2017 那场 *Change and Constant* 里"化学引擎"的意义【实证】：一套统一的物理/元素规则（火会烧、金属会导电、风会推），让玩家的工具互相作用，于是每个问题都有多解，于是玩家开始规划，于是目标由玩家自己生成。

**注意这条线索的完整因果链**：

```
统一的交互规则 → 多解 → 玩家形成意图（"我要试试用 X 解决 Y"）
    → 可感知的后果（成功或失败都看得见）→ 玩家自己的故事
```

**手游对照**：《原神》的元素反应系统（[第 24 章](./24-genre-card-rpg.md) 拆解过它的战斗面）同时也承担了这个角色——用火烧草、用雷导电、用冰在水面搭桥。**同一套规则同时服务战斗、解谜和探索，这是这类设计最高的性价比：一套规则，三处内容**【推导】。这一点值得任何做手游大世界的策划抄：与其做三套系统，不如做一套能被三个场景复用的规则。

## 6. 开放世界之四：手游移植的取舍

把开放世界搬进 F2P 手游，有四个必须做的取舍。这一节全部是【推导】——从公开表现反推的判断。

| 取舍 | 买断制开放世界的做法 | 手游的做法与原因 | 代价 |
|---|---|---|---|
| **探索产出 vs 日常循环** | 探索本身就是主要产出（装备、能力、剧情） | **把探索产出与养成资源隔开**：探索给一次性收益（宝箱、剧情、成就），养成资源锁在体力制的副本里 | 探索是一次性的，探完就不再回来；世界从"生活的地方"变成"看过的地方" |
| **会话长度** | 一次玩两小时，鼓励迷路 | 一次玩 15~30 分钟，需要明确的完成感 | 闲逛型会话被日常挤压（第 3.3 节） |
| **操作复杂度** | 手柄，多按键，复杂地形交互 | 触屏，简化操作，减少精细跳跃/攀爬要求 | 地形的"决策性"下降，第 3.2 节的三角形法则效果减弱 |
| **商业化载体** | 无（买断） | 角色抽卡。**于是开放世界主要承担"叙事与美术的展示场"以及"角色的活动场"，而不是"资源循环的主战场"** | 开放世界与核心付费循环的耦合弱，容易变成"很贵的背景板" |

**最后一行是本节最重要的判断【推导】**。讲清它之前要先拆开三个常被混为一谈的东西：

| 说的是哪个循环 | 指什么 | 开放世界能不能承担 |
|---|---|---|
| **核心玩法循环** | 探索 → 战斗 → 奖励 → 更能探索 | **完全可以**，这本来就是开放世界的形状 |
| **日常循环** | 每天上线要做、且能反复做、产出可再生的那一套（[第 07 章](./07-loops.md)） | **难以单独承担**——探索产出是一次性的，探完就不再生 |
| **商业化循环** | 付费在哪一环接入 | 通常不直接接入，付费挂在角色抽卡上 |

**所以准确的说法是：开放世界在 F2P 手游里可以是核心玩法，但很难单独撑起长期的日常循环。** 于是它的实际职责通常是三个：

1. **首因体验与买量素材**（第一小时的震撼决定了转化）；
2. **叙事与角色的容器**（让抽到的角色有一个"存在"的地方，强化情感投入，这是回到 [第 24 章](./24-genre-card-rpg.md) 的"叙事身份"）；
3. **差异化的护城河**（同品类里做不出来的东西）。

**这三个职责都成立，但没有一个能单独撑起日常留存。** 所以做手游大世界的团队必须清醒：**你需要另一套可再生的日常循环来撑留存，开放世界撑的是首因、情感和差异化。** 把这一点写进设计支柱（[第 27 章](./27-lead-designer.md)），可以省掉后面两年里无数次"为什么大世界没人逛"的争论。

## 7. 叙事驱动：选择与后果的结构

[第 12 章](./12-narrative.md) 讲过叙事的四层、结构和 ludonarrative 一致性。本节只补一件事：**选择与后果在工程上怎么搭，以及每种搭法的成本。**

### 7.1 三种结构

```
 ① 树状分支（Branching）           ② 分支汇合（Branch & Bottleneck）      ③ 状态追踪（State Tracking）

      ●                                   ●                                  ●
     / \                                 / \                                 │   [记录: 你救了他]
    ●   ●                               ●   ●                                ●
   / \ / \                               \ /                                 │   [记录: 你说了谎]
  ●  ● ●  ●                               ●  ← 汇合点                        ●
 内容量 2^n                              / \                                 │
 成本爆炸                               ●   ●                                ●  ← 结算时读取所有记录
                                         \ /
                                          ●
```

| 结构 | 内容成本 | 玩家感受 | 适用 |
|---|---|---|---|
| **树状分支** | **指数级**，n 个选择要 2ⁿ 段内容 | 选择"很重" | 只在极短的段落里可行 |
| **分支汇合** | 线性可控（每个分支只写一小段就汇合） | 短期有 agency，长期发现"殊途同归" | **绝大多数商业游戏的实际做法** |
| **状态追踪** | 中（内容量线性，但**测试与验证成本高**） | 后期突然发现前期的小事被记住了，冲击力最强 | 需要严格的状态管理与工具支持 |

**给你的工程直觉一个类比**：树状分支是把所有可能的状态都物化成内容（内存爆炸）；状态追踪是只存状态、在需要时计算表现（内存小但逻辑复杂、测试组合爆炸）。**做叙事系统时你要做的就是这个经典取舍。**

### 7.2 一条实用准则：后果要被"提及"，不一定要被"实现"

状态追踪之所以性价比高，是因为**玩家感受到的"后果"，大部分可以是叙事上的提及，而不是玩法上的分歧**：

- 昂贵：因为你救了那个人，第三章多出一整条支线（内容成本高）
- 便宜且几乎同样有效：因为你救了那个人，第三章有个 NPC 说了一句"听说你在 X 城救了人"（内容成本极低）

**多数时候玩家要的是"我的选择被记住了"，而不是"我的选择改变了流程"**【行业口径】。抓住这一条，你可以用很低的成本制造很强的 agency 感。在手游的内容产能约束下，这通常是最现实可行的选择系统做法【推导】——真分支不是做不了，是很难在每个版本里持续供给。

### 7.3 玩家 agency 与作者控制的平衡

这是叙事设计永恒的张力：

| 偏向玩家 agency | 偏向作者控制 |
|---|---|
| 玩家的选择真的改变结局 | 故事的质量、节奏、主题得到保证 |
| 玩家有主人翁感 | 高潮和情感冲击可以被精确设计 |
| 风险：故事变得平庸（因为每条分支都要写好很难）；玩家做了选择但没得到好故事 | 风险：**ludonarrative 不一致**——玩法说"你是自由的"，剧情说"你必须这么做" |

Clint Hocking 在 2007 年那篇讨论 BioShock 的博客里提出的 ludonarrative dissonance【实证】，讲的正是这个：一个游戏的玩法在鼓励一种价值（自利、掠夺），而它的剧情在宣扬另一种价值（利他、反抗），两者互相拆台。

**给系统策划的可操作结论**：在写任何带选择的系统案时，明确写下**"这个选择改变的是玩法、是叙事、还是只是措辞"**。三者成本差一个数量级，而团队里最常见的事故就是文案以为是第一种、程序按第三种实现、玩家期待第二种。

### 7.4 手游的现实

手游叙事分量普遍低的原因 [第 12 章](./12-narrative.md) 讲过。这里补一个品类角度的结论：**手游里能承担"选择与后果"的地方非常有限，但有两个位置是划算的**：

1. **角色好感/羁绊线**（[第 24 章](./24-genre-card-rpg.md) 的叙事身份）：小规模、可复用、直接服务于角色的情感价值；
2. **限时活动剧情**：一次性内容，可以承受一些分支成本，且分支本身是活动的话题点。

主线剧情做真分支在手游里风险很高【推导】：产能通常撑不住，且它会和"所有玩家看同一个版本"的运营节奏冲突（版本公告、剧情向活动、社区讨论都默认大家看的是同一段内容）。要做，就得先想清楚分支在之后每一个版本里怎么继续供给——**分支的成本不是发布那一次，是往后每一次。**

## 8. Roguelike：run 结构、随机构建与元进度

### 8.1 run 结构：一局的长度决定了一切

**"一局多长"是 roguelike 设计的第一个、也是最有传导性的决定。** 它决定了：

| run 长度 | 死亡的代价 | 构筑深度上限 | 元进度的必要性 | 典型平台 |
|---|---|---|---|---|
| **3~10 分钟** | 几乎无痛 | 低（来不及成型） | **极高**（否则没有长期目标） | 手游 / 小游戏 |
| **20~40 分钟** | 有感但可接受 | 中 | 高 | 主机 / PC 动作 roguelite |
| **40~90 分钟** | 明显（会心疼） | **高**（构筑能完整成型并被检验） | 中（可以只解锁选项不解锁数值） | PC 构筑类 |
| **数小时** | 极重 | 高 | 低（传统 roguelike 靠玩家自己的知识增长） | 传统 roguelike |

**一条经验准则【行业口径】**：**run 越短，元进度通常要越强；run 越长，元进度可以越弱。** 因为 run 内的成就感和 run 外的成就感是替代关系——一局能提供完整的构筑弧线时，玩家不需要外部进度来证明自己在前进；一局只有三分钟时，run 内什么都成不了型，往往得靠元进度提供"我在变强"的长期感。

**这条准则有明确的反例，别当定律用**：短 run 但用排行榜、每日挑战、社交攀比来提供长期目标的产品，元进度可以做得很轻；长 run 但走内容解锁路线的产品，元进度的"条数"也可能很多，只是不给数值。**真正不变的是那个替代关系本身：长期目标总得有人提供，元进度只是提供它的方式之一。**

### 8.2 run 内的弧线

一局 roguelike 内部有一条标准的三段弧线，它和 [第 07 章](./07-loops.md) 的循环、[第 08 章](./08-goals-progression-rewards.md) 的目标层级是对应的：

```
 ┌──── 起步期 ────┬──── 成型期 ────┬──── 检验期 ────┐
 │ 选项少、随机   │ 找到方向、开始 │ 构筑基本定型、 │
 │ 权重高、玩家   │ 围绕一个思路   │ 面对最强的考验 │
 │ 在"接受命运"   │ 做取舍         │                │
 │                │                │                │
 │ 体验：好奇     │ 体验：规划     │ 体验：验证     │
 │ 决策：少而重   │ 决策：多而难   │ 决策：执行为主 │
 └────────────────┴────────────────┴────────────────┘
      ↑ 这里最容易"开局就废"        ↑ 这里最容易"稳赢无聊"
```

两端各有一个典型病症，都值得单独设计：

- **"开局就废"**：前几个随机选项全是垃圾，玩家知道这局没戏但还得打完。解法：起步期给保底（首次选择质量下限）、允许快速重开、或者让起步期的随机影响小一些。
- **"稳赢无聊"**：构筑成型后碾压一切，剩下的时间是执行不是玩。解法：把最大的挑战放在最后（Boss、难度递增），或者给玩家"主动加难度"的选项。

### 8.3 随机构建与 build 的涌现

输入随机与输出随机的区别见 [第 10 章](./10-randomness.md)，"随机的位置决定了它是玩法还是收费"这条与抽卡的对照见 [第 24 章第 2.1 节](./24-genre-card-rpg.md)，这里不重复。**只留一句：Roguelike 是输入随机最纯粹的形态**——随机先发生，玩家用决策去应对它。

制造"构筑涌现"的四个手段：

| 手段 | 作用 | 代价 |
|---|---|---|
| **稀缺的选择**（三选一、只能带 N 个） | 每次获得都是一次取舍，构筑因此有方向 | 选项池要足够大，否则重复感强 |
| **协同放大**（几个元素组合起来效果远超相加） | 制造"我发现了一套组合"的高光，是这个结构最强的爽点 | 协同过强 → 只有一条最优路线；数值面见 [game-solo 第 08 章](../game-solo/08-synergy-scaling.md) |
| **携带上限 / 空间限制** | 强迫取舍，防止无脑全拿 | 上限太紧会让玩家不敢拿，探索欲下降 |
| **商店与事件作为调节阀** | 让玩家用资源"纠偏"（买想要的、删不要的） | 调节太强会削弱随机性本身的意义 |

**关键判据：一个 build 好不好，看玩家会不会给它起名字。** 玩家自发命名一套组合（"XX 流"），说明这套组合有清晰的身份、可复现、且需要被讨论——这三点合起来正是 build 深度成立的证据。这个判据在 [第 24 章](./24-genre-card-rpg.md) 讲阵容深度时也用过一次，它是通用的。

**数值面**：构筑多样性怎么量化、怎么判断池子是不是有效、超模组合怎么处理，见 [game-solo 第 07 章](../game-solo/07-build-diversity.md)。本章不重复。

### 8.4 元进度：让"失败也在前进"

Roguelike 的核心体验是失败，而 F2P 乃至所有商业游戏都受不了纯粹的失败。**元进度（meta-progression）就是这个矛盾的解法：run 内失败，run 外前进。**

元进度有三种，性质完全不同：

| 类型 | 内容 | 优点 | 危险 |
|---|---|---|---|
| **数值型** | 永久属性提升（血量 +5%、伤害 +3%） | 最容易做，最容易感知 | **腐蚀 run 内的技能表达**：玩家失败时会归因为"我练度不够"而不是"我打法不对"，游戏从技巧游戏滑向养成游戏 |
| **内容型** | 解锁新角色、新武器、新道具进入随机池 | **增加可能性空间而不是增加强度**，是最健康的一种 | 早期池子小，前几局的多样性不足 |
| **叙事型** | 每次死亡推进剧情、角色关系、世界观 | 让失败本身有意义，且几乎不影响平衡 | 内容成本高（需要大量上下文相关的对白） |

**一条准则**：**数值型元进度是止痛药，内容型是营养，叙事型是奢侈品。** 三者的配比取决于你的 run 长度和商业模式：

- 长 run 的构筑型 → 主要用内容型（解锁选项），数值型尽量少或做成"难度选项"；
- 短 run 的手游 → 必须有数值型（否则前几局太弱、留存撑不住），但要设计"数值型的终点"，否则后期玩家碾压一切；
- 有叙事野心的 → 叙事型是把 roguelike 从"玩法"变成"作品"的关键。

**《哈迪斯》是叙事型元进度最有名的实现**。Supergiant 的 Greg Kasavin（创意总监）与 Darren Korb（音频总监）在 GDC 2021 的 *Breathing Life into Greek Myth: The Dialogue of 'Hades'* 里讲过这套对白系统怎么写、怎么录、怎么在早期访问期间持续扩充【实证】。从玩家能观察到的规则看：每次死亡后玩家回到同一个起点，那里的 NPC 会对**这一次**的死亡做出反应——死在哪、被谁杀、这次带了什么武器、你和谁的关系推进到哪一步，都会影响他们说什么。**于是"又死了"这件事从惩罚变成了推进剧情的方式**【推导】。

这是一个可以直接迁移的设计模式：

> **把失败绑定到一个"每次都会发生、但每次内容不同"的仪式上，失败就不再是纯损失。** 这个仪式可以是叙事（对话），也可以是别的（结算画面里的成长记录、解锁提示、下一局的建议）。

### 8.5 一个反直觉的判断【推导】

**元进度做得太强，会杀死 roguelike。** 因为这个结构的核心快感是"这一局我打得好"，而强元进度会把归因转移到"我练度够了"。一旦玩家开始相信"打不过就多刷几局攒资源"，他就不再研究这一局怎么打，游戏的技能维度坍塌成时间维度。

**诊断信号**：玩家论坛里讨论的是"多少级能过"而不是"怎么配能过"。

## 9. 三种结构的共同点：用结构制造"玩家自己的故事"

回到第 1 节的主线。把三种结构并排放：

| | 开放世界 | 叙事驱动 | Roguelike |
|---|---|---|---|
| **稀缺资源是什么** | 时间与注意力（去哪、走多远） | 选择的不可撤销性 | 局内资源（生命、金钱、格子、回合） |
| **随机 / 变化在哪** | 也有随机（天气、掉落、敌人行为、遭遇），但**结构上的变化主要来自玩家的路径选择** | 随机很少，**分歧来自玩家的选择** | 输入随机（局内），且它就是结构变化的主要来源 |
| **玩家的故事从哪来** | "我本来要去 A，结果……" | "我当时选了 B，所以……" | "这局我拿到了 C，于是……" |
| **内容被放大的倍数来自** | 空间的排列 | 状态的组合 | 元素的组合 |
| **设计者交付的** | 一个可穿行的空间 + 引力点 | 一套状态与它的读取点 | 一个元素池 + 一套获取规则 |
| **失败的意义** | 有失败（死亡、任务失败、资源损失），但**失败不是探索结构的必要终止条件**——玩家可以从任意一点继续探索 | 后果（不可撤销） | run 结束（重来）：**失败就是这个结构的终止点** |

**共同的设计工作是同一件事：设计者不写故事，设计者写一台机器，让玩家在使用它的过程中长出故事。**

这台机器有三个共同的零件，无论你做哪一种：

1. **可感知的因果**（Doug Church 的 perceivable consequence）：玩家必须能看到"因为我做了 X，所以 Y"。看不到因果，就没有故事，只有事件流水。
2. **不可撤销性**：可以随便读档/重来的选择不产生故事。开放世界靠时间成本，叙事靠存档设计，roguelike 靠 run 的一次性。
3. **可讲述性**：结果必须能被玩家用一句话讲给别人听。**"我的故事"必须是可复述的，否则它只是一段经历。** 这也是社区、攻略、短视频传播的原材料——**对手游而言，这直接就是买量素材和自然流量**。

**给你写案子的直接用法**：当你要在一款手游里加一个"玩家自己的故事"的模块时，检查这三个零件是否齐全。缺"可感知的因果"，玩家不知道为什么赢；缺"不可撤销性"，玩家不在乎；缺"可讲述性"，你得不到传播。

## 10. 代表作拆解

按 [第 00 章](./00-how-to-learn.md) 的纪律：机制层写可观察的规则结构，**具体数值与版本细节以你自己验证到的为准**；意图层一律 `【推导】`。

### 10.1 《杀戮尖塔》：run 结构与构筑

**为什么选这个系统**：它是"输入随机 + 构筑涌现"最干净的实现，而且它的设计者在 GDC 2019 公开讲过他们怎么用数据做平衡（Giovannetti, *Slay the Spire: Metrics Driven Design and Balance*）【实证】，是少数有一手来源的案例。

**机制层（规则结构）**

1. 一局由若干幕组成，每一幕是一张**从下往上的分支路径地图**，玩家在开局就能看到整张图，并选择自己的路线。
2. 节点类型包括：普通战斗、精英战斗、休息处、商店、宝箱、未知事件、Boss。**不同节点的收益与风险不同，于是"怎么走"本身是一次贯穿全幕的规划。**
3. 战斗胜利后从**三张牌里选一张**加入卡组（可以跳过）。这是构筑的主要输入，也是最频繁的决策点。
4. **卡组是累积的**：加进去的牌会一直在。因此"不拿"是一个真实的策略——卡组越厚，抽到关键牌的概率越低。
5. 遗物提供永久被动效果，主要来自精英战斗、Boss 和商店。遗物往往比单张卡更能定义一局的方向。
6. **生命值跨战斗保留**，只能在休息处恢复。于是生命值是一种贯穿全局的战略资源，而不是每场重置的战术资源。
7. 休息处通常是**二选一**：回血，或者升级一张卡。这是全局最常见的"当下 vs 长期"取舍。
8. 商店可以买卡/遗物/药水，也可以**花钱删牌**——删牌是构筑的减法工具，稀缺且昂贵。
9. 战斗内每回合有能量上限、抽固定张数、回合结束弃手牌。**这套约束让"卡组质量"直接决定"每回合能做什么"。**

**动态层**

- **两个层级的构筑同时进行**：宏观是"我这局要走什么路线"（卡组方向、走不走精英），微观是"这一回合怎么打"。两层互相影响，这是它耐玩的核心。
- **"不拿牌"和"删牌"是高级玩家与新手的分水岭。** 新手看到三选一就想拿，老手知道卡组厚度是隐形代价。**一个"跳过"按钮制造了这个游戏最深的一层决策**，这是极高效率的设计。
- **生命值跨战斗保留**把每一场战斗都变成了"赢了但花了多少代价"，而不只是输赢。于是玩家会为了省血而改变打法。
- **地图路线可见**让玩家在幕开始时就能规划：走精英多的路（高风险高遗物）还是走商店休息多的路（稳）。**这就是第 5 节说的"意图"——玩家先形成计划，再执行，再看到后果。**
- **涌现**：玩家自发命名了大量流派，并围绕"什么牌配什么遗物"形成了庞大的社区知识体系。

**决策层**

| 决策点 | 选项 | 信息是否充分 | 有无明显最优解 |
|---|---|---|---|
| 幕开始时的路线 | 精英多 vs 商店/休息多 | 充分（整张图可见） | 没有，取决于当前血量与构筑。**好决策** |
| 三选一拿哪张 / 跳过 | 加强方向 vs 保持卡组精简 | 充分 | 没有，**这是全局最好的决策点** |
| 休息处回血还是升级 | 短期生存 vs 长期强度 | 充分 | 没有，**好决策** |
| 金币花在买牌、买遗物还是删牌 | 加法 vs 减法 | 充分 | 没有，**好决策** |
| 战斗内出牌顺序 | 执行层 | 充分 | 有较优解，属于技巧 |

**意图层【推导】**

- **职责**：这套结构让"随机"变成了"题目"而不是"判决"。每一局给你一手不同的牌，你的水平体现在你能用这手牌打到多远。
- **删掉会怎样**：如果去掉"跳过"和"删牌"（只能加牌），构筑就退化成收集，卡组越来越臃肿，玩家的水平差异消失；如果去掉"生命值跨战斗保留"，每场战斗都独立，战略层消失，只剩战术层。**这两条规则各撑起了这个游戏的一半深度。**
- **一句话设计目标**：**用"稀缺的加法 + 昂贵的减法 + 跨战斗的资源"，把一手随机的牌变成一道每次都不一样、但每次都有解的题。**

**可复用模式**：**"减法也要设计"**——任何构筑系统都要同时设计"怎么获得"和"怎么去掉"。只有加法的构筑系统会稳定地滑向"全都要"，从而消灭取舍。这条模式在手游的养成、天赋、装备系统上同样成立。

### 10.2 《哈迪斯》：元进度与失败的意义

**为什么选这个系统**：它是"叙事型元进度"的代表，也是"失败不再是纯损失"这条设计原则最完整的实现。Kasavin 与 Korb 在 GDC 2021 的 *Breathing Life into Greek Myth: The Dialogue of 'Hades'* 里讲过它的对白规模与制作流程【实证】。

**机制层（规则结构）**

1. 一次 run 从固定起点出发，穿过若干个区域，每个区域由一连串房间组成；**房间之间的门上会显示下一个房间的奖励类型**，玩家据此选择走哪扇门。
2. 主要的 run 内构筑来自**神明的赐福**：不同的神提供不同类型的效果，赐福会附加到玩家的某个动作上（普攻、特殊技、冲刺、法术等）。**因为槽位有限，"这个神的赐福加在哪个动作上"是一次取舍。**
3. 部分赐福需要**前置组合**才能出现（需要先拥有特定两位神的特定赐福），于是玩家会主动追求某种神明搭配。
4. 武器有多种，且每种武器有不同形态，改变基础手感与打法。
5. **死亡后回到起点**，run 内的赐福全部失去。
6. **元进度分成几条**：一种资源用于解锁/提升永久能力（可随时重新分配）；另一种用于解锁新的选项与内容；礼物类资源用于推进与 NPC 的关系并解锁剧情。
7. **难度是玩家自选的**：通关后可以主动叠加限制条件来提高难度与收益。
8. 每次死亡后回到起点时，NPC 会**针对这一次的具体情况**说话（死在哪、进度如何、关系推进到哪）。

**动态层**

- **"看得见的门"把随机变成了选择。** 玩家不是被随机丢进下一个房间，而是在两三个已知奖励类型的门之间选——**这一个小设计把大量输出随机改造成了输入随机**（[第 10 章](./10-randomness.md)）。
- **槽位有限 + 组合赐福**制造了一局之内的构筑目标："我这局想凑出 X"，于是玩家有了自己给自己定的目标（第 5 节的"意图"）。
- **死亡的三重收益**：带回资源（数值元进度）、推进剧情（叙事元进度）、增长知识（玩家自己的技能）。**三条同时前进，所以失败几乎不产生"白玩了"的感觉。**
- **可重新分配的永久能力**让元进度不惩罚试错，玩家愿意换打法。
- **自选难度**把"太简单了"这个后期问题交还给玩家自己解决，同时让高手有可炫耀的目标。

**决策层**

| 决策点 | 选项 | 信息 | 有无明显最优解 |
|---|---|---|---|
| 走哪扇门 | 已知的奖励类型 | 充分（门上写着） | 没有，取决于当前构筑缺什么。**好决策** |
| 赐福加在哪个动作上 | 槽位取舍 | 充分 | 没有，**好决策** |
| 要不要为了凑组合而绕路 | 追求强力组合 vs 拿稳当的收益 | 部分（不知道后面会遇到谁） | 没有，**好决策** |
| 永久能力怎么分配 | 元进度取舍 | 充分，且可撤销 | 有较优解，但因为可重配所以不惩罚 |
| 要不要加难度 | 收益 vs 风险 | 充分 | 玩家自定义 |

**意图层【推导】**

- **职责**：这套元进度体系的真正目的不是让玩家变强，是**让每一次失败都有一件事在前进**。数值、剧情、知识三条线里，任何一条动了，玩家就不会觉得这局白打。
- **删掉叙事型元进度会怎样**：游戏仍然成立，但它会变成一个"很好的动作 roguelite"而不是一个"想一直玩下去的作品"。**叙事型元进度提供的是继续玩的理由，而数值型提供的只是继续玩的能力。**
- **一句话设计目标**：**把"死亡"从惩罚重新定义为"一次推进"，方法是让死亡触发一个每次内容都不同的仪式。**

**可复用模式**：**"三线并进的失败补偿"**——给失败同时挂上数值、内容、叙事三条前进线中的至少两条，失败就不再是纯损失。这条模式在手游里可以直接用：一次挑战失败之后，玩家至少应该拿到（a）可累积的资源、（b）关于怎么打的信息、（c）一点点剧情或收集进度中的两样。

### 10.3 两个案例放在一起看

| | 杀戮尖塔 | 哈迪斯 |
|---|---|---|
| 深度来自 | 卡组的加法与减法 + 跨战斗资源 | 槽位取舍 + 组合追求 + 操作 |
| 随机怎么被驯服 | 整张地图可见 + 三选一可跳过 | 门上写着奖励类型 |
| 元进度类型 | 内容型为主（解锁选项、难度层级） | 数值 + 内容 + 叙事三线并进 |
| run 长度 | 长（构筑能完整成型） | 中（一次完整尝试 20~40 分钟） |
| 失败之后玩家想的是 | "这局我路线走错了" | "再来一次，我想看后面的剧情" |

**最后一行是两种设计哲学的分野**【推导】：一个把重来的动力放在**玩家自己的胜负欲**上，一个放在**外部的牵引**上。前者纯粹但受众窄，后者更宽但需要巨大的叙事产能。**做手游 roguelike 时多半要偏向后者，因为手游的玩家结构里，靠纯胜负欲长期留存的那部分人占比通常不足以撑起大盘。**

## 11. Roguelike 在手游的移植：割草肉鸽

微信小游戏里的割草肉鸽（几分钟一局、自动攻击、升级三选一、越打越多的怪）是这两年 IAA 市场的主力品类之一。它的数值设计是姊妹课程 [game-solo](../game-solo/README.md) 的主题，**本节只讲设计面的移植取舍，数字全部交给那门课**。

| 维度 | PC roguelike | 手游割草肉鸽 | 原因与代价 |
|---|---|---|---|
| **run 长度** | 20~90 分钟 | **3~15 分钟** | 会话碎片化。代价：构筑来不及成型，必须在开局 60 秒内就让玩家感到"这局有方向" |
| **操作** | 需要技巧 | 自动攻击 / 单摇杆 | 降低门槛、可单手玩。代价：技能表达几乎消失，胜负主要由构筑与元进度决定 |
| **构筑决策** | 几十次有意义的选择 | **十几次三选一**，且要在 1~2 秒内看懂 | 决策必须"一眼可读"：图标 + 一句话 + 立刻可感知的效果变化 |
| **失败** | 惩罚 + 学习 | **广告触发点**（复活、翻倍） | 失败从体验事件变成了变现事件，见 [game-solo 第 06 章](../game-solo/06-difficulty-as-lever.md) |
| **元进度** | 弱到中 | **强**（承担几乎全部长期留存） | 代价：容易滑向"多刷几局就能过"，杀死构筑决策（第 8.5 节的诊断信号） |
| **随机** | 玩法的核心 | 玩法核心 **+ 广告点位**（免费重抽） | 重抽既是体验缓冲也是变现，见 [game-solo 第 09 章](../game-solo/09-randomness.md) |

**移植时最容易做错的两件事：**

1. **把 run 压短了，却没有相应加强元进度**——玩家三分钟死一次，什么都没成型，也没有长期目标，第一天就走。
2. **把元进度加强了，却没有给数值型元进度设终点**——两周后玩家碾压一切，构筑决策消失，游戏变成挂机。**解法是把后期的元进度从"数值型"切换到"内容型 + 难度选项"**（这正是第 8.4 节那张表的用法）。

**一个设计判断【推导】**：割草肉鸽真正卖的不是 roguelike 的深度，是**"变强的密度"**——单位时间内玩家感受到自己变强的次数。PC roguelike 一局 40 分钟给你 30 次选择，手游一局 5 分钟也要给你 15 次。**所以它的设计重心不在构筑的深度，而在反馈的密度**（[第 13 章](./13-game-feel-and-feedback.md)：数字跳字、升级光效、屏幕上越来越夸张的弹幕）。这也解释了为什么这个品类的美术和特效投入比玩法深度更能决定成败。

## 12. 三种结构的设计清单

### 开放世界

- [ ] 玩家站在任意位置抬头，视野里有几个"引力点"？我验证过吗？
- [ ] 地形有没有承担"遮挡—再暴露—给选择"的作用，还是只是障碍？
- [ ] 我的地图上四层内容（主目标/次目标/微内容/留白）的比例是多少？留白够吗？
- [ ] 玩家从一个引力点到下一个引力点平均要走多久？
- [ ] 玩家能不能自己产生目标？四个条件（可见的远处目标 / 多解 / 可组合的工具 / 无强制顺序）各满足了吗？
- [ ] 有没有一套统一的交互规则同时服务战斗、解谜和探索？
- [ ] （手游）开放世界承担的是首因、情感还是差异化？**我的日常留存靠什么？**
- [ ] （手游）打卡型会话和闲逛型会话怎么在同一张地图上共存？

### 叙事驱动

- [ ] 我的选择系统是树状分支、分支汇合还是状态追踪？成本估过吗？
- [ ] 每一个选择改变的是玩法、叙事还是措辞？我在案子里写清楚了吗？
- [ ] 后果是被"实现"还是被"提及"？提及够不够？
- [ ] 玩法在鼓励的价值和剧情在宣扬的价值一致吗？（ludonarrative）
- [ ] （手游）选择系统放在角色好感线还是活动剧情里？为什么不放主线？

### Roguelike

- [ ] 一局多长？这个长度对应的元进度强度我配对了吗？
- [ ] run 内的三段弧线（起步/成型/检验）各有多长？"开局就废"和"稳赢无聊"我各做了什么防护？
- [ ] 构筑系统有减法吗？（跳过、删除、替换）
- [ ] 我的元进度里数值型、内容型、叙事型各占多少？数值型有终点吗？
- [ ] 失败之后玩家至少拿到哪两样东西（资源 / 信息 / 叙事）？
- [ ] 玩家会给我的 build 起名字吗？
- [ ] 玩家论坛里讨论的是"多少级能过"还是"怎么配能过"？
- [ ] （手游）单位时间的"变强次数"是多少？三选一能不能在 2 秒内读懂？

### 三者共同

- [ ] 可感知的因果：玩家能说出"因为我做了 X，所以 Y"吗？
- [ ] 不可撤销性：玩家的选择有代价吗？还是可以随便重来？
- [ ] 可讲述性：玩家能用一句话把这一次的经历讲给别人听吗？

## 13. 常见误区

| 误区 | 为什么错 | 正确的想法 |
|---|---|---|
| "开放世界就是把地图做大" | 大而空且没有引力点的地图只会让玩家赶路 | 大小由"引力点之间的时间预算"决定，不由平方公里决定 |
| "地图要填满，不能有空地" | 到处都有东西 = 发现失去价值 + 玩家变成扫图机器 | 留白承担呼吸、期待和规模感三个功能 |
| "给玩家自动寻路，体验更顺畅" | 自动寻路消灭了"路上被打断"，而那正是玩家故事的来源 | 打卡型会话给传送，闲逛型会话保留未标记区域 |
| "手游做了大世界，留存就有了" | 探索产出是一次性的：它可以是核心玩法循环，却很难单独撑起可再生的日常循环 | 开放世界撑首因、情感和差异化，日常留存要另一套可再生的循环 |
| "选择要真的改变结局才有意义" | 真分支成本指数级，且每条分支都难写好 | 玩家要的是"被记住"，提及比实现便宜一个数量级 |
| "主线做分支剧情，玩家会喜欢" | 手游产能撑不住，且与统一运营节奏冲突 | 把选择放在角色好感线和活动剧情里 |
| "roguelike 就是随机生成关卡" | 随机生成是手段，构筑的取舍才是核心 | 先设计"选择与取舍"，再考虑随机怎么给素材 |
| "元进度越强，玩家越愿意长期玩" | 强元进度会把归因从"打法"转到"练度"，杀死这个结构的核心快感 | 数值型是止痛药，要设终点；内容型才是营养 |
| "构筑只要设计怎么获得就行" | 只有加法的构筑会滑向"全都要"，取舍消失 | 减法（跳过/删除/上限）必须一起设计 |
| "手游 roguelike 就是把 PC 的压缩一下" | run 长度一改，元进度、决策密度、反馈密度全都要重配 | run 长度是第一个决定，其他参数跟着它走 |
| "这三种结构是三个品类，跟我做的手游没关系" | 它们是三种放大玩家自主经历的工具，可以单独移植 | 按产能结构挑：空间最贵、真分支最难复用、组合最省素材 |

## 14. 动手

### 14.1 拆解：一局 run 的输入随机点与元进度

打一局《哈迪斯》或《杀戮尖塔》（没有的话，用你手机上任意一款割草肉鸽小游戏也可以，但要在拆解里注明差异）。**边打边记录**，然后用 [templates/deconstruction.md](./templates/deconstruction.md) 写一份拆解。

**必须产出的是一张"run 时间轴"**，按下面的格式画出来：

```
 时间轴：  开局 ─────────────────────────────────────────────→ 结束
 
 随机点：   R1      R2         R3        R4          R5
 我的选择： C1      C2         C3        C4          C5
 构筑状态： [起步]      [成型：什么方向]        [检验：够不够]
 元进度：                                          M1  M2  M3
```

具体要求：

1. **标出这一局的每一个输入随机点**（R）：随机给了你什么？给的时候你有几个选项？这个随机是"输入"（你能用决策应对）还是"输出"（结果直接砸下来）？至少标 8 个。
2. **标出每一个真正的决策点**（C）：你在这里犹豫了吗？如果没犹豫，说明有明显最优解，标注出来。
3. **标出构筑成型的时刻**：从哪一步开始你有了"这局我要走 X 路线"的想法？（如果整局都没有，这本身是重要发现）
4. **标出所有元进度**（M）：这局结束后你带走了什么？逐条分类成数值型 / 内容型 / 叙事型。
5. **回答**：这一局失败/结束的时候，你的第一反应是"再来一局"还是"算了"？为什么？把原因追溯到上面时间轴的某一个具体位置。
6. **run 内三段弧线**：起步期、成型期、检验期各占多长？有没有出现"开局就废"或"稳赢无聊"？
7. **意图层【推导】**：这个游戏的设计者用什么手段防止"开局就废"？用什么手段防止"稳赢无聊"？
8. **可复用模式**：一到两条，写进 `notes/模式库.md`。

### 14.2 写作：为一款手游设计一个 roguelike 模式

用 [templates/one-pager.md](./templates/one-pager.md) 写一页纸。设定：

> 你在一款已上线的收集养成手游（就用你正在玩的那款）做系统策划。主策的需求是："玩家的角色养成已经到顶了，日常太单薄，我们要一个能让老玩家用现有角色玩出新花样的模式。" 你决定提一个 roguelike 模式。

必须回答（这是本作业相对模板的补充）：

1. **run 长度是多少？** 说清楚你为什么选这个长度（会话结构、玩家习惯、这款游戏的战斗节奏）。这是第一个决定，后面所有东西都跟着它。
2. **run 内的构筑素材是什么？** 在一款已有角色养成的游戏里，run 内的"随机获得物"应该是什么？（新技能？临时增益？阵容限制？敌人变化？）**注意一个关键约束：它不能和角色养成打架**——如果 run 内的构筑完全由养成决定，那就不是 roguelike，是数值检定。
3. **run 内的三段弧线**：起步、成型、检验各多长？"这局有方向了"的时刻应该在第几分钟出现？
4. **减法在哪里？** 你的构筑系统怎么让玩家做减法（跳过 / 替换 / 上限）？
5. **元进度是什么？** 三种类型各用多少？**数值型的终点在哪**（到什么程度就不再给数值了）？说明理由。
6. **它和现有养成的关系**：现有的角色练度在这个模式里算不算数？算多少？**这是本题最难的一问**——完全不算数，老玩家的投入被否定；完全算数，模式退化成数值检定。写出你的方案与理由。
7. **失败之后玩家拿到什么？**（资源 / 信息 / 叙事，至少两样）
8. **一张图**：run 的结构图（区域/节点/随机点/决策点）或时间轴。
9. **接口**：它和哪些现有系统耦合？（至少：角色与养成、体力/次数限制、奖励与经济、活动排期）
10. **风险与验证**：最大的不确定性是什么？怎么用最便宜的方式验证？（提示：纸面推演一局，或者用现有战斗系统做一个只有 5 个随机元素的最小版本）
11. **不做什么**。

篇幅一页（约 900~1100 字 + 一张图）。写完后用 [templates/review-checklist.md](./templates/review-checklist.md) 自评，重点看第二层的"决策有没有明显最优解"和"成熟玩家一个月后还会用它吗"。

### 14.3 思考题

1. 第 3.2 节说"路上被打断"是开放世界循环里最重要的一步。但手游的日常任务系统天然鼓励"直达"。如果让你在一款手游大世界里设计一个**奖励"绕路"的机制**，你会怎么做？它会不会反而变成新的清单？
2. 第 7.2 节说"后果被提及比被实现便宜一个数量级，而且几乎同样有效"。这个结论有没有边界？在什么情况下"只是提及"会让玩家感到被欺骗？
3. 第 8.4 节的三种元进度里，叙事型被称为"奢侈品"。假设你的项目没有做大量上下文对白的产能，有没有更便宜的方式实现"叙事型元进度"的效果（让失败本身有意义）？列出两个方案并说明它们各自失去了什么。
4. 第 8.5 节的诊断信号是"玩家讨论的是多少级能过而不是怎么配能过"。但对一款 IAA 小游戏来说，"多少级能过"恰恰意味着玩家愿意反复刷、多看广告。这时候你还要不要修正这个信号？你的判断依据是什么？（提示：把它和 [game-solo](../game-solo/README.md) 的商业模式放在一起想）
5. 第 9 节说三种结构都在"用结构制造玩家自己的故事"，并给了三个共同零件。回头看 [第 23 章](./23-genre-slg.md) 的 SLG：SLG 也在制造玩家自己的故事（"我们盟那次攻城"）。它用的是哪种放大方式？三个零件它齐全吗？它和本章三种结构最大的不同是什么？
