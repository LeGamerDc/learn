# 06 - 规则、系统与涌现

> **本章目标**：把"一堆规则"看成"一个会自己跑起来的系统"。学完你应该能：画出一个系统的反馈回路并说出它给玩家的体验含义、判断一个游戏的内容是涌现出来的还是被脚本安排好的、估算一条规则改动会波及哪些系统、以及知道在什么情况下不该追求涌现。

## 1. 两种做法，同样的效果，完全不同的成本

先看一个具体问题：**"火箭"这个东西怎么做出来？**

玩家有普通的木箭，附近有火堆，你希望玩家能把箭点着射出去。有两种做法：

**做法 A（枚举）**：加一个新道具"火箭"，加一条规则"在火堆旁按 X 键可以把木箭转换成火箭"，加一条规则"火箭命中时附加燃烧效果"。

**做法 B（属性交互）**：不加"火箭"这个道具。改为给每个物件标属性——木箭有"可燃"属性，火堆有"火"元素；再写一条通用规则："火元素接触可燃物 → 可燃物进入燃烧状态"；再写一条："燃烧状态的物体命中目标 → 目标进入燃烧状态"。

两种做法玩家看到的结果一模一样：把箭伸进火里，箭着了，射出去点燃了敌人。

但成本完全不同。做法 A 加了一个功能；做法 B **同时**做出了：火箭、点燃草地、点燃木箱、点燃敌人的木盾、把火把扔进草丛、雷雨天举着金属武器会被雷劈、木筏被火烧掉……以及一大堆设计者根本没想过的组合。

**做法 B 就是《塞尔达传说：旷野之息》的做法**，任天堂团队在 **GDC 2017 的演讲 *Change and Constant: Breaking Conventions with The Legend of Zelda: Breath of the Wild* 里把它称为"化学引擎"**【实证】。本章后半会把它拆开。

而**绝大多数手游用的是做法 A**。这不是因为手游策划不懂，而是因为做法 B 有做法 A 没有的代价，这些代价在 F2P 长线运营的环境下可能是致命的。**本章的目标不是让你崇拜涌现，是让你知道这两条路各自的成本、收益和风险，然后有能力选。**

从工程视角看，这就是"每个 case 写一个 if 分支"和"抽象出一套属性与规则引擎"的区别。你在代码里做过这个取舍无数次，也知道抽象不是免费的：抽象层写错了，所有 case 一起错；组合爆炸之后，测试覆盖不了。**游戏设计里的这个取舍，和你熟悉的那个是同一件事，只是错了的代价是"玩家找到了一个能刷无限金币的组合"。**

## 2. 系统是什么：部件、循环、整体

日常说"系统"这个词太随便了：公会是系统，背包也是系统，战斗也是系统。要设计系统，先要有一个更精确的定义。

Michael Sellers 在 *Advanced Game Design: A Systems Approach* 里给的三层结构最实用【实证】：

| 层 | 是什么 | 游戏里的例子 | 服务端类比 |
|---|---|---|---|
| **部件**（parts） | 有状态、有行为的最小单位 | 一个角色、一块地、一张牌、一个建筑 | 一个数据结构 / 一个实体 |
| **循环**（loops） | 部件之间的**相互作用**，特别是那些会绕回来的作用链 | 兵多 → 打赢 → 占地 → 产粮 → 兵更多 | 一个会自我触发的调用链 / reconcile 循环 |
| **整体**（wholes） | 循环跑起来之后出现的、**在部件层面看不到**的东西 | "服务器的势力格局""版本环境""流派生态" | 集群在负载下涌现的行为（缓存雪崩、惊群） |

三层里最关键的判断是：

> **一堆部件不会自己跑起来，有循环才会。**

**这里必须把话说准，因为它最容易误导工程师读者**：Sellers 这套三层讲的是"**什么样的东西会产生系统性的动态**"，不是"什么东西才配叫系统"。你在工程意义上说的系统（有状态、有规则、有输入输出、有接口）和这里说的"会产生动态的玩法系统"是两回事。本课把它们分开叫：

| | **功能系统**（feature） | **玩法系统**（systemic gameplay） |
|---|---|---|
| 例子 | 背包、邮件、好友列表、公告、公会成员管理 | 装备强化、资源经济、联盟争地、build 构筑 |
| 有没有闭合的回路 | 没有，或只有很短的一条 | 有，而且回路会自我放大或自我抑制 |
| 主要风险 | **规格漏洞**：容量、堆叠、过期、并发、丢件 | **结构性失控**：通胀、垄断、最优解锁死 |
| 评审时先看什么 | 状态机、边界条件、异常路径、和别的系统的接口 | 回路的极性、强度、延迟 |

所以：**背包不是玩法系统，但它是一个需要完整规格的功能系统**——它一样有状态、有规则、有输入输出，它的容量上限还可能构成一条真实的负反馈（背包满了逼你卖东西，就是一个汇），它的溢出规则写错一样能造成经济事故。**别把"它不是玩法系统"读成"它不重要"或者"它可以少写点规格"。**

这个区分的实用价值在评审上：**拿到一份"系统案"，先找它的回路。找到回路的，按玩法系统评（先看结构）；找不到的，按功能系统评（先看规格与边界条件）。** 两种评审要看的东西不一样，用错模板就会漏掉真正的风险（第 15、26 章会用到这条）。

第三层"整体"是这一章真正的主题，也是最难的一层。**整体层的性质不能从部件层直接推出来。** 你把每条规则单独看都合理，跑起来却出现你没预期的局面——服务器上出现了三个大联盟瓜分资源、出现了"代肝"产业、出现了所有人都用同一套阵容。这些东西在你的设计文档里一条都没写，但它们是你的规则的直接后果。

**这是本课"系统思维"的核心态度**：

> 你不是在设计玩家的行为，你是在设计一组约束，然后**玩家的行为会从这组约束里长出来**。你能控制的是约束，不是行为。

工程师对这句话应该有天然的亲切感：你不控制用户怎么调你的接口，你只能定义接口的契约，然后看着流量长成你没预料的形状。区别在于，服务端的流量不会故意跟你作对，而**玩家会**——玩家是有智能、有动机、会互相交流的对手方，他们会系统性地寻找你规则里的最优解和漏洞。

## 3. 存量、流量、回路：本章只讲体验含义

存量（stock）、流量（flow）、回路（loop）这套语言，[game-numeric 第 03 章](../game-numeric/03-resource-flow.md) 已经完整讲过了：五个基本元件（源、汇、池、门、转换器）、画图的六步法、四种一眼可见的缺陷、Machinations 工具。**本章不重复任何一条，请你先去读那一章再回来。**

这里只给最小的复习，然后立刻转到本章的问题：**这些结构对玩家的感受意味着什么。**

```
   源 ──→ 【存量】──→ 汇        存量 = 玩家拥有的量（金币、兵、体力、进度）
           │  ▲                流量 = 单位时间的变化（每天产 3000 金币）
           │  │                回路 = 流量反过来被存量影响
           └──┘
```

**回路是最需要设计师亲自盯的东西**——但不是唯一的：源和汇写错一样能出经济事故（见 [game-numeric 第 24 章](../game-numeric/24-economy-security.md)）。区别在于，源和汇多半是局部的、可以事后调数值补救，而**回路是结构性的，改起来要动很多东西**，所以它必须在写案子的时候就想清楚。

分工说清楚：

| 问题 | 归谁 | 在哪一章 |
|---|---|---|
| 每天投放多少金币、体力恢复多快、成长曲线什么形状 | 数值 | [game-numeric 04/07/08](../game-numeric/07-faucets.md) |
| 这条回路是正的还是负的、它会给玩家什么感受、要不要给它加刹车 | **系统策划（本章）** | 本章第 4、5、6 节 |
| 这条回路和另外三个系统怎么耦合、改它会波及谁 | **系统策划** | 本章第 10 节 + [第 15 章](./15-system-design-method.md) |
| 加了刹车之后具体的系数是多少 | 数值 | game-numeric |

**记住这条分工**：系统策划说"这里需要一个负反馈，因为我不想让领先的联盟在第 10 天就锁定胜局"；数值策划说"那战损率配 4%，平衡点在 950 兵"。两句话缺一不可，但方向是从体验到数字，不能反过来。

## 4. 正反馈：它给玩家的是什么感觉

**正反馈回路（positive feedback loop）**：状态越好，变好的速度越快。

```
   ┌────────────────────────────┐
   │                            │
   ▼                            │
 【战力】──→ 打更高的关 ──→ 更多资源 ──┘
   增加         成功率↑        投入战力
```

数值面它叫"滚雪球"。**体验面它给玩家的东西有四样，都很重要：**

| 正反馈给的体验 | 为什么 | 一旦失控 |
|---|---|---|
| **成长感 / 复利快感** | 玩家能感觉到"我的每一次投入都在变得更值钱"，这是养成类游戏最核心的爽点 | 变成数字通胀，玩家对增长麻木（[game-numeric 第 21 章](../game-numeric/21-power-creep.md)） |
| **早期决策变重要** | 因为早期的差异会被放大，所以开局那几个选择真的有分量 | 一步走错满盘皆输 → 新手劝退、逼人看攻略 |
| **"势"的形成，戏剧性** | 局势会倒向一边，比赛有高潮，观战有看点 | 胜负在中途就定了，剩下的时间是走过场 |
| **缩短游戏时长** | 正反馈会加速终局到来，这在有明确终局的游戏里是好事 | 在没有终局的手游里，它会加速把玩家推到"没东西可做"的天花板 |

**最后一条是手游和买断制最大的差别，值得展开。**

买断制游戏有终局。《文明》类策略游戏、桌游《大富翁》、一局 MOBA，都需要"某一方最终赢"，所以正反馈是必要的引擎——没有正反馈，比赛会无限拖下去。**Adams 和 Dormans 在《游戏机制》里就是用大富翁讲这件事的**：拿到地产 → 收租 → 买更多地产，这条正反馈保证了游戏能结束【实证】。

**手游没有终局。** 它要跑三年。这时候一条不加限制的正反馈的后果是：玩家在第 30 天就把系统吃干抹净，然后无事可做。所以**手游的正反馈永远是被刹车限制着的**，刹车有三种：指数成本（升级越来越贵）、时间门（每日上限、CD）、内容门（等级/关卡锁）。这三种刹车的数值形态在 [game-numeric 第 04 章](../game-numeric/04-growth-curves.md)，本章只需要你记住：**你看到一条正反馈，第一反应必须是"它的刹车在哪"。**

### 三个例子

**手游例子 1：SLG 的联盟资源州循环。**

```
 占领高级资源州 ──→ 全盟产出加成 ──→ 成员兵力增长快
        ▲                                    │
        │                                    ▼
   打赢更多仗 ◄────────── 集结战力更强 ◄──────┘
```

这是一条非常强的正反馈，而且是**群体级**的：强盟越打越强，弱盟越打越弱。它给玩家的体验是"我们盟正在崛起"这种集体成就感，这是 SLG 最独特的爽点之一。它的刹车在下一节讲。

**手游例子 2：卡牌养成的"集中培养"。**
资源有限时，把资源全砸在一队上 → 这队战力高 → 能过更高的关卡 → 掉落更好的资源 → 继续砸这队。结果是玩家的阵容会**收敛**：绝大多数玩家最终只有一队能打。体验上这条正反馈制造了"我的主力队真的很强"的满足，代价是**新角色对老玩家的吸引力下降**（练不动），这是卡牌品类的一个结构性问题（第 24 章）。

**买断制对照：《杀戮尖塔》的遗物滚雪球。**
早期拿到一个强遗物 → 战斗更轻松 → 血量保得住 → 敢打精英怪 → 精英怪必掉遗物 → 更强。一局杀戮尖塔的胜负，很大程度上在前两层就已经倾斜了。**设计者显然是知道并接受这一点的**【推导】：因为它是一局 40 分钟的游戏，正反馈带来的"这局稳了"的爽感和"这局崩了，重开"的干脆，都是 roguelike 体验的一部分。**同一条正反馈，在 40 分钟的 run 里是特色，在 3 年的手游里是灾难。**

## 5. 负反馈与平衡机制：怎么把差距压住

**负反馈回路（negative feedback loop）**：状态越好，变好的速度越慢；或者状态越差，恢复越快。

**先立一条命名纪律，因为业内把这个词用得太松了。** 只有满足下面两条的，本课才叫它**反馈回路**：

1. **因果链是闭合的**：系统读取当前状态 → 据此改变某个流量 → 这个流量又改变当前状态。
2. **极性可判定**：能说清"状态越好，它就越怎样"。

不满足这两条、但同样起到压差距作用的东西，本课统称**平衡机制**（balancing mechanism）。常见的三类是：**上限/下限约束**（固定的天花板，不随谁领先而变）、**定时的外生事件**（到点就发生，不读取任何人的状态）、**准入分层**（分段位、分服、分梯队）。它们都能压差距，但**它们不是回路，所以不要用回路的语言去分析它们**——问一个体力上限"它的增益是多少、延迟多久"是没有意义的。

```
   ┌─────────────────────────┐
   │                         │
   ▼                         │
 【兵力】──→ 战斗 ──→ 战损（按比例）
   增加              兵越多损失越多
```

| 负反馈给的体验 | 为什么 | 一旦过头 |
|---|---|---|
| **追赶的希望** | 落后的玩家知道自己还有机会，不会提前退出 | 领先玩家觉得"我努力了却被系统惩罚"，努力失去意义 |
| **拉长游戏、维持悬念** | 差距被压住，胜负拖到后期才定 | 拖沓、没有高潮、所有人都在原地 |
| **保护弱势生态位** | 免费玩家 / 新玩家还有存在空间，服务器不会只剩几个人 | 大 R 觉得充值没用，付费动力下降 |
| **自动稳定，不需要人工干预** | 真正的负反馈不设硬上限也能把状态拉回来 | 玩家如果能感知到它，会觉得"这游戏在暗中调我"（第 10 章讲感知） |

**负反馈里最常被推荐的形态是"按比例的损耗"**，因为它不需要设硬上限、自动生效，而且玩家不会觉得被针对。

但这里有一个必须讲清的陷阱：**按比例损耗压住的是绝对差距的增长速度，不一定缩小相对差距。** 如果双方都按同一个比例损耗，两边的比值原封不动——领先的还是领先那么多倍。它之所以在实践里有用，是因为通常还叠了别的东西：领先方的存量更大，同比例损耗的**绝对**损失更大，而补充产能又有上限，于是有效差距被压住了。**所以写案子时不要只写"按比例损耗，会自动收敛"，要写清楚"收敛的是绝对差距还是相对差距、靠的是哪一条附加约束"。** 数值分析见 [game-numeric 第 03、08 章](../game-numeric/08-sinks.md)。

### 三个例子（注意后两个不是回路）

**手游例子 1：率土之滨的体力上限——一条上限约束，不是回路。**
[第 00 章](./00-how-to-learn.md)已经拆过：体力上限对所有人一样、不能买。**它不读取任何人的领先程度，也没有闭合的因果链，所以按上面的纪律它不是负反馈回路，是一条上限约束。** 但它确实压差距：它对领先玩家的限制远大于对落后玩家的限制（落后玩家本来也用不完），所以它把所有人的**行动次数**压到同一水平。体验上，它给免费玩家的是"我每天能做的事和大 R 一样多"，这是率土生态的地基。**这个例子说明：平衡机制不必是回路也能非常有效**——它甚至比回路更好懂、更好调、更不容易被玩家骂"暗中调我"。

**手游例子 2：赛季重置——一个定时的外生事件，也不是回路。**
率土-like 的赛季制每隔两三个月把服务器状态清空（或部分清空）。**它到点就发生，不读取谁领先谁落后，因果链没有闭合，所以它同样不是反馈回路**，而是一个周期性的外生重置事件。它的体验含义是双向的：对落后者是"重开一局，我还有机会"，对领先者是"我的成果被清空了"。所以赛季制必须配一套**跨赛季继承**（继承一部分养成，不继承局势），把"清空"控制在局势层而不是资产层。这个平衡的数值面在 [game-numeric 第 22 章](../game-numeric/22-seasons-and-merges.md)，设计面在第 23 章。

**买断制对照：《哈迪斯》的"神之模式"（God Mode）。**
《哈迪斯》里有一个可以随时开关的选项：开启后，玩家每死一次就永久获得一点额外的伤害减免，累积上去。这是一条**教科书式的显式负反馈**，而且它有三个设计细节值得学【推导】：

1. **它是可选的**，玩家自己决定要不要用，所以没有剥夺任何人的成就感（第 03 章的"自主"）。
2. **它按失败次数增长**，也就是说它精确地补偿了"卡住"这件事本身，而不是补偿"技术差"这个身份。
3. **它是显式的、有名字的、在设置里明写的**，而不是偷偷调难度。**这一点是很多手游做动态难度时最该学的**：偷偷调的负反馈一旦被玩家发现，会引发"这游戏在骗我"的信任崩塌（第 09、10 章）。

### 正负反馈的组合：引擎 + 刹车

真实系统里正反馈很少单独存在。**一个健康的系统通常是"一条强正反馈提供爽感，两三条刹车限制它的失控"——注意刹车里既有真正的负反馈回路，也有上限约束和定时重置这类平衡机制，混着用是常态。**

拿第 4 节那条 SLG 联盟正反馈，把刹车画上：

```
                    ┌───────────────────────────────┐
                    │        正反馈（引擎）          │
                    ▼                               │
     占领资源州 ──→ 产出加成 ──→ 兵力增长 ──→ 集结更强 ──┘
          ▲                        │
          │                        │
   ┌──────┴──────┐          ┌──────▼──────┐
   │ 刹车①        │          │ 刹车②        │
   │ 体力上限      │          │ 战损按比例    │
   │（个人行动次数 │          │（兵越多损失   │
   │  平等）       │          │  越多）      │
   └─────────────┘          └─────────────┘
                    ┌──────────────┐
                    │ 刹车③         │
                    │ 赛季重置      │
                    │（周期性清零） │
                    └──────────────┘
```

三个刹车作用在三个不同的层次上：**刹车①限制个人的行动频率（上限约束），刹车②限制单次行动的净收益（真正的负反馈回路，因为它读取当前兵力），刹车③周期性重置整个局势（定时的外生事件）。** 这就是"引擎 + 多级刹车"的标准结构——**三个刹车里只有一个是回路，另外两个是平衡机制，但它们一样有效。**

**评审一个系统时，你要能像这样在一张图上同时指出引擎和刹车。**【行业口径】只有引擎没刹车的系统往往上线不久就炸（SLG 里通常以周计）；只有刹车没引擎的系统，玩家会觉得"努力没用"然后慢慢走掉。这两个时间尺度都不是能写进案子的数字，它们只提醒你：**两种病的发作速度差一个量级，所以前者要在上线前查，后者可以留到运营期观察。**

### 两个容易被忽略的旋钮：强度和延迟

回路除了正负，还有两个属性，它们对体验的影响不比正负小：

| 旋钮 | 含义 | 调大了会怎样 | 调小了会怎样 |
|---|---|---|---|
| **强度** | 一圈回路能放大/削弱多少 | 正反馈：几天就锁死胜局。负反馈：努力毫无意义 | 玩家感觉不到这条回路存在，等于没设计 |
| **延迟** | 从行动到反馈绕回来要多久 | **玩家学不会因果**，会归因错误，觉得系统随机 | 反馈太即时，系统变得可被精确利用（刷子行为） |

**延迟这个旋钮被严重低估。** Doug Church 的"可感知的后果"（[第 05 章](./05-decisions.md)第 3.3 节）在系统层面就是这件事：一条回路如果绕一圈要三天，玩家几乎不可能把结果归因到三天前的那个决定上，那这条回路对玩家来说就是不存在的——它仍然在影响他的处境，但他学不到任何东西，只会感到"这游戏莫名其妙"。

SLG 里大量的抱怨来源就是长延迟回路：今天铺路的位置决定了一周后能不能参与攻城，但新手当时完全不知道。**解法不是缩短延迟（那会破坏 SLG 的节奏），而是把回路显式化**：给玩家看地图规划、给盟主一个能标记的工具、在盟内聊天里让老玩家替系统解释。**这是"用社交层补偿系统层延迟"的典型做法**【推导】，第 11 章会再讲。

## 6. 涌现与递进：内容从哪里来

这是本章的第二个核心框架，来自 Ernest Adams 与 Joris Dormans 的《游戏机制：高级游戏设计技术》【实证】。他们把游戏产生内容的方式分成两种结构：

- **涌现（emergence）**：少量规则 + 大量交互 → 大量的、设计者没有逐一指定的局面。围棋、模拟游戏、沙盒、大部分策略游戏。
- **递进（progression）**：设计者预先安排好的一连串内容，玩家按顺序经过。线性关卡、剧情章节、任务链。

对比：

| | 涌现（emergence） | 递进（progression） |
|---|---|---|
| 内容从哪来 | 规则交互产生 | 设计者逐个做出来 |
| 规则数量 | 少而通用 | 多而具体（每关一套） |
| 内容成本 | **前期高**（引擎/规则难做对），后期趋近于零 | **线性**：想要 100 关就得做 100 关 |
| 重玩性 | 高（每次不同） | 低（知道答案就没意思了） |
| 可控性 | **低**。设计者不知道玩家会遇到什么 | **高**。可以精确控制每一分钟的体验 |
| 平衡难度 | 高（组合爆炸） | 低（一关一关调） |
| 叙事能力 | 弱（很难保证剧情节点按顺序发生） | 强（可以讲一个完整的故事） |
| 新手友好度 | 低（不知道该干什么） | 高（跟着走就行） |
| 典型 | 围棋、《我的世界》、SLG 的服务器博弈、《旷野之息》的野外 | 关卡制手游主线、剧情章节、大部分教程 |

**关键认识：这不是两个阵营，是一根轴，而且几乎所有商业游戏都是混合的。** 混合的常见形态有三种：

| 混合形态 | 结构 | 例子 |
|---|---|---|
| **涌现内核 + 递进外壳** | 玩法本身是涌现的，但用关卡/章节把它切成段落发放 | 《旷野之息》（野外涌现 + 神庙和主线递进）、大部分策略手游 |
| **递进内核 + 涌现表层** | 内容是排好的，但允许玩家用自己的方式通过 | 大部分动作游戏的关卡 |
| **递进的元层 + 涌现的局内** | 每一局是涌现的，局外进度是排好的 | Roguelike + 元进度：《哈迪斯》《杀戮尖塔》、割草类小游戏 |

第三种是**当代最流行的结构**，因为它同时解决了两个问题：涌现提供了无限的重玩性（内容成本低），递进提供了明确的长期目标和叙事（留存钩子）。第 07 章讲循环时会从另一个角度再看它，第 25 章讲品类时会拆到细节。

**手游的默认形态是"重递进 + 弱涌现"**，原因不止一条【推导】：

1. **可运营**：递进内容可以按周排期、可以做成活动、可以精确控制投放（[game-numeric 第 07 章](../game-numeric/07-faucets.md)的预算制需要可预测的产出）。涌现内容的产出量是不可控的。
2. **可测试**：递进内容 QA 能穷举，涌现内容测不完。
3. **可买量**：广告素材需要一个可预期的爽点。涌现体验很难用 15 秒讲清楚。
4. **新手友好**：递进有明确的"下一步"，涌现需要玩家自己找目标，这在 FTUE 阶段是致命的（第 18 章）。

**但纯递进的手游有一个绕不开的问题：内容产能要跟得上消耗速度。** 头部玩家通常比你的产能快（[game-numeric 第 20 章](../game-numeric/20-long-term-pacing.md)的"内容跑道"讲的就是这个）。所以长线手游一般要在某个地方引入涌现，给自己一条不靠产能的内容来源。

**这里是本课反复引用的那条成本假设，完整版在这里说一次**（[第 03 章](./03-why-players-play.md) 第 9.1 节和 [第 05 章](./05-decisions.md) 第 11.4 节只是引用它）：

> 【行业口径】**"别的玩家"通常是边际内容成本最低的一条内容来源**：对手自己会变、会学习、会互相制造事件，你不需要为此持续掏产能。这是很多长线手游都带 PvP 或强社交的主要经济原因。

**三条限定必须和这句话一起记，否则它会变成一条错误的教条：**

| 限定 | 说明 |
|---|---|
| **它不是唯一的低成本来源** | 程序生成、UGC、深 build 空间带来的系统精通、持续的版本更新，都能撑起纯 PvE 的长线产品。各有代价：生成内容容易同质、UGC 的真正瓶颈在分发与激励、系统精通对新手不友好、持续更新是最贵的那条路 |
| **"把别人当内容源"不等于"必须做 PvP"** | 它可以是异步的、非对抗的：排行榜、留言与血迹、助战、观战、共建、看别人的 build 和阵容。真人对抗只是其中最强、也最危险的一种形态 |
| **它不免费** | 换来的是生态风险（强者压制弱者的正反馈）、毒性与举报，以及一整套匹配和分层的成本（[game-numeric 第 17、19 章](../game-numeric/19-server-ecology.md)） |

所以正确的问法不是"要不要做 PvP"，而是：**我用什么方式让玩家成为彼此的内容，以及我愿意为此承担多少生态成本。**

## 7. 可能性空间

**可能性空间（possibility space）**：规则允许的所有局面的集合。

这个概念有用，但**用错的方式比用对的方式更常见**。

先看怎么估算。它通常是组合数：

| 系统 | 可能性空间的粗略量级 |
|---|---|
| 石头剪刀布（单轮） | 9 |
| 一个 6 角色阵容，从 100 个角色里选 | C(100,6) ≈ 10⁹ |
| 一副 15 张的杀戮尖塔牌组，从约 75 张池子里选 | 天文数字 |
| 围棋 | 更大的天文数字 |

看到问题了吗？**"从 100 个角色里选 6 个"的组合数比围棋小得多，但没有人会说那个卡牌手游比围棋深。** 所以：

> **可能性空间的大小几乎不说明任何问题。有意义的是"其中有多少个局面是玩家会真正区别对待的"。**

我把这个叫**有效可能性空间**（本课的说法）。它由三个因素决定：

1. **选项之间有没有真实差异**（100 个角色里如果 80 个是同一个模板换皮，有效空间立刻少一个数量级）
2. **玩家能不能感知到差异**（第 05 章的"后果可感知"）
3. **有没有情境让不同的选择各有优势**（第 05 章的"没有明显最优解"）

第三条最关键。**如果版本环境只有一种，那么再大的名义空间都会坍缩成"最优解 + 其他"。** 这就是为什么卡牌游戏必须持续变换环境（新关卡机制、新克制关系、活动的特殊规则）：**环境的多样性是有效可能性空间的乘数。**

**估算有效空间的一个土办法**：去看玩家社区。如果攻略区里流通的阵容有 15 套且各有适用场景，你的有效空间大概是 15 的量级；如果只有 2 套且其中一套是"没有前一套的替代品"，那就是 1。**不管你的名义组合数是 10⁹ 还是 10²⁰。**

## 8. 简单规则怎么才能长出复杂行为

不是所有"规则少"的系统都会涌现，大部分只是简陋。要让简单规则长出复杂行为，需要满足下面这些条件。这张清单可以当成**"涌现潜力评估表"**直接用：

| 条件 | 说明 | 反例（缺了它就不涌现） |
|---|---|---|
| **① 元素有多种，且属性正交** | 元素之间要在不同维度上有差异，不能只是数值大小不同 | 100 个角色只有攻击力不同 → 只有一个维度 → 很容易只剩一个最优解 |
| **② 交互规则是通用的，不是逐对枚举的** | 规则应该写成"火 × 可燃 → 燃烧"，而不是"木箭 + 火堆 → 火箭" | 每种组合配一条表 → 组合数被产能限制死 |
| **③ 元素之间要能互相作用，不只是各自和系统作用** | 有交互的元素**对**越多，组合空间涨得越快。"N² 而不是 N"是个方便的口号，不是硬指标——**不需要全连接**，只要有足够多的元素对之间存在**显著**交互就够了 | 每个角色只和敌人交互，角色之间没有互动 → 阵容 = 数值加总 |
| **④ 状态能在一段时间里积累** | 这一步的结果要能留下来影响下一步。**时间尺度可以很短**——杀戮尖塔一场战斗内的中毒层数、格挡、能量就足以涌现出局面，并不需要跨局持久化 | 每一步都完全重置、什么状态都不携带 → 不会积累出局面 |
| **⑤ 后果可感知** | 玩家看得到组合产生了什么（第 05 章 3.3 节） | 组合有效果但没有表现 → 玩家永远发现不了 |
| **⑥ 玩家有表达空间** | 玩家能主动组合，而不是被动接受系统给的组合 | 自动战斗、一键最优 → 组合空间被系统自己吃掉了 |

**②和③是最容易在手游里丢掉的两条。**

- 丢掉②的表现：策划案里出现"配置表：组合 ID / 组合条件 / 组合效果"。一旦你的设计需要一张这样的表，你就已经站在枚举那一边了。这**不一定错**（可控、可测、可运营），但你要清楚你放弃了什么。
- 丢掉③的表现：一个 6 人阵容的战力 = 6 个角色战力之和。这时候"阵容"不是一个玩法系统，是一个加法。**要让阵容变成玩法系统，必须有角色之间的交互**（羁绊、增益、职责互补、连携），而且交互必须显著到能改变选择。注意**不需要人人互相影响**：三四对强交互就足够撑起一个可玩的组合空间，全连接反而会让平衡失控。

**一个诊断问题**：把你系统里的一个元素换成"数值相同但没有任何特殊属性的通用元素"，系统的行为会不会变？不会变，说明那个元素的属性是装饰。

## 9. 系统间耦合：改一条规则影响谁

这是本章对你日常工作最有直接价值的一节。

**手游的复杂度不在单个系统里，在系统之间。** 一款成熟手游有三四十个系统，任何一条规则改动都可能穿过好几个系统冒出来。作为服务端开发你太熟悉这件事了：改一个字段的语义，八个下游服务出问题。**游戏里更糟，因为下游里有一个是"玩家的行为"，而玩家不读你的变更日志。**

### 耦合的四种形态

| 耦合类型 | 定义 | 例子 | 改动时的风险 |
|---|---|---|---|
| **资源耦合** | 两个系统消耗/产出同一种资源 | 强化和抽卡都花钻石；日常和活动都花体力 | 改了一边的价格，另一边的消耗量跟着变；**这是最常见也最容易被漏掉的耦合** |
| **状态耦合** | 一个系统读另一个系统的状态做判断 | 关卡按战力开放；活动按 VIP 分档；公会按等级给加成 | 上游改了状态的定义或分布，下游的门槛全部失准 |
| **时间耦合** | 两个系统争夺玩家的同一段时间 | 限时活动和赛季结算撞车；两个玩法都要求晚上 8 点在线 | 参与率互相吃掉；玩家被迫二选一并因此不爽 |
| **注意力耦合** | 两个系统争夺玩家的认知带宽和"这周我要干什么"的目标位 | 同时上线三条养成线；主界面五个红点 | 玩家哪个都做不深；新系统的数据难看，但原因在旧系统 |

**后两种最容易被忽略**，因为它们在代码里没有任何依赖关系——两个系统可能一行代码都不共享，但它们在玩家的一天里是直接竞争的。**"这两个系统在技术上不耦合"和"这两个系统在体验上不耦合"是两个完全不同的命题**，而策划要负责的是后者。

### "改一条规则影响谁"的四步法

这是一个可以直接在评审会上用的动作。拿到任何一条规则改动，按顺序问：

**第一步：这条规则动了哪个存量或流量？**
（例："降低精英本的体力消耗"→ 动了体力的流量和材料的产出量。）

**第二步：这个存量/流量还被谁用着？**
把所有消耗和产出同一资源的系统列出来。**这一步必须查表，不能凭记忆**，因为一款成熟手游里同一种资源的去向通常有十几个。

**第三步：它在哪条回路上？这条回路的正负和强度会不会变？**
（例：体力便宜了 → 材料多了 → 战力涨得快 → 更容易过关 → 更多体力（如果关卡给体力）。**正反馈被加速了。**）

**第四步：谁的决策会因此改变？**
这是最容易被跳过、也最重要的一步。（例：原本"这口体力刷经验还是刷材料"是个真决策，体力便宜之后玩家两个都能刷 → **决策消失了**（第 05 章 3.4 节的"权衡"没了）。你以为你在做体验优化，实际上你删掉了一个决策点。）

**用一个具体的完整例子走一遍**，这也是 13.2 节作业要求的格式：

> **改动**：某卡牌手游把"扫荡"从"需要通关三星"改成"通关即可扫荡"。
>
> 1. **动了什么**：扫荡的准入门槛（一个门），间接提高了材料的产出流量。
> 2. **谁在用**：三星评价这个状态还被"关卡成就奖励""挑战任务""新手引导的教学关"用着。
> 3. **回路**：原本"打三星"是一条**驱动玩家优化阵容**的回路（想扫荡 → 要三星 → 要研究关卡机制 → 要练特定角色 → 消耗养成资源）。改动**直接切断了这条回路**。
> 4. **谁的决策变了**：玩家不再需要研究关卡机制，"练哪个角色"从"关卡需要什么"变成"哪个角色数值最高"。**决策类型从偏好型/规划型降级成了算力型**（第 05 章第 5 节），而算力型有唯一最优解。**副作用：所有需要特定角色才能三星的关卡设计，其价值一起归零；关卡策划的工作被作废了一半。**
>
> **结论**：这条看起来纯属"体验优化"的改动，实际上改的是养成系统的决策结构。要不要做？可能还是要做（因为它显著降低了老玩家的操作负担），但**必须同时补上一个新的"研究关卡机制"的动机**，否则关卡设计这条线会慢慢死掉。

**这就是系统思维的样子。** 完整的耦合矩阵工具在 [第 15 章](./15-system-design-method.md)，本章先把这个四步法练熟。

## 10. 涌现的坏一面

到这里为止本章对涌现基本是正面的。现在讲代价，**而且这一节对手游从业者比前面所有节都重要**。

| 风险 | 表现 | 真实后果 | 缓解手段 |
|---|---|---|---|
| **不可控** | 玩家发现了一条你没想到的路径，整个玩法坍缩到那一条上 | 你精心设计的十种玩法，玩家只玩最优的那一种（游戏设计里叫"退化策略"） | 用规则消除支配性策略；给不同路径设不同的适用情境 |
| **可被利用** | 组合出无限资源、无限循环、卡状态 | **经济事故**：一个能刷金币的组合一旦被发现并扩散，服务器经济很快就废了，而且**产出不可回收**（[game-numeric 第 24 章](../game-numeric/24-economy-security.md)） | 硬上限、每日次数、监控异常曲线、灰度发布 |
| **平衡困难** | 组合数爆炸，穷举测试不可能 | 每次加一个新元素，都要考虑它和已有 N 个元素的交互 → 成本 O(N)，长期不可持续 | 限制交互的维度；把元素分组，只允许组内交互；接受"不完全平衡" |
| **体验不可预测** | 有的玩家碰巧组合出神装，有的玩家一路平庸 | 玩家之间的体验差距巨大，客服和社区口碑失控 | 保底、引导、推荐组合 |
| **新手看不懂** | 系统不告诉你能做什么，玩家不知道自己在干嘛 | 次留崩掉。**这是手游里涌现设计最常见的死法** | 用递进外壳把涌现内核包起来，前期强引导（第 18 章） |
| **难以运营** | 无法预排内容、无法做买量素材、无法预测投放量 | 运营团队没有抓手 | 混合结构：把可运营的部分做成递进 |

**这张表解释了为什么手游普遍不敢做强涌现**【推导】：上面六条里，有四条直接打在 F2P 的命门上（经济安全、次留、可运营、可测试）。这不是保守，是商业模式决定的理性选择。

但也要说反面：**完全没有涌现的手游，其寿命由内容产能决定，而内容产能通常追不上头部玩家的消耗速度。** 所以现实中的正确问法不是"要不要涌现"，而是：

> **在我的哪一个子系统里，涌现的收益大于它的风险？**

一个实用的判断框架：

| 系统的性质 | 适合涌现吗 | 为什么 |
|---|---|---|
| **和经济直接相连**（产出资源） | **不适合** | 一个漏洞 = 经济事故，损失不可逆 |
| **纯表达 / 装饰**（外观、家园、称号组合） | **非常适合** | 玩家玩出花来对你只有好处，没有经济风险 |
| **PvP 的策略层**（阵容、战术、外交） | **适合**，且这是最主要的引入点 | 涌现出的内容是免费的，且对手也在学习，深度理论上无限 |
| **新手前 3 天接触的系统** | **不适合** | 玩家还没有心智模型，涌现对他就是混乱 |
| **付费直接相关的系统** | **不适合** | 玩家会觉得"我花钱买的东西效果不确定" |

**这张表是本章最实用的产出物之一。** 下次有人在评审会上说"我们能不能做一个像塞尔达那样万物皆可交互的系统"，你可以用它给出一个有结构的回答，而不是"手游做不了"。

## 11. 贯穿案例 A：《旷野之息》的化学引擎

回到第 1 节的火箭。任天堂团队在 **GDC 2017 的 *Change and Constant: Breaking Conventions with The Legend of Zelda: Breath of the Wild* 里公开讲了这套设计**【实证；讲者是藤林秀麿、堂田卓宏、滝澤智】。顺便更正一个流传很广的归属错误：常和它一起被提到的**"三角形法则"（用三角形的地形引导视线和路径）和地图上的"引力"（吸引玩家注意的地标），出自任天堂 2017 年 CEDEC 的场景/地形设计分享**（GMTK 等渠道有转述），**不是这场 GDC 演讲的内容**——那两部分留到第 25 章讲开放世界。这里只拆化学引擎。

### 11.1 规则长什么样

核心是把世界拆成两套引擎【实证，来自该演讲】：

- **物理引擎**：管质量、力、运动、碰撞、浮力。
- **化学引擎**：管**状态的变化**——火、水、电、风这些"元素"，作用在有对应属性的"材质"上。

化学引擎的规则大致是这样一张**元素 × 属性**的表（下面的具体条目是我玩过之后整理的观察，不是原始文档）：

| 元素 \ 材质属性 | 可燃（木、草、布） | 导电（金属、水） | 可冻（水面、湿的东西） |
|---|---|---|---|
| **火** | → 燃烧（并且燃烧本身也是火源，会传播） | 加热 | 融化 |
| **电** | — | → 导电（伤害沿着导体传） | — |
| **冰** | 熄灭 | — | → 冻结 |
| **水** | 熄灭 | 使其导电 | — |

关键在于**规则写在属性上，不写在物件上**。设计者从来没有写过"木箭 + 火堆 = 火箭"这条规则，他们写的是"木头可燃"和"火会点燃可燃物"。**火箭是这两条规则的推论，不是一个功能。**

### 11.2 这套规则长出了什么

因为规则通用，所以下面这些全都是"免费的"：

- 木箭伸进火里 → 火箭
- 火箭射进草地 → 草地烧起来 → **火产生上升气流** → 玩家打开滑翔伞被气流托上天（**这是两条独立规则的三级组合**：火→燃烧、燃烧→热空气、热空气→上升力）
- 雷雨天举着金属武器 → 引雷劈自己（很多玩家第一次死于此）
- 把金属箱子扔到敌人堆里 + 雷雨天 → 定点清除
- 敌人的木盾可以烧掉
- 下雨时岩壁变滑 → 攀爬会下滑（**这一条把"天气"和"移动"耦合了起来，直接改变了玩家的行程规划**）
- 冰冻水面 → 造出可以站的平台

**注意最后两条**：它们不是"有趣的小把戏"，它们改变了玩家的**决策**。下雨天要不要爬这座山，是一个真决策（第 05 章的四个构件全齐：有选项、有信息、有后果、有代价）。**一个好的涌现系统会自动生产决策**，这是涌现和"彩蛋"最大的区别。

### 11.3 它满足第 8 节的六个条件吗

| 条件 | 旷野之息怎么做的 |
|---|---|
| ① 元素多且属性正交 | 火/水/电/冰/风 × 可燃/导电/可冻/可推动，是真正的多维 |
| ② 规则通用不枚举 | **核心**：规则写在属性上 |
| ③ 交互是 N² | 任何元素可以作用于任何材质，且**结果本身又是元素**（燃烧产生火和热气），所以能形成链 |
| ④ 状态持久 | 烧掉的草地会留下焦土；湿的状态会持续一段时间 |
| ⑤ 后果可感知 | 表现做得极强：火有声音、有光、有烟、草会一片片烧过去 |
| ⑥ 玩家有表达空间 | 玩家可以主动把任何东西扔向任何地方，系统不阻止"不该做的事" |

**第⑥条是最难学的一条。** 大部分游戏会限制玩家的动作（"这个道具不能扔在这里"），因为不限制就会出 bug 或者被利用。旷野之息选择了尽量不限制，代价是玩家确实找到了大量设计者没预料的玩法（各种"飞天"技巧）。**任天堂显然接受了这个代价**【推导】——因为这是一款买断制单机游戏：玩家找到破解方法只会自娱自乐，不会破坏别人的体验，也不会造成经济事故。**换成一个有 PvP 和交易系统的手游，第⑥条会被立刻收紧。**

## 12. 贯穿案例 B：一个 SLG 联盟系统的滚雪球（对照）

现在把同一套工具用在手游上。下面这个系统是我按常见 SLG 的公开表现整理的一个**典型形态**，具体规则各游戏不同，**所有关于设计意图的判断都是【推导】**。

### 12.1 规则（可观察的事实层，你玩的那款请自己核对）

- 联盟可以占领地图上的据点/州，占领需要成员集结出兵
- 占领后全盟获得产出加成或特定资源的开采权
- 成员的兵力增长依赖资源产出
- 集结的战力大致是成员战力的某种叠加（叠加效率是关键参数，见 [game-numeric 第 18 章](../game-numeric/18-slg-core-loop.md)）
- 战斗有战损，战损按参战部队的比例计算
- 个人行动受体力/行动力限制，上限对所有人相同
- 赛季结束时地图重置

### 12.2 画出回路

```
  ┌──────────────────────── 正反馈引擎 ─────────────────────────┐
  │                                                             │
  ▼                                                             │
【联盟控制区】──→ 全盟产出↑ ──→【成员兵力】──→ 集结战力↑ ──→ 打赢 ─┘
  ▲   │                            ▲   │
  │   │                            │   │
  │   └─→ 新玩家愿意加入强盟 ───────┘   └─→ 战损（比例负反馈）
  │        （社交正反馈！）                       │
  │                                              ▼
  └──────────────────────────────────── 【伤兵，需要时间恢复】
```

**这里有两条正反馈，而不是一条。** 第二条经常被漏掉：

- **资源正反馈**：占地 → 产出 → 兵力 → 打赢 → 占更多地
- **社交正反馈**：赢的盟名声好 → **强玩家会跳槽过来** → 更强 → 赢更多

**社交正反馈通常比资源正反馈更强、更快，而且它没有数值刹车**【推导】。资源正反馈可以用产出系数压，社交正反馈压不住，因为它跑在玩家的心理和社交网络上，不在你的配置表里。这是 SLG 里"一超多强"格局形成得那么快的主要原因之一。

### 12.3 三个刹车分别刹住了什么

| 刹车 | 作用在哪条边上 | 刹住了什么 | 刹不住什么 |
|---|---|---|---|
| **体力上限（个人平等）** | 【成员兵力】→ 行动次数 | 单个玩家（包括大 R）每天能打的次数 | 联盟规模带来的总行动次数（100 人的盟就是 100 份体力） |
| **比例战损** | 打赢 → 兵力 | 大规模作战的净收益，防止一战定乾坤 | 长期的产出差距 |
| **赛季重置** | 全图 | 局势的永久固化 | 赛季**内**的滚雪球；跨赛季的养成积累 |

**看这张表的"刹不住什么"一列。** 三个刹车都刹不住"**联盟规模**"这条边。这直接推出一个设计判断：

> **如果你不额外限制联盟规模，SLG 的终局一定是大盟合并小盟，直到地图上只剩两三个巨盟对峙。**

这不是"玩家素质问题"，是回路结构的必然结果。所以现实中的 SLG 一定会有第四类刹车，作用在联盟规模上：成员人数上限、同盟标记/外交关系数量上限、跨盟集结的限制、"一个盟只能占 N 个州"的规则、赛季内的分区/分服设计。**你在任何一款 SLG 里看到这类看起来很扫兴的限制，都可以先假设它是在给某条正反馈装刹车**【推导】，然后去验证。

### 12.4 和旷野之息对照：两种涌现的对比

| | 旷野之息的化学引擎 | SLG 的联盟系统 |
|---|---|---|
| 涌现来自 | **物件之间的规则交互** | **玩家之间的博弈** |
| 元素数量 | 几十种材质 × 几种元素 | 几万个玩家 × 几十个联盟 |
| 交互规则 | 设计者写死的物理/化学规则 | 设计者定的战斗和资源规则 + **玩家自己发明的社交规则**（外交、协议、停战） |
| 涌现的内容 | 玩法组合 | **服务器政治**：结盟、背叛、迁服、开荒战、和平协议 |
| 出问题时 | 玩家飞天，无伤大雅 | **一超独大 → 其他人退游 → 服务器死掉** |
| 设计者能否事后干预 | 不需要 | **必须能**：这就是运营的存在意义（第 22 章） |
| 商业模式 | 买断，一次性收钱 | F2P，需要服务器活三年 |

**最后两行是全表的重点。** 单机游戏的涌现出了问题，最坏结果是玩家自己玩坏了自己的存档；**多人 F2P 的涌现出了问题，结果是一个服务器的几万人一起流失，而且这个损失是不可逆的。**

**所以 F2P 的涌现设计必须自带三样东西**（这三样在买断制单机里都不需要）：

1. **监控**：能看到局势正在往哪个方向滑（[game-numeric 第 23 章](../game-numeric/23-metrics.md)的指标体系）
2. **干预手段**：赛季重置、合服、活动引导、外交规则调整（第 22 章）
3. **兜底**：即使局势彻底固化，落后玩家仍有留下的理由（这是"生态位设计"，见 [game-numeric 第 19 章](../game-numeric/19-server-ecology.md)）

## 13. 常见误区

| 误区 | 为什么错 | 正确的想法 |
|---|---|---|
| "涌现比脚本高级" | 两种结构解决不同问题。递进给可控性和叙事，涌现给重玩性和低边际成本 | 问"我这个子系统需要哪一种"，并且知道混合是常态 |
| "规则越少越可能涌现" | 规则少但元素之间不交互，只会得到一个简陋的系统 | 涌现要的是**通用的规则 + 多维的元素 + 足够多的元素间交互**（第 8 节六条） |
| "可能性空间大就是深度大" | 组合数和深度没有直接关系；坍缩到一个最优解的巨大空间等于没有空间 | 看**有效**可能性空间：社区里流通几套解法 |
| "正反馈是坏的，要消除" | 正反馈是成长感和戏剧性的来源，删了游戏会变得毫无爽点 | 保留引擎，装多级刹车；问的是"刹车够不够"不是"要不要引擎" |
| "加个负反馈就能平衡" | 负反馈过头会让领先玩家觉得努力无效，是另一种流失；而且很多被叫做"负反馈"的东西（体力上限、赛季重置）根本不是回路 | 先按第 5 节的纪律分清**反馈回路**和**平衡机制**；真的要用负反馈，让它作用在**差距**上而不是作用在**努力**上（参考哈迪斯 God Mode 的三个细节） |
| "这两个系统代码上不耦合，所以互不影响" | 时间耦合和注意力耦合在代码里完全看不到，但在玩家的一天里是直接竞争 | 耦合有四种，后两种要靠画玩家的一天来发现（第 07 章） |
| "玩家找到了漏洞是玩家的问题" | 玩家一定会寻找最优解，这是规则的必然结果不是道德问题 | 出现退化策略，先改规则；同时准备好经济事故的应急预案 |
| "先做出来上线，涌现的问题以后再调" | 经济类涌现漏洞的损失是不可逆的（资源已经发出去了） | 与经济相连的系统必须先做上限和监控，再上线（第 10 节的适合性表） |
| "这个系统我改一条小规则，不用评审" | 一条规则可能同时动了资源、状态、回路和玩家的决策类型 | 用第 9 节的四步法过一遍，特别是第四步"谁的决策变了" |

## 14. 动手

### 14.1 拆解：你在玩的 SLG 的"联盟/公会"系统

用 [templates/deconstruction.md](./templates/deconstruction.md)，重点写**第三层（动态层）**。要求回答下面 10 个问题，写进 `notes/拆解/06-系统-游戏名-联盟.md`：

1. 用 Sellers 的三层拆一遍：这个系统的**部件**有哪些？**循环**有哪几条？跑了 30 天之后，服务器上出现了什么**整体层**的现象（格局、文化、潜规则）？
2. 找出至少 **2 条正反馈回路**，画出来。其中有没有"社交正反馈"（不在配置表里的那种）？
3. 找出至少 **2 条负反馈回路**（刹车），画出来。分别作用在正反馈的哪条边上？
4. 对每个刹车，回答"**它刹不住什么**"（照抄 12.3 节那张表的格式）。有没有哪条边完全没有刹车？
5. 这些回路的**延迟**分别是多久（从行动到能感知结果）？有没有延迟超过一天的回路？玩家怎么学会它的——是系统教的，还是老玩家在群里教的？
6. 用第 6 节判断：这个系统里，玩家消耗的内容有多少是**涌现**的（其他玩家的行为）、多少是**递进**的（策划排好的活动和进度）？比例大概是多少？
7. 用第 7 节：这个系统的**有效可能性空间**有多大？（去联盟群或者论坛看，玩家实际在讨论几种打法？）
8. 用第 8 节六个条件给它打分，哪几条不满足？
9. 用第 10 节的适合性表：这个系统里哪些部分适合涌现、哪些部分被设计者刻意做成了不可涌现的？找出至少一条"看起来很扫兴、实则是刹车"的规则。
10. 第五层【推导】：如果把联盟系统整个删掉，这款 SLG 会变成什么？（提示：先想它的内容来源会剩下什么。）

### 14.2 写作作业：反馈回路图 + "改一条规则影响谁"

**产出物两份**，写进 `notes/作业/06-系统.md`。

**第一份：一张完整的反馈回路图。**
挑一个你熟悉的系统（14.1 拆的那个联盟系统，或者你公司项目里你最熟的那个系统），画一张回路图，要求：

- 至少画出 **2 条正反馈 + 2 条负反馈**
- 每条边**标注它传递的是什么**（"产出加成""兵力""名声"），不要画光秃秃的箭头
- 每个刹车**标注它作用在哪条边上**
- 标出每条回路的**延迟量级**（秒 / 分钟 / 小时 / 天 / 周）
- 用一句话写出这张图对应的**体验判断**：这个系统会让玩家感受到什么？强者和弱者分别感受到什么？
- 最后写一条：**这张图上哪条边没有刹车？** 如果没有找到，说明你还没画全

用 ASCII 画就行，参考本章第 5、12.2 节的样式。**画不出闭合回路的系统，请回到第 2 节重读"一堆部件不构成系统"。**

**第二份："改一条规则影响谁"分析。**
给你上面那个系统提一条**具体的规则改动**（真的想改的那种，不要举无所谓的例子），然后严格按第 9 节的四步法写一份分析。格式照抄 9 节最后那个扫荡的例子，要求：

- **第一步**必须指名道姓地说出动了哪个存量或流量
- **第二步**必须列出**至少 4 个**共用这个资源/状态的其他系统（列不出 4 个说明你没查表，去查）
- **第三步**必须说出回路的正负和强度变化，并判断这是加速了引擎还是削弱了刹车
- **第四步**必须回答"**谁的决策变了**"，并用 [第 05 章](./05-decisions.md)第 5 节的决策类型说明有没有发生**降级**（比如偏好型被压成算力型）
- 最后给结论：**做 / 不做 / 做但要同时补什么**。三个结论都可以，但必须有理由

这份作业是第 15 章耦合矩阵的前置练习，请认真写。

### 14.3 思考题

1. 第 1 节的两种做法，如果让你在一款有交易系统的 MMO 手游里实现"火可以点燃可燃物"，你会选 A 还是 B？把第 10 节的六个风险逐条套一遍再回答。
2. 第 5 节说"负反馈要作用在差距上而不是作用在努力上"。《哈迪斯》的 God Mode 是按死亡次数增长的，这算作用在差距上还是努力上？如果改成"按游戏时长增长"呢？
3. 一个系统同时存在正反馈和负反馈，怎么判断哪一条占主导？（提示：看**强度**和**延迟**，不要只看数量。）
4. 12.2 节里那条"社交正反馈"（强盟吸引强玩家）没有数值刹车。如果让你给它装一个刹车，你会装在哪？装了之后玩家会有什么感受？（这题没有好答案，很多 SLG 都在挣扎，你想到的方案很可能已经有游戏试过并且失败了。）
5. 第 7 节说"环境的多样性是有效可能性空间的乘数"。那么一款每个版本都换环境的卡牌游戏，和一款环境固定但角色极多的卡牌游戏，哪个的运营成本更低？哪个的玩家学习成本更低？
