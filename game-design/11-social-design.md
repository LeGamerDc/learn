# 11 - 社交、竞争与合作

## 1. 一个思想实验：把社交全部关掉

拿一款你正在玩的 SLG，在脑子里做一次手术：删掉同盟、删掉聊天、删掉排行榜、删掉世界频道、删掉好友，把所有玩家的地块之间加一堵墙，让每个人只能打 NPC。规则一条不改，数值一个不动。

结果是什么？

- **内容瞬间见底。** 原本"打谁、什么时候打、跟谁一起打"这个每天都不一样的决策消失了，剩下的是一张固定的 NPC 地图，一周之内被最优解扫平。
- **留存曲线塌掉。** 玩家流失的时候，拦住他的从来不是"我的城还没升满级"，是"我走了 A 和 B 怎么办"。
- **付费动机塌掉一半。** 花钱变强，是为了在别人面前变强。没有别人，变强只剩下"更快地扫 NPC"这一个用途，而这个用途的上限很低。
- **口碑归零。** 没有人会跟同事说"我昨天扫了 12 块地"。所有能被讲出去的故事都有第二个人。

这个思想实验的结论很直白：**在 F2P 手游里，社交不是一个功能模块，它是内容的生产方式、留存的主要粘合剂和付费的主要动机来源。** 你可以做一款没有社交的手游（大量小游戏就是），但你要清楚地知道你放弃了什么，以及你打算用什么来替代它（通常是靠买量和快速迭代硬撑）。

"其他玩家是最好的内容"这句行业口头禅经常被误读成"多加社交功能就有内容"。它准确的意思是：**其他玩家是唯一一种你不用花钱生产、每天自动更新、并且永远不会被玩家看完的内容。** 一个关卡策划一个月做 20 关，玩家两天打完；一万个活人玩家每天生产的博弈、背叛、援助和吹牛，永远做不完。代价是你完全无法控制这些内容的质量：同一套规则，可能长出互助的社区，也可能长出霸凌的团伙。

**本章讲的就是这个代价怎么管。**

## 2. 社交为游戏做的四件事（以及各自的反面）

先把"为什么要做社交"拆成四条可以分别设计、分别验证的收益。每一条都有对应的反面，**不看反面就是在写公司宣传稿而不是设计文档**。

| 收益 | 机制原理 | 手游例子 | 买断制对照 | 反面（代价） |
|---|---|---|---|---|
| **留存** | 社会关系是最强的沉没成本；退游不只损失账号，还损失关系与身份 | 率土之滨的同盟；MMO 的固定队 | 《怪物猎人》的联机狩猎让单机内容延长数十小时 | 关系断了退得比谁都快；一个核心玩家退游常带走一串人 |
| **内容生成** | 玩家的行为是不重样的输入；他人的不可预测性是最廉价的不确定性来源 | SLG 的每日战况；MMO 的公会战 | EVE 的势力战争；《魔兽世界》副本的社交组织 | 内容质量不可控；可能长出毒性 |
| **付费动机** | 变强只有在被比较时才有意义；表达只有在被看见时才有意义 | 战力排行、公会贡献榜、皮肤 | 买断制里对应"炫耀性外观"（多数不卖） | 制造军备竞赛；破坏免费玩家生态位（[game-numeric 第 19 章](../game-numeric/19-server-ecology.md)） |
| **口碑与拉新** | 社交结构自带传播链路；组织有招人的动机 | 同盟去外部群拉人；师徒、邀请码 | 朋友推荐 | 拉来的人是"被朋友拉的"，动机弱，留存质量低于自然量 |

这张表里有一个新手最容易忽略的结构：**留存和付费这两条收益是靠"比较"和"绑定"实现的，而比较和绑定正是社交压力的来源。** 你不可能只要收益不要代价，只能选择代价的形态。第 7 节专门讲这件事。

另外要区分清楚两种"社交动机"（[第 03 章](./03-why-players-play.md) 讲过 SDT 的三个基本需要）：

- **关联需要（relatedness）**：我想被一群人接纳、想有归属。这是纯正的社交动机，公会、师徒、固定队服务它。
- **被比较驱动的胜任需要（competence）**：我想在排行榜上看到自己比别人高。这不是社交需要，是**用社交做度量衡的胜任需要**。

把这两者混为一谈的后果是：你以为在做社交系统，实际做的是攀比系统。攀比系统能拉付费，但**几乎不产生留存粘性**，因为攀比不了的人会直接离开，而不是留下来做朋友。设计一个社交系统之前，先明确它主要服务哪一个。

## 3. 社交结构的谱系：从好友到跨服

社交系统不是一个功能，是一个**层级结构**。每一层有不同的规模、不同的准入方式、不同的退出成本，因此产生完全不同的玩家行为。下面这张谱系表是本章最该背下来的东西。

```
   规模 ↑            退出成本 ↑         身份强度 ↑
                                                                 跨服 / 大区
 ┌──────────────────────────────────────────────────────────┐    （几万~几十万）
 │                        服务器 / 大区                       │
 │  ┌───────────────────────────────────────────────────┐   │
 │  │                   阵营 / 势力（自动分配）            │   │
 │  │  ┌─────────────────────────────────────────────┐  │   │
 │  │  │             公会 / 同盟（几十~上百）           │  │   │
 │  │  │   ┌───────────────────────────────────────┐  │  │   │
 │  │  │   │        小队 / 分组（3~10 人）           │  │  │   │
 │  │  │   │   ┌───────────────────────────────┐   │  │  │   │
 │  │  │   │   │      好友 / 一对一（1~50）      │   │  │  │   │
 │  │  │   │   └───────────────────────────────┘   │  │  │   │
 │  │  │   └───────────────────────────────────────┘  │  │   │
 │  │  └─────────────────────────────────────────────┘  │   │
 │  └───────────────────────────────────────────────────┘   │
 └──────────────────────────────────────────────────────────┘
```

| 层 | 典型规模 | 准入方式 | 退出成本 | 身份来源 | 主要设计问题 |
|---|---|---|---|---|---|
| **好友 / 一对一** | 1~50 | 主动加，双向确认 | 几乎为零 | 无（不构成身份） | 怎么让加好友有理由？空好友列表是最常见的死系统 |
| **小队 / 分组** | 3~10 | 临时匹配或邀请 | 一局结束即解散（临时）/ 中等（固定队） | 弱，角色分工带来"我是奶妈"式身份 | 临时队怎么减少摩擦；固定队怎么不变成负担 |
| **公会 / 同盟** | 几十~上百 | 申请 + 审核，或邀请 | **高**：贡献、职位、领地、关系 | **强**：名字挂在头上 | 本章重点，见第 3.2 节 |
| **阵营 / 势力** | 几百~几千 | 通常系统自动分配或一次性选择 | 极高（通常不可换） | 中：靠"我们 vs 他们"，不靠人际关系 | 人数不平衡怎么办；弱势阵营怎么不放弃 |
| **服务器 / 区服** | 几千~几万 | 注册时确定 | 极高（换服=重来） | 中：老区的"服荣誉" | 生态老化、贫富分化（[game-numeric 第 19 章](../game-numeric/19-server-ecology.md)）、合服（[第 22 章](../game-numeric/22-seasons-and-merges.md)） |
| **跨服** | 几万~几十万 | 系统撮合 | 无（打完就散） | 弱 | 跨服的人际关系无法沉淀，只适合承载竞争不适合承载归属 |

### 3.1 每一层要回答的四个问题

设计任何一层社交结构，都要回答这四个：

**问题一：规模。** 规模决定这一层能承载什么行为。有一个流行的说法是，人能维持的稳定社交关系大约在一百多人这个量级【行业口径】，而**能真正协同行动的小组通常远小于这个数**。经验上：

| 规模 | 能承载的行为 | 不能承载的行为 |
|---|---|---|
| 3~8 | 实时协同、明确分工、彼此认脸 | 政治、层级、大规模战役 |
| 20~60 | 有活跃核心、有边缘成员、能组织一次战役 | 匿名（每个人还是会被注意到） |
| 100~500 | 政治、派系、层级管理、外交 | 每个人都被看见；必然出现"沉默的大多数" |
| 1000+ | 只能承载"标签式认同"（我是红方） | 任何需要具体协作的事 |

**设计上最常见的错误是把公会规模定得太大。** 一个 200 人的公会里，绝大多数成员一辈子不会和会长说一句话，他的体验和单机没区别，但他占着一个名额，还要被活跃度考核。**手游公会 30~60 人通常比 200 人更健康**【行业口径】：小到每个人都能被看见，大到能凑出一次团队活动。

**问题二：准入。** 准入门槛决定了组织的同质性和玩家的第一印象。三种典型：

| 准入方式 | 效果 | 风险 |
|---|---|---|
| 一键加入 / 系统推荐 | 新手不会卡在"没有公会"这一步 | 组织没有筛选，凝聚力低，僵尸公会多 |
| 申请 + 审核 | 组织有主体性，会长有筛选动机 | 新手可能被反复拒绝，卡在门外（**这是真实的流失点**） |
| 纯邀请制 | 凝聚力最高 | 新玩家完全进不去，把社交做成了老玩家特权 |

**成熟的做法是分层**：给新手一条"一键加入推荐公会"的低门槛路径保证他有组织，同时保留申请制让高质量组织能筛人。**永远不要让一个新玩家在"没有公会"的状态下过夜**，因为公会通常绑定了每日任务、福利和一部分玩法，没公会等于半个游戏被锁。

**问题三：退出成本。** 退出成本是社交系统的核心杠杆，也是伦理红线所在。

- 退出成本太低：公会变成刷福利的临时旅馆，没有归属感，也没有留存价值。
- 退出成本太高：玩家在一个让他难受的组织里熬着，或者干脆连游戏一起退掉。**"我退不掉，所以我退游"是一种真实且常见的流失路径**【行业口径】。

健康的退出成本应该来自**关系和积累**（我在这里有朋友、有职位、贡献攒了三个月），而不是来自**惩罚**（退会扣光贡献、24 小时不能加入新公会、赛季内退会失去所有奖励）。前者是玩家自愿承担的，后者是设计者施加的。**惩罚型退出成本的每一分留存收益，都在制造对应的怨气**。

**问题四：身份。** 玩家在这一层是不是"某某公会的谁"？身份的载体包括：名字前缀/后缀、职位称号、公会形象（旗帜/图腾/驻地）、可见的贡献排名、公开的战绩。

**没有身份载体的组织不构成社交结构，只是一个功能容器。** 判断标准很简单：**这个组织的名字会不会出现在别人能看到的地方？** 如果一个公会的名字只在公会界面里出现，那它对玩家的意义就止于"每天能领的福利"。

### 3.2 公会/同盟层为什么最难设计

因为它是**唯一一层同时具备"规模够大能做事"和"退出成本够高能留人"的结构**，所以几乎所有 F2P 手游都会做它，也几乎所有问题都出在它上面：

```
        ┌──────────────┐
        │  组织需要活跃  │
        └──────┬───────┘
               ▼
        ┌──────────────┐        设计者的意图：
        │ 给组织考核指标 │        用组织自我管理，
        │（活跃度/贡献） │        节省运营成本
        └──────┬───────┘
               ▼
        ┌──────────────┐
        │ 会长为达标施压 │  ←──── 这一步是设计者把"管理成本"
        └──────┬───────┘        转嫁给了玩家
               ▼
     ┌─────────┴──────────┐
     ▼                    ▼
┌──────────┐       ┌─────────────┐
│ 高活跃玩家 │       │ 低活跃玩家被踢 │
│ 感到被绑架 │       │ 或自己退游     │
└──────────┘       └─────────────┘
```

这个回路是 F2P 公会设计的**结构性陷阱**：你越想用组织提升留存，就越要给组织考核压力，而考核压力最终由玩家施加给玩家。第 7 节给缓释方案。

## 4. 竞争结构：排行、匹配、赛季、锦标赛

竞争是社交的一种形态，不是社交的反面。**竞争让"别人"变得重要**，这本身就是社交价值。

匹配算法、分数系统、赛季重置的数学一律见 [game-numeric 第 17 章](../game-numeric/17-pvp-matchmaking.md) 与 [第 22 章](../game-numeric/22-seasons-and-merges.md)。本节只讲设计面：**同样的算法，用不同的结构包装，玩家的体验完全不同**。

### 4.1 排行榜的四个设计决定

排行榜看起来是最简单的系统（拿个字段排序），实际上是手游里最容易做坏的系统之一。四个决定：

| 决定 | 选项 | 后果 |
|---|---|---|
| **榜什么** | 绝对值（战力/等级）/ 增量（本周成长）/ 效率（通关用时/伤害） | 榜绝对值 = 榜付费，前十名永远是那几个人，99% 的玩家看一眼再也不看；榜增量和效率能让新玩家上榜 |
| **榜多长** | 前 10 / 前 100 / 全服可查自己名次 | 只显示前 100 且不显示自己名次 = 对大多数人不存在。**能看到自己的名次和"离上一名差多少"，才构成目标** |
| **榜的范围** | 全服 / 分段 / 公会内 / **好友榜** | 好友榜通常是转化效果最好的排行榜【行业口径】：可比性强（水平接近）、社交压力低（不是陌生人）、有明确的追赶目标 |
| **结算周期** | 永久 / 赛季 / 周 / 单次活动 | **永久榜很容易死掉**【行业口径】：一旦头部名次被锁死，后来者就没有追赶的理由。除非榜本身在不断长出新维度（新赛季分榜、新玩法榜、新地区榜），否则周榜和赛季榜才是给后来者的重置机会 |

**一条实用判据：一个排行榜如果 90% 的玩家一个月内不会打开第二次，它就该被改成分段榜或好友榜，而不是被删掉。** 删掉排行榜会同时删掉那 10% 玩家的主要目标。

### 4.2 竞争的两种时间结构

| 结构 | 形态 | 体验 | 适合什么 |
|---|---|---|---|
| **连续型** | 天梯、段位、常驻排行 | 压力持续存在；上分焦虑；掉分痛苦 | 硬核竞技（MOBA、格斗）；能承受"每天都在被评价" |
| **周期型** | 赛季、锦标赛、限时争夺 | 有开始有结束；输了还有下一季；**结束本身是内容** | 大多数手游；SLG 的赛季制 |

**周期型的核心价值是它给了失败者一个不带羞辱的退出点。** 连续型天梯里，落后的人要么继续挨打要么退游；周期型里，"这一季结束了"是一个所有人都能接受的重置理由。这也是为什么赛季制在 F2P 里几乎成了标配（数值面见 [game-numeric 第 22 章](../game-numeric/22-seasons-and-merges.md)）。

### 4.3 锦标赛结构的设计面

单败淘汰、双败淘汰、瑞士轮、小组赛+淘汰赛，这些结构在竞技体育里是成熟工具。用到游戏里的时候，**唯一需要你判断的问题是：被淘汰的玩家接下来干什么？**

| 结构 | 淘汰速度 | 被淘汰者的处境 | 手游适配性 |
|---|---|---|---|
| 单败淘汰 | 极快，一半人第一轮就出局 | 无事可做，观赛或离开 | 差，除非有观赛/竞猜内容 |
| 双败淘汰 | 中 | 败者组还有戏 | 中 |
| 瑞士轮 | 慢，所有人打满固定轮次 | **始终有比赛可打，只是对手水平在下调** | **好**，这是手游竞技活动最常用的结构 |
| 循环赛 | 无淘汰 | 全程有事做 | 好，但赛程长 |

**手游里被叫作"锦标赛"的活动，多数其实是瑞士轮或积分赛的变体【行业口径】，原因就是这一条：纯淘汰制会让一半玩家在活动第一天就没有内容了。** 竞技的严肃性要给参与率让路。

### 4.4 一条容易被忽略的设计原则：给输家设计

竞技设计里最需要刻意练习的能力是**为输的那一方设计**。一场 PvP 里必然有 50% 的失败者，一个排行榜里必然有 99% 的非第一名。他们的体验决定了系统的实际留存效果。

给输家的设计工具：

- **保底收益**：输了也有资源产出（但要低于赢，否则竞争消失）
- **归因可见**：让玩家知道自己为什么输（战报、伤害统计、对手阵容）。**看不懂为什么输 = 归因给运气或不公平**
- **分段与保护**：段位保护、连败补偿（数值面见 game-numeric 第 17 章）
- **叙事重构**：把"你输了"包装成"你的部队撤退了，损失了 X"，而不是一个红色的 DEFEAT
- **另一条赛道**：全服第一争不了，公会内第一、好友内第一、本周成长第一都可以争

关于竞技心态，David Sirlin 的《Playing to Win》里有一个有用的概念【实证】：**"scrub"** 指的是那种给自己加上一堆规则之外的自我限制、然后指责用完整规则打赢自己的人"不讲武德"的玩家心态。Sirlin 本人讲的是竞技心态，**下面这条设计推论是本课加的【推导】**：当玩家大规模地认为某个合法策略"不该被使用"时，值得先去查这个策略的存在感、可对抗性或获取门槛是不是出了设计问题，而不是先归因到玩家素质。

## 5. 合作设计：为什么大多数"合作"其实是"并行"

先给结论：**手游里绝大多数号称合作的玩法，实际上是"多个人在同一个房间里各玩各的"。** 判断标准只有一个问题：

> **如果把队友换成一个数值相同的 NPC，玩家的体验会变吗？**

如果不会变，那它不是合作，是"人形挂件"。真正的合作必须让玩家之间产生**信息或行动上的依赖**。

### 5.1 真合作的三个条件

| 条件 | 含义 | 缺了会怎样 | 例子 |
|---|---|---|---|
| **分工** | 不同玩家做不同的事，能力不可互换 | 所有人做同一件事 = 人数只是数值倍率 | MMO 的坦克/治疗/输出；《怪物猎人》的打断与陷阱分工 |
| **互补** | 一个人的短板由另一个人补上，且这个补位是有意义的选择 | 分工存在但可以一个人全包 = 分工失效 | 治疗职业只有在别人会掉血且自己打不动怪时才成立 |
| **共同目标 + 共同结算** | 结果是集体的，不是个人成绩的加总 | 只有个人结算 = 每个人只优化自己 | 公会战的城池归属；副本的通关而非伤害榜 |

第三条最容易被破坏：**你加了一个伤害排行榜，合作就变成了竞争。** 队伍内的个人排行是一个强力工具，但它会把"我们要赢"改写成"我要在我们赢的时候排第一"，这两者经常冲突（比如为了刷伤害不去救人）。要不要加个人榜，是一个明确的设计取舍，不是顺手加的 UI。

### 5.2 搭便车问题（free rider）

只要收益是集体分配的，就必然有人选择"少付出、照样拿"。这是公共品博弈的标准结论（博弈论工具见 [game-numeric 第 16 章](../game-numeric/16-game-theory.md)），不是玩家道德问题。

**搭便车不总是坏事。** 一个健康的组织里本来就该容纳低强度参与者：他们是人数、是氛围、是未来的核心。你要防的是两件事：**(a) 搭便车的收益高到让认真玩的人觉得自己是傻子；(b) 组织被迫用社交手段（羞辱、踢人、点名）来解决这个问题。**

解法清单，按副作用从小到大排列：

| 解法 | 机制 | 副作用 |
|---|---|---|
| **贡献可见** | 战报、贡献日志、参与记录 | 小；但要小心变成公开羞辱榜 |
| **参与门槛** | 不参与就不发奖（而不是"参与少就少发"） | 小；门槛要低到"上线点一下就算" |
| **收益与个人行为挂钩** | 集体奖 + 个人奖双轨，个人奖按行为发 | 中；容易滑向"合作变竞争" |
| **人头即资源** | 集结需要凑够队伍数、副本需要满员开启 | 中；让在场本身有价值，但制造"等人"体验 |
| **上限封顶** | 个人贡献设日/周上限 | **小且强力**：肝帝也只能贡献这么多，弱化了"你怎么不多打点"的压力 |
| **自动清退** | 系统按活跃度自动移除 | 中；比会长手动踢人温和（**把执法从人转移到规则**） |
| **组织自治** | 会长可踢人、可调整权限 | **大**：这是把管理成本外包给玩家，也是社交压力的主要来源 |

**"上限封顶"和"自动清退"这两条值得单独记住**，因为它们的共同思路是：**把人与人之间的冲突转化成人与规则之间的关系。** 玩家可以接受"系统规定每天最多捐 3 次"，很难接受"会长说你捐得少"。

### 5.3 合作的手游形态与买断制对照

| 形态 | 手游例子 | 买断制对照 | 合作真伪 |
|---|---|---|---|
| 实时同屏协同 | MMO 副本、《原神》联机 | 《怪物猎人》《双人成行》 | 真（如果有分工） |
| 组织级战役 | SLG 的集结攻城 | EVE 的舰队战 | 真（依赖指挥与时序） |
| 异步互助 | 借将、助战、送体力 | 《黑暗之魂》的留言与召唤 | 弱合作，但成本极低 |
| 共同进度条 | 公会累计任务、全服活动 | 少见 | **伪合作**（本质是并行，除非有分工） |
| 一起挂机 | 挂机放置类的组队加成 | 无 | 伪合作 |

**伪合作不是错误设计。** 公会累计任务的目的往往就是"给一个上线理由 + 让成员感到自己属于一个集体"，它便宜、无摩擦、不需要玩家在线时间对齐。你要做的是**知道自己在做伪合作**，不要指望它产生真合作的粘性，也不要为它设计需要真合作才成立的奖励结构。

## 6. 异步社交：手游的主要形态

主机和 PC 的社交想象力是"我们一起在线打一场"，手游的现实是**大多数玩家永远不会同时在线**。会话短（几分钟）、时段分散、网络不稳、随时可能被现实打断。所以手游社交的主干是**异步的**。

异步社交的定义：**A 的行为在 A 下线之后，仍然被 B 感知到，并且 B 的回应又会被 A 在下次上线时感知到。** 它构成一个跨越时间的循环：

```
  A 上线：留下一个"痕迹"          B 上线：看到痕迹 + 回应
  （借将/留言/防守阵容/送礼）  ──→  （借用/回复/进攻/回礼）
        ▲                                    │
        │                                    ▼
        └──────  A 下次上线：看到回应的结果  ←┘
                （借用记录/被打战报/回礼）

  循环周期 = 一天，而不是一局
```

**这个循环的周期是"一天"而不是"一局"，这是手游社交设计的第一原理。** 它决定了：反馈可以延迟，但**必须在下次上线时被明确呈现**。玩家上线后看不到"我不在的时候发生了什么"，异步社交就断了。

常见的异步社交形态：

| 形态 | 机制 | 满足什么 | 手游例子 | 买断制对照 |
|---|---|---|---|---|
| **助战 / 借将** | 借用好友的角色打关卡，好友获得回报 | 让"加好友"有硬收益；展示自己的养成成果 | 卡牌 RPG 的助战位 | 《黑暗之魂》的召唤 |
| **留言 / 板** | 留下文字，被后来者看到 | 表达、玩笑、警告 | 公会公告、留言板 | 《黑暗之魂》的留言系统、《死亡搁浅》的设施共享 |
| **互访** | 进入别人的空间参观 | 展示与窥探 | 家园、庄园、岛屿 | 《动物森友会》的岛屿访问 |
| **点赞 / 表情** | 极低成本的正反馈 | 被看见 | 几乎所有手游 | 少见 |
| **离线防守** | 我的阵容在我下线时被别人挑战 | 让养成有 PvP 意义而不需要在线 | 竞技场 | 少见 |
| **战报** | 上线时看到不在场期间发生的事 | 异步循环的闭环点 | SLG 的战报系统 | 少见 |

**异步社交的设计要点，一句话：把"痕迹"做得比"结果"更重要。** 借将系统里，玩家真正在意的往往不是那点助战奖励，而是"我的角色被借用了 37 次"。这个数字是他被别人看见的证据，成本几乎为零，价值极高。

### 6.1 一个对照：《动物森友会》的松散社交

《动物森友会》（买断制，任天堂）的社交结构和 SLG 几乎是两个极端，值得作为参照系：

- **准入**：访问别人的岛需要好友码或一次性的临时口令（Dodo Code），**没有公会、没有阵营、没有排行榜**。
- **互动内容**：参观、交易（大头菜价格）、送礼、留言、带走对方岛上的资源。
- **竞争**：几乎为零。没有战力，没有名次，唯一的"比较"是岛的样子好不好看，而这是审美不是数值。
- **退出成本**：零。今天不去朋友岛上，什么也不会失去。

【推导】这套设计的意图大概是：把社交完全限制在"展示与馈赠"这一种行为上，**用彻底放弃竞争来换取零社交压力**。它的代价也很明显：社交无法承担留存任务，玩家的留存靠的是每日的收集和布置，不是"我不上线队友会骂我"。

《原神》的联机（多人世界）是另一个中间态：最多四人、可以互相进入世界打怪和采集，但**剧情不能在联机中推进、没有公会、没有长期组织**。【推导】这是刻意把社交限制在"临时互助"这一层：它解决了"打不过某个 boss"和"想炫耀角色"的需求，但不承担组织化的留存与压力。

**这两个对照的共同点是：它们都明确选择了"社交不承担留存 KPI"。** 一旦你的项目决定让社交承担留存 KPI，设计就会被持续推向公会、考核和压力这条路【推导】——因为这是最直接见效的做法。要绕开它不是不可能，但通常得接受另一种代价（社交对留存的贡献更低、更依赖内容更新）。这是结构问题，不是善恶问题。

## 7. 社交压力与毒性

这一节是本章最实用的部分。**社交系统的绝大多数投诉，不是"功能不好用"，是"我被逼的"。**

### 7.1 社交压力的来源分类与缓释表

| 压力来源 | 典型机制形态 | 玩家的原话 | 缓释设计 |
|---|---|---|---|
| **时间绑架** | 团本/集结/攻城必须在固定时段在线 | "我为了打攻城请假了" | 多时段开放；参与窗口拉长；**托管/预约出兵**；离线也能贡献的形式 |
| **KPI 化** | 公会活跃度考核、周贡献榜、末位淘汰 | "玩游戏像上班" | **贡献封顶**；按人均而非总量算；设一条"低强度合格线"，达标即可 |
| **强依赖** | 没有公会就打不了某内容 / 拿不到某资源 | "我不想加公会但被迫加" | 提供单人或临时组队的替代路径（效率可以低，但不能没有） |
| **不可退出** | 退会惩罚、赛季内绑定、贡献清零 | "我退不掉只能退游" | 退出成本来自积累而非惩罚；设"转会窗口"；贡献部分可携带 |
| **公开羞辱** | 末位公示、最低贡献红名、公开踢人记录 | "我被挂出来了" | **只公示正向**（本周之星），不公示末位；低段位隐藏排名 |
| **代肝与借号** | 玩法可以被完全代打，于是"你怎么不找人代" | "不代打就跟不上" | 让核心动作需要实时决策/不可托管；引用 [game-numeric 第 24 章](../game-numeric/24-economy-security.md) 的账号安全面 |
| **骚扰与毒性** | 私信、世界频道、被针对性打击 | "我被人盯上了" | 屏蔽/举报/一键静默；默认限制陌生人私信；被反复攻击的保护机制 |

**这张表就是本章作业要写的那份"社交压力风险清单"的骨架。**

### 7.2 缓释设计的三条通用原则

**原则一：把人对人的约束改写成人对规则的约束。**

玩家可以接受系统的限制，很难接受另一个玩家的要求。所以：与其让会长去踢不活跃的人，不如让系统自动清退（并且提前通知）；与其让公会靠喊话凑集结，不如给集结加一个"预约出兵"的功能让离线也能参与。**每当你看到一个设计要求"组织自己去管"，都要问一次：这个管理动作能不能变成规则？**

**原则二：给压力设上限，而不是给压力设方向。**

贡献封顶是本章最推荐的单条机制。它的作用不是限制肝帝（虽然表面上是），而是**给所有人一个"我做到这里就够了"的明确终点**。没有上限的贡献榜意味着永远有人比你多，永远可以被要求"再多一点"。有了上限，一个每天花五分钟的人也能理直气壮地说"我满了"。

**原则三：所有强社交系统都要有一条"低强度合格路径"。**

对每个社交系统问一遍：**一个每天只上线 5 分钟、不进语音、不看群消息的玩家，能不能体面地待在这个组织里？** 如果不能，你就把这部分玩家（通常是大多数）推向了两个选择：假装很努力，或者退游。

### 7.3 毒性：竞争环境的必然产物与它的设计面

毒性行为（辱骂、挂机报复、恶意针对、组团霸凌）在有竞争、有匿名、有队友依赖的地方必然出现。设计上能做的事：

| 层次 | 手段 | 说明 |
|---|---|---|
| **预防** | 减少无意义的公开对抗；限制陌生人的沟通渠道；新手保护期 | 最便宜的手段是**不给毒性提供接口**：没有全服喊话就没有全服对骂 |
| **归因** | 让失败的原因可见（战报、数据） | **看不懂为什么输，玩家就会归因给队友**。清晰的战报是最被低估的反毒性设计 |
| **惩戒** | 举报、行为分、禁言、匹配隔离 | 【行业口径】常见做法是把高举报率玩家匹配到一起，而不是直接封号 |
| **正向激励** | 赛后点赞、好评标签、组队优先 | 效果弱于惩戒，但副作用小 |
| **退出通道** | 一键屏蔽、退出不受惩罚、换服/换盟成本可控 | 让被骚扰者能走，是底线 |

**一条判断题**：如果你的游戏里，一个玩家被另一个玩家持续针对（比如 SLG 里被反复打城），他有没有一条不需要求人、不需要付费、不需要退游的出路？如果没有，这个设计迟早会制造大规模的差评。SLG 里常见的出路是迁城、赛季重置、加入更强的同盟；这三条都是**设计者提供的逃生舱**，不是玩家自己想出来的。

## 8. 两个分类工具

理论章节的价值在于给你**分类的词汇**，让你在评审时能说出"这个系统只覆盖了竞争，没有覆盖表达"，而不是"我感觉少了点什么"。

### 8.1 Amy Jo Kim 的社交行动矩阵

Amy Jo Kim 在 2014 年的博客文章 *Beyond Player Types: Kim's Social Action Matrix* 里提出：与其给玩家贴人格标签，不如去看**他们实际在做什么动词**【实证：Amy Jo Kim 2014 年博客原文；她后来的《Game Thinking》可作补充引用】。她把常见的社交动词摆进两个轴：

- **纵轴：Acting（主动施加）↔ Interacting（往复互动）**
- **横轴：Content（指向内容与系统）↔ Players（指向人）**

四个象限按原图的位置是：

|  | **Content 指向内容** | **Players 指向人** |
|---|---|---|
| **Acting 主动施加** | **Explore 探索**：查看、收藏、评分、投票、点评、整理与查阅攻略 | **Compete 竞争**：赢、挑战、比较、炫耀、挑衅 |
| **Interacting 往复互动** | **Create / Express 创造与表达**：设计、搭建、装饰、自定义、挑选外观 | **Collaborate 协作**：评论、点赞、打招呼、帮忙、分享、贡献 |

两处最容易记错的地方要特别指出：**Kim 的 Explore 指的是"看 / 收 / 评 / 理"这一类对内容的消费与整理**，不是"打高难副本"；而 **Compete 和 Collaborate 分别落在 Acting 和 Interacting 两侧，不是同一根轴的两端**——"竞争↔合作"不是这张图的轴。

用法很简单：**把你的游戏里所有社交相关的功能填进这四格，看哪一格是空的。**

常见诊断结果：

- **大多数 SLG**：Compete 和 Collaborate 极强，Explore 和 Create 几乎空白。后果是不喜欢对抗的玩家完全没有位置，而这部分人在大盘里占比不低。补法通常是加称号、皮肤、同盟旗帜与主城外观（Create），以及图鉴、战报回放、赛季志、阵容与攻略分享（Explore）。
- **大多数卡牌养成**：Explore（图鉴、角色资料、阵容评分与攻略）和 Create（角色收集、皮肤、阵容搭配与分享）强，Collaborate 弱（合作多是伪合作）。后果是社交留存靠不住，主要靠内容更新。
- **《动物森友会》**：Create 极强，Compete 几乎为零。
- **传统 MMO**：四格都有，这也是 MMO 生命周期长的结构原因之一【推导】。

**这张表最大的价值是提醒你：社交不等于竞争和公会。** 一个让玩家能展示自己（Express）的系统，社交价值可能高于第三个排行榜。

### 8.2 回看 Bartle 的四型

Richard Bartle 在 1996 年的《Hearts, Clubs, Diamonds, Spades: Players Who Suit MUDs》里把玩家分成成就者（Achiever）、探索者（Explorer）、社交家（Socializer）、杀手（Killer）四型【实证】。[第 03 章](./03-why-players-play.md)讲过它作为动机模型的局限（它是对 MUD 玩家的观察归纳，不是经过验证的心理学量表），但**它在社交设计里仍然是最好用的粗分类**，因为它的两个轴恰好就是社交设计的两个轴：

```
                    Acting（主动施加）
                            ▲
                            │
       杀手 Killer          │        成就者 Achiever
     （对其他玩家动手）       │      （对世界动手：刷分、清图）
                            │
 Players ◄──────────────────┼──────────────────► World
（指向玩家）                 │                  （指向世界）
                            │
     社交家 Socializer       │        探索者 Explorer
    （与其他玩家互动）        │      （与世界互动：挖机制）
                            │
                            ▼
                  Interacting（往复互动）
```

（注意：Bartle 的横轴是"玩家在左、世界在右"，Kim 的横轴反过来是"内容在左、玩家在右"，两张图的象限位置对不上，但两个轴的含义是同一套。）

在社交设计里的具体用法：

| 类型 | 他需要什么社交结构 | 你没给他会怎样 |
|---|---|---|
| **社交家** | 聊天、公会、师徒、互访、无目的的相处空间 | 他会去外部（微信群、QQ 群）社交，然后**在外部群里被拉去别的游戏** |
| **杀手** | PvP、可对抗的目标、能让别人感受到自己的手段 | 他会把破坏欲转向队友和公会内部，成为毒性来源 |
| **成就者** | 排行、进度、可展示的成果 | 他会流失到别的有明确目标的游戏 |
| **探索者** | 未知内容、机制深度、可挖掘的系统 | 他会看完攻略后离开 |

**"社交家会去外部群社交"这条最值得记住。** 手游的公会几乎都在游戏外有一个 QQ/微信群，真正的社交发生在那里。这既是好事（关系更牢固，留存更强），也是风险（竞品挖角就是挖一整个群）。【推导】这也解释了为什么很多手游花力气把社交搬回游戏内（语音、动态、公会主页），效果通常有限：**游戏内 IM 打不过微信，这是产品结构问题不是设计问题。** 更实际的做法是承认外部群的存在，并让游戏内提供外部群做不了的事（职位与权限、出兵与对时工具、战报、同盟资产）。

## 9. 贯穿案例：《率土之滨》的同盟系统

现在把上面所有工具用到一个真实系统上。选率土之滨的同盟，是因为它是国内手游里**社交结构做得最深、最能看清"规则如何塑造组织"的样本之一**。

> **纪律提醒**：下面第 9.1 节全部是可观察的规则（第 00 章拆解模板的第二层），**具体数字随版本和赛季变化，以你自己服里的为准，本节不写死数字**；第 9.3 节全部是【推导】。另外，本节会反复把《率土之滨》和《万国觉醒》一类的 COK-like SLG 做对照——**这两套规则长得像但完全不是一回事，写案子时混用是常见错误**。

### 9.1 机制层：规则是什么

**（1）组织结构与职位**

- 同盟有成员数上限（数量级在几十到上百，随版本/赛季变化）。
- 职位分层：盟主、副盟主（数名）、官员/管理（可任命多名）、普通成员。
- 职位对应**权限差异**，主要包括：审批入盟申请、踢出成员、任命下级职位、发布同盟指令与战略标记、分配同盟打下来的城池与关卡（包括任命城池的主官）、处理外交（结盟、宣战、不侵犯）。
- 关键点：**职位不是称号，是权限。** 一个副盟主能决定同盟往哪个方向推进、优先铺哪条线，这个决定影响所有成员未来几周的玩法内容。

**（2）地是个人占的，路是集体铺的**

这是最容易和 COK-like 写混的一处，先把两套规则摆开：

| | 率土-like（率土之滨 / 三国志·战略版） | COK-like（万国觉醒一类） |
|---|---|---|
| 谁占地 | **玩家个人**逐块攻占、升级地块，地是个人资产 | 联盟用**旗帜 / 联盟要塞**圈出领土，领土是联盟资产 |
| 扩张的连通规则 | **连地出征**：出征目标必须与"自己已占的地"相邻；**同盟成员的地也算**，这就是"借道" | 新插的旗必须与联盟已有领土相连（最终连回联盟要塞），中间断一节，后面整片失效 |
| 前进基地 | **要塞、分城这类个人建筑**，建在自己的地上，把自己的出征起点前移 | 联盟要塞与旗帜，由有权限的成员代表联盟建造 |
| "铺路"是什么 | 一串成员各自把地占成一条链，后面的人**借这条链**继续往前打 | 联盟按顺序插旗，把领土整体推过去 |

对率土-like 来说，这条规则的直接后果是：**你的个人扩张能走多远，取决于你的邻居是谁、他们往哪个方向打。** 于是扩张变成一个**有方向、有次序、需要集体商量**的过程：先打哪块、谁负责铺哪条线、要塞建在哪、优先往哪个州推进。你想去打远处那块高级地，得等有人先把路铺过去。

**这一条是整个同盟系统的地基。** 它把"社交"从一个附加功能变成了**玩法的前置条件**：没有同盟，你的个人成长会在某个阶段直接卡死。

**（3）多人打一个目标：压秒，还是集结？**

高价值目标（高等级地、要塞、城池、强势玩家的部队）单人打不下来，必须多人上。但"多人上"在两类 SLG 里是两套完全不同的机制，**这是本节最需要记住的区分**：

| | 率土-like 的常规协同 | COK-like 的集结（rally） |
|---|---|---|
| 形态 | 每个人**各自出兵**，各自走各自的行军时间 | 一名玩家**发起集结**，其他人把队伍加进他的集结队列，倒计时结束后作为一支部队出发 |
| 协同的难点 | **压秒**：算好行军时间，让若干支部队在同一分钟、同一战斗轮次前后到达 | 卡住集结倒计时；发起者的**集结容量**决定这一波能带多少兵 |
| 关键角色 | 会算时间的指挥 + 每个人自己按点出兵 | **集结手**（集结容量高的那个号）+ 加入的人 |
| 典型翻车 | 零散到达被逐个击破 | 没赶上倒计时；集结手不在线，整个联盟打不出伤害 |

《率土之滨》里"集结"一词另有所指：同盟拿下城池后可以设**太守**，成员把部队**集结到该城池**，由太守统一编成军团出征（可调动的队伍数与城池等级挂钩，各版本有调整）。它是一个特定的城池玩法，不是"每次多人打架都点一下集结"。**本课其他章节在泛指 SLG 协同时用的"集结"，指的是 COK-like 那一种。**

- **玩家在这里做的决定**：我这支队伍要不要投进这一波（投出去到回城之前不能做别的事）、我该带什么阵容（拆城防还是打守军）、我该几点几分点出兵才能和大部队一起到。

**（4）攻城**

攻城是同盟系统的高潮，也是组织要求最高的动作。典型的组织要求包括：

| 环节 | 组织要求 | 对应的社交结构 |
|---|---|---|
| 前期准备 | 成员各自占地把路铺到城下、建要塞前移出发点、备足兵与器械 | 需要长期的集体规划（几天到几周） |
| 时间约定 | 全盟在同一时段上线 | **时间绑架的主要来源** |
| 分工 | 有人拆城防/耐久、有人打守军、有人牵制敌方援军、有人守自家 | 真合作（分工+互补） |
| 指挥 | 指挥者定目标优先级和出兵时刻表（谁几点几分点，压秒） | 职位权限的实际用途 |
| 后续 | 打下来之后要守（防反扑）、要治理（设主官、分配收益） | 集体资产带来集体责任 |

**攻城把第 5.1 节的"真合作三条件"全部凑齐了**：分工（不同人打不同目标）、互补（拆耐久的队伍打不过守军，反之亦然）、共同结算（城池归同盟所有，不归个人）。这是它体验强度极高的机制原因。

**（5）退出与流动**

- 退盟通常有冷却时间（离开后一段时间内不能加入新同盟），这是明确的退出惩罚。
- 迁城：玩家可以把主城迁到别处，这是**被针对时的逃生舱**。
- 赛季结束：整张地图重置，所有同盟归零。

**（6）翻盘机制**

率土的翻盘机制值得单独列，因为它是这类高压竞争游戏能长期运转的关键：

| 机制 | 作用 | 属于第 4 节的哪种结构 |
|---|---|---|
| **赛季重置** | 地图、领地、同盟格局全部归零，只保留部分个人积累 | 周期型竞争；最大的翻盘器 |
| **兵役/伤兵成本** | 打赢也要付出兵力代价，无法零成本连续进攻 | 负反馈；限制滚雪球 |
| **体力等时间闸门** | 每人每天能做的行动量接近（见 [第 00 章](./00-how-to-learn.md) 的拆解示例） | 负反馈；压缩付费差距 |
| **多线牵制** | 强盟同时被多个方向进攻时无法兼顾 | 涌现出的政治手段，非设计者直接给的机制【推导】 |
| **迁城** | 个体的空间性逃生 | 退出通道 |
| **外交** | 弱盟联合对抗强盟 | 玩家自己创造的负反馈 |

### 9.2 动态层：规则跑出了什么

- **核心社交循环**：同盟制定方向 → 个人在方向内选目标并铺路 → 攻城需要时间对齐（压秒） → 战报产生集体叙事 → 强化组织认同 → 下一轮方向。
- **组织化程度是玩家最大的实力差**。同等付费下，一个能凑齐三十人同时上线的同盟，能打赢一个战力更高但一盘散沙的同盟。**这是率土最重要的动态：它把"组织能力"变成了一种可以对抗"付费能力"的资源。**
- **涌现行为**：外部 YY/微信指挥体系、专业指挥角色、"打手"与"内政"的玩家自发分工、赛季前的招募与转会市场、盟与盟之间的条约与背叛。这些都不是设计者写在案子里的，是规则跑出来的。
- **代价**：时间绑架极强（攻城要请假）、指挥岗位极累（一个盟的体验高度依赖两三个核心）、新手进不了好盟就基本没有内容。

### 9.3 意图层【推导】

- **职责**：同盟不是一个社交功能，它是率土的**内容生产机制**。地图上每天不同的战况，全部由同盟之间的博弈生成。没有它，率土就是一个扫地图的单机游戏。
- **删掉会怎样**：整个游戏的中后期内容消失。个人的成长会在中期完全失去目标（没人借道就走不远，没人压秒就打不动高价值目标），会话结构也会从"多次短会话 + 一次长会话（攻城）"退化成纯粹的挂机。
- **为什么用"连地出征 + 同盟借道"这条规则**：它用一条极简单的空间规则，同时实现了三件事：让扩张需要集体决策、让新成员的个人利益与集体绑定、让地图上的势力范围可视化。**用一条规则解决三个设计问题，这是本课后面反复会强调的"机制经济性"。**
- **为什么保留退盟冷却**：防止赛季关键节点的临阵倒戈和"打不过就投降加入对方"，代价是被困在坏同盟里的玩家会更难受。
- **一句话设计目标**：**用一套强制协同的规则，把玩家的组织能力变成一种可以与付费能力抗衡的核心资源，从而让免费玩家有存在价值、让付费玩家有必须争取的东西。**

### 9.4 批评与对照

| 维度 | 率土之滨的同盟 | 《动物森友会》的岛屿互访 | 《原神》的联机 |
|---|---|---|---|
| 社交是否为玩法前置 | **是**（没盟等于半个游戏被锁） | 否 | 否 |
| 组织化程度 | 极高（职位、权限、外交） | 无 | 无 |
| 时间对齐要求 | 高（攻城） | 无 | 中（要约同时在线） |
| 退出成本 | 高（惩罚 + 积累 + 关系） | 零 | 零 |
| 社交压力 | **高** | 极低 | 低 |
| Kim 矩阵覆盖 | Compete + Collaborate 满，Create / Explore 弱 | Create 满，其余基本空 | Collaborate + Explore 有，Compete 空 |
| 谁被排除在外 | 不能固定时段上线的人、不想被管的人 | 想竞争的人 | 想要长期组织归属的人 |

**"谁被排除在外"这一行是本章最想让你养成的提问习惯。** 任何社交结构都在选择自己的玩家。率土用高组织度换来了极强的留存和内容，代价是它天然排斥一大批人。这不是缺陷，是定位。**你要做的是有意识地选，而不是默认抄一套公会系统然后奇怪为什么留存没涨。**

## 10. 常见误区

| 误区 | 为什么错 | 正确的想法 |
|---|---|---|
| "加个公会就有社交了" | 公会只是容器；没有必须一起做的事，公会就是个领福利的按钮 | 先想清楚"玩家在这里必须依赖别人做什么"，再决定要不要容器 |
| "社交功能越多越好" | 每个社交功能都要有人用才成立；空的好友列表和死的聊天频道是负资产 | 宁可只做一个能跑起来的（通常是公会或助战），也不要五个半死的 |
| "把公会规模做大，社交更热闹" | 200 人的公会里绝大多数人是隐形的，反而更冷清 | 30~60 人量级更容易让每个人被看见【行业口径】 |
| "排行榜能刺激付费所以多做几个" | 榜绝对值的榜对 99% 的玩家不存在，还会打击中低玩家 | 分段榜、好友榜、成长榜比全服战力榜有效得多 |
| "合作玩法就是多人一起打" | 队友可以被 NPC 替换的玩法不是合作 | 用"换成 NPC 体验会变吗"来测真伪 |
| "搭便车是玩家素质问题" | 集体收益 + 个人成本必然产生搭便车，这是结构不是道德 | 用封顶、门槛、自动清退把冲突从人转移到规则 |
| "社交压力是玩家自己造成的" | 是设计把管理成本转嫁给了会长，会长只是执行者 | 每一条需要"组织自己去管"的规则，都要问能不能变成系统规则 |
| "毒性靠举报系统解决" | 举报是事后的；毒性的接口是设计给的 | 先减少无意义的公开对抗接口，再谈惩戒 |
| "跨服能让社交更丰富" | 跨服关系无法沉淀，打完就散 | 跨服适合承载竞争，不适合承载归属 |
| "游戏内做个好用的聊天就能把社交留在站内" | 游戏内 IM 打不过微信 | 承认外部群，让站内提供外部群做不了的事（权限、集结、战报） |

## 11. 动手

### 11.1 拆解：《率土之滨》（或三国志·战略版 / 万国觉醒）的同盟系统

用 [templates/deconstruction.md](./templates/deconstruction.md) 完整写一份，**必须自己进游戏验证规则，不要照抄本章第 9.1 节**（本章刻意没写死数字，就是为了逼你去查）。要回答下面这份问题清单：

**机制层（只写事实，每条标注"已验证/未验证"）**

1. 同盟的成员上限是多少？满员之后新人怎么办？
2. 一共有几种职位？每种职位的权限逐条列出来（至少列 6 条权限）。谁能踢人、谁能建建筑、谁能发集结？
3. 加入一个同盟需要经过哪些步骤？有没有申请门槛（战力/等级/答题）？被拒绝之后会发生什么？
4. 退盟的完整代价是什么？冷却多久？已有的贡献/领地/建筑权限会怎么样？
5. 集结的完整规则：谁能发起、最多几支队伍、等待时间多长、距离怎么限制、中途能不能取消、失败了损失什么？
6. 攻打一座城需要哪些前置条件？从"决定打"到"打下来"最少需要多少个环节、涉及多少人？
7. 同盟层面有哪些"考核"型的指标（活跃度、贡献、周任务）？它们的奖励怎么分配（平均分 / 按贡献分 / 阶梯）？有没有上限？

**动态层**

8. 观察你所在同盟一周的聊天记录（或外部群），统计：多少条消息是组织协调（集结、时间、目标），多少条是纯社交（闲聊、玩笑），多少条是催促/施压？
9. 你所在同盟里，有多少比例的成员在最近一次集结中出过兵？没出兵的人受到了什么对待（系统的 / 人的）？

**决策层**

10. 列出至少 3 个"因为有同盟才存在"的玩家决策点，按第 05 章的四要素（选项/信息/后果/权衡）填表。哪一个是最好的决策？

**意图层【推导】**

11. 如果把"领地必须连续"这条规则删掉，允许在地图任意位置建同盟建筑，同盟这个组织会发生什么变化？（提示：从"集体决策还有没有必要"入手。）
12. 用第 8.1 节的 Kim 矩阵给这个游戏的所有社交功能分类，指出哪一格是空的，并说明这一格的空缺让哪一类玩家流失了。

### 11.2 写作作业：一份"社交压力风险清单"

**选题**：从你正在玩的任意一款手游里选一个社交系统（公会、军团、战队、师徒、结婚、跨服战都可以）。

**产出**：一份文档，写进 `notes/作业/11-社交压力清单-XX.md`，包含三部分：

**第一部分：风险清单表**（至少 6 条，用第 7.1 节的分类）

| 编号 | 压力来源分类 | 具体机制（这个游戏里的哪条规则） | 玩家会怎么表达这种不适（写一句玩家原话） | 严重度（高/中/低） | 影响的玩家群体 |
|---|---|---|---|---|---|

要求：
- 每一条必须指向**一条具体规则**，不能写"公会氛围不好"这种没有机制指向的东西。
- "玩家原话"这一列要写得像真的（去看游戏的应用商店差评和社区帖子找语料）。
- 至少有一条是**你自己感受到过**的压力，标出来。

**第二部分：两个缓释设计**（详细写，每个 400 字以上）

从清单里挑严重度最高的两条，各给一个缓释设计。每个设计必须包含：

1. **改动的规则**（原来是什么 → 改成什么，写成可实现的规则，不要写"优化一下体验"）
2. **它把压力从哪里转移到了哪里**（对照第 7.2 节的三条原则，说明你用的是哪一条）
3. **代价**：这个改动会削弱什么？（**必须写**。任何缓释都有代价，通常是削弱留存或降低组织活跃。写不出代价说明你没想清楚）
4. **怎么验证**：上线后看什么指标能知道它起作用了？（引用 [game-numeric 第 23 章](../game-numeric/23-metrics.md) 的指标框架，比如公会成员的次留、退会率、投诉量）

**第三部分：一个反对意见**

站在制作人的立场，写 200 字反对你自己的第一个缓释设计（比如"这会让公会活跃度下降 15%，而公会活跃度是我们这个版本的核心指标"）。然后写 100 字回应它。

**这一部分是本作业最重要的训练**：社交压力的设计永远是留存收益和玩家体验的权衡，**能同时说出两边的话，才算真的理解了这个系统**。

### 11.3 思考题

1. 第 2 节说"攀比系统能拉付费但几乎不产生留存粘性"。你同意吗？举一个反例（一个靠攀比留住人的系统），并说明它为什么是例外。
2. "把执法从人转移到规则"是本章推荐的原则，但它有一个明显的副作用：**规则是死的，人是活的**。系统自动清退不会考虑"这个人这周家里有事"。你怎么设计一个既减少人对人施压、又保留人情空间的清退机制？
3. 假设你要给一款**单人为主的放置类小游戏**加社交（这类游戏的玩家很多是明确不想社交的），你会加哪一层结构？为什么不加公会？（提示：想想第 6 节的异步社交和第 8.1 节矩阵里的 Express 格。）
4. 率土用"组织能力"对抗"付费能力"。请设想一款卡牌养成游戏，它的核心是个人养成，几乎没有强制协同的场景。在这种品类里，有没有可能设计出类似的"组织能力也是一种资源"的结构？如果没有，那卡牌游戏的社交应该做到哪一层就停？
