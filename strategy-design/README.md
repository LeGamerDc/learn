# 策略游戏设计：从"不会下"到能设计博弈的系统课程

> **面向对象**：在游戏公司写服务端的工程师，学过同仓库的 [game-design](../game-design/README.md)（策划通识）和 [game-numeric](../game-numeric/README.md)（数值设计）。**本人不擅长玩策略游戏，也很少亲自带入去想。**
> **终点定位**：**纯桌游 / 实体卡牌设计**。学完你应该能够：坐到任何一款策略桌游前，说清楚玩家在想什么、为什么这么想；用博弈论和"策略空间"的语言分析一个设计；从一个核心决策出发，打样、测试、迭代出一款 2~5 人的策略桌游或卡牌游戏，并写出别人照着就能玩的规则书。
> **案例范围**：经典抽象棋类与扑克 / 现代德式欧式桌游 / 牌组构筑与集换式卡牌 / 社交推理与谈判。数字游戏（炉石、自走棋）只作偶尔对照。
> **动手形式**：**纯推演与写作，不写代码。** 每章有分步揭示的思考路径、分级练习题（附参考答案）和动手作业。从第 15 章起，你会用**一副扑克牌 + 一把硬币**做自己的原型。

本课程编写于 **2026 年 10 月**。

---

## 0. 先说结论：这门课为什么和别的设计课不一样

大部分游戏设计教材默认读者"本来就会玩"：讲到"玩家会在这里权衡"，作者心里有一个活生生的权衡过程，读者也有，于是一句话就够了。**你的情况不一样**：你不常玩策略游戏，即使玩也很少真正带入去想，所以这句话在你那里是空的。你知道"玩家会权衡"，但不知道权衡的那几秒钟里，脑子里具体转过哪些念头。

这不是小问题。策略游戏设计师设计的不是规则，而是**规则在玩家脑子里引发的那串思考**。一条规则好不好，取决于它让玩家想了什么：是"这两个选项我都想要，只能选一个"的纠结，是"他是不是在骗我"的猜疑，还是"算了随便拿一个"的放弃。一个自己没有经历过这串思考的人，可以背下所有设计原则，但没法判断自己的原型到底在玩家脑子里制造了什么。

所以这门课的第一性原理是：

> **先学会像玩家一样想，再学会像设计师一样想。** 前者是后者的原材料。

整门课围绕三个能力递进：

```
 入门                         掌握                            进阶
 像策略玩家一样想              用工具分析博弈与策略空间          设计、测试、迭代
┌──────────────────┐        ┌───────────────────────┐       ┌───────────────────────┐
│ 四问扫描          │        │ 收益矩阵 / 纳什均衡     │       │ 八个机制族的深度拆解    │
│ 博弈树与倒推      │  ───▶  │ 混合策略 / 承诺 / 信息  │ ───▶  │ 纸面原型               │
│ 估值 / 行动经济   │        │ 多人政治 / 合作与谈判   │       │ 测试、平衡、规则书      │
│ 读对手 / 计划     │        │ 策略空间 / 深度 / 平衡  │       │ 端到端做出一款游戏      │
│ 复盘              │        │ 运气 / 互动 / 张力弧    │       │                       │
└──────────────────┘        └───────────────────────┘       └───────────────────────┘
   第 02~08 章                    第 09~20 章                      第 21~31 章
```

**几件你现在就该知道的事：**

**第一，策略思考是可以拆开学的技能，不是天赋。** 你觉得自己"不擅长策略游戏"，多半不是因为算力不够（你每天写的代码比任何桌游都复杂），而是因为没有人告诉过你**轮到你的时候按什么顺序看什么**。高手和新手的差距，很大一部分在"先看哪里"。第 02 章的"四问扫描"就是这个顺序，它会贯穿整门课的每一个思考路径。

**第二，博弈论是语言，不是答案。** 第 09~14 章会教收益矩阵、纳什均衡、混合策略、承诺、信息、联盟。这些工具让你能把"感觉这里不太对"说成"这里有一个占优策略，它让另外三个选项变成了死代码"。但均衡不等于好玩，也不等于不好玩：很多游戏理论上有解，桌上依然是活的，因为玩家找不到、执行不了，或者要随对手调整（第 15 章区分了"存在均衡"和"策略坍缩"）。真正要警惕的是一种**容易掌握的固定做法**取代了你想让玩家反复比较的决策。你学博弈论是为了看清结构，不是为了替玩家把游戏解掉。

**第三，策略游戏的设计对象是"策略空间"，不是"规则"。** 规则是你写的东西，策略空间是规则跑起来之后玩家实际能走的路线集合。你改一条规则，策略空间可能纹丝不动，也可能整片坍缩。第 15 章开始的阶段三全部围绕这个对象：怎么画它、怎么检测它坍缩、怎么让它保持开阔又可读。

**第四，你的工程背景是资产。** 博弈树就是递归搜索，估值函数就是启发式剪枝，纳什均衡就是"没有任何一方有动机单方面改配置的稳态"，规则书就是 API 文档，占优策略就是一个让其他分支全部变成死代码的 bug。课程里会适度用这些类比。但要警惕一件事：工程师容易把"算得清楚"当成"想得明白"。策略游戏里大部分决定是在算不清的情况下做的，那正是它好玩的地方。

## 3. 怎么学（请认真读）

**这门课的实验室是"你自己做的决定"。** 数值课靠跑模型建立数感，策划通识课靠拆解建立设计感，这门课靠反复经历"自己决定 → 看到后果 → 修正判断"来建立**策略感**：看到一个局面，能本能地问"我离赢多远、对手下一步想干什么、这两个选项各丢掉了什么"。这种本能读多少书都替代不了。

### 3.1 思考路径：本课的核心

每章至少有两个**思考路径**：一个具体的游戏局面，按"分步揭示"的方式展开：

1. 先给你**当时能看到的全部信息**（隐藏信息游戏里只给你能看到的部分）；
2. 要求你**在纸上写下三样东西**：你的选择、一句话理由、你预测对手怎么应对；
3. 然后才逐层揭示：提示 → 专家怎么扫描和列候选 → 专家怎么推演和决定 → 实际发生了什么；
4. 最后是**三层对照表**（初学者 / 熟练者 / 专家各会怎么做、各漏看了什么）和**设计师旁注**（是哪条规则制造了这个决策，改掉它会怎样）。

揭示部分在 Obsidian 里默认折叠。**请不要跳过"先写下来"这一步。** 先写下自己的决定再看答案，和直接看答案，学到的东西完全不同：前者让你发现"原来我漏看的是这一步"，后者只会让你觉得"嗯，有道理"。整门课最大的风险，就是你读完了所有思考路径，觉得都看懂了，但轮到自己坐在桌前还是不知道先看哪里。

> 关于真实性：思考路径里的"熟练者 / 专家的想法"是**作者按策略原理重建的思考过程**，不是真人口述。局面大多是为教学构造的，引用真实对局时会注明出处。

### 3.2 练习题：按产物分三级

| 级别 | 你要交出什么 | 例子 |
|---|---|---|
| **★ 看懂** | 补全信息、识别威胁和机会、指出某条规则制造了什么决策。答案唯一 | "这个局面里，对手下一步能做的威胁动作有哪几个？" |
| **★★ 会下** | 独立选招并写出预测；然后**改变一个条件**再做一次，说明决定为什么变或不变 | "如果对手多 2 枚硬币，你的选择会变吗？" |
| **★★★ 会设计** | 改一条规则，写出假设、一个可能推翻它的反例、一个测试方案 | "把平局改成先手胜，策略空间会怎样变？怎么测？" |

答案在每章末尾（默认折叠）。★★★ 没有唯一正解，答案给的是"一个合格答案的样子"和评判标准。

### 3.3 动手：真的去玩、真的去做

- **第 00~14 章**：去玩指定的游戏（大多能在 Board Game Arena 免费在线玩），挑 2~3 个关键回合填 [出声思考记录](./templates/think-aloud.md)。
- **第 15 章起**：在你自己的扑克牌原型上实践本章原理。**第 20 章交付一个能完整玩一局的原型 + 规则书 v0.1**，第 31 章交付规则书、盲测记录和修改依据。

### 3.4 建议节奏

按每天 1~1.5 小时估算，其中至少一半时间在玩和做练习：

| 阶段 | 章节 | 预计用时 | 阶段验收标准 |
|---|---|---|---|
| 零 | 00~01 | 2~3 天 | 在 Board Game Arena 上完成至少 3 局对局，填完一份出声思考记录 |
| 一 | 02~08 | 约 3 周 | 第 08 章验收：拿到一个**没见过的游戏**的局面，能独立走完四问、推演、估值、读人，并写出自己的决定和理由 |
| 二 | 09~14 | 约 2.5 周 | 能给一个桌游里的同时行动写出收益矩阵，找出均衡，并说出它对体验意味着什么 |
| 三 | 15~20 | 约 3 周 | 交付一个能完整玩一局的扑克牌原型 + 规则书 v0.1 + 一份策略地图 |
| 四 | 21~28 | 约 3 周 | 能给任意一款没玩过的策略桌游写出"策略游戏拆解"，并指出它属于哪几个机制族 |
| 五 | 29~31 | 约 2 周 | 交付规则书、至少一次盲测记录和每处修改的依据 |

### 3.5 哪些必须读，哪些按需

上表的用时是作者的估计，没有经过学习者验证。全书约 53 万字，**不需要从头读到尾**：

| 类别 | 内容 | 怎么用 |
|---|---|---|
| **核心路线** | 第 00~20 章、第 29~31 章 | 按顺序读，做每章的思考路径和 ★、★★ 练习 |
| **按目标选** | 第 21~28 章的八个机制族 | 先读和你想做的游戏最接近的 2~3 章（做卡牌游戏就先读 24、25、26；做推理游戏先读 27），其余等需要时再读。每章的"动手"只做选读的那几章 |
| **按需查用** | 附录 A、B、D、E，各章的 ★★★ 练习 | 碰到问题再查；★★★ 题在做原型阶段当热身 |
| **延迟练习** | 附录 C | 读完一章隔两三天再做；两组**综合验收**分别在第 14 章、第 20 章之后做 |
| **可选** | [evidence/](./evidence/README.md) | 只给想追查数字来源的人，课程本身不需要写代码 |

一周的时间大致这样分（以每周 7~10 小时计，同样是估计）：

- **阅读与思考路径**：约四成。思考路径一定要先写再看。
- **练习与复盘**：约三成。包括附录 C 的延迟练习。
- **对局**：约两成。阶段一、二主要在 Board Game Arena 上玩；阶段三起主要玩自己的原型。
- **找人测试**：阶段五才需要，但招募比想象的慢，**第 20 章交付原型时就开始约人**。

每个阶段结束时问自己的不是"读完了没有"，而是"这一阶段的验收我能不能不看书完成"。综合验收题不标章节，就是在测这一点：面对陌生问题，你能不能自己选对工具，并说清结论在什么条件下不成立。

### 3.6 几条学习原则

1. **先写下决定，再看答案。** 写下来的那一刻，模糊的直觉才变成可以被纠正的判断。这一条比其他所有原则加起来都重要。
2. **输了不要紧，说不清为什么这么下才要紧。** 第 08 章会教你区分"决策错了"和"运气不好"。初学阶段赢输几乎不说明任何问题。
3. **一次只练一件事。** 每局对局前想好"这局练第几章的什么"，只在那件事上刻意思考，其他凭感觉。
4. **找一个比你强一点的人一起玩。** 对局后请他讲一个你没想到的念头。高手最有价值的不是答案，是他"先看了哪里"。
5. **设计前先做玩家。** 阶段三开始做原型时，你会想跳过阶段一二。不要跳：你给自己的原型做出声思考的质量，取决于你给别人的游戏做过多少次。
6. **把你的工程直觉当工具，不当答案。** 能算的地方就算，但要知道玩家在桌上不会算，他们靠估值、靠读人、靠赌。设计要服务于在桌上的那个人。

## 5. 关于可靠性标注

策略游戏的知识来源混杂：有的是规则原文，有的是数学定理，有的是心理学实验，有的是竞技圈的共识，有的只是作者的分析。本课用五种标注把它们分开：

| 标注 | 含义 | 你该怎么对待它 |
|---|---|---|
| `【规则】` | 游戏规则原文可查 | 可以直接用；版本差异会单独说明 |
| `【数学】` | 可证明或可精确计算，编者已验算 | 在给定假设下成立；**注意假设** |
| `【实验】` | 有论文或公开数据支持 | 只在实验条件下成立，不要外推成口诀 |
| `【行业口径】` | 竞技圈或社区的共识与惯例 | 会随环境变化，自己验证 |
| `【推导】` | 对设计意图的推测、作者自己的分析 | 可能是错的；你可以不同意，并用测试反驳 |

有一条特别要注意：**算术验算只能证明数学结论，不能证明行为判断或设计效果。** "这条规则会让玩家更纠结"永远是【推导】，直到你拿到测试数据。

## 6. 资料地图

完整书单、文章和播客见 [附录 B](./B-glossary.md)。最重要的几本（按本课的依赖顺序）：

| 书 | 作者 | 讲什么 | 对应本课 |
|---|---|---|---|
| **Characteristics of Games** | Elias, Garfield, Gutschera | 从游戏的结构特征（人数、时长、运气、信息、技巧……）分析游戏，三位作者里有万智牌的设计者。**最贴近本课的一本** | 全程，尤其 13、15~20 |
| **Building Blocks of Tabletop Game Design** | Engelstein, Shalev | 桌游机制的百科全书，按机制族分类 | 21~28 |
| **Thinking Strategically** / **The Art of Strategy**（中译《策略思维》《妙趣横生博弈论》） | Dixit, Nalebuff | 不用数学讲博弈论，例子极多 | 09~14 |
| **The Strategy of Conflict** | Thomas Schelling | 承诺、焦点、威胁的可信性 | 11、14 |
| **The Evolution of Cooperation** | Robert Axelrod | 重复囚徒困境与以牙还牙 | 14 |
| **Playing to Win** | David Sirlin | 竞技玩家心态、"读对手"的层级 | 06、08 |
| **Rules of Play** | Salen, Zimmerman | 游戏的定义与"有意义的玩" | 01 |

> 资料的诚实说明：设计理论有共识，但**具体游戏的设计意图几乎都没有公开答案**。网上所有"某游戏为什么这么设计"都是推测，包括本课里的，所以一律标【推导】。本课只引用编者核实过存在的书、文章和演讲，不确定出处的观点不署名。
