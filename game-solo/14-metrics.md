# 14 - 指标、埋点与调优

> **本章目标**：知道该埋什么、上线后先看什么、以及**你的 DAU 撑得起什么样的 AB 实验**。
> **本章有模型**：`models/s14_metrics.py`
> **本章第 4 节会给出一个对小团队不友好、但必须面对的结论。**

## 1. 指标树：把收入公式拆到可埋点的字段

```
日收入 = DAU × IPU × eCPM ÷ 1000 × 分成
          │      │       │
┌─────────┘      │       └──── 平台侧，你只能通过"人群质量"间接影响
│                │
│         ┌──────┴──────────────────────────┐
│         │  IPU = 会话数/人 × 每会话广告次数  │
│         │           │              │       │
│         │    离线上限(第11章)  点位设计(第05章)│
│         └─────────────────────────────────┘
│
└── DAU = 新增 + 留存 × 昨日DAU
          │        │
      买量/自然量   ├── 次留 ← 前 3 分钟闭环（第 02 章）
                   ├── 7 留 ← 会话结构、元进程（第 11、12 章）
                   └── 30留 ← 内容寿命（第 03、12 章）
```

> **每一个叶子节点，都要对应至少一个埋点字段。**
> **如果某个叶子你埋不到，那条链路上的问题你永远看不见。**

### 1.1 七个必埋事件

| 埋点事件 | 能算出什么 | 对应哪一章的判据 |
|---|---|---|
| 会话开始/结束 | 会话数/人、单次会话时长 | [11](./11-offline-earnings.md)：离线上限调对了吗 |
| 单局开始/结束/结果 | 每会话局数、通关率、死亡房间 | [02](./02-session-pacing.md)、[06](./06-difficulty-as-lever.md) |
| 广告点位触发 | 各点位的触发次数 | [05](./05-ad-placement.md)：触达率 |
| 广告发起/完成 | 各点位的渗透率与完成率 | §2 的漏斗 |
| **三选一的选项与选择** | 道具选取率、构筑分布 | [07](./07-build-diversity.md)：dominant 判据 |
| 元进程等级变化 | 内容消耗速度 | [12](./12-meta-and-content.md)：产能倒推 |
| 离线收益领取 | 离线上限的实际吃满率 | [11](./11-offline-earnings.md) |

> ⚠️ **最容易漏的是"三选一的选项"。**
> 大多数人只埋"玩家选了什么"，不埋"当时给了他哪三个"。
> **没有分母，选取率就算不出来**——[第 07 章](./07-build-diversity.md)那套判据全部失效。

> **⇒ 凡是"率"，都要同时埋分子和分母。这是埋点设计的第一条铁律。**

## 2. 广告漏斗：每一步都会掉人

```bash
cd models && python s14_metrics.py
```

```
步骤            单步转化   累计    每 1000 次触发剩
------------------------------------------------
点位触发         100.0%  100.0%       1000
展示按钮          92.0%   92.0%        920   冷却/每日上限/平台间隔
玩家点击          48.0%   44.2%        442   ← 这一步才是"渗透率"
广告加载成功       94.0%   41.5%        415   无填充、网络差
完整看完          91.0%   37.8%        378   中途退出
奖励发放          99.5%   37.6%        376   发奖失败 = 投诉主来源
```

> **1000 次触发，最后只有 376 次真正产生了广告收入。**

**两条实践含义：**

**① 算 IPU 时不能用"触发次数"，要用"完成次数"。** 按触发次数算会**高估 2.7 倍**。

**② "广告加载成功率"和"完整看完率"是工程指标，但它们直接乘在收入上。**

加载成功率从 94% 掉到 85%，**收入直接掉 10%**——而这通常是 SDK 配置、预加载时机、网络重试的问题。

> ⚠️ **漏斗里唯一由数值设计决定的是"玩家点击"那一步。其余五步都是产品/工程问题。**
>
> 新手容易花大力气调奖励倍率去提渗透率，**却没发现真正的漏在加载失败上。**
> **先看漏斗，再调数值。**

## 3. AB 实验：你的 DAU 撑得起什么

假设 DAU 5,000、日新增 800（独立开发者的典型量级），α=0.05，功效 80%：

```
想检测的效应      类型   每组需要样本   入组天数  +观察期   总天数
------------------------------------------------------------------
IPU +5%          连续       2,788      1.1      0      1.1
IPU +10%         连续         697      0.3      0      0.3
次留 +5pp        二元       1,505      3.8      1      4.8
次留 +2pp        二元       9,408     23.5      1     24.5   ⚠️ 偏长
7留 +1.5pp       二元       8,885     22.2      7     29.2   ⚠️ 偏长
30留 +1pp        二元       8,844     22.1     30     52.1   ❌ 做不了
LTV(30) +5%      连续      14,332     35.8     30     65.8   ❌ 做不了
```

**样本量公式**（连续/二元）：

```
n = 2(z_{α/2} + z_β)² · σ² / Δ²          连续
n = 2(z_{α/2} + z_β)² · p(1−p) / Δ²      二元
```

### 3.1 留存类实验难一到两个数量级

**三条原因，而且是叠加的：**

| | |
|---|---|
| **二元指标方差大** | 次留是 0/1，没有中间值 |
| **只能用新增用户** | 老用户的留存已被历史影响。**分母从 DAU 掉到日新增，本例少了 6.3 倍** |
| **还要等观察期** | 测 7 留多等 7 天，测 30 留多等 30 天 |

### 3.2 本章最该记住的一句

[第 04 章](./04-ad-revenue-math.md)证明过：**留存是超线性杠杆，IPU 是线性杠杆。**

> **⇒ 你最想优化的那个东西，恰恰是最难用 AB 验证的。**
>
> **这不是你的产品的问题，是统计学的性质。**

## 4. 三条应对（按优先级）

### ① 能用大效应就别测小效应

```
次留 +2pp  →  24.5 天
次留 +5pp  →   4.8 天      ← 差 5 倍
```

> **与其做十个 +1% 的微调，不如做一个 +5% 的大改。**
> **小团队的 AB 只适合验证"方向对不对"，不适合"抠效率"。**

### ② 小效应用模型和判断，不用 AB

[第 06 章](./06-difficulty-as-lever.md)那个 LTV 曲面就是为此存在的。

> **模型不需要样本量。**
> 它的代价是假设可能错，**但"假设可能错"总好过"根本测不出来"。**

**这也是这门课每一章都配模型的最终理由**——不是因为模型比数据准，是因为**在你的量级上，很多东西根本拿不到数据。**

### ③ 用代理指标缩短周期

测"次留"要等 1 天，但这两个**当天就能看到**，且和次留高度相关：

- **首次会话时长**
- **首次会话内是否完成一局**（[第 02 章](./02-session-pacing.md)的"3 分钟闭环"）

> **⇒ 先用代理指标快速筛掉明显更差的版本，再用真指标验证少数几个。**

### 4.1 一个必须避开的坑

> ⚠️ **别做多个并行 AB 然后挑最好看的那个。**
>
> 跑 10 个实验，即使全是无效改动，也有 **40%** 的概率至少有一个"显著"（α=0.05）。
> **这就是 p-hacking，在小样本下尤其致命。**

**要么预先声明主指标，要么做多重比较校正。**

## 5. 上线后按什么顺序调

**顺序由"改动成本"和"确定性"共同决定：**

| 步骤 | 查什么 | 改动成本 | 确定性 |
|---|---|---|---|
| **1** | **漏斗的工程步骤**（加载成功率、完成率） | 几乎为零 | **极高**——这是 bug，不是权衡 |
| **2** | 前 3 分钟的闭环完成率（[02](./02-session-pacing.md)） | 低 | 高——次留是超线性杠杆 |
| **3** | 通关率分布是否在健康带内（[06](./06-difficulty-as-lever.md)、[07](./07-build-diversity.md)） | 低 | 中——看你的钟形曲线假设准不准 |
| **4** | 内容消耗速度 vs 产能（[12](./12-meta-and-content.md)） | **高** | 高——这是算术 |
| **5** | **广告倍率和点位**（[05](./05-ad-placement.md)、[06](./06-difficulty-as-lever.md)） | 低，但**能加不能减** | 中 |

> ⚠️ **第 5 步排在最后是有意的。**
>
> 它见效最快，所以最诱人——**但它也是最难回退的一步**：广告奖励调低会被骂惨
> （[第 01 章](./01-iaa-model.md)：投放能加不能减，在 IAA 里同样成立）。
>
> **先把前四步的免费收益吃干净，再动变现旋钮。**
