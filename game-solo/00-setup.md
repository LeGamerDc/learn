## 2. 第一个模型：一局 roguelike

场景是所有 roguelike 的骨架：

> 玩家连续闯 50 个房间。敌人强度随深度指数增长；玩家打赢会掉血，但也会拿到战利品变强。血量归零，这局结束。

```bash
cd models && python s00_first_run.py
```

模型本体在 `run_model.py`（第 00、02、06、13 章共用），`s00_first_run.py` 只负责跑实验和出图。

### 2.1 关键参数

```python
power_gain    = 1.020    # 普通房间的强度提升
elite_every   = 5        # 每 5 个房间一个精英房/宝箱
elite_bonus   = 0.15     # 精英房的大件战利品 +15%
enemy_growth  = 1.0495   # 敌人强度每房间 ×1.0495
luck_sigma    = 0.35     # 战利品**幅度**的随机性
base_dmg      = 3.9      # 强度比 = 1 时每房间受到的伤害
dmg_exp       = 2.0      # 伤害对强度比的敏感度
```

### 2.2 两个值得单独说的设计

**① 随机性作用在增益的幅度上，不作用在方向上**

```python
power *= 1 + (power_gain - 1) * rng.lognormal(0, luck_sigma)
```

战利品永远是正的——**玩家不会因为运气差而变弱，只会变强得慢**。第 09 章会讲为什么"可能变弱"几乎总是糟糕的随机设计。

**② 伤害对强度比高度敏感**

```python
伤害 = base_dmg × (敌人强度 / 玩家强度) ^ dmg_exp
```

`dmg_exp` 这个参数决定了整个游戏的手感，值得停下来想清楚：

| `dmg_exp` | 死因 | 手感 |
|---|---|---|
| **1.0** | 血线慢性流失 | 强度比几乎不起作用，玩家感觉"怎么都是慢慢磨死"，**构筑没有意义** |
| **2.0** | 跟不上就被撕碎 | 强度比是生死线，构筑质量直接决定成败——**这才是 roguelike 的手感** |
| 3.0+ | 悬崖 | 差一点点就秒死，容错极低，接近硬核 |

> **这是本课第一个"参数决定品类"的例子。** 同一套模型，只改这一个指数，做出来是完全不同的两款游戏。

## 3. 三个发现

### 发现一：单局的全部张力，是两条指数曲线在赛跑

看 `figures/s00_first_run.png` 的第 ② 张图：玩家强度和敌人强度都是指数增长，画在对数轴上是两条直线。

玩家的等效每房增长率：

```
玩家：1.020 × 1.15^(1/5) = 1.020 × 1.0283 = 1.0489
敌人：                                      1.0495
```

**敌人快 0.06%。整局游戏的胜负，就取决于这个 0.06% 能不能被运气抹平。**

第 ③ 张图画的是"强度比"——它才是玩家真正感受到的难度。这条线跌破 1.0 就开始被撕碎。

**一个残酷的数字**：

```
通关局的最低强度比（中位）  0.94
失败局的最低强度比（中位）  0.89
```

**赢家和输家都跌破了 1.0，差别只有 5 个百分点。** 指数赛跑就是这样——过程中的差距小到肉眼难辨，结果却是二元的。

> **这就是 [game-numeric 第 04 章](../game-numeric/04-growth-curves.md) 的成长曲线，被压缩到 30 分钟的尺度上。**
> 那门课里成本增速和产能增速的赛跑，在这里变成了敌人强度和玩家强度的赛跑。同一套数学。

### 发现二：指数赛跑对增长率极度敏感

这是本章最该记住的一条。模型第 ④ 段自动跑了这个扫描：

| 普通房增益 | 精英加成 | 等效每房增长 | 通关率 |
|---|---|---|---|
| 1.016 | 0.15 | 1.0448 | **6.0%** |
| 1.018 | 0.15 | 1.0469 | **15.5%** |
| 1.020 | 0.15 | 1.0489 | **33.5%** |
| 1.022 | 0.15 | 1.0510 | **54.8%** |
| 1.020 | 0.19 | 1.0561 | **88.5%** |

（对照：敌人每房增长 1.0495）

> **等效增长率从 1.0448 变到 1.0561——差 1.1%——通关率从 6% 跳到 88.5%。**

**实践含义**：单机的战斗数值**不能靠手调**。你以为"把精英奖励从 +10% 提到 +15% 影响不大"，实际上它能把你的游戏从"几乎不可能通关"变成"随便玩玩就过"。

**必须跑仿真。** 这也是这门课每一章都配模型的原因。

### 发现三：胜负早就定了，但玩家很晚才知道

模型最后一段算了"某个房间的强度比"和"最终胜负"的相关性：

```
    房间     强度比与最终胜负的相关性
     5              0.438   ← 开始显现
    10              0.591
    20              0.716   ← 结局已大半可预测

死亡房间中位数：第 36 房（进度 72%）
```

**玩家在进度 40% 时结局就大半注定了，却要玩到 72% 才揭晓。**

这是纯指数赛跑的固有特征，也是 roguelike 最经典的设计问题之一：

> **"我早就输了，却又白玩了 20 分钟。"**

三种处理办法（第 02 章展开）：

| 办法 | 说明 | 例子 |
|---|---|---|
| **给早期信号** | 让玩家能自己判断"这局有没有戏" | 显示推荐战力、精英怪的压力测试 |
| **留翻盘手段** | 让后期还有大幅改变强度比的机会 | 高风险高回报的事件、boss 掉落 |
| **缩短单局** | 从根上减少浪费的时间 | 一局 15 分钟而不是 40 分钟 |

**"缩短单局"往往是小团队最优的选择**——它同时降低了开发成本和玩家的沉没成本。

## 4. 读懂另外两张图

`figures/s00_death_dist.png`：

**④ 死亡房间分布**：中位数第 36 房，P10/P90 = 29/47，**前 10 房几乎没人死**。这是好事还是坏事？

- 好：**新手不会开局就死**，挫败感低，符合"前 3 分钟必须闭环"的要求（第 01 章）；
- 坏：**死亡集中在后半程**，意味着玩家每局都要投入大半的时间才知道结果。

**⑤ 生存曲线**：走到第 N 房的玩家比例。它的形状告诉你"内容的实际触达率"——如果你在第 45 房放了精心设计的 boss，只有约三分之一的玩家会见到它。

> **这条曲线是单局版的"留存曲线"。** 它决定了你的内容投入该往哪儿放。

**做 IAA 的话，这条曲线还有第二个用途**：它同时是**广告点位的触达率曲线**。
放在第 40 房的那个"看广告拿宝箱"，只有 40% 的局会走到——**你算 IPU 的时候必须乘上这条曲线，
而不是假设每个点位都被看到**。第 05 章会用它。

## 5. 动手：三个实验

### 实验 A：改 `dmg_exp`，做出另一款游戏

把 `run_model.py` 里的 `dmg_exp` 改成 1.0 和 3.0，各跑一次 `s00_first_run.py`。

观察三件事：
- 通关率和死亡分布怎么变？
- "通关局 vs 失败局的最低强度比"这两个数拉开了还是靠拢了？
- 第 ⑤ 段的相关性表变了吗？

**目标**：理解 `dmg_exp` 是怎么把"构筑质量"从无关变成决定性的。

> `dmg_exp = 1.0` 时你会发现两组的最低强度比几乎没差别——**这说明构筑好坏对结果不重要**，
> 玩家会感觉"打不打得过全看运气/血量"。这就是很多平庸 roguelike 的手感来源。

### 实验 B：让死亡分布更分散

现在死亡集中在 P10=39 / P90=48，区间很窄。试着让它更分散（比如 P10=15 / P90=48）。

提示：调 `LUCK_SIGMA`。跑完之后问自己——**分散是好事吗？**

<details>
<summary>参考思路</summary>

分散意味着"运气对结局的影响变大"。

- **好处**：每局的体验差异更大，重复可玩性更强；偶尔的神运气会带来爆发式的爽感；
- **坏处**：玩家会觉得"结果不取决于我的操作"，技巧的价值被稀释。

**这是随机性设计的核心权衡**，第 09 章整章讲它。没有标准答案，但有一条经验：**随机应该决定"你这局玩什么"，而不是"你这局能不能赢"。**
</details>

### 实验 C：加入"技巧"这一维

给 `one_run` 加一个 `skill` 参数（0~1），让它影响：受到的伤害（技巧高则少挨打）和战利品的选择质量（技巧高则更会挑）。

跑三档技巧（新手 0.3 / 普通 0.6 / 高手 0.9），看通关率分别是多少。

**目标**：理解"通关率"这个数字必须绑定玩家水平才有意义。第 06 章讲"难度即变现旋钮"时会大量用到这个模型。

## 7. 常见坑

| 现象 | 原因 | 解决 |
|---|---|---|
| `ModuleNotFoundError: numpy` | 忘了激活环境 | `source ../game-numeric/.venv/bin/activate` |
| 图里中文是方框 | 字体没设置 | 确认脚本开头有 `use_cjk_font()` |
| 通关率是 0% 或 100% | 指数赛跑失衡 | 这不是 bug，是发现二。回去调增长率 |
| `RuntimeWarning: Mean of empty slice` | 通关率 100% 导致死亡列表为空 | 模型里已加保护；如果你自己改代码要注意 |
| 改了一个"小参数"结果天翻地覆 | 指数的正常行为 | 永远跑仿真，不要手估 |
