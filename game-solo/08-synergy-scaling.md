# 08 - 协同与爆发的控制

> **本章目标**：搞清楚"数值膨胀的爽感"是怎么来的，以及怎么在不失控的前提下把它做出来。
> **本章有模型**：`models/s08_synergy.py`
> **本章有一个推翻直觉的发现**（§3），是我在跑模型时被纠正的——原来的框架整个是错的。

---

## 1. 维度间相乘：+50% 怎么变成 ×5

割草类的 DPS 通常是几个维度**相乘**：

```
DPS = 攻击力 × 攻速 × 暴击期望 × 弹幕数量
```

```bash
cd models && python s08_synergy.py
```

```
每维提升   加法直觉(1+4x)   实际((1+x)^4)   差距
------------------------------------------------
  10%          1.40           1.46        1.05×
  25%          2.00           2.44        1.22×
  50%          3.00           5.06        1.69×
  75%          4.00           9.38        2.34×
 100%          5.00          16.00        3.20×
```

> **这就是"数值膨胀爽感"的全部数学。**

**一正一反两条推论：**

| | |
|---|---|
| ✅ **正面** | 这是割草类"屏幕炸开"的爽感来源。玩家感觉到的不是"我强了 3 倍"，是"我强了 5 倍"，**而且每加一件都在加速**。在 IAA 里这尤其值钱——**爆发是分享的触发点，而分享是最便宜的量**（[第 04 章](./04-ad-revenue-math.md) §4.1） |
| ⚠️ **反面** | **跨维度的参数不能分开调。** 你在一个维度上试"+25% 不多"，四个维度一起动就是 2.44 倍 |

> **维度之间的相乘你改不掉**——DPS 的物理含义就是几个量的乘积。
> **所以你唯一的抓手是：管住同一个维度内部的叠加方式。**

## 2. 五种同维叠加规则

| 规则 | 公式（k 件堆在同一维度） |
|---|---|
| **同维乘法** | `(1+s)^k` |
| **同维加法** | `1 + s·k` |
| **递减收益** | `1 + s·Σ 0.7^i`（第 n 件只有 0.7^(n-1) 的效果） |
| **硬上限** | `1 + s·min(k, 3)` |
| **软上限** | `1 + M·k/(k+K)`（[game-numeric 第 04 章](../game-numeric/04-growth-curves.md)的饱和公式） |

## 3. 本章最重要的发现：纯乘法会消灭构筑决策

模型引入一个指标：

```
决策价值 = 最优分配的总倍数 ÷ 最差分配的总倍数
```

它回答："玩家把道具分配对了，能强多少？"**如果是 1.0×，那分配根本不重要。**

```
规则        均分总倍数   全堆一维   决策价值   随机分配中位   判断
--------------------------------------------------------------------
同维乘法        5.96      5.96     1.00×       5.96    ★ 决策完全失效
同维加法        5.06      3.00     1.69×       4.69    决策有一点分量
递减收益        4.12      1.79     2.31×       3.64    ← 决策很有分量
硬上限          5.06      1.75     2.89×       4.59    ← 决策很有分量
软上限          6.55      2.09     3.13×       5.62    ← 决策很有分量
```

> **⚠️ 同维乘法的决策价值恰好是 1.00×——不是接近 1，是精确等于 1。**

**这不是巧合，是恒等式：**

```
∏_d (1+s)^(k_d) = (1+s)^(Σ k_d) = (1+s)^N
```

**总倍数只取决于你拿了几件，和怎么分配完全无关。**

> **⇒ 纯乘法叠加会彻底消灭构筑决策。**
> 玩家的"三选一"变成了"随便点，反正一样"。

**这是[第 07 章](./07-build-diversity.md)说的"构筑系统是装饰品"的另一种死法，而且更隐蔽**——因为**数值看起来一直在涨，很爽，只是选择没有意义了。**

### 3.1 规律：凹性越强，决策越值钱

```
乘法（在对数尺度上是线性的）→ 凹性为零 → 决策价值 1.00
加法                        → 弱凹   → 1.69
递减 / 硬上限 / 软上限        → 强凹   → 2.31 / 2.89 / 3.13
```

**加法为什么会让均分最优？** 是 **AM-GM 不等式**：在 `Σk_d` 固定时，`∏(1+s·k_d)` 在均分时取最大。

> **⇒ 软上限不只是个刹车，它还是个引导。**
> **它让"雨露均沾"自动成为最优解，你不需要写任何规则去强制玩家均衡发展。**

## 4. 那爆发感从哪来？

模型加入两个真实来源：**道具数量的运气方差**（泊松分布）和 **13% 概率的稀有协同 ×1.6**（承[第 07 章](./07-build-diversity.md)）：

```
规则        中位倍数   P99 倍数   P99/中位   爆发感
------------------------------------------------
同维乘法      5.96      35.53      5.96    ★ 有巅峰体验
同维加法      4.79      15.75      3.29    ★ 有巅峰体验
递减收益      3.64       8.37      2.30    ★ 有巅峰体验
硬上限        4.38      11.03      2.52    ★ 有巅峰体验
软上限        5.62      13.72      2.44    ★ 有巅峰体验
```

**对比 §3 的表：加进"运气 + 协同"之后，爆发感才出现了。**

> **⇒ 爆发感的来源不是叠加规则，是随机性。**
> **叠加规则决定的是另一件事：分配决策值不值钱。**

**这两件事要分开设计，也要分开体检：**

| 你想要什么 | 拧哪个旋钮 |
|---|---|
| 更多巅峰局 | **随机性**（第 09 章）和**协同门槛**（第 07 章） |
| 构筑决策更有分量 | **同维叠加的凹性**（§3） |

> **新手最常犯的错是拿错旋钮**：觉得"不够爽"就去改叠加公式，改成乘法之后确实数字更大了，
> **但同时把构筑决策删掉了**——玩家会说"越来越无脑"。

### 4.1 一个陷阱：P99/中位 最高的恰恰是最差的规则

**同维乘法的爆发感指标是全场最高的（5.96）。看指标它是"最好"的规则！**

但那个方差是从哪来的？**从道具数量的运气来的。** 乘法把件数的随机波动指数放大了——多拿 3 件就是 ×1.95。

> **⇒ 乘法用"玩家控制不了的东西"（运气），换掉了"玩家能控制的东西"（分配）。**
> **爆发感的数字很好看，玩家的感受却是"全看脸"。**

**⇒ 爆发感不能只看一个 P99/中位。要同时问：这个方差是谁贡献的？**

**运气贡献的方差和决策贡献的方差，在玩家那里是完全不同的两种体验**——第 09 章整章讲这个区别。

## 5. 接回变现

把总倍数换算成通关率（以"同维加法"的中位局标定在[第 06 章](./06-difficulty-as-lever.md)平顶中央）：

```
规则        中位通关率   P99通关率   落在健康带   太易(>45%)
--------------------------------------------------------
同维乘法       44.3%      99.3%       40%        45%
同维加法       32.7%      86.5%       40%        30%
递减收益       21.3%      60.5%       50%         5%
硬上限         28.8%      73.2%       45%        20%
软上限         40.2%      81.2%       45%        40%
```

> **你要的形状是：中位留在健康带内，P99 冲出去。**
> 这正是[第 07 章](./07-build-diversity.md) B 方案"稀有协同超模"的形状——**主体不动，右尾长出去。**

### 5.1 最终建议

> **同一个维度内部用软上限，维度之间保持相乘。**

这样你同时得到三样东西：

1. **维度间相乘** → "每加一件都在加速"的爽感（§1）
2. **维度内饱和** → 分配决策最值钱（§3），且**自动引导均衡发展**
3. **随机性 + 协同** → 巅峰局（§4），而主体分布不动

**三者是三个独立的旋钮，别混着调。**

## 6. 三条工程侧的提醒

**割草类的数值膨胀会直接撞上性能墙**，这不是数值问题但由数值引起：

| 现象 | 原因 | 数值侧能做什么 |
|---|---|---|
| **弹幕数量维度** | 它同时是数值和实体数。×10 倍数 = ×10 个对象 | 用**软上限**卡住这一维，或改成"单发伤害提升"而非"数量提升" |
| **敌人数量 × 弹幕数量** | 碰撞检测是 O(n×m)，**平方级爆炸** | 同上；或做**范围伤害**替代多弹幕 |
| **数字显示溢出** | 后期伤害数字长到看不清 | 早点定好数量级压缩（K/M/B）和位数上限 |

> **微信小游戏的性能预算比你想的紧。** 低端安卓机上，屏幕里几百个实体就会掉帧，
> 而**掉帧直接伤留存**——[第 04 章](./04-ad-revenue-math.md)证明了留存是超线性杠杆。
>
> **⇒ "弹幕数量"这一维度应该是你最先加软上限的地方，理由既是数值也是工程。**

<details>
<summary>参考思路</summary>
