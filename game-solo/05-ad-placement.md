# 05 - 广告点位设计

> **本章目标**：把[第 03 章](./03-three-economies.md)那句"广告 = 资源龙头"落到具体点位上——**每个点位给多少、放在哪、铺几个**。
> **本章有模型**：`models/s05_ad_placement.py`
> **本章故意留一个开口**：广告倍率这个旋钮，在本章的框架内**定不下来**。为什么定不下来，正是第 06 章的入口。

---

## 1. 先分清两种广告

**【实证】微信小游戏可用的广告组件**（[官方文档](https://developers.weixin.qq.com/minigame/introduction/commercialization/)）：激励视频、插屏、Banner、原生模板、格子广告。

它们分成性质完全不同的两类：

| | **激励广告**（激励视频） | **强制广告**（插屏 / Banner / 格子） |
|---|---|---|
| 玩家要同意吗 | **要**，主动触发 | 不用 |
| eCPM | **高**（本课假设 60 元【行业口径】） | 低得多 |
| 受"玩家意愿"约束 | **是**，本章模型的全部内容 | 否 |
| 对留存的伤害 | 小（他自己选的） | **大**（打断心流） |
| 数值设计要参与吗 | **是，深度参与** | 基本不用，是 UI 决策 |

> **本章只讲激励广告。** 它是 IAA 收入的主体，也是唯一需要数值设计的那类。

**【实证】一条平台约束**：一个激励视频与一个插屏广告之间会有系统动态调整的间隔。**所以你不能靠"堆频次"来提 IPU**——这条从平台侧就被堵死了。

> **对强制广告的一条建议**：它是纯粹的"拿留存换钱"，而[第 04 章](./04-ad-revenue-math.md)已经证明留存是超线性杠杆。
> **小团队的默认选择应该是不用或极少用插屏**，把精力全放在激励视频上。

---

## 2. 七类激励点位

按[第 03 章 §5](./03-three-economies.md) 的分层，先把点位排开：

| 点位 | 玩家买到什么 | 层 | 触发时机 | 吃内容寿命 |
|---|---|---|---|---|
| **复活** | **容错**——这局不用重来 | 局内 | 死亡 | 几乎不 |
| **重抽三选一** | 构筑质量 | 局内 | 每次选择 | 不 |
| **局内翻倍拾取** | 局内购买力 | 局内 | 拾取/宝箱 | 不 |
| **临时增益** | 局内强度 | 局内 | 战斗前/休息点 | 不 |
| **结算翻倍** | 元货币 ×2 | 局外 | 每局结束 | **吃** |
| **离线翻倍** | **时间**——跳过等待 | 局外 | 会话开头 | **吃，大头** |
| **每日免费领** | 元货币 | 局外 | 每日 | **吃** |

**两个品类的重心不同**（[第 03 章 §6](./03-three-economies.md)）：

> **割草 / Roguelike 卖的是「容错」**——定价看"玩家有多不想重开这一局"。
> **放置 / 经营卖的是「时间」**——定价看"他还要等多久"。

这决定了同一个点位在两类游戏里的价值不同：**复活在割草里是最强点位，在放置里基本不存在；离线翻倍在放置里是命脉，在割草里可有可无。**

## 3. 广告倍率：一个本章解不了的旋钮

```bash
cd models && python s05_ad_placement.py
```

**玩家意愿模型**：玩家愿意花 30 秒看广告，当且仅当收益抵得上若干分钟的正常游戏产出。

```
p = logistic(K × (收益折算分钟数 − 2.0))
每看一次，后续所有点位的意愿 × 0.40（疲劳）
```

> **疲劳系数 0.40 是标定出来的**：调到让基准（7 个点位、倍率 2.5×）的**每会话广告次数 ≈ 3.3**。
>
> ⚠️ **注意单位，这是最容易搞错的地方：**
> **本模型算的是"一个会话"，而[第 04 章](./04-ad-revenue-math.md)的 IPU 是"一天"。**
>
> ```
> 日 IPU = 每会话广告次数 × 每天会话数（第 11 章）
> 割草类约 1.8 次会话/天 → 3.3 × 1.8 ≈ 6，与第 04 章的基准对上
> ```
>
> **这两个量差一个会话数，混用会让回本模型错 2 倍以上。**
> （写这一章时我就混用过一次，直到第 15 章把它们接起来才发现——见[第 15 章](./15-end-to-end-lab.md) §5。）

扫描广告倍率：

```
广告倍率   每会话广告   增幅    局外注入   注入增幅   每点注入换广告
--------------------------------------------------------------
  1.5×      2.08      —        1.5       —         1.428
  2.0×      2.71    30.5%      3.4    131.9%       0.804
  2.5×      3.07    13.3%      5.2     53.2%       0.594
  3.0×      3.27     6.5%      6.7     29.9%       0.487
  3.5×      3.39     3.5%      8.0     19.5%       0.422
  4.0×      3.45     1.9%      9.3     16.1%       0.370
  5.0×      3.51     1.7%     12.0     28.9%       0.292
  6.0×      3.53     0.5%     14.9     23.6%       0.238
```

（局外注入只算广告**额外**给出去的部分——基础奖励本来就要给）

### 3.1 形状：这是本章最该记住的东西

```
每会话广告   1.5× → 6.0×：2.08 → 3.53   （1.7 倍）  ← 饱和
局外注入     同一区间：    1.5  → 14.9   （10 倍）   ← 停不下来
```

> **你多付出 10 倍的内容代价，只换到 1.7 倍的广告展示。**

| 区段 | 判断 |
|---|---|
| **1.5× → 2.5×** | IPU 涨得快。这段是"**给得太少没人看**"，加倍率很划算 |
| **2.5× → 3.5×** | 边际递减开始 |
| **3.5× 以上** | **IPU 基本不动，注入还在涨。这段是纯亏** |

### 3.2 为什么本章定不下来

看"每点注入换 IPU"那一列：**它单调递减。**

意味着按这个效率指标选，答案永远是"倍率越低越好"——**而那显然不对**，倍率 1.0× 等于没有广告，IPU 直接归零。

> **⇒ 这个旋钮在本章的框架内是定不下来的。**
>
> 你必须把"内容寿命"换算成留存、再换算成 LTV，
> 才能在**多赚的广告钱**和**少赚的留存钱**之间比大小。

**这正是第 06 章要做的事。** 本章交付给你的是形状：

> **IPU 会饱和，内容消耗不会。**

**一条可以先用的经验**：在第 06 章的完整模型跑出来之前，**默认从 2.0×~2.5× 起步**——那是边际收益还没塌下去的区间。

## 4. 点位互相蚕食

模型逐个加点位，看 IPU 怎么涨：

```
点位数   新增的点位     每会话广告   边际增量   该点位自身次数
--------------------------------------------------------
  1      复活            1.57      1.57        1.57
  2      重抽三选一       2.15      0.58        1.03
  3      局内翻倍拾取     2.32      0.16        0.37
  4      临时增益        2.54      0.22        0.51
  5      结算翻倍        2.89      0.35        0.86
  6      离线翻倍        2.95      0.07        0.20
  7      每日免费领       3.07      0.12        0.33

单独测每个点位再相加：8.59
七个点位一起跑：      3.07        ⇒ 蚕食掉了 64%
```

> **点位不是加法关系。你加的第 7 个点位，抢的是前 6 个点位的观看次数。**

**注意最后一列**：越晚加进来的点位，自己拿到的展示越少——**不是因为它设计得差，是因为轮到它时玩家已经看过好几个了。**

### 4.1 两条实践含义

**① 点位的价值排序要按"单点位效率"，不是按"能不能加"。**

**加满七个不如做好三个。** 模型里前两个点位（复活 + 重抽）就贡献了 2.15 次，占最终 3.07 的 **70%**；后面五个加起来只贡献 30%。

**② 点位之间要错开时机。**

如果所有点位都堆在会话前段，疲劳会把后面的全废掉。这就是为什么行业默认布局长这样：

```
会话开头 ──── 每局中 ──── 每局末 ──── 会话末
   │            │           │           │
 离线翻倍     复活/重抽    结算翻倍     每日领
（意愿最高）  （分散触发）  （节奏点）  （补一次）
```

> **"离线翻倍"放在会话最开头**，是因为那时玩家的意愿预算是满的，
> 而它恰好是价值最高的点位（等价的产出时长最长）。**这不是巧合，是算出来的。**

## 5. 触达率：点位放在哪

局内点位受[第 00 章](./00-setup.md)那条生存曲线约束——放在第 40 房的点位，只有 45% 的局能走到。

```
放在第几房   触达率   该点位实际展示   相对第 5 房
------------------------------------------------
     5       100%        0.125          100%
    10       100%        0.125          100%
    20        95%        0.120           96%
    30        82%        0.102           82%
    40        45%        0.056           45%
    48        35%        0.044           35%
```

> **同一个点位，放在第 40 房只能拿到放在第 5 房的四成展示。**

**这不是设计问题，是生存曲线的算术后果。** 三条推论：

| 推论 | 说明 |
|---|---|
| **重要点位放前段** | 后段点位在服务"少数走得远的玩家"，展示量天然就少 |
| **后段点位要用更高价值补偿** | 否则它在你的数据表里会显得莫名其妙地差，**你会误判成"这个点位设计得不好"** |
| **想做分层就故意放后段** | 高倍率的挑战奖励放在后段，**自动完成了核心玩家筛选** |

> **中间那条最容易踩。** 上线后看数据，你会发现后段点位的展示数很难看——
> **先除以触达率再比较**，否则你会砍掉一个其实很好的点位。

## 6. 混合变现：去广告礼包的悖论

大多数 IAA 小游戏会加一点 IAP，最常见的就是"去广告礼包"（一次性 6~30 元，之后不再有强制广告，或激励广告改为免费领取）。

**它看起来是白赚的钱，实际上不是：**

```
净收益 = 付费率 × (售价 × IAP分成 − 该用户剩余生命周期的广告 LTV)
```

> **关键在"该用户"三个字。**
> **买去广告礼包的，恰恰是玩得最久、看广告最多的那批人。**
> 他们的广告 LTV 远高于平均值——**你卖掉的是最值钱那批人的广告收入。**

**怎么办：**

| 做法 | 说明 |
|---|---|
| **只去掉强制广告，保留激励广告** | 行业主流。玩家买的是"不被打断"，不是"不用看" |
| **定价按重度玩家的 LTV 算，不按平均 LTV** | 平均 LTV 1.43 元，但会买礼包的那批人可能是 8 元 |
| **把礼包做成"永久激励广告免费领"** | 玩家得到便利，你保留了他的日活；**收入从广告变成一次性，但 DAU 没丢** |

**第 15 章的端到端方案会把这笔账完整算一遍。**

## 7. 点位设计检查表

设计每一个点位时，逐条过：

- [ ] **它卖的是「容错」还是「时间」？**（决定定价逻辑）
- [ ] **注入哪一层？** 局外的话，[第 03 章](./03-three-economies.md)那条"计入内容预算"要执行
- [ ] **收益折算成多少分钟正常产出？** 低于 2 分钟基本没人看
- [ ] **触发时机在会话的哪一段？** 和其他点位错开了吗
- [ ] **触达率是多少？** 局内点位记得乘生存曲线
- [ ] **倍率定在 2.0×~2.5× 起步了吗？**（第 06 章会给最终答案）
- [ ] **玩家不看广告，游戏还完整吗？** ⭐

**最后一条是红线，值得单独说：**

> **不看广告必须能正常通关，只是慢一些。**
>
> 一旦玩家形成"不看广告就打不过"的认知，他不会更愿意看广告——**他会直接卸载。**
> 广告应该是"加速"和"容错"，永远不能是"门票"。

<details>
<summary>参考思路</summary>

疲劳系数高 = 玩家更耐受广告。经验上和三件事相关：
**① 广告本身的时长和可跳过性；② 奖励是否即时可见；③ 玩家对游戏的投入度**。
