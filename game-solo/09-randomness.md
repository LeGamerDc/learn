# 09 - 随机性与保底

> **本章目标**：回答[第 08 章](./08-synergy-scaling.md)留下的那个问题——**"这个方差是谁贡献的？"**——并把保底和重抽广告接上去。
> **本章有模型**：`models/s09_randomness.py`
> **本章会给出一条被很多人当成 UI 惯例、实际上是数值决策的结论**（§2.1）。

---

## 1. 随机性的三个层次

不是所有随机都一样。**先按"玩家能不能应对"分层：**

| 层次 | 例子 | 玩家的反应 | 好不好 |
|---|---|---|---|
| **① 决定"这局玩什么"** | 三选一给了哪三件、地图布局 | "这把牌不好，我换个思路" | ✅ **最好的一种，这是深度** |
| **② 决定"这次点击的结果"** | 暴击、闪避 | 察觉不到单次，只感受总体 | ✅ 可以，前提是**频繁到能被平均掉** |
| **③ 决定"这局能不能赢"** | 这局掉了几件道具、开局属性 | "这局怎么这么穷" | ⚠️ **危险，这是纯运气** |

> **一条贯穿本章的原则：**
> **随机应该决定"你这局玩什么"，而不是"你这局能不能赢"。**

## 2. 方差归因：逐个冻结随机源

```bash
cd models && python s09_randomness.py
```

模型逐个冻结随机源，看构筑分的方差降多少：

```
配置                    构筑分方差   占基线   协同触发率
--------------------------------------------------
全随机（基线）             11.551     100%      59%
冻结'拿到几件'              0.587       5%      70%
冻结'每次给哪三件'          11.217      97%      59%
两个都冻结                  0.448       4%      73%
```

> **冻结"拿到几件"，方差掉到 5%；冻结"每次给哪三件"，方差几乎没动。**

**这两件事在玩家那里的感受完全不同：**

| 随机源 | 玩家看得见吗 | 他会说什么 |
|---|---|---|
| **每次给哪三件** | **看得见，也能应对** | "这把牌不好，我换个思路"——**这是决策的一部分** |
| **这局拿到几件** | **看不见，也应对不了** | "这局怎么这么穷"——**这是纯粹的运气** |

> **⇒ 设计原则：把方差尽量放在玩家看得见的那一侧。**
> **同样的总方差，摆在"选什么"上是深度，摆在"给多少"上是挫败。**

### 2.1 先别抄那个 95%——拆开看更有用

**这个结果有一半是模型的性质。** 模型里道具价值只在 0.85~1.15 之间波动，**彼此差别很小**，于是构筑分 ≈ 件数 × 平均价值——**件数当然主导一切。**

**但这本身就是一条设计结论，而且比那个百分比重要：**

> **如果你的道具彼此差异不大，"拿到几件"就会淹没"选了哪件"，
> 玩家的选择再怎么设计都没有影响力。**

**两条出路，通常要一起用：**

1. **把件数的随机性压掉**——固定每局的选择次数
2. **拉大道具之间的差异**——[第 07 章](./07-build-diversity.md)的"通用模块 + 传说件"结构

> **⇒ "每层必给一次三选一"不是 UI 惯例，是一条数值决策。**
> **它把方差从看不见的一侧，搬到了看得见的一侧。**

这也解释了为什么几乎所有成功的 roguelike 都这么做——**它们不是抄的界面，是抄的这个数学性质。**

## 3. 保底：改的是尾巴，不是均值

场景：玩家想凑齐 5 件同标签触发协同。单次 offer 里出现目标标签的概率是 59.7%。

```
机制             期望次数   中位   P90   P99   标准差   8次内凑齐
--------------------------------------------------------------
无保底             8.39     8     12    16    2.37      59%
硬保底             7.82     8     10    12    1.69      67%
递增概率(PRD)      7.50     7     10    11    1.51      76%
```

> **三种机制的期望值差不多（8.4 / 7.8 / 7.5），但尾巴完全不同。**
> **保底改的是尾巴，不是均值。**

**无保底的 P99 要等 16 次，而一局只有 8 次抽取**——这意味着**有一批玩家永远凑不齐**，而他们并不知道自己只是运气差。

### 3.1 保底在单人游戏里的目的和 F2P 不同

| | 保底的目的 |
|---|---|
| **F2P（抽卡）** | 控制**最坏付费**——不让玩家花到破产 |
| **买断单机** | 保证**这局不会开局就废** |
| **IAA 小游戏** | 上面第二条，**再加一条**：控制看广告的边际收益（§4） |

### 3.2 硬保底 vs PRD，选哪个

| | 优点 | 代价 |
|---|---|---|
| **硬保底**（连续 N 次不出则必出） | 好实现、好解释 | **玩家会学会数数**："我已经两次没出了，下次稳了" |
| **PRD**（每次不出则概率递增） | 手感更自然，没有硬规律 | **玩家说不清为什么**，也就没法用它做决策 |

> **给小游戏的建议：用硬保底。**
>
> **可预测性在单局尺度上是优点**——它让玩家能规划"我还差 2 件，还有 3 次机会，来得及"。
> **而这正是[第 02 章](./02-session-pacing.md)说的"早期信号"**：让玩家自己判断这局有没有戏。

（在 F2P 抽卡里结论相反，因为那里"玩家算得清"意味着他能算出最省钱的抽法。）

## 4. 重抽广告：一个点位干三件事

玩家在 offer 里没有想要的时，可以看广告重抽。

```
每局可重抽次数   协同触发率   实际观看次数   每次广告换来的触发率
------------------------------------------------------------
       0          52.0%        0.00              —
       1          62.5%        0.96           11.3%
       2          70.9%        1.85           10.4%
       3          78.2%        2.64           10.1%
       5          85.3%        3.83            8.8%
       8          89.2%        4.82            7.8%
```

**这是 IAA 里性价比最高的点位之一，因为它同时干三件事：**

| 作用 | 说明 |
|---|---|
| **① 保底** | 削掉"开局就废"的尾巴，和 §3 的硬保底同一个作用——**但成本由玩家自己决定要不要付** |
| **② 变现** | 天然发生在玩家最想要的时刻（"这三个都不想要"），渗透率高（[第 05 章](./05-ad-placement.md)） |
| **③ 方差控制** | 愿意投入的玩家方差更小、不愿意的照旧——**相当于一个玩家自选的难度档** |

### 4.1 要限次，但理由不是"边际递减"

**看最后一列**：每次广告换来的触发率从 11.3% 降到 7.8%——**递减是有，但很温和**。光看这一列，你会得出"多给几次也无所谓"的结论。

**真正的理由在第二列**：重抽 8 次时，协同触发率从 52% 涨到 **89%**。

而[第 07 章](./07-build-diversity.md)证明过：**触发率接近 100% 的超模不是惊喜，是新的基线。**

**无限重抽会让你的道具池退化成"想拿什么拿什么"，然后三件事一起崩：**

- 第 07 章的**构筑决策**消失（反正能抽到想要的）
- 本章的**随机性**消失（方差被玩家用广告买掉了）
- 第 08 章的**巅峰体验**也消失（人人都有 = 不叫巅峰）

> **⇒ 设计建议：每局限 2~3 次重抽。**
> **这个上限不是为了"逼玩家看更多广告"，恰恰相反——是为了保住随机性本身。**

### 4.2 又一个指标失灵

**"边际收益递减"这个指标在这里给出了错误的建议。**

限次的真正理由不在效率列，在**它对其他系统的破坏**上。

> **⇒ 调参时永远要看这个改动溢出到了哪些别的系统。**

（这和[第 07 章 §4.1](./07-build-diversity.md) 的"指标本身也需要测试"是同一类教训。本课到这里已经出现三次了——**这不是巧合，是数值工作的常态。**）

## 5. "运气不好"和"设计不公"的区别

这是玩家投诉里最常见、也最容易被误读的一类。**两者的客观数值可能完全一样，感受却天差地别。**

| 玩家的判断 | 触发条件 |
|---|---|
| **"运气不好"**（可接受） | 他**看得见**随机在哪里发生、**知道**自己本来有机会 |
| **"设计不公"**（会流失） | 随机**发生在看不见的地方**，或**结果与他的操作无关** |

**四条具体做法：**

| 做法 | 为什么 |
|---|---|
| **让随机可见** | 展示"这次三选一给了什么"，而不是暗中调整掉落 |
| **让随机可应对** | 给重抽、给保底、给"跳过这层"的选项 |
| **不要暗改概率** | 动态难度（偷偷降低掉落）一旦被玩家发现，信任就没了（第 12 章） |
| **失败要可归因** | [第 02 章](./02-session-pacing.md)：归因不了的失败在 IAA 里会被读成"游戏想坑我看广告" |

> ⚠️ **在 IAA 里这条尤其致命。** 买断制玩家觉得"这游戏不公平"会给差评；
> **IAA 玩家会直接把"不公平"和"想让我看广告"连起来**——
> 然后他不但流失，还会拒绝所有广告点位。**你损失的是 DAU 和 IPU 两头。**

## 6. 动手

### 6.1 改模型

**任务 A：验证 §2.1 的两条出路。** 把 `VAL` 的分布从 `uniform(0.85, 1.15)` 改成 `uniform(0.6, 1.8)`（拉大差异），同时固定件数。**现在"每次给哪三件"贡献多少方差了？**

**任务 B：调保底强度。** 硬保底的触发条件从"连续 2 次"改成 1 次和 4 次；PRD 的递增步长从 0.18 改成 0.08 和 0.35。**画出 P99 和标准差的权衡曲线。**

**任务 C：重抽的上限扫描。** 把重抽次数和[第 05 章](./05-ad-placement.md)的意愿模型接起来——**玩家不是每次都会用掉重抽机会**。加一个 `p_use` 参数，重跑 §4 的表。**真实的触发率涨幅比现在小多少？**

**任务 D：种子与每日挑战。** 让所有玩家用同一个种子跑一局，看构筑分分布。**方差还剩多少？** 想一想：每日挑战为什么是个好设计（提示：它把随机变成了公共知识，玩家可以互相比较**技巧**）。

**任务 E：造一个"不公平"的版本。** 让掉落数量随玩家当前强度**反向**调整（强了就少给）。跑出来的通关率分布会更集中——**从数据上看是"更平衡"了。** 想清楚为什么这仍然是个坏设计。
