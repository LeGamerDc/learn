# 15 - 端到端实战

> **本章目标**：把前面 15 章接成一条流水线——**输入 6 个制作人决策，输出一份可以开工的数值方案，并自动检查它是否自洽**。
> **本章有模型**：`models/s15_full_spec.py`
> **本章会展示一个"每句话都合理、合起来不自洽"的方案**（§4），那是全课存在的理由。

---

## 1. 输入不是参数，是决策

```python
spec(genre,              # 品类：割草 / 放置
     run_sec,            # 单局时长（秒）
     r1,                 # 目标次留
     content_per_month,  # 内容产能：一个月能做多少"级"
     growth,             # 增长方式：买量 / 自然量
     difficulty,         # 难度取向：偏易 / 标准 / 偏难
     prestige)           # 有没有 prestige 层
```

**这七项都是产品判断，不是数值参数。** 数值参数是它们的**推论**。

```bash
cd models && python s15_full_spec.py
```

## 2. 方案 A：割草肉鸽 · 标准难度 · 自然量

```
【单局与会话】
  单局时长        150 秒                    第 02 章
  每会话局数      5.8 局                    第 02 章（需 ≥3）  ✅
  每天会话数      1.8 次                    第 11 章

【难度】
  目标通关率      31%                       第 06 章（带 20%~45%）  ✅
  每会话死亡      4.0 次                    第 02 章 = 复活广告机会

【广告点位】（倍率 2.5×）
  点位            层     每会话触发   价值(分钟)   实际观看
  复活            局内       4.0        3.0       0.65
  重抽三选一       局内       8.0        1.2       0.55
  局内翻倍拾取     局内       5.0        1.0       0.26
  结算翻倍        局外       5.8        2.0       1.42
  每日免费领       局外       2.0        2.5       0.17
  每会话广告次数   3.04                       第 05 章意愿模型
  IPU            5.47                       第 04 章（目标 4~9）  ✅

【经济与内容】
  局外注入倍数    0.20×                      第 03 章
  内容寿命        244 天                     第 03 章（需 ≥35）  ✅
  prestige       有（等效内容 ×2.5）          第 11 章
  需要月产能      31 级/月                   第 12 章  ✅

【收入与回本】
  次留            40%
  90 天活跃天数   7.9 天
  到手 ARPDAU     0.164 元
  LTV(30) 现金    0.79 元
  LTV(90) 现金    1.30 元
  广告金          0.63 元
  买量线          1.42 元
  增长方式        自然量 / 社交裂变

  自洽性检查：✅ 全部通过
```

> **注意"实际观看"那一列**：复活触发 4.0 次却只看了 0.65 次，重抽触发 8 次只看 0.55 次——
> **这就是[第 05 章](./05-ad-placement.md)的意愿模型和疲劳在起作用。**
> **触发机会 ≠ 观看次数**，这条在方案里必须体现，否则收入会高估几倍。

## 3. 方案 B：放置经营 · 偏易 · 买量

关键差异：

| | 方案 A（割草） | 方案 B（放置） |
|---|---|---|
| 每天会话数 | 1.8 | **2.6**（离线上限拉回访，[第 11 章](./11-offline-earnings.md)） |
| 每会话广告次数 | 3.04 | 2.59 |
| **IPU** | 5.47 | **6.73** |
| 内容寿命 | 244 天 | 204 天 |
| 增长方式 | 自然量 | **买量** |

> **放置类的 IPU 天然更高**，原因在[第 10 章](./10-idle-production.md)：它的加速点位价值都远超意愿阈值，
> 而且会话数更高（离线上限拉回访）。**所以它才撑得起买量。**

> **⇒ 这不是巧合：微信小游戏的买量大盘以放置/经营类为主，就是这个原因。**

## 4. 方案 C：一个会失败的方案

**这一套是故意做坏的，但它的每个决策单独看都不离谱：**

> **"我想做个有深度的硬核肉鸽，一局 5 分钟，一个人慢慢做内容，靠买量起量。"**

```
决策：割草 / 单局 300 秒 / 次留 30% / 月产能 15 级 / 买量 / 偏难 / 无 prestige

  每会话局数      2.9 局      ❌  第 02 章：需 ≥3
  目标通关率      22%         ✅  勉强在健康带下沿
  IPU            4.89        ✅
  内容寿命        71 天       ✅
  需要月产能      42 级/月     ❌  你只有 15 级/月

  自洽性检查：❌ 会话装得下 3 局、产能够用
```

**三条约束互相加剧：**

```
单局 300 秒 → 一次会话装不下 3 局 → 玩家走不到"第 3 局"那个留存建立的时刻
                                    ↓
                          次留上不去，而你又要买量
                                    ↓
偏难 + 无 prestige → 内容消耗快 → 月产能 42 级，你只有 15 级
```

> **⇒ 每句话都合理，合起来不自洽。**
>
> **这就是本课全部 15 章的意义：让"合起来不自洽"在开工前就被发现，
> 而不是上线三个月后。**

## 5. 一个真实的踩坑记录：单位不一致

**写这门课时我犯过一个错，直到本章把所有模型接起来才暴露出来，值得完整记下来。**

[第 05 章](./05-ad-placement.md)的意愿模型算的是**一个会话**的广告次数；
[第 04 章](./04-ad-revenue-math.md)的 IPU 是**一天**的次数。

```
日 IPU = 每会话广告次数 × 每天会话数
```

**我把两者当成同一个量用了。** 单独看每一章都自洽，接起来才发现 IPU 差了 1.8 倍。

**同时暴露的还有第二个错误**：[第 05 章](./05-ad-placement.md)的模型把触发次数 ×10 来降低离散误差，**但疲劳指数 `FATIGUE^k` 里的 `k` 也跟着涨了 10 倍**——疲劳被多算了一个数量级。两个错误一个高估、一个低估，**在单章内部互相掩盖了。**

### 5.1 三条教训

| 教训 | |
|---|---|
| **每个量都要标单位** | "IPU"这个词本身不带单位。**"每会话"还是"每天"，必须写出来** |
| **端到端串联是最强的检查** | 单章自洽 ≠ 全局自洽。**只有把所有模型接到同一个目标函数上，单位错误才会暴露** |
| **两个错误可能互相掩盖** | 这是最阴险的。**修一个的时候，结果反而变得更离谱**（我修完第一个后 IPU 从 6 跳到 23） |

> **⇒ 这也是本章存在的理由之一：它不只是"生成方案"，它是全课的集成测试。**

**修正的连锁反应**：这个修复让[第 06 章](./06-difficulty-as-lever.md)的一个结论不再成立
（"留存越好，最优倍率越低"）。**我把它改写成了"一个我预期错了、被模型纠正的发现"，并保留了推理过程**——
因为**发现自己错了的过程，比一个正确的结论更有教学价值。**

## 6. 用法

### 6.1 四步

```
1. 把你自己的 6 个决策填进 spec()，跑一遍，看自洽性检查
2. 不通过的话，改决策，不要改常量
3. 通过之后，把输出的参数表当成开工文档
4. 做出原型 → 跑第 13 章的体检套件 → 上线 → 按第 14 章的顺序调
```

> **第 2 步是关键：常量（eCPM、分成、健康带、意愿阈值）是外部约束，不归你调。**
>
> 改常量让方案"通过"是自欺——**你只是改了记分牌，没改比赛。**

### 6.2 输出里的每个数字都有出处

| 输出 | 来自 |
|---|---|
| 每会话局数、每会话死亡 | [02](./02-session-pacing.md) |
| 局外注入、内容寿命 | [03](./03-three-economies.md) |
| ARPDAU、LTV、广告金、CPA 上限 | [04](./04-ad-revenue-math.md) |
| 点位表、实际观看次数 | [05](./05-ad-placement.md) |
| 目标通关率、广告倍率 | [06](./06-difficulty-as-lever.md) |
| 池子结构、协同门槛 | [07](./07-build-diversity.md) |
| 同维叠加规则 | [08](./08-synergy-scaling.md)、[10](./10-idle-production.md) |
| 保底、重抽上限 | [09](./09-randomness.md) |
| 离线上限、每天会话数、prestige | [11](./11-offline-earnings.md) |
| 元进程结构、产能校验 | [12](./12-meta-and-content.md) |

**没有一个是拍脑袋的。** 这也是为什么这一章能放在最后。

## 7. 最后一句

> ⚠️ **这份方案会错。**
>
> [第 06 章](./06-difficulty-as-lever.md)那条钟形曲线是推导的，
> [第 05 章](./05-ad-placement.md)的意愿模型是标定的，
> eCPM 明天就可能变。
>
> **方案的价值不在于"算得准"，在于它让每个假设都变成了显式的、可以被数据推翻的东西。**

**对比一下没有这套东西的做法**：凭手感定参数，上线后发现不对，但**你不知道该改哪个**——因为所有参数都纠缠在一起，而你没有一条能把它们连起来的链子。

**这条链子就是这门课交付的东西。**

## 8. 动手

### 8.1 改模型

**任务 A：跑你自己的方案。** 填进你的 6 个决策。**自洽性检查过了吗？没过的话，改哪个决策最省力？**

**任务 B：找出你的约束边界。** 固定其他决策，扫描单局时长（30~400 秒），找出**同时满足所有检查项的区间**。这个区间可能很窄——**那就是你真正的设计空间。**

**任务 C：加一个决策维度。** 现在 `sessions_per_day` 是按品类写死的。把它改成由离线上限决定（用[第 11 章](./11-offline-earnings.md)的模型）。**离线上限成了一个可调的决策。**

**任务 D：接上第 13 章。** 让 `spec()` 的输出直接喂给 `s13_auto_playtest.py` 的 `TARGET`。**这样"方案"和"体检"就闭环了。**

**任务 E：做敏感度分析。** 对每个决策扰动 ±20%，看哪个对最终 LTV 影响最大。**那就是你该最先想清楚的那个决策。**

### 8.2 完成你的方案文档

**这是全课最后一次作业。** 把 `notes/concept.md` 里累积的 78 个回答，整理成一份完整方案：

```
一、产品定位
    品类、一句话描述、参考作品、差异化（第 01 章 Q1-3, 10）

二、规模与约束
    人力、工期、内容产能、包体（Q4-6）

三、核心循环
    单局、会话、天 三层节奏（Q7-10, 13-15）
    核心决策是什么（Q8）

四、玩法数值
    池子结构、协同门槛、同维叠加、保底、随机源分层（Q39-52）
    产出链比率 / 离线参数（Q53-63）

五、变现
    点位表、倍率、渗透率预估、IPU、ARPDAU（Q11-12, 24-33）
    难度与健康带（Q34-38）

六、长线
    元进程结构、内容消耗速度 vs 产能、prestige（Q64-69）

七、验证
    体检套件的 TARGET、埋点清单、AB 可行域（Q70-78）

八、自洽性检查结果
    s15_full_spec.py 的输出
```
