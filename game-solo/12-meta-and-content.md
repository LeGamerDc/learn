# 12 - 元进程与内容消耗速度

> **本章目标**：设计元进程（跨局的永久成长），并算清你的内容能撑多久、你需要多大的产能。
> **本章有模型**：`models/s12_meta_content.py`
> **本章会给出小团队最该先算的一张表**（§4）。

---

## 1. 元进程要同时干三件互相冲突的事

| | 目标 | 冲突 |
|---|---|---|
| **①** | 把落后的玩家推回健康带（[第 07 章](./07-build-diversity.md)） | 和 ② 冲突 |
| **②** | 别把领先的玩家推出健康带（推过头 = 无聊流失） | 和 ① 冲突 |
| **③** | 元进程本身就是内容（[第 03 章](./03-three-economies.md)：局外经济的 sink 几乎都是内容） | **给得越快，内容耗尽得越早** |

**①② 的冲突有一个漂亮的解法，③ 没有——③ 只能靠算。**

## 2. 两种元进程结构

```bash
cd models && python s12_meta_content.py
```

| | 机制 | 对分布的影响 |
|---|---|---|
| **均匀型** | 人人有份，上限相同 | **整条分布一起往右移** |
| **地板型** | 只把玩家"补到"一条基线，超过基线的人拿不到 | **左尾折叠到基线上，右尾原封不动** |

> ⚠️ **一个我踩过的坑，它本身就是本章的一半内容：**
> 第一版模型把"追赶型"实现成了"落后的人涨得**快**、但**上限相同**"，
> 结果两种结构在 90 天后完全收敛——**都顶到同一个上限了。**
>
> **真正的追赶必须让上限也不同。** 只改速度不改上限，等于只改了过渡期。

3000 名玩家，技巧服从正态分布（±2σ 相当于 `power_gain ±0.0044`），健康带取通关率 20%~45%：

```
元进程上限   占技巧跨度   均匀型 90天均值  均匀型 终局太易   地板型 90天均值  地板型 终局太易
------------------------------------------------------------------------------------
  0.0004        5%          42%           32%           72%           26%
  0.0007        8%          41%           37%           72%           26%
  0.0010       11%          40%           42%           72%           26%
  0.0013       15%          38%           47%           72%           26%
  0.0016       18%          35%           54%           12%          100%   ← 悬崖
  0.0020       23%          33%           61%           12%          100%
  0.0026       30%          28%           71%           12%          100%
  0.0035       40%          24%           83%           12%          100%
  0.0050       57%          20%           94%           12%          100%
```

### 2.1 均匀型的问题：左右手互搏

**落后的还没进带，领先的已经被推出"太易"了。** 上限 0.0050 时有 **94%** 的玩家最终变成"太简单"。

**好处是退化平缓**——调错了只是效果差一点。

### 2.2 地板型：覆盖率接近两倍，但有一个悬崖

**最优覆盖率 72%，接近均匀型的两倍**——因为它不动右尾，所以能把左尾整个折上来而不伤到强玩家。

**但看那个悬崖：**

```
地板 0.0013 → 覆盖率 72%，太易 26%
地板 0.0016 → 覆盖率 12%，太易 100%
```

**原因很直白：地板本身如果落在健康带上方，那所有人都会被顶到带外。**

> **地板型是把整个左尾"钉"在地板上的——钉错位置，就是全体一起错。**

> **⭐ 地板型元进程的唯一硬约束：
> 地板对应的通关率必须落在健康带内，而且要靠近下沿**（给玩家留出靠技巧继续上升的空间）。

### 2.3 怎么选

| | 均匀型 | 地板型 |
|---|---|---|
| 最优覆盖率 | 低（40%） | **高（72%）** |
| 参数敏感度 | **平缓** | **悬崖式** |
| 适合 | 你还不知道玩家技巧分布 | 你已经有真实数据 |

> **⇒ 上线前用均匀型，拿到真实技巧分布后换地板型。**
>
> 这不是妥协，是"先求稳、再求优"的正确顺序——
> **地板型的收益依赖于你知道健康带在哪，而那要等第 14 章的埋点数据。**

### 2.4 一个天花板

**两种结构都没能把覆盖率做到 80% 以上。**

> **元进程救不了所有人。** 技巧分布本身太宽的时候，
> 你需要的是**难度选项**（让玩家自己选档），而不是更强的元进程。

**难度选项的三条实践要点：**

| | |
|---|---|
| **默认档要偏易** | 开发者是自己游戏最熟练的玩家，**默认档几乎总是定得太难** |
| **可以随时切换** | 卡住时能降档，比"重开一个存档"友好得多 |
| **别用动态难度偷偷调** | 玩家一旦发现，就会把它和"想让我看广告"连起来（[第 09 章 §5](./09-randomness.md)） |

## 3. 内容消耗速度 vs 你的产能

元进程共 100 级（= 你做出来的全部内容）：

```
元进程增速倍数   一半玩家顶满   90天顶满比例   需要的月产能
--------------------------------------------------------
    0.50×        >90 天          48%           —
    0.75×         63 天         100%      48 级/月
    1.00×         47 天         100%      64 级/月
    1.50×         32 天         100%      94 级/月
    2.00×         24 天         100%     125 级/月
    3.00×         16 天         100%     188 级/月
```

> **最后一列把"内容消耗速度"翻译成了你必须持续交付的产能。**

### 3.1 三条结论

**① 元进程增速是你的产能约束的镜像。**

你一个人一个月能做出多少新内容？**先诚实回答，再反推增速。**

> **绝大多数独立开发者的错误是按"手感"定增速，然后被更新压垮。**

**② 广告注入会成倍放大这个压力**（[第 03 章](./03-three-economies.md)）。

离线翻倍 + 结算翻倍能让日产出接近 2 倍，**等于把你的产能要求也乘了 2**。

**③ Prestige 是唯一能打破这个循环的东西**（[第 11 章](./11-offline-earnings.md)）。

它用同一批内容造出新的进度曲线，**产能要求几乎为零**。

## 4. 小团队最该先算的一张表

把上面的东西合起来，就是一张排序表：

| 优先级 | 手段 | 产能要求 | 说明 |
|---|---|---|---|
| **1** | **Prestige / 重置层** | **几乎为零** | 同一批内容，新的进度曲线 |
| **2** | **程序生成的组合** | **一次性** | 见 §5 |
| **3** | 难度档位 / Ascension 阶梯 | 很低 | 同一批内容，更高的挑战 |
| **4** | 元进程等级扩容 | 中 | 加数值容易，但玩家很快会腻 |
| **5** | 手作新内容 | **线性，不可持续** | 最后才做 |

> **这个顺序对一个人开发的项目几乎是强制的。**
> 反过来做（先手作内容，撑不住了再想办法）是独立小游戏最常见的死法。

## 5. 程序生成的性价比

```
方案                  制作成本(人日)   产出的不同体验数   每份体验的成本
------------------------------------------------------------------
手作 10 个关卡              30              10          3.00
手作 40 个关卡             120              40          3.00
手作 80 个关卡             240              80          3.00
程序生成（8 个零件）          37              20          1.87
程序生成（12 个零件）         43              77          0.56
程序生成（16 个零件）         49             196          0.25
程序生成（20 个零件）         55             399          0.14
```

（假设：写生成器 25 人日、每个零件 1.5 人日、每个手作关卡 3 人日，
**组合里只有 35% 是"真的有差别"的**）

**性价比来自组合数的立方级增长，但有两个前提：**

| 前提 | 说明 |
|---|---|
| **一次性成本很高** | 写生成器 + 调参。**零件少于 10 个时，手作更划算** |
| **组合的"有效率"是关键参数** | 如果零件之间没有真正的交互，100 种组合玩起来是同一种 |

> **第二条正是[第 07](./07-build-diversity.md)、[08 章](./08-synergy-scaling.md)讲的：
> 协同和凹性决定了组合有没有意义。**
>
> **⇒ 没有足够多的、互相有交互的零件，程序生成只会产出
> "看起来不同、玩起来一样"的东西。**
> **第 07 章那个"通用模块 + 传说件"的池子结构，是本节的前置条件。**

## 6. 分享与自然量：内容之外的第二条留存线

[第 04 章](./04-ad-revenue-math.md) §4.1 说过，IAA 小游戏活下来的第一条路是**自然量/社交裂变**（CPA 趋近 0）。而分享动机来自哪里，前面几章其实已经答完了：

| 分享触发点 | 来自哪一章 |
|---|---|
| **"这局我摸到神了"** | [第 07 章](./07-build-diversity.md)的稀有协同（触发率 5~15%） |
| **数值爆炸的截图** | [第 08 章](./08-synergy-scaling.md)的维度间相乘 |
| **"我通了第 N 层"** | 本章的难度阶梯 |
| **每日挑战的排名** | [第 09 章](./09-randomness.md)任务 D：固定种子把随机变成公共知识 |

> **⇒ 分享动机不是一个单独要做的系统，它是巅峰体验的副产品。**
> **如果你的游戏没人分享，多半不是缺分享按钮，是缺巅峰体验。**

## 7. 动手

### 7.1 改模型

**任务 A：找你的地板位置。** 把 `BAND` 改成你自己的健康带，扫描地板位置，**找出悬崖在哪**。留出多少安全边际你才敢上线？

**任务 B：混合结构。** 做一个"地板 + 少量均匀"的元进程（保证落后玩家被补到基线，同时所有人有一点点成长感）。**覆盖率能超过 72% 吗？悬崖还在吗？**

**任务 C：技巧分布变宽。** 把 `skill` 的标准差从 1 改成 1.6，重跑。**覆盖率掉多少？** 这就是"用户越泛，越需要难度选项"的量化版本。

**任务 D：接上 LTV。** 把覆盖率换算成留存、再换算成 LTV（用[第 06 章](./06-difficulty-as-lever.md)的框架）。**均匀型和地板型的 LTV 差多少钱？**

**任务 E：产能倒推。** 假设你一个月能做 20 级新内容。**元进程增速最多能定到多少？** 再叠加广告注入 1.5× 之后呢？

### 7.2 更新你的概念文档

64. 你的元进程是均匀型还是地板型？**如果是地板型，地板对应的通关率是多少？**
65. 元进程总共多少级？**按你定的增速，一半玩家几天顶满？**
66. **你一个月能做多少新内容？** 和上一题的消耗速度对得上吗？
67. 按 §4 的优先级表，你接下来三个月做哪几项？
68. 你有多少个"零件"？它们之间有真正的交互吗？
69. **你的游戏里，玩家会在什么时刻想截图分享？**
