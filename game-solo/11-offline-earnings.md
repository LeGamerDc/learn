# 11 - 离线收益与放置数学

> **本章目标**：把放置类最强的那个钩子——离线收益——算清楚，并搞懂 prestige 为什么是小团队最划算的长线手段。
> **本章有模型**：`models/s11_offline.py`
> **本章有一个被两个约束"夹"出来的漂亮结论**（§2.2）。

---

## 1. 离线收益只有三个参数

| 参数 | 作用 |
|---|---|
| **离线效率** | 离线时拿到在线的百分之几（常见 30%~60%） |
| **离线上限** | 最多累积几小时 |
| **翻倍广告** | 看广告把这一次的离线收益 ×2 |

**看起来是三个"福利"旋钮。实际上第二个是 DAU 旋钮，第三个是 IPU 旋钮。**

---

## 2. 离线上限决定玩家一天上线几次

```bash
cd models && python s11_offline.py
```

假设离线效率 50%、睡眠 8 小时：

```
离线上限   上线2次  上线3次  上线4次  上线6次  上线8次  2→3次增益  睡眠捕获率   判断
--------------------------------------------------------------------------------
   1h        100     150     200     300     400      50%       12%    睡眠被浪费
   2h        200     300     400     600     800      50%       25%    睡眠被浪费
   4h        400     600     800    1000    1000      50%       50%    睡眠被浪费
   8h        800    1200    1200    1200    1200      50%      100%   ← 两者兼得
  12h       1000    1200    1200    1200    1200      20%      100%   ← 两者兼得
  24h       1200    1200    1200    1200    1200       0%      100%   没有回访动机
```

### 2.1 两个要同时满足的条件

**① 回访动机** = "一天上线 2 次改成 3 次能多拿多少"

当上限**小于所有间隔**时，收益严格正比于上线次数——增益恒为 50%，**动机最强**。上限一旦超过睡眠时长，睡眠那一段就吃不满了，增益开始掉：12h 时降到 20%，**24h 时归零**（玩家一天来一次就够了）。

**② 睡眠捕获率** = 睡醒那次拿到了睡眠时长的百分之几

上限低于 8h 时，**玩家睡一觉在亏钱**——早上打开会很失望，而"早上打开"恰恰是一天里最重要的那次回访。

### 2.2 两条曲线的交点就是答案

> **离线上限 ≈ 睡眠时长（6~10 小时）。**
>
> - **低于它** → 睡眠被浪费，最重要的那次回访体验很差
> - **高于它** → 回访动机开始下降，玩家一天只来一次

**这不是经验值，是这两个约束夹出来的。** 也解释了为什么市面上放置类的离线上限几乎都落在 8~12 小时。

### 2.3 为什么这件事对 IAA 至关重要

**会话数直接乘在 IPU 上，而且不是线性关系。**

[第 05 章](./05-ad-placement.md)的意愿模型是**按会话**建的：一个会话有一份意愿预算，**疲劳在会话内累积，跨会话会重置**。

> **⇒ 玩家一天来 3 次 vs 1 次，广告观看次数差的不是 3 倍，
> 而是"3 份会话预算"和"1 份会话预算"的差别——前者远大于后者的 3 倍。**

**⇒ 拆分会话是提高 IPU 最"干净"的手段：**

| | 代价 |
|---|---|
| 提高广告倍率 | 吃内容寿命（[第 03 章](./03-three-economies.md)） |
| 增加点位 | 互相蚕食（[第 05 章](./05-ad-placement.md)） |
| **拆分会话** | **几乎没有代价**——只是把同样的注意力分成几次用 |

> **这是本课发现的少数"免费午餐"之一。** 但它有上限：
> **上线太频繁玩家会烦**，而"烦"会直接反映在留存上。**离线上限是这个权衡的旋钮。**

## 3. 离线翻倍广告：它同时买 IPU 和 DAU

离线上限取 8h、玩家一天上线 3 次：

```
方案                   日离线收益   相对基线   广告次数/天
------------------------------------------------------
不看广告                   1200      1.00×        0
只在睡醒那次翻倍            1600      1.33×        1
每次上线都翻倍              2400      2.00×        3
```

> **只在"睡醒那次"翻倍，就拿到了大部分价值**——因为睡眠那一段是唯一能吃满上限的间隔。

**两条设计含义：**

### ① 离线翻倍要按"这次能翻多少"动态展示

睡醒那次弹"+800"，白天那次弹"+280"——**玩家自己会判断值不值。**

> **弹一个不值的广告，比不弹更伤。** 它会拉低玩家对**所有**广告点位的预期
> （[第 05 章](./05-ad-placement.md)的意愿模型里，这等于永久调低了 `THRESH` 那条线）。

### ② 它是"会话开头点位"的最佳人选

意愿预算满、价值最高、**且它本身就是玩家打开游戏的理由**。

### ③ 但它是吃内容寿命最狠的点位

"每次上线都翻倍"那一行让日产出接近 2 倍——按[第 03 章](./03-three-economies.md)的模型，**那会把内容寿命砍掉近一半**（79 天 → 40 天）。

> **⇒ 建议：每天限 1~2 次，并且优先给最大的那一段。**
> **这既是内容预算的要求，也恰好是玩家体验最好的做法——两者难得地一致。**

## 4. Prestige：小团队最划算的长线手段

**Prestige = 重置进度，换一个永久加成。**（Kongregate《The Math of Idle Games》的核心机制）

模型的设定（**两个机制缺一不可**，见 §4.2）：

```
一轮内进度会饱和：   P(c) = P_MAX · c / (c + 8h)        ← 升级成本涨得比产出快
每次重置有固定开销： 重爬早期流程要花 3 小时，与本轮玩多久无关
prestige 收益：      √P                                ← 递减（第 10 章的药）
```

```
重置周期   总重置次数   本轮进度(满额%)   60天后的加成   相对最优
--------------------------------------------------------------
  0.5h       411            6%           35.7        64.2%
   1h        360           11%           48.8        88.4%
  1.5h       320           16%           53.8        97.8%
   2h        288           20%           55.0       100.0%   ★
   3h        240           27%           52.4        95.2%
   4h        205           33%           47.5        86.0%
   6h        160           43%           38.5        69.5%
   8h        130           50%           31.0        55.5%
  12h         96           60%           22.0        38.8%
  24h         53           75%           10.7        17.9%
```

### 4.1 存在明确的最优周期，两边都变差

| | 为什么变差 |
|---|---|
| **周期太短**（0.5h） | 每轮只吃到 6% 的进度，**而每次重置还要付 3 小时固定开销——开销吃掉了收益** |
| **周期太长**（24h） | 进度早就饱和了（75% vs 20%），**多花 22 小时只多拿一点点** |

### 4.2 这个最优点是两个机制夹出来的，缺一个就不存在

> - **只有饱和、没有重置开销** → 越短越好（无限刷）
> - **只有开销、没有饱和** → 越长越好（永远别重置）
>
> **设计 prestige 时这两样必须同时有。**

**这是本章第二个"被两个约束夹出来"的结论**（第一个是 §2.2 的离线上限）。**这种结构在数值设计里非常常见，值得形成条件反射：**

> **当你发现某个参数"越大越好"或"越小越好"时，说明你少了一个约束。**

### 4.3 Prestige 的三条设计要点

| 要点 | 理由 |
|---|---|
| **最优周期要"算得出来但要想一想"** | 如果最优是"随时重置"或"永远别重置"，这个系统就没有决策 |
| **加成用 √P 而不是 P** | 线性加成会让"攒一大波再重置"永远最优——**同样是消灭决策**（[第 10 章](./10-idle-production.md)那条通用规律的又一次应用） |
| **每一轮都要比上一轮快** | 这是 prestige 的爽点来源："上次花 6 小时的进度，这次 40 分钟就到了" |

### 4.4 它对 IAA 的特殊价值

> **Prestige 是一个几乎免费的内容延长器。**

[第 03 章](./03-three-economies.md)证明**内容寿命是留存的天花板**，而 prestige **用同一批内容造出了新的进度曲线**——这是小团队最划算的长线手段。

**代价**：它只对"愿意重复"的那部分玩家有效。**第 12 章会讲怎么判断你的玩家里有多少这种人。**
